## TL;DR (read first)
Per 533-ms chunk (8 control steps at 15 Hz), the GPU server (a) runs pi0.5 (LoRA, 16-D state/action, 3 RGB views 224x224) to get a 50x16 absolute-joint chunk, (b) runs a *second copy* of the same checkpoint to read one attention cell (layer 8, head 2, first denoise step, last action-token query) as three 16x16 maps, (c) lifts the maps to 3-D by back-projecting the 3 MuJoCo depth images (480x640), fuses them on a 10 mm voxel grid (attention = max over views), (d) clusters 3-D points grown from top-5 % attention seeds, keeps only graspable (narrowest PCA extent <= 71.46 mm), non-destination clusters, stabilises the choice over 3 frames -> "manipulated object" (Target), (e) builds a cuRobo Mapper TSDF (5 mm) -> 2-tier ESDF (20 mm coarse / 5 mm fine, 128^3 each) over ALL depth (robot pixels masked), plus a *target-free* fine layer (ball around the Target removed above the table) that **only the active hand's gripper links** query, (f) solves a 3-iteration SQP (OSQP) over the 14 arm joints for the 8 executed steps: track the policy chunk, smooth, continuity, joint/vel/acc limits, linearised clearance rows `d - r - margin >= 0` for 122 tiny gripper spheres (margin 0 in T39), (g) a verdict/HOLD gate decides if the client executes the refined chunk or freezes the arm. cuRobo is used only for TSDF/ESDF (Mapper); trajectory refinement is project-written SQP/OSQP. The registry snapshot described here records T39 (48 paired runs, clear scene, apple/left arm, simulation): E0 30/48 vs E3b 29/48, McNemar p=1.0; E3b not real-time (1.29 s median vs 0.533 s period).

IMPORTANT global caveat: several READMEs (benchmark/trajopt/README.md, benchmark/ag3s/README.md) are 14-D-era (chunk[50,14], "TO: 미구현"). Code is 16-D; trust code over those READMEs.
Another caveat: defaults in code != the evaluated T39 E3b configuration. T39 E3b flags are in outputs/verify/T39/p/start_server.sh and run_client.sh (quoted below in §8). Always describe the *evaluated* configuration, and say where defaults differ.

## 1. End-to-end data flow per control step

### 1.1 Two processes
- **Client (sim)**: MuJoCo (RB-Y1 scene `model_transport.xml`, headless OSMesa) + control loop `pi05_TO_hybrid/rby1_bringup/pi05_infer.py` (run on local PC in the original setup; in T39 run on the GPU server too, `run_client.sh`). **[CODE]**
- **Server (GPU)**: `benchmark/trajopt/serve_safe.py` — loads pi0.5 policy, wraps it in `SafePolicy` (`benchmark/trajopt/safe_policy.py:85`), websocket, one process runs pi0.5 + a second copy of the checkpoint for attention + AG3S + cuRobo field + SQP/OSQP TO. **[CODE]** serve_safe.py docstring L1-30.
- E0 = same server started with `--no-safe` (only a `SeededPolicy` wrapper, no AG3S/TO) (outputs/verify/T39/p/start_server.sh). **[CODE]**

### 1.2 Timing constants (client)
- `CTRL_HZ = 15` (pi05_infer.py:142) -> control period 66.7 ms. `OPEN_LOOP_HORIZON = 8` (pi05_infer.py:143): a new chunk is requested every 8 control steps -> 533 ms per chunk. **[CODE]**
- MuJoCo timestep 0.002 s (model_transport.xml:10) -> `steps_per_action = round(1/(15*0.002)) = 33` physics steps per control step (pi05_infer.py:1339). **[CODE]**
- Policy chunk length H = 50 (`Pi0Config.action_horizon: int = 50`, pi05_TO_hybrid/openpi/src/openpi/models/pi0_config.py:26), padded action_dim 32 (pi0_config.py:25); 16 valid columns. **[CODE]**
- Receding horizon: server returns the full 50-row refined chunk, client executes only rows 0..7 (`chunk_step` 0..7), then re-captures and requests again (pi05_infer.py:1716 `if chunk is None or chunk_step >= OPEN_LOOP_HORIZON`). TO plans only the executed window by default (`HorizonConfig.plan_horizon = "execution"` -> `planned == execution_length == 8`; benchmark/trajopt/config.py:33-122); rows 8..49 are returned as the policy's own (unrefined) output. **[CODE]**

- A T39 run = `--max-steps 600` control steps = 75 chunks (run_client.sh; LOG T38 "한 run 은 75 chunk"). `--warmup-steps 1000` (=2.0 s sim) deterministic warm-up before first inference. **[CODE]**

### 1.4 Action channel semantics (16-D)

- Optimiser variables: 14 joints (both arms, 7 each); grippers (cols 7, 15) and padding passthrough unchanged byte-for-byte (`ChunkLayout.passthrough`, `SafePolicy._preserve_grippers` safe_policy.py:1299); torso/head are fixed (`fixed_q`) but enter FK. **[CODE]** (types.py:51-75, 162-200)

The right arm is still an optimisation variable, but contact-authorisation and collision rows concern the gripper links under `--links gripper` (see §5/§6). **[CODE]**

## 2. Attention extraction from the VLA

- Model: the same pi0.5 (PaliGemma-style: SigLIP image encoder + Gemma-2B LoRA prefix; Gemma-300M LoRA action expert). Attention is read from the **action expert's suffix queries attending to the prefix keys** (image tokens) — cross-attention from action tokens to image tokens. (pi05_attention.py `_suffix` L~133-155 in benchmark/ag3s/experiments/sources/pi05_attention.py.) **[CODE]**
- Why a second model copy: `Pi0Config.return_attn_probs=True` breaks `Pi0.sample_actions` (3-tuple unpack), so `AttentionPolicy` (benchmark/trajopt/attention_policy.py:1-30) loads a **second copy of the same checkpoint** with the flag on and drives `PaliGemma.llm` directly via `AttentionSampler`. The served actions come from the untouched original policy; attention comes from a separate forward pass (not the same denoising trajectory/noise as the served action: it starts from `noise_seed=0` Gaussian noise). **[CODE]**
- Cell actually used in serving (hard-coded): **denoise step 0 (first Euler step, t=1), aggregation `last` (attention of the LAST of the 50 action-token queries), layer 8, head 2** (attention_policy.py:38-41: `_DENOISE_STEP=0, _AGG="last", _LAYER=8, _HEAD=2`). Gemma-2B: 18 layers x 8 heads (multi-query, K=1; LOG term table "18 × 8 × 3 × 3 = 1296 cells"). **[CODE]**
- Token layout: prefix = 3 images x 256 tokens (16x16 SigLIP patch grid at 224 px, patch 14) -> keys 0-255 `cam_high`, 256-511 `cam_left_wrist`, 512-767 `cam_right_wrist`; language tokens start at 768 (policy_record.py:43-51 `CAMERA_BINDINGS`, `LANGUAGE_TOKEN_START=768`). Output = per-camera `[16,16] float32` **raw softmax mass** (softmax is over all keys incl. language/state tokens and suffix, so image-token mass does not sum to 1; values ~ 1/768 scale); no normalisation on the server (attention_policy.py:55-60, 118-131). **[CODE]**
- Aggregation over layers/heads: none — a single (layer, head) cell is used (no head averaging). Aggregation over action tokens: `last` only (AGGREGATIONS: mean/first/last, pi05_attention.py:~60). **[CODE]**
- Cost: only Euler step 0 is evaluated for attention (one prefix pass + one suffix pass), plus the `kv_L4` subtask feature from the same prefix pass (attention_policy.py doc "Cost"). **[CODE]**
- How the cell was chosen: LOG T1-a: `denoise 0 · agg last · L8H2` came from the **14-D era** study `docs/archive/step-verification-20260904/step-01-attention.json` (hit_rate 1.0 on 44 frames, prompt "put the apple in the basket"); it was NOT re-selected for the 16-D model. A 1296-cell sweep on 16-D records found `peak_on_target` 0 for **cam_high** in every cell because the apple is never visible in the head camera (0/15, 0/50 frames; visible only in `wrist_cam_l`: 15/15, 42/50 frames; LOG §T1-a lines 1217-1300). Grounding therefore effectively relies on the left-wrist-camera attention. **[LOG]**
- Per-camera attention is attached to each camera's depth observation (`wire.unpack_camera_observations`, wire.py:524-551 `attention_map=attention.get(cam)`); AG3S then treats a `[16,16]` array as a patch grid (`GridAttentionAdapter`, stages/attention_lifting.py:~150-205). **[CODE]**
- Upsampling: bilinear with pixel-centre alignment from 16x16 to depth resolution 480x640 (attention_lifting.py `_resample`; `attention.interpolation: "bilinear"`, config.py:109). The policy images were 4:3 squashed to 224x224 — the squash leaves normalised image coordinates unchanged, so the 16x16 grid maps linearly onto the 480x640 depth frame (policy_record.py:603 doc). **[CODE]**
- Subtask label (side product, same prefix pass): linear probe on `kv_L4` (layer-4 V cache, head 0, [mean over text tokens | mean over 768 image tokens], 512-D) -> p(pick/place/home) used by the "subtask gate" (§4). (attention_policy.py doc; stages/subtask_probe.py; LOG SUBTASK §). **[CODE+LOG]**
- Note: SEAM (benchmark/seam_vla) is part of the repo but **not in the evaluated pipeline** (serve_safe uses pi0.5 -> AG3S -> TO; SEAM only mentioned in the module docstring). [CODE: no seam flag in serve_safe argparse]. Do not describe SEAM as part of the method.

## 3. 2D -> 3D lifting and multi-view fusion

Orchestration: `AG3S._run` (benchmark/ag3s/runtime/pipeline.py:1249-1560) -> `fuse_observations` (benchmark/ag3s/runtime/multiview.py:407) for 3 cameras. Order: per-camera [back-project -> self-filter -> attention lifting] -> fuse on base-frame voxel grid -> support-plane RANSAC -> grounding -> ... **[CODE]**

- **Depth use (two consumers, same depth)**: (a) point cloud path (`backproject`, stages/reconstruction.py:58-108): pinhole `X=(u-cx)Z/fx, Y=(v-cy)Z/fy, Z=D`, then `T_base_cam`; valid iff `depth_min=0.05 m <= D <= depth_max=3.0 m` (config.py:493-494) and radial `range_max` (server default `--range-max 2.0 m`, serve_safe.py:1017; passed as `pointcloud.range_max`), voxel-downsampled (`pointcloud.voxel_size 0.005`, `max_points 200000`, deterministic "voxel growth" cap; config.py:490-492). Used for **target grounding / clustering / support planes**. (b) TSDF path: the (self-filtered) depth images go to cuRobo `Mapper.integrate` (§5), used for the **collision field**. The robot-self mask is decided once per camera at full resolution and reused for both (T38 B2, pipeline.py:2104-2146). **[CODE]**
- **Calibration**: intrinsics from MuJoCo `cam_fovy` (square pixels, principal point at image centre; mujoco_source.py:229-238); extrinsics through URDF FK at capture state: `T_base_cam = FK(q_capture, mount_link) @ T_link_cam` (multiview.py header; `CameraObservation.resolve_T_base_cam`), `T_link_cam` solved from MuJoCo poses (mujoco_source.py:998-1015). Simulation: no calibration error beyond URDF-vs-MJCF kinematics mismatch (measured by `link_pose_error`, value not collected here). Per-camera capture-time `robot_state` is used (no global `q_now`). **[CODE]**
- **Freshness validity**: `TimingConfig` max_state_age/transform_age/camera_skew 0.1 s each (config.py:1301-1303); exceeded -> frame validity degrades (`DEGRADED`/`INCOMPLETE`) -> `geometry_certified=False`. In sim all cameras get the same frozen stamp (`stamp_mode=sim_frozen`, wire.py). `max_field_age_sec=None` (not checked) by default. **[CODE]**
- **Attention lifting** (stages/attention_lifting.py): server delivers `[16,16]` raw map per camera; adapter `GridAttentionAdapter` -> bilinear (pixel-centre aligned) upsample to depth resolution (480x640) -> every reconstructed point reads the map at its source pixel `uv` (integer lookup). **Never removes points for low attention** (`lift` returns exactly `len(cloud)` entries; header comment). Raw and normalised values are both kept. **[CODE]**
- **Fusion** (`fuse`, multiview.py:313-404): all cameras' points are put on a base-frame voxel grid of `timing.fusion_voxel_size = 0.01 m` (config.py:1301); one representative = an actually observed point (first in input order — deterministic), all observations (camera, uv, time, attention) retained in CSR. **Attention aggregation across views = `max` of raw attention over the observations falling in the voxel** (`np.maximum.reduceat`), then **normalised once after fusion** (F2 fix: per-camera normalisation made `max` choose the most generously scaled camera) with `normalization = "percentile"` over `percentile_range = (5, 99)` -> [0,1] (attention_lifting.py `normalize_attention`; config.py:104-107). Rank order is preserved. **[CODE]**
- **Is attention used to pick which geometry becomes an obstacle?** No: README contract ("Attention picks target only; geometry decides what can collide") and `lift` never drops points. All depth enters the TSDF regardless of attention; attention only seeds grounding (§4). **[CODE]**
- **Support surfaces**: deterministic RANSAC planes (`max_planes=2`, `distance_threshold 8 mm`, `min_inliers 500`, normal within 25 deg of +z; config.py:641-650) fitted on the fused cloud; used to (i) exclude support-plane points from grounding (`exclude_mask=support_mask`), (ii) cut the target-exclusion ball at the table plane, (iii) lift the held-object spheres off the table (J1). The live ESDF path does **not** carve support surfaces (`exclude_support_surfaces=False`): the table stays in the field. **[CODE]**
- **Self-filter / robot mask** (stages/robot_filter.py): ball query of points against the robot's whole-body sphere chain at the capture-time `q` (≈ 194-sphere model per docstring; `filter_robot.n_spheres` logged at start), inflation `self_filter_inflation = 0.0 m` since T26 (config.py:524; earlier 0.05, then 0.02), plus gap-filling capsules for links with no spheres (`UNCOVERED_LINKS`), a "target guard" sphere that stops the filter from erasing the manipulated object near the fingers (`--self-filter-target-guard`), and held-object spheres added to the filter model while an object is held (T32 H1). Masked depth pixels become **unobserved, not free** (pipeline.py:2113-2115). **[CODE+LOG]**
- Numbers about the 3D point clouds themselves (counts per frame, etc.) are not in this sheet; see LOG T38 phase A table for timing. **[LOG]**

## 4. Target grounding: scoring, clustering, TargetConfirm, destination, phase machine, Target vs Obstacle labels

### 4.1 Per-frame grounding (`ground_target`, benchmark/ag3s/stages/target_grounding.py:1611; docstring L1-80) **[CODE]**
1. Peak = argmax of the **un-normalised fused raw attention** over the fused cloud (`attention_cloud.peak_signal`).
2. **Seeds** = points with normalised attention >= 95th percentile (`attention.seed_percentile=95.0`, config.py:105; cap `max_seed_points=4000`, config.py:328) restricted to non-support points (support-plane inliers are masked out of connectivity).
3. **3D growth** (`grow_region` / DBSCAN, `clustering.method=dbscan`, `eps=0.03 m`, `min_points=20`, config.py:143-146): grow from the seeds into the *full* non-support cloud (geometry decides extent, attention only decides which object). Flat attention map -> `NO_ATTENTION`; no seed -> `NO_SEED`; nothing clusters -> `NO_GEOMETRY`-like statuses; failure is reported, never invented.
4. **Cluster score** = `(w_att*mean_attention + w_geo*sqrt(compactness*peak_proximity)) / (w_att+w_geo)` with `w_attention=0.7`, `w_geometry=0.3`, `compactness=exp(-rms_radius/0.05)`, `peak_proximity=exp(-dist(centroid, attention peak)/0.10)` (`_score_cluster`, target_grounding.py:1566-1608; config.py:326-334). Score is used as a **ranking**, not an absolute confidence (`target_score_threshold=0.0` since T5e: "never reject on score"; config.py:166).
5. Admissibility filter (T26, stages/admissibility.py header): a cluster can be the **manipulated object** only if (i) graspable: narrowest principal-axis (PCA) extent <= max gripper opening, **71.46 mm for RB-Y1, computed from the robot model's finger spheres at the finger joint open limit** (not hard-coded; `clustering.gripper_max_opening=None`; fail-closed if unknown) and (ii) not the destination (fewer than `destination_overlap_fraction=0.5` of its points within one voxel of the registered destination). The crate is declared "never a ball / never manipulated, under any circumstances" (user ruling quoted in admissibility.py L10-14).
6. Attention-split (T31b): before a grasp, a cluster whose narrowest extent fits the gripper but whose largest does not is re-clustered at 15 mm; if components' mean attention ratio >= 2.0, the highest-attention-mass component is the target candidate, the rest stay obstacles (`attention_split_radius=0.015`, `attention_split_ratio=2.0`; stages/attention_split.py).

### 4.2 Cross-frame identity: `TargetConfirm` (target_grounding.py:518) **[CODE]**
- Holds a persistent **manipulated object** identity (id, last observed geometry, state `visible | occluded | lost`). A different cluster must be the highest-ranked **admissible** challenger with score >= `target_switch_min_score=0.1` for `target_confirm_frames=3` consecutive frames to replace it (config.py:173, 186, 192). `target_lost_frames=None` (never "lost").
- Hidden != replaced: if the held object produces no cluster, the frame's target is its last observed geometry (`occluded`). Pre-grasp association rule: nearest cluster is the same object only if centroid moved <= object radius and narrowest/middle extents within ratio 2.5 (`manipulated_extent_ratio`); anchor geometry is replaced only if the new observation covers >= 90 % of anchor (`manipulated_anchor_coverage=0.9`, else `subset_kept_anchor`); hand-occlusion suppression: challenger frames do not count while a hand sphere is within 30 mm of the object (`hand_occlusion_reach=0.03`). Frozen (no switch) while a grasp is in progress or an object is attached (`freeze`, pipeline.py:1415).
- **Destination registration** (`DestinationRegistry`, admissibility.py:239): a non-graspable cluster leading the attention ranking at score >= 0.1 for 3 consecutive frames (same object within 60 mm or inside its AABB) is registered as the destination (the crate; it is a free body so cannot come from static geometry). The destination is **never removed from any field**; injectable via `reset(destination_points=...)`.
- Hysteresis was added because frame-independent grounding flickered (ep1807: 2 chunks pear, 1 apple inside crate run; LOG T5d-e). **[LOG]**

### 4.3 "Phase machine" - what actually exists in the evaluated system
- `Phase` enum = `transit | approach | pre_grasp | grasp` (benchmark/ag3s/types.py:30-41) is an **injected external input, never inferred by AG3S** ("AG3S contains no transition logic"). Per-phase clearance scale on contact-authorised links: transit 1.0, approach 0.4, pre_grasp 0.1, grasp 0.0 (+ `contact_permission=True` only in grasp) (config.py:770-780). **[CODE]**
- **In the evaluated closed loop (T39 E3b) the phase is constant `approach`** (`--safe-phase approach` default, pi05_infer.py:801; run_client.sh), with `--safe-manipulators left`. So transit/pre_grasp/grasp phases are *not exercised* in the evaluation; the paper must not claim a perception-driven phase machine for the Method unless it describes this honestly. **[CODE]**

### 4.4 Target vs Obstacle labels - how they are produced
- **Target (manipulated object)** = the highest-ranked *admissible* cluster in the attention-grounded cluster list, stabilised by TargetConfirm; so "Target" = attention + geometry (graspable size, not destination, hysteresis, association) - not attention alone. **[CODE]**
- **Obstacle** = everything else. There is no obstacle detector; the TSDF integrates all depth, so every observed surface (table, crate, other fruit, other objects, unmodelled) is in the field regardless of attention. Low-attention geometry still collides ("attention is only used to pick the target"; README contract). **[CODE]**
- **Destination** (crate) = separate label (`DESTINATION_LABEL`), margin 20 mm for held spheres vs destination (`contact.destination_margin=0.020`, config.py:1151), not excluded. Label layer: cuRobo `site_index` lookup (nearest-surface voxel id) gives "is the nearest surface label X" (curobo_builder.py doc L1-45). (config.py clustering.subtask_gate=True; LOG SUBTASK §§2-9.) **[CODE+LOG]**

## 5. Environment representation: TSDF -> ESDF, two tiers, label layer, Target exclusion, what is NOT excluded

### 5.1 TSDF -> ESDF with cuRobo `Mapper` (fields/curobo_builder.py) **[CODE]**
- One `curobo.perception.Mapper(MapperCfg(...))` integrates the (robot-masked) depth of 3 cameras per chunk into a block-sparse TSDF: `voxel_size = tsdf_voxel_size = 5 mm` (server `--tsdf-voxel 0.005`, serve_safe.py:1260), workspace extent from `default_bounds()` = base-frame box x in [-0.3, 1.2] m, y in [-0.9, 0.9] m, z in [0, 1.6] m (fields/esdf.py:777-790; `esdf.bounds_lower/upper` unset -> default), `truncation_distance`: coarse = `truncation_voxels(3) x voxel_size(20 mm)` = **60 mm** (config.py:819 + docs/term table), fine = **30 mm** (`fine_truncation_m=0.030`, config.py:956; a **second** Mapper with the fine truncation is created, `separate_fine_tsdf`, curobo_builder.py:585-600), `depth_minimum_distance=0.05`, `depth_maximum_distance=3.0` (EsdfConfig 826-827), `max_weight=64` (cumulative weight cap; observation accumulates over the episode: no decay by default `time_decay=1.0`, `frustum_decay=1.0`, config.py:898-902). Depth integrated is the self-masked depth (robot pixels -> unobserved, not free). Unknown space policy `free`. **TSDF is cumulative across chunks within an episode** (residual traces of moved objects persist: see 5.6). cuRobo commit pinned: `78fd485` (curobo_src HEAD; `_assert_curobo_surface`, curobo_builder.py:545-565).
- ESDF from the TSDF with cuRobo's PBA+ (parallel banding) distance transform: sign from TSDF, magnitude = distance to nearest seed (surface) voxel. Grid shape is fixed **128^3 per tier** (cuRobo ESDF grid shape; record: `esdf_shape=[128,128,128]`). `esdf.max_distance=0.4 m` passed by serve_safe (serve_safe.py:810); distances are signed (negative inside surfaces) (LOG 부호 규약).
- **Two tiers**: coarse **20 mm** x 128 = 2.56 m cube (record origin [-0.82,-1.27,-0.47]); fine **5 mm** x 128 = 0.64 m cube (`--voxel 0.020 --fine-voxel 0.005`, T39 start_server.sh). Query = `min(coarse, fine)` wherever the fine tier covers the point (`CuroboEsdfField._evaluate`, curobo_field.py:478-495), gradient taken from the winning tier (curobo_field.py:243-261). Fine window **placement** (`fine_window_placement="hand_swept"`, config.py:1013): axis-aligned box centred on the union of AABBs of the **contact-authorised links' spheres** (current `q_now` + the K=8 executed rows of the policy's reference chunk, each sphere inflated by radius + margin + 2 fine voxels), unioned with the manipulated object's AABB if it fits, else priority hand-now -> executed steps -> object (`place_fine_window`, curobo_builder.py:362-420). (Earlier rule centred the window on the target centroid; T21 replaced it because the window followed the apple to the crate.) **[CODE]**
- Late/old statements to avoid: log term table says window "follows the grounded target centroid" (`build_rollout_fields.py:110`) - that is the *offline* script / pre-T21 rule.
- **Integrator private API use**: the project calls cuRobo's private `integrator._seed_esdf_impl` and `_propagate_and_distance_impl` (instead of `Mapper.compute_esdf`) to remove seed voxels between seeding and propagation (curobo_builder.py:1010-1070). cuRobo itself is unmodified; a start-up assertion checks these private symbols exist. **[CODE]**
- Optional (off in T39): analytic static geometry channel `min(voxel, analytic)` (`--static-geometry none` default; serve_safe.py:1305); temporal decay (off).

### 5.2 Label layer **[CODE]**
- cuRobo's PBA+ keeps `site_index` (nearest surface voxel per voxel); a lookup tells whether a query's nearest surface belongs to a labelled point set (`DESTINATION_LABEL`, `TARGET_LABEL`, `__attached__`), median 0.10 mm vs geometric check (curobo_builder.py:1-45). Used for: destination margin (20 mm only for held spheres whose nearest surface is the destination, linearize.py:751), diagnostics, "which object caused the worst row" attribution. **Target exemption does not rely on labels** (coarse-grid label/value mismatch at the grasp point; curobo_field.py:331-336). **[CODE]**

### 5.3 How the Target is excluded from the collision field (pre-grasp) - policy `exclude_authorized` (T39 E3b flag `--target-field-policy exclude-authorized`; **default is `relax`**, serve_safe.py:1171, config.py:1255)
1. Main layers (coarse + fine) are built from ALL depth, target included - **never altered** (E1 finding: carving the target out of the shared field would also hide it from forearm/torso/other arm; field is anonymous, so exclusion must be by *who asks*). 
2. A separate **target-free fine layer** is built every chunk while: policy != relax, nothing is attached, a manipulated object exists (`visible` or `occluded`) and passed the exclusion gate (`_exclusion_gate`, pipeline.py:1782). It is the fine tier re-propagated with seed voxels **inside an exclusion ball removed** (`TargetBall`, curobo_builder.py `_exclude_ball_seeds`): ball centre = centre of a sphere fitted to the observed surface of the target (`fit_surface_sphere`, radius capped at half the max opening), radius = max(furthest-point distance quantile (`target_ball_quantile=1.0` = max), fitted radius) + `target_ball_pad_voxels (1.0) x fine voxel (5 mm)`, **cut below at the support plane z (+pad)** so the table is not carved (pipeline.py:2781-2850). If the support plane z is unavailable the ball is not built and the layer falls back to point removal (which deleted 0 voxels of the apple in T13) - recorded as mode "points". table/crate/other fruit are still in the target-free layer. **[CODE]**
3. Only **contact-authorised** robot spheres query it: `contact.contact_links` = left: `ee_left, ee_finger_l1, ee_finger_l2`; right: `ee_right, ee_finger_r1, ee_finger_r2` (config.py:785-788), authorised only for the manipulators named in the injected context (T39: `left`). Mask built in `build_constraint_set` (to_adapter.py:227-241). Composition: `d = min(f, max(d_main, b))` inside the target-free window (f = target-free layer distance, b = distance to the window boundary), `d_main` outside - always >= d_main (never creates new violations; curobo_field.py:306-355). `exclude_all` (E1-style: every sphere) exists but is not used. **[CODE]**
4. Contact margin on top (`manipulated_link_margin`): authorised links get `margin_scale x esdf_margin` by phase (approach 0.4, pre_grasp 0.1, grasp 0.0). For rows that ask the target-free layer this phase relaxation is **not** applied (T30 F1: only `esdf_margin`); with `--esdf-margin 0` (T39) margins are all zero anyway. Zero margin != off: a row still forbids penetration (clearance >= 0 against everything left in the field). **[CODE]**
5. If grounding produces no manipulated object, nothing is excluded and everything keeps full clearance (pipeline.py note "no target (...); all geometry held at full clearance") = fail-closed. **[CODE]**

### 5.4 After the grasp: held object becomes part of the robot ("attach"; AttachedCollisionGeometry)
- When the latch reaches HELD (evidence-based, §4.3) `AG3S.attach` is called (pipeline.py:594-810) with the manipulated object's observed points: object admissibility is re-checked (a non-graspable cluster -> `AttachRejected`), reach gate 0.12 m, then the points are fitted by a **surface sphere** (`fit_surface_sphere`, radius <= half max opening) plus small cover spheres for protruding points (<= `max_attached_primitives=4` total), rigidly attached to the palm link `ee_left` (hold_link; parent finger link `ee_finger_l1` for the reach gate) in the *capture-time* frame (T32 H2). Query spheres for the optimiser = fit + 5 mm (docs term table: "질의 구 = fit + 5 mm, self-filter 복사본 = fit + 25 mm"), reflecting pad of one fine voxel (attach docstring). **[CODE+LOG]**
- Field side: with the cuRobo backend the held object's volume (the spheres' volume as fine-voxel points; `n_voxels_freed` coarse+fine in the record) is **set free in the TSDF** (`held_free`, T32 H3: `_free_tsdf_points` sets voxel to +truncation) and its seeds are excluded; held spheres are also added to the self-filter model so the depth pixels of the held object are masked (T32 H1). (`seed exclusion` stays for legacy paths.) If the object stood on the table, a "support lift" (J1) raises the sphere centre by its table-penetration so the sphere bottom sits at table + ESDF surface band (~9 mm). Option `--held-body-cover` (T43 R2, off by default) covers whole body. **[CODE]**
- Held spheres then act as additional robot query points against the **rest of the field** (table, crate, other objects, destination margin 20 mm). Held-vs-own-robot rows exist (`constraint.self_collision=True` default) but E3b runs `--no-self-collision`, so *no* self-collision of any kind is checked in T39 (this is the only self-collision mechanism in the codebase; there is no pairwise robot-vs-robot check) (config.py:1218-1231). **[CODE]**
- `attach_revoked` (T34 J2): false attach is withdrawn after <= `revoke_chunks` executed chunks if the opening keeps closing / is not blocked, the object is observed elsewhere, or it does not follow a lift. **[CODE+LOG]**

## 6. Constrained refinement (benchmark/trajopt/)

### 6.1 Robot sphere model & clearance
- Constraint robot model: `UrdfSphereChain` built from RB-Y1 URDF **capsule collision primitives** (radius/length/origin per link), each capsule filled by a chain of spheres (spacing `sphere_spacing` x capsule radius, <= `max_spheres_per_capsule`, default 8), numpy and CasADi FK are the same code (`_fk_chain`), so self-filter and constraints cannot disagree (robot_models/urdf_sphere_chain.py:1-30; `build_constraint_robot_model`, experiments/reports/grounding_report.py). **[CODE]**
- **T39 E3b constraint model**: `--links gripper` = 2 palms + 4 fingers (`PALM_LINKS+FINGER_LINKS` = `GRIPPER_LINKS`; grounding_report.py:121), `--capsule-radius-scale 0.05 --sphere-spacing 0.4 --max-spheres-per-capsule 32` => **122 spheres, radii 2.6-6.2 mm** (record chunk_00020.npz `sphere_radii`). I.e. the collision geometry of the hand is nearly point-like; coverage of the real mesh is deliberately *not* maintained (the start-up log warns when capsules are not covered, serve_safe.py:1090). Defaults if no flags: radius scale 1.0 (URDF), spacing 1.0, max 8 spheres/capsule. **[CODE]**
- **Clearance (per query sphere i, step k)**: `h_ik(q) = d_ESDF(p_ik(q)) - r_i - m_ik` (`_esdf_clearance`, benchmark/trajopt/linearize.py:652-786; docstring L1-8 "d_esdf(p) - r_robot - margin"), feasible iff `h >= 0`. `d` is the signed field (negative inside surfaces). Query points = robot spheres (+ held-object spheres after attach). `p_ik(q)` = sphere centre by FK at joint config `q_k`. **[CODE]**
- Margin `m_ik`: base `esdf_margin` (**server default 0.05 m** `--esdf-margin`, serve_safe.py:1030; **T39 E3b used `--esdf-margin 0`**), overridden per row: (a) rows whose nearest field surface is the manipulated object and whose link is authorised: `manipulated_link_margin` = phase scale x margin (approach 0.4, pre_grasp 0.1, grasp 0.0 - applied to the base margin) - **but exempt for rows answered by the target-free layer** (T30 F1; they use plain `esdf_margin`); (b) held spheres whose nearest surface is the destination: `destination_margin = 0.020 m`; (c) optional `--obstacle-margin` extra for non-target/non-support obstacles (T41a; default 0 = off; main-only, not in T39). **[CODE]**
- => In the evaluated T39 E3b configuration the safety requirement is `d - r >= 0`, i.e. *zero* extra margin (point-like gripper spheres must stay on the free side of the field), plus a 5 mm linearisation back-off inside the QP. Do not describe it as "50 mm clearance". **[CODE]** (start_server.sh)
- Verdict tolerance: violated iff max penetration > `safety.violation_tolerance = 1e-4 m` (benchmark/trajopt/config.py:664). **[CODE]**

### 6.2 What is optimised
- Variables: chunk joint trajectory `Q in R^{14 x P}` for the **planned window P = 8 steps** (= executed window; `HorizonConfig.plan_horizon="execution"`), 14 = left 7 + right 7 arm joints (ChunkLayout.rby1 arm_joint_dim=7; types.py:162-200); torso/head fixed in FK; grippers and rows P..49 pass through unchanged (`trajectory_to_chunk`: writes only planned rows; `_preserve_grippers`). Plus slack variables: collision slacks (`rows_per_step=24` per step), velocity slack and acceleration slack (kinematic, weighted 10 x `w_slack`). (problem.py:1-46, 120-300). **[CODE]**
- Objective (problem.py:build_problem; objective() L300-340): `w_track*||Q - Q_ref||^2 (track_decay=1) + w_smooth*||Δ²Q||² + w_cont*||Q - Q_prev||²(overlap) + w_slack*||s||₁` with `w_track=1.0`, `w_smooth=0.05` (second difference of position = step-unit **acceleration, NOT jerk** — old docs say jerk), `w_continuity=0.5`, `w_slack=1e3` (config.py:147-158). `Q_ref` = the policy's chunk (physical joint targets), `Q_prev` = tail of the previous chunk **as actually executed** (from `exec_feedback`; aligned by executed step count; `grasp_continuity_off` default False). (safe_policy.py:468-515). **[CODE]**
- Constraints (QP, all in absolute joint coordinates, OSQP form `l <= A z <= u`):
  * box = joint position limits ∩ trust region `|Q - Q_k|_inf <= r` ∩ first-step anchor `|Q_0 - q_now| <= max_step` (a bound, not a pin) (problem.py:200-225). Position range from the MJCF (`limits.source=model_xml`; URDF range was too narrow for arm_6), margin 0.02 rad from hard stops; velocity/acceleration limits from URDF x `velocity_scale 0.9` / `acceleration_scale 0.9`, as softened rows with slack (config.py:214-236). **[CODE]**
  * linearised collision rows `h_ik(Q_k) + ∇h_ik·(Q - Q_k) + s_ik >= backoff`, `s >= 0`, with `backoff = reduction.linearization_backoff = 5 mm` (append_collision_rows, linearize.py:1679-1720; config.py:380). `∇h = (∇d(p)) · ∂p/∂q`: ESDF gradient from the same tier that supplied the distance (`gradient()` uses the winning layer; for target-free rows the target-free distance/gradient) times the sphere position Jacobian. **[CODE]**
  * Row selection (fixed sparsity): per step only the `rows_per_step=24` smallest-clearance rows among (S query spheres x ...) with `h < activation_band=0.35` are shown to the QP, remaining rows are inactive placeholders; **every returned trajectory is re-checked on ALL rows at full resolution** (`_finish` -> `worst_row`), so pruning can cost convergence but cannot hide a violation. Active-band rule needs `activation_band > trust_radius` (config enforces). **[CODE]**
- Algorithm (sqp.py `solve`, L125-470): real-time-iteration SQP. Initial iterate = reference (or the mean of reference and the shifted previous solution only if the plan window < full horizon: here it is skipped since P = K). Loop for at most `sqp.max_iterations = 3` iterations (and at least `sqp.min_iterations = 3`; the wall-clock budget `time_budget_ms = 50` is only checked after the minimum): linearise -> assemble QP -> OSQP solve (warm start; `eps_abs = eps_rel = 1e-3`, `max_iter = 4000`, no polish; config.py:511-525) -> evaluate **merit = cost + w_slack * max violation (full resolution)** -> accept if merit <= current merit; trust region `r0 = 0.15 rad`, x2 on accept (max 0.6), x0.5 on reject (min 0.01); stop on step < 1e-5 or QP failure shrinking below min. Best iterate by merit is returned; a limit-only violating reference falls back to its projection onto the limits (T31 G2-ii). **[CODE]**
- Return status: `OPTIMAL` (converged inside budget), `FEASIBLE` (budget/iteration cap hit but no violation), `VIOLATED` (max violation > 0.1 mm *or* geometry not certified: "clear" is a statement about the model, not the world), `SOLVER_FAILED`, `UNCONSTRAINED` (no geometry; NOT safe) (sqp.py:632-700; types.py:29-48). A violated trajectory is still returned (best effort) together with the worst row identity. **[CODE]**
- QP solver backend: OSQP (`qp.solver="osqp"`; alternatives proxqp/highs allowed; `ipqp` aborted the interpreter and is excluded; benchmark in trajopt/README.md: osqp 2.6 ms re-solve on 1,884 vars / 4,116 rows vs highs 332 ms). **[CODE+README]** README numbers are 14-D, H=50 era.

### 6.3 Gate and HOLD logic
- Server verdict (`SafePolicy._verdict`, safe_policy.py:1316-1420): reasons list; `safe = no HOLD-class reason`. Execute-class: `allowed_contact` (every violating row is an authorised gripper link vs the manipulated object), `budget_only`, `occluded_target`, `uncertified_waived`, `subtask_no_target`. HOLD-class: `collision` (violation by an unauthorised link or vs a non-manipulated object, > tolerance), `uncertified` (geometry not certified), `unverified` (solver failed/unconstrained, or authorised-link rows answered by an unresolved tier), `comms` (client: timeout/stale/error), `no_perception`. Unknown kind => HOLD (fail closed) (wire.py:120-150, GATE_DEFAULT). **[CODE]**
- `geometry_certified` (types.py:962 property, safe_policy.py:1574): AG3S's own claim that the scene was fully accounted for (all cameras fresh, no capped/incomplete point cloud, etc.); `False` forces `VIOLATED` in the optimiser even with positive clearance (`require_certified_geometry=True`). In the subtask gate path "target deliberately cleared" frames are certified. **[CODE]**
- Client (pi05_infer.py:~1950-2000; `--safe-gate reasons` default; T39 E3b: `--safe-timeout 120 --safe-hold-mode fixed`): HOLD => none of the 8 policy rows are executed; arm joint target frozen at `q_hold` (the last commanded `d.ctrl` at HOLD entry) and gripper command frozen at its last value; the next request is made at the next chunk boundary with the `exec_feedback` saying n_hold=8. Unlimited consecutive HOLD unless `--safe-max-hold-chunks` (None). HOLD on T39 E3b: 294 / 3,600 chunks, 18/48 runs had >=1 HOLD; kinds `collision` 198, `uncertified` 89, `unverified` 62 chunk-level counts (they can co-occur) [LOG T39 §"HOLD", SUBTASK table]. **[CODE+LOG]**
- Important caveat for the paper: HOLD freezes the arm; "a HOLD is a safe action" is **not established** (CLAIMS.md: HOLD counts must not be read as improved physical safety).

### 6.4 Rigid vs movable spheres (the LOG term) - status in code
- `rigid_spheres(...)` (constraints/attached.py:304-340) classifies robot spheres whose distance to the held object cannot be changed by the optimised joints (probing random perturbations of free joints, 24 trials, scale 0.3 rad, tolerance 1e-6) to avoid unsatisfiable held-object-vs-robot self-collision rows. **It is only referenced by `tests/ag3s/test_rigid_spheres.py`; nothing in benchmark runtime calls it** (grep), and E3b disables held-vs-robot rows entirely (`--no-self-collision`). In the live path, the "not a movable constraint" set is the explicit allow-list `attached.allowed_contact_links` via `self_collision_mask` (attached.py:~370). So **do not describe rigid/movable sphere splitting as part of the evaluated method**. **[CODE]**

## 10. Known limitations / assumptions the paper must state honestly

Scope of the T39 registry entry: MuJoCo simulation only; one robot (RB-Y1, fixed base); one task family (`randomized_pick_place`, `place_one`, container = basket/"crate"); the 24 evaluated episodes are all **test-split (1800-1999), target = apple, left arm, 3 distractor fruits (banana, orange, pear), no extra obstacles ("clear scene")**, prompts = 3 paraphrases ("Place the apple into the basket." / "Pick up the apple and place it in the basket." / "Put the apple in the basket."), verified in `pi05_TO_hybrid/data/rby1_randomized_pick_place_16d_v1/meta/randomized_episodes.jsonl` (all 24: `used_arm=left`, `target_fruit=apple`, `grasp_retries=0`, `recovery_type=None`). **[CODE/DATA]**

1. **Simulation only.** Depth is MuJoCo-rendered (no sensor noise/holes/flying pixels), quantised to 1 mm; camera intrinsics are exact; extrinsics via URDF FK with MJCF-derived hand-eye (mismatch between URDF and MJCF chains is absorbed into calibration; per-link error `link_pose_error` not quoted here). Robot state is exact joint positions. All three cameras are rendered at one frozen sim instant (`stamp_mode=sim_frozen`); the **simulation is paused while the server computes** (synchronous loop) so no latency-induced error appears. Real-robot experiment P006 is optional/planned, no data. **[CODE]**
2. **Not real-time in the evaluation**: E3b round trip median 1.29 s vs 0.533 s period (all 3,552 chunks over; first chunk after reset ~2.8 s median); E0 median 0.22 s. Real-time claim C007 is `NOT_ESTABLISHED`; AG3S+TO alone replay 314.5 ms median (offline T38). **[LOG, EVID]**
3. **Task success is not preserved/improved**: E0 30/48 vs E3b 29/48; discordant 8 vs 7; McNemar exact p = 1.0; no non-inferiority margin or sample-size plan fixed (METRICS.md "TBD"); do not write "preserves performance" or "no loss". **[EVID]**
4. **No physical-safety metric in the registered evidence.** Success is defined by apple lift >= 50 mm (planning-row z vs initial) and last-planning-row apple centre inside crate bounds (|x|<0.077, |y|<0.137, -0.052<z<0.075 m in the crate frame; outputs/verify/T39/s23/analysis.json). Collision rate, safe-success, true clearance (M002-M004) are `NOT_MEASURED` for T39. HOLD counts (294/3,600 chunks, 18/48 runs) are *not* a safety measure and E0's lack of HOLD is not "unsafe". **[EVID]**
5. **Collision checking covers only the gripper (2 palms + 4 fingers)**, with 122 near-point spheres of 2.6-6.2 mm radius and 0 mm margin; forearm/wrist/elbow/torso/head/base have no rows; held-object-vs-robot self-collision is off (`--no-self-collision`), and there is no robot-vs-robot pairwise check anywhere. The sphere model covers only a fraction of the real hand mesh (16 % palm / 35 % finger surface points within 2.5 mm; T43 R). So the correct claim is "gripper-link clearance against the observed field", not "collision-free". Evaluated checks are at command waypoints only (the position servo lags the command; between-waypoint sweeps exist only with T43 Q, not in T39). **[CODE, LOG]**
6. **Target is excluded only for the active hand's three gripper links and only while a manipulated object exists/not yet attached;** the field itself is unchanged for everything else. A wrong target (e.g. a neighbouring fruit merged with the apple) would be silently exempted for the authorised links; mitigations (admissibility, association, anchor, attention split) are heuristics tuned on the T14/T17/E3 recordings (thresholds were fit on 3 episodes: 1807/1800/1808 + a few records; e.g. extent ratio 2.5 from 155 associations of one apple). **[CODE+LOG]**
7. **Phase is injected and constant (`approach`), manipulator injected (`left`);** AG3S does not infer phase or arm; the grasp latch does grasp-state inference from executed commands and measured gripper opening. The `grasp`/`pre_grasp` phase rules were not exercised in T39. **[CODE]**
8. **Grounding depends on attention from a single hard-coded cell (L8 H2, denoise 0, last-token)** chosen on a 14-D model and prompt "put the apple in the basket", never re-selected for the 16-D checkpoint; in the T1-a records the apple is visible only to the left wrist camera (head cam 0/65 frames), so grounding is effectively wrist-camera attention. No registered grounding-accuracy metric (M005 NOT measured). The attention forward is a separate model copy with a fixed noise seed, so it is not the same denoising pass that produced the served action. `has_target` means "a cluster was selected", not "correct" (T1-a: with the stale 14-D cell on a 50-frame 16-D record, `has_target` 31/50 but `on_apple` 0/50). **[LOG]**
9. **Destination (crate) identification** relies on "attention leader that is not graspable (narrowest extent > 71.46 mm) for 3 frames"; goal objects that are graspable-sized (bowl, plate, stacking) are not covered; the LOG states it as unmeasured (SUBTASK §1). Subtask probe (gate) is a post-T39 alternative, validated on pick/place/home with 0.98 val / 0.96 closed-loop accuracy, **not part of the T39 evidence**. **[LOG]**
10. **Field limitations**: TSDF is cumulative and has no decay: traces of moved objects can persist; unobserved space is treated as free (`unknown_policy=free`, block-sparse TSDF cannot report an unknown fraction); thin walls seen from one side can have a zero-width negative band; 20 mm coarse tier has up to half-voxel discretisation bias (-10 mm, "safe-side"); coarse tier (60 mm truncation) vs fine tier (30 mm) answers differ; distances > `max_distance` are clipped. Depth masks of the robot rely on the sphere model (inflation 0), leaks fixed by model edits (gap-filling capsules). **[CODE+LOG]**
11. **Held-object model**: spheres fit to partial observations (fit + pad), snapshot at capture-time pose; attach evidence thresholds heuristic; `attach_revoked` handles false attach; T43 S measured the held sphere covering only 43-64 % of the apple mesh (bottom contact 3.6-15.5 mm outside). **[LOG]**
12. **cuRobo dependence**: private API of the integrator pinned to commit 78fd485; update requires re-validation. cuRobo's MotionGen/optimiser not used or compared. **[CODE]**
13. **Solver**: 3 SQP iterations, OSQP eps 1e-3, 24 rows/step; a chunk may end `VIOLATED` (returned best-effort; then gate decides). Only the first 8 rows are refined; rows 8-49 are the policy's own output. Joint-limit and velocity/acceleration are soft (slack) rows. Gripper channel never refined (pass-through). **[CODE]**
14. **Right arm**: both arms' 14 joints are optimisation variables, but contact authority and held-object logic are built for the manipulator injected by the client (T39: left only). Right-arm pick was found to be a *policy* (demonstration grasp pose) problem (T43 S). **[CODE+LOG]**
15. **Policy-level confounds**: E0 is non-deterministic across processes unless seeded (S1: `policy_seed` re-keys the JAX RNG per episode; autotune off for bitwise reproducibility across servers: S2-1 passed).
