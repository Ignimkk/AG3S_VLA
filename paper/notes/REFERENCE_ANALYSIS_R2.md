## 1. VLSA / AEGIS  (file: VLSA_...Plug-and-Play_Safety_Constraint_Layer.pdf, 8 pp)
- Exact title: "VLSA: Vision-Language-Action Models with Plug-and-Play Safety Constraint Layer" (p1)
- Authors: Songqiao Hu*, Zeyi Liu*, Shuang Liu, Jun Cen, Zihan Meng, Shihefeng Wang, Xiang Li, Xiao He† (Tsinghua Automation / IEBR; TetraBOT; DAMO Academy Alibaba) (p1)
- Venue/id as printed: "arXiv:2512.11891v2 [cs.RO] 2 Jul 2026" (p1 margin). No conference/journal venue printed -> venue NOT PRINTED. Format is IEEE-style (robotics) preprint.
- Problem: VLAs ignore hard collision safety; naive CBF integration has a perception gap (raw pixels -> geometry) and a semantic gap (treats task-needed objects as obstacles -> over-conservative) (p1).
- Method (AEGIS = Action Execution Guarded by Invariant Safety; architecture named VLSA): (1) a VLM (GLM-4.5V, p5) gets the instruction + agent-view RGB and is prompted to name the SINGLE most critical non-robot obstacle (p3); (2) GroundingDINO localizes that name -> top-confidence 2D box -> back-project with depth from agent-view + auxiliary back-view camera, fuse point clouds, workspace crop, drop farthest 20%, DBSCAN largest cluster (p3-4); (3) fit MVEE ellipsoid to obstacle and fixed ellipsoid Qef=diag(0.06,0.12,0.11) m to end-effector; (4) CBF h(x) from ellipsoid-to-tangent-plane signed distance (Eq.9); QP min||u-u_vla||^2 s.t. h_dot >= -alpha(h), alpha(h)=10h, applied per control step to the VLA's EE velocity command (Eq.2, p3-5). Forward-invariance theorem (Thm 1, p5) is conditional on perfect perception/enclosure.
- Eval: SafeLIBERO (own benchmark): 16 tasks over 4 LIBERO suites x Level I (obstacle near target) / Level II (obstacle blocking path) = 32 scenarios x 50 episodes = 1,600 episodes (p2,p5). Base pi0.5-LIBERO, baseline OpenVLA-OFT. Franka Panda OSC_POSE, 20 Hz (p5). Metrics CAR/TSR/ETS. Table I (p6): translational-only avg CAR 77.9% / TSR 68.1% / ETS 262.3 vs pi0.5 18.7/50.9/278.2 vs OFT 15.1/22.8/323.2; full action space AEGIS 68.9/67.5/257.6 vs pi0.5 17.1/57.8/260.8 vs OFT 5.7/26.2/313.9. SC layer 0.356 ms/step on RTX 4090, 1.86% of cycle (p6-7, Fig.10). Real-world: Franka + pi0.5-DROID zero-shot, 2 tasks x 2 levels, qualitative only (supplementary video), no numbers in main text (p7).
- Stated limitations (p7): residual collisions from obstacle misidentification / inaccurate grounding / aggressive point-cloud filtering; only the END-EFFECTOR is constrained so other links may collide; "safety-induced distribution shift" (avoidance drives policy OOD, e.g., higher altitudes); future work: dynamic obstacles, whole-body avoidance.
- vs OUR IDEA:
  * Target-vs-obstacle separation: via an EXTERNAL VLM (text reasoning) + GroundingDINO, picking ONE obstacle by name. NOT the VLA's internal attention. Closest conceptual overlap: explicitly states the problem "treating necessary objects as obstacles" (p1) and solves it by only naming the obstacle (implicitly excludes the Target). So the claim "Target excluded from the collision constraint" is functionally present here but by obstacle-whitelisting (single obstacle) not by target-removal from a dense field. FLAG: overlaps the motivation of Target exclusion.
  * Collision representation: one MVEE ellipsoid for ONE obstacle + EE ellipsoid; no TSDF/ESDF, no scene-level field, no multiple obstacles/unmapped clutter.
  * Refinement: per-step reactive CBF-QP on a single-step EE velocity (6-D Cartesian), not constrained refinement of an action CHUNK; no trajectory optimization, no joint-space/whole-body.
  * Authority: EE-only; paper itself lists whole-body as future work -> supports our whole-body/payload/contact claim as a gap. No payload/contact modelling seen.
  * Attention use: none (UNVERIFIED beyond text; no attention maps mentioned anywhere in the text).
- Overlap flags: (a) "plug-and-play, training-free safety layer on top of pi0.5" is the same framing as ours; (b) "first approach that integrates CBFs into VLA" (p2) - not a conflict (we use ESDF refinement). (c) Level I benchmark (obstacle near target) is exactly our Target/Obstacle confusion case.

Obstacle-avoidance Table II (p6), 5 trials per obstacle, 'w/o guidance' 0% for all; ours (column mapping inferred from Table III + layout, treat as semi-verified): pouring Bottles 100%, Box 60%, Kettle 80%, Phone 100%, Laptop 60%; Brush-Bottles 40%; Item-in-drawer-Bottles 20%.   * Whole-body/payload/contact: Q* depends on the grasped object size (a crude payload-aware margin, p4) — closest thing to payload awareness; whole-body explicitly future work.

## 8a. cuRoboV2 — "cuRoboV2: Dynamics-Aware Motion Generation with Depth-Fused Distance Fields for High-DoF Robots"
- File: "cuRoboV2_ Dynamics-Aware Motion Generation with Depth-Fused Distance Fields for High-DoF Robots.pdf" (52 pp) + curobov2.txt (same text; I cross-checked key lines in curobov2.txt: arXiv id, "safety layer", "learned RGB-based", ZED/2.5 mm TSDF). - Provides: unified motion-generation stack: (1) B-spline trajectory optimization with torque limits; (2) GPU-native TSDF -> dense ESDF perception pipeline fusing depth + primitives; (3) scalable whole-body kinematics/inverse dynamics/map-reduce self-collision.

### What IS implemented in cuRoboV2 (limits our novelty) — with pages
- Problem formulation (p6, Eqs 1-9): minimize smoothness+length+energy over B-spline control points U; constraints incl. C_scene(FwdKin(theta_t)) <= 0 (Eq 4) and C_robot (self-collision, Eq 5). Re-solving after a short horizon = MPC (p7). Optimizer: L-BFGS per iteration with B-spline interpolation (4 interpolation points per control point, N_interp = 4, p9); loop in Fig. 1 (p7). Table 1 (p5) lists MPPI and L-BFGS solvers, MPC modes; check-mark glyphs were lost in text extraction so the per-framework feature matrix (incl. "Depth" row, "Voxel/ESDF Integrator" row: cuRoboV2 = "ESDF", MoveIt/cuRobo = "Voxel"?) is UNVERIFIED in detail.
- Robot as spheres: "approximating the robot as spheres [60, 67, 69], converting signed distance to point queries" (p9); manipulation spheres 1-5 cm (p11-12), mobile base up to 50 cm; collision cost = approximate swept-volume check between timesteps stepping along the trajectory by signed distance, with CHOMP speed metric scaling (p13); "swept-sphere" in the loop figure (p7). Auto sphere fitting from URDF (appendix, p46-47).
- TSDF (Sec 5.1-5.3, pp9-11): block-sparse, 8^3-voxel blocks, hash table + CAS, per-voxel depth_sum/depth_wt (4 B) + geom_sdf (2 B) float16 channels; query = min(depth, geom) so depth-fused surfaces and known primitives contribute jointly (p9). ~350 MB for 100K blocks, ~11x less than dense (p9). Voxel-centric "Voxel-Project" depth integration, no atomics (pp10-11). Cuboids and meshes stamped analytically (p11). Two-tier weight decay (time alpha_t e.g. 0.99; frustum alpha_f e.g. 0.5) + block recycling for dynamic scenes (p11, Eq 18).
- ESDF (Sec 5.4, pp11-13): dense ESDF on demand at a coarser, task-specific resolution than TSDF (e.g. 5 mm ESDF for 1-5 cm spheres; p11-12), 3 stages: site seeding (gather 7-point stencil, CUDA-graph safe), exact Euclidean distance via PBA+ (parallel banding), sign recovery by adjacent TSDF sample; O(1) trilinear queries anywhere in the workspace (p12). Depth-only surfaces: "we assume positive sign (exterior) outside the truncation band, since depth observations only see the front surface" (p12) — so unobserved/occluded interior is treated as free.
- Benchmarks vs nvblox (Sec 7.6, p30-32): at 10 mm TSDF full coverage, 1.69 ms vs 12.68 ms (7x), 1.63 GB vs 11.87 GB, recall 92.5% vs 92.0%; at 20 mm 1.52 ms vs 2.97 ms, recall 97.0% vs 85.4%, 0.82 GB vs 2.55 GB (p30). Abstract: up to 10x faster, 8x less memory, up to 99% collision recall (p1). Known geometry stamped into TSDF reduced mean planning time 47 -> 38 ms (-19%) (p32). Total planning (IK+TrajOpt) 30.83 ms => >30 Hz (p22).
- Live-depth MPC on a real robot (Sec 7.7, pp32-33): I2RT YAM arm + calibrated ZED Mini stereo camera, ZED Neural Plus depth at 1080p, 15 Hz; robot removed from the depth image by projecting the kinematic sphere model into image space; segmented depth -> 2.5 mm TSDF -> 2 cm ESDF; ESDF drives MPC "avoiding dynamically-observed obstacles", whole pipeline in a single control loop (p32, Fig 23 p33). Robot-segmentation detail (appendix p48): mask any point whose L2 distance to nearest collision sphere is within the radius. => depth fusion, dense ESDF, live-depth MPC are ALL IMPLEMENTED and demonstrated (single obstacle avoidance qualitative, Fig 24; no quantitative real-world table seen in what I read — unverified).
- Eye-to-hand ICP calibration tool + robot-from-depth filtering are shipped (appendix A.1.3, p48).

### What is NOT implemented / explicitly future work
- Learned-policy safety layer: p38 "Limitations & Future Work": "MPC could also serve as a safety layer that enforces collision-free, dynamically-feasible execution of learned policies." => stated as FUTURE WORK, not done. (The only "policies" that appear experimentally are RL locomotion policies trained on cuRoboV2-retargeted references, Sec 7.5.2 pp26-30 — unrelated to VLA/chunk refinement.)
- Learned/RGB semantic segmentation for perception: p38 "geometric robot segmentation is sensitive to depth estimation errors; learned RGB-based segmentation could improve robustness" (future work); single camera gives partial coverage, multi-camera future (p38).
- No notion of Target vs Obstacle: the only masking is removing the ROBOT from depth. Grep over the text for target/exclude/ignore/semantic found only "target poses" for IK/MPC and self-collision ignore matrices (appendix p47). Nothing excludes a task object from the collision field. NO VLA, no attention, no action-chunk refinement of a foundation-model policy anywhere in the paper (grep VLA: no hits).
- Occlusion/unobserved space: depth-only sign is "exterior" beyond truncation band (p12), and voxels with no observation default to positive/exterior (p13) — unobserved space is free; relevant to our grasp-target region.

### Relation / overlap with our idea
- cuRoboV2 already provides the entire back-end we plan to use (depth -> TSDF -> dense ESDF -> sphere-based swept collision cost -> MPC/trajopt) and a real-robot live-depth demo. Our paper cannot claim novelty for the TSDF/ESDF pipeline or for depth-based reactive avoidance. Novelty must sit in (i) deriving Target-vs-Obstacle from VLA internal attention, (ii) removing the Target from the collision field (TSDF stamp/zeroing) so the grasp is not blocked while non-target obstacles still repel, and (iii) coupling this to action-chunk refinement of a VLA policy (a case the authors list as future work: "safety layer ... for learned policies").
- Be careful: an obvious baseline is "cuRoboV2-MPC safety layer with ALL depth in the ESDF" — it will block the grasp at the target. This baseline is exactly what Target exclusion fixes; cite p12-13 for the ESDF treatment and p38 for the future-work statement.
