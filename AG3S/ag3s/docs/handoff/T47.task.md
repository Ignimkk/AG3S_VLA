## 왜 지금 이것인가

AG3S 가 attention 을 쓰는 곳은 하나 — 재구성된 3D cluster 중 어느 것이 **target** 인지 이름을 붙이는 일이다.
지금 그 attention 은 **한 cell** (`denoise 0 · agg last · L8 · h2`, `AG3S/trajopt/attention_policy.py:37-41`) 에서 온다.
그 cell 이 고른 근거는 지금 운영 조건과 다르다:

| | L8H2 를 고른 때 (step-01, 2026-09-04) | 지금 운영 |
|---|---|---|
| model | 14D | **16D** |
| camera | `cam_high` 1 대 | **3 대** (head + 양 wrist, multi-view max fusion) |
| frame | 28 (선택 = 평가 같은 frame) | 여러 episode · 과일 |
| 기준 | `peak_on_target` 하나 (GT 필요) | — |

- T1-a (2026-09-25) 는 *"L8H2 가 16D 에서 성립하는가"* 를 **배선 문제** (offline 이 `zed_left` 에만 attention 을 붙임) 로 닫았고 판정 8 로 배선을 고쳤다. **head 자체는 16D · 3 camera 에서 다시 고르지 않았다.**
- T44b D-merge: per-pixel attention argmax 가 target 위에 놓인 frame — `zed_left` 0/58 · `wrist_cam_l` 1/32 · `wrist_cam_r` 1/32. 그런데도 chosen cluster 는 62/64 frame 에서 target 쪽. **2D map 은 약하고 3D 집계가 그것을 메우고 있다.**
- 논문 근거: 모든 head 평균은 쓸 수 없고, label 없는 두 기준 (① image attention sum ② spatial entropy) + 여러 sample 에 걸친 **selection frequency** 로 고른 **고정 k=3 head 합산**이 1 head 보다 낫다 (Tab.4 평균 RES 64.5 → 67.1). 기준 하나만 쓰면 무너진다 (Tab.5 RES 18.8 ~ 25.7). sample 마다 고르는 greedy 는 고정보다 나쁘다 (63.8 vs 76.1).

```
카메라 depth → 로봇 마스크 → [attention lifting → target grounding] → TSDF/ESDF
                              ↑ 여기: 어느 (layer, head) 의 map 을 넣는가
            → 거리장 어댑터 → SQP 선형화 → QP 해
```

### 우리에게 맞춘 차이 (논문 그대로가 아닌 곳)

1. **query 가 다르다.** 논문은 마지막 *text* token, 우리는 *action* (suffix) token. action token 의 attention 이 **한 덩어리로 모이는 대상이 target 이 아니라 gripper · 목적지 (basket/crate) 일 수 있다.**
   논문도 "localized 이지만 text 와 무관한 head" 를 경고했다 (§6.3). → **GT 로 "무엇에 모였나" 를 class 별로 반드시 분해한다** (측정 #4).
2. **camera 가 3 대.** 논문은 이미지 1 장. 기준을 camera 별 map 에 적용하고, "모든 camera 공통 head set" 과 "camera 별 head set" 을 둘 다 만든다.
3. **attention 값은 renormalize 안 된 raw softmax mass** (`attention_policy.py:57-58`) — 즉 npz 의 768 image token 합이 그대로 논문의 `S_img` 이다.
4. **grid 16×16** (논문 LLaVA-1.5 는 24×24). Gaussian smoothing σ 는 grid 단위 {0, 1}.
5. **최종 판정은 3D end-to-end.** 우리 pipeline 은 2D map 을 3D cluster 점수로 소비하므로 2D 개선이 3D 개선을 보장하지 않는다.

## 구현에 요청하는 것 (→ implementer, Opus)

**새 파일만 만든다.** 산출: `AG3S/ag3s/experiments/studies/t47_head_selection.py` (+ 필요하면 같은 폴더 helper), `tests/ag3s/test_t47_head_selection.py`, `AG3S/ag3s/docs/handoff/T47.impl.md`.

### I1 — 순수 함수 (numpy, GT 불필요)
- `image_attention_sum(cell_maps)` — camera 별 `S_cam` (16×16 합) 과 전체 `S_img` (3 camera 합).
- `spatial_entropy(map16)` — 논문 부록 B.1 Eq.4–7 그대로: `ReLU(A − mean(A))` → **8-connectivity** connected components → `H = −Σ P(C) log P(C)`, `P(C) = |C| / Σ|C|` (raw nats; 정규화 변형을 쓰면 이름을 분리). 성분이 0 개면 정의를 impl.md 에 명시 (예: NaN → 선택 불가).
- `max_curvature_threshold(values)` — 오름차순 정렬 곡선의 최대 곡률 지점 τ (논문 §4.1). 구현한 곡률 정의 (이산 2 차 차분 / Kneedle 등) 를 impl.md 에.
- `selection_frequency(entropy[frame, cell], eligible[frame, cell], n_lowest=10)` — frame 마다 eligible 중 entropy 최저 N 개를 고르고 cell 별 선택 비율.
- `combine_maps(maps, cells, sigma)` — cell 별 Gaussian smoothing (σ grid 단위, σ=0 은 원본) 후 **element-wise 합**.
- 정책 고정 사항: **L0 · L1 제외** (논문 §4), primary query = `denoise 0` (서빙과 같고 가장 싸다) × agg {last, mean, first}; `denoise 4, 9` 는 secondary 로 같은 계산만.

### I2 — GT 추출 (MuJoCo replay, osmesa, CPU)
- 기존 `policy_record.load_run · replay_scene · pose_scene · patch_coverage` 를 재사용해 frame × camera 별 body 의 16×16 **patch coverage** 와 pixel 수를 만든다
  (`AG3S/ag3s/experiments/reports/attention_report.py:94-118` 의 `ground_truth` 가 `zed_left` 만 하던 것을 **3 camera 로**; camera 이름 대응은 `policy_record.CAMERA_BINDINGS`).
- body class: `target` (prompt 대상) · `destination` (basket/crate) · `other_object` (나머지 과일) · `robot` (`mujoco_source.is_robot_body`; gripper/finger 는 `robot_gripper` 로 따로 셀 수 있으면 분리) · `table/support` · `background`.
- **한 번 render 해서 `$AG3S_RUN_DIR/verify/T47/gt_cache/*.npz` 에 캐시** — 이후 분석은 캐시만 읽는다. replay 가 기록 RGB 와 맞는지 frame 몇 개에서 pixel 차이로 자가 점검.

### I3 — 2D 분석 CLI (`--stage select`, `--stage validate`)
- select: selection set 에서 τ (camera 별 `S_cam` 기준 = primary; 전체 `S_img` 기준 = variant), selection frequency, rank, **공통 head set top-k** 와 **camera 별 head set top-k** (k = 1..5).
- validate (held-out, GT 사용): head/조합별 2D 지표 — target mass 몫, **lift** (= target mass ÷ target 면적 몫, step-01 정의), `peak_on_target`, **mean-binarized map vs GT target patch mask IoU** (GT patch mask = coverage ≥ 0.5; 0.25 변형도), **class 별 mass 분해** (target / destination / other_object / robot(gripper) / table / background).
  Spearman ρ (selection rank vs held-out IoU, vs lift) — 논문 Fig.6 (b) 대응.
- 비교 대상 (전부 같은 frame · 같은 지표):
  (a) **L8H2** (현재) · (b) **paper-style top-k** (공통 / camera 별, σ ∈ {0,1}) · (c) head-average (L2–17 전부) · (d) uniform ·
  (e) **GT-oracle** — selection set 에서 GT `peak_on_target`(step-01 방식, 단 3 camera) 으로 고른 best single cell 과 top-3 (**상한 참고용, 채택 후보 아님**).
- target 이 camera 에서 `< 200 px` 인 (frame, camera) 은 2D 지표에서 제외 (step-01 의 `--min-target-px` 관례). 제외 수를 보고.

### I4 — 3D end-to-end CLI (`--stage e2e`)
- **live 서빙과 같은 multi-camera 경로** (판정 8 이후: camera 3 대 각각에 attention map 을 붙이고 `pipeline.process_multi` 로 fusion → grounding) 를 재사용.
  기존 offline 진입점 중 판정 8 정렬이 된 것을 찾아 쓴다; 없으면 **pipeline 을 고치지 말고** 새 study 파일 안에서 같은 호출 순서를 조립하고 그 근거 (file:line) 를 impl.md 에.
- attention source 만 바꾼다: (a) L8H2 · (b) 선택된 top-3 (공통) · (b') top-3 (camera 별) · (c) head-average · (e) GT-oracle top-3. map 은 `{camera: 16×16}` raw 합 (adapter 의 percentile 정규화는 pipeline 이 그대로 한다).
- 지표: `has_target`, **`on_target`** (grounding 중심이 GT target body 에서 0.10 m 안 — T1-a 정의), **silent failure** (`has_target ∧ ¬on_target`), target seed precision / recall (GT seg 기준), chosen cluster 의 target 점 비율, frame 당 ms.
- config 는 **기본값** (T46 의 새 option 은 off). 실행 시점 `git rev-parse HEAD` 와 `git status --porcelain` 을 결과에 기록.

### unit test (`tests/ag3s/test_t47_head_selection.py`, MuJoCo 없이 합성 data)
- spatial entropy: 한 덩어리 → 0; 같은 크기 두 덩어리 → ln 2; 대각선으로만 붙은 두 pixel 은 8-connectivity 로 **한 성분**; 균일 map 처리.
- max curvature: 알려진 knee 를 가진 합성 곡선에서 τ 위치.
- selection frequency: 손으로 계산한 작은 예와 일치; eligible 아닌 cell 은 선택 불가.
- combine_maps: σ=0 은 단순 합; 합의 질량 보존 (smoothing 경계 처리 명시).
- `.venv-ag3s` 로 `pytest tests/ag3s/test_t47_head_selection.py` 통과 + 기존 `tests/ag3s` 회귀가 깨지지 않음 (T46 test 는 다른 session 의 것이므로 실패해도 원인만 기록).

## 되돌아올 지점
- 선택된 head 가 class 분해 (#4) 에서 **gripper · 목적지에 모인다**면: label-free 기준만으로는 action-token query 에서 target head 를 못 고른다 → (i) 기준에 GT 지표를 섞는 supervised 선택 (sim 한정), 또는 (ii) 명사 token query (D) 로 넘어간다.
- 2D 는 좋아지는데 3D (#6) 가 그대로면: 병목이 head 가 아니라 3D 쪽 (merge · self-filter) — head 교체는 보류하고 B/C 또는 T44b 의 merge 원인으로.
- held-out 3 record 가 작아 차이가 frame 몇 개 수준이면: 결론을 내리지 않고 record 추가 (GPU attention pass 필요 — 사용자 승인 사항) 를 제안.
- 채택 (L8H2 교체) 은 이 STEP 에서 하지 않는다 — 결과 보고 → 사용자 판정 → 별도 STEP.
