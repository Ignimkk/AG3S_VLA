## 0. 왜
- T92 (세션 e1/eb) 가 3 단계 gate 의 label 을 학습 분류기 대신 grasp latch 상태로 만들었다 (`--subtask-from-latch`). 9 run 결과는 분류기 gate 와 같았다 (9 / 9, 놓기 전에 gate 가 막은 요청 0).
- 그러나 offline (T77 test 207 run, 허들 211 제외, 장면 평균) 에서 latch 상태만으로 본 단계는 위험한 오판 (정답이 접근 · 쥐기인데 운반 · 놓기로 봄) 이 **2.5 %**, T91b 는 **0.49 %**, 분류기 1.38 % 다 (`verify/T91/t91_eval_A_h4_img3_last.json` 의 `C_latch_only`, `verify/T91b/t91b_eval.json`). latch 는 빈손으로 닫아도 HELD 로 갈 수 있다 → gate label 이 place 가 되면, 쥐지 못하고 다시 쥐려는 run 에서 target 선택이 막힐 수 있다.
- 그래서 같은 9 run 의 성공 수로는 차이가 안 보일 수 있다. **먼저 고정 입력 재생으로 두 출처의 label 이 다른 요청이 있는지, 그 요청에서 gate 결정이 바뀌는지를 보고**, 바뀌는 요청이 있을 때만 closed-loop 를 돌린다.

## 1. 방법
- 새 flag `--subtask-from-phase-machine` (기본 꺼짐). 켜면 `SafePolicy._subtask_gate_input` 이 `PhaseMachine` (T91b 설정: `finger_gap_mode="on"`, `finger_gap_source="depth"`, `gap_tau=0.3`, `gap_m=1`, d 0.03–0.09 m, T91 문턱은 `verify/T91/thresholds.json` 그대로) 의 5 단계를 3 단계 one-hot 으로 바꿔 넘긴다: approach · grasp → pick, carry · place → place, retreat → home (T82 `subtask3_probabilities` 와 같은 대응). AG3S debounce 그대로.
- 요청마다 입력: 측정 개도 (쥐는 손), 쥐는 손 EE site 위치, ATS target 중심 (+ fresh 여부), 목적지 위치, VLA chunk gripper 열 (앞 16 행), 손목 카메라 depth 의 손가락 사이 표면 비율. 결측은 `PhaseObservation` 의 None 규칙대로.
- 단계 출처는 하나만: `--subtask-from-latch` · `--hsr5` · `--hsr-gt-stage` · `--no-subtask-gate` 와 같이 주면 거절. run 사이 `reset()`.
- 기록: `summary_json.subtask_source = "phase_machine"` + `phase_machine` (stage · label · evidence: 개도 정규값 · finger_gap · comotion 판정). 꺼짐이면 key 없음 (기록 bit 동일).

## 2. 평가 (결과 전 고정)
1. **재생 비교 (먼저, 주 판정):** T92 P0m 기록 (storage `20261103T133225+0900_ed0145a692ad_6e6100ee51f4/verify/T92/CL/p0m`, 9 run + 허들 12 run, 허들 211 제외) 의 요청 입력으로 `PhaseMachine` 을 인과적으로 돌려, 요청마다 (a) latch label (기록), (b) phase machine label, (c) MuJoCo 정답 단계 (있으면) 를 낸다. 지표: label 이 다른 요청 수 · 그 중 정답과 맞는 쪽, label 차이로 gate 결정 (새 target 선택 막음) 이 바뀌는 요청 수.
2. **closed-loop (조건부):** 1 에서 gate 결정이 바뀌는 요청이 1 개 이상인 run 만, P0m 서버 인자에서 `--subtask-from-latch` 를 `--subtask-from-phase-machine` 으로 바꿔 같은 seed 로 돌린다 (독점 lock, 서버 1 개). 주 지표 = 금지 접촉 없는 성공 (쥐는 순간 이웃 과일 접촉 면제), 금지 접촉 · 탁자, 놓기 전에 gate 가 막은 요청 수.
3. 판정: gate 결정이 바뀌는 요청이 0 이면 "같은 기록에서 latch 와 구분 못 함" — 더 단순한 latch (T92) 를 기본 후보로 두고 T91c 는 기본 꺼짐으로 남긴다 (벤치마크에서 손목 depth 가 있을 때의 선택지). 바뀌는 요청이 있으면 closed-loop 결과로: 성공 ≥ latch 이고 놓기 전 막음 ≤ latch 일 때만 "더 낫다".
