# SL10 §2.2 — Panda action 한계 제약 (`--to-action-box`) — 구현

> writer: ag3s-implementer · 읽는 쪽: lead, verifier(`wip/sl10-replay` 재풀이 도구 구현자 포함), scribe
> 2026-11-04, worktree `.runtime/worktrees/sl10-actionbox`, branch `wip/sl10-actionbox`, base `62c0076f`. GPU 검증 미실행 (CPU 단위 검증만).

## 무엇을 했나 (평이한 요약)

변환 C 는 TrajOpt 의 작은 수정(몇 mm)을 1/β(위치 14배, 회전 32배)로 키워 action 으로 보내고 ±1 에서 자른다. TrajOpt 는 이 한계를 몰랐다.
이제 `--to-action-box` 를 켜면 TrajOpt QP 에 "변환 C 가 돌려줄 action 이 `[-1+margin, 1-margin]` 안" 이라는 선형 부등식 행이 들어간다.
제약 때문에 충돌을 못 피하면 충돌이 그대로 `violated` 로 남고, 그 뒤는 기존 HOLD/위반 규칙이 정한다(안전 규칙은 건드리지 않았다).
기본은 꺼짐이고, 꺼짐이면 TrajOpt 결과가 HEAD(`62c0076f`)와 bit 단위로 같다.

**주의할 결과:** 합성 chunk 에서 꺼짐은 "충돌 해소(feasible)" 로 끝나지만 그 계획은 action 이 ±1 로 잘리는 계획이다(실행 action 포화 5행 전부).
켜면 포화 0 이지만, 같은 장면이 `violated`(1.4 mm 남음, 깊은 장면은 23 mm 남음)로 끝난다. 로봇이 실제로 낼 수 있는 만큼만 비키기 때문이다.
closed loop 에서 HOLD 가 늘 수 있다 — §3 판정에서 볼 것.

## 설계

### 식 (`AG3S/trajopt/action_box.py` 모듈 docstring 에 전부)
행 k(실행 행 K=5 개), 성분 i(위치 3 + 회전 3, world frame):

```
raw_k,i = a_k,i + g_i (dy_k,i − α_i dy_{k−1},i),   g_i = 1/(β_i·scale_i)
dy_k = R_wb [ (p_k − p_{k−1}) − (pr_k − pr_{k−1}) ;  rotvec(R_k R_{k−1}ᵀ) − rotvec(Rr_k Rr_{k−1}ᵀ) ]
lo_k,i ≤ raw_k,i ≤ hi_k,i,    hi = max(1−margin, a),  lo = min(−(1−margin), a)
```
`p,R` = `panda_grip_site` 자세(`LinkPoseFK`), `pr,Rr` = reference 의 같은 값. `a` = 정책 action 을 [-1,1] 로 clip 한 것.
- 상수는 복제하지 않았다: `action.RESPONSE`(= `osc_response_fit.json`), `OSC_POS_SCALE/ORI_SCALE`, `OSC_INPUT_CLIP` 를 `action.action_box_from_conversion` 이 읽어 `ActionBox` 에 담는다. 모드 A·C 는 lag 역변환, 모드 B 는 α=0, β=1.
- **task 문서와 다른 점 하나:** bound 를 `max(1−margin, a)` 로 넓혔다. 정책 자신이 `1−margin` 을 넘는 성분(예 0.98)이면 문서 식 그대로는 Dy=0(reference) 이 불가능해져, 장애물이 없어도 TrajOpt 가 chunk 를 건드린다. 넓히면 reference 가 항상 안에 있다. 차이는 정책 성분이 (1−margin, 1] 인 경우뿐이다.
- 변환 C 는 clip 이 없으면 A 와 같은 식이다(`action.py` docstring). 상자 안이면 clip 이 없으므로 이 식이 C 의 출력이다. 합성 chunk 에서 예측과 실제 C 출력이 2e-3 안에서 맞는다(test).

### 선형화
SQP iterate X 에서 1차: `p_k(Q) ≈ p_k(X) + Jp_k (Q_k − X_k)`, `rotvec(R_k R_{k−1}ᵀ) ≈ w0 + Jl⁻¹(w0)(Jw_k dQ_k − S0 Jw_{k−1} dQ_{k−1})`, `S0 = R_k(X) R_{k−1}(X)ᵀ`, `Jw` = `LinkPoseFK` 의 공간 각속도 Jacobian. 그래서 `dy_k ≈ c_k + A_k dQ_k + B_k dQ_{k−1}`, 행 k 는 `Q_k, Q_{k−1}, Q_{k−2}` 를 건드린다. X 에서 정확하고 오차는 2차(test).
- **첫 행:** `Q_{−1} = q_now`(고정), `Dy_{−1} = 0`. `action.joint_chunk_to_delta_chunk` 와 같다(`fk_s[0] = fk_r[0] = fk(q_now)`, `dyp_prev = 0`). 그래서 행 0 은 `dy_0` 만, 행 1 은 `dy_1, dy_0`.
- 정책이 이전 chunk 의 마지막 실현 step(`prev_step_world`) 을 갖는 것은 `a_k` 쪽(forward 변환)에 이미 들어 있고, reverse 의 Dy 체인에는 들어가지 않는다 — C 도 마찬가지다.

### QP 형태
`add_action_box`(`grasp_anchor.add_goal_box` 와 같은 방식): 행마다 슬랙 s≥0 하나(새 열, `QpProblem.n_action_slack`, 모든 변수 뒤), `G Q + e − s ≤ hi−a`, `G Q + e + s ≥ lo−a`, `s ≥ 0`. 가격 `w_slack × ACTION_BOX_SLACK_SCALE(=10)` per action unit (L1).
- 부드러운 이유: warm start iterate 가 상자 밖일 수 있고 선형화 오차가 있어도 QP 가 infeasible 이 되면 안 된다. 가격은 충돌 슬랙보다 훨씬 커서(행 하나의 최대 dual ≈ w_slack×0.1 이하), 둘이 부딪히면 상자가 이기고 충돌이 `violated` 로 남는다.
- 행은 SQP 반복마다 새 iterate 에서 다시 만든다(`TrajectoryOptimizer._abox_rows`, `append_collision_rows`·anchor 다음). 희소 패턴은 iterate 와 무관하게 고정(0 항목도 유지, test).
- **merit:** 후보 수락 merit 에 "clip(±1) 을 넘는 정확한 초과" × 같은 가격을 더했다(`_merit_terms`). 상자 안 `margin` 은 선형화 오차의 완충이고, 넘는 것만 벌한다. 이 항이 없으면 선형 행은 지키지만 실제 action 이 포화하는 step 이 수락된다(측정: 초과 0.056). 상자 없는 solve 는 `_merit_terms_base` 그대로.
- look-ahead gate: Panda 판은 `--lookahead obstacles`(planned 10 > K 5)라 window optimizer(5 행)가 있다. 게이트가 닫히면 window optimizer 가 같은 상자를 받는다(`_solve_window(action_box=)`). 열리면 본 optimizer(10 열, 앞 5 행만 제약).
- **QP 예산:** 행의 계수가 커서(~10²) OSQP 가 느리다: 상자 없이 300–1000 iteration, 있으면 2000–6000. 기본 cap 4000 에서는 첫 QP 가 `maximum iterations reached` 로 실패했고, 실패한 QP 는 iterate 를 그대로 둬서 상자가 조용히 꺼지는 결과가 났다(깊은 장면에서 3 QP 전부 실패, 36 mm "violated" 가 사실은 QP 실패였다 — max_iter 30000 에서 23 mm 가 진짜 한계). 그래서 `--to-action-box` 에서만 `qp.max_iter = 30000`(`server.ACTION_BOX_QP_MAX_ITER`, `action_box_qp_config`). SQP 반복 수(3)와 시간 예산은 그대로. solve 시간: graze 20 → 81 ms, deep 36 → 213 ms (CPU, 이 pod).

## verifier 가 알아야 할 것
- 새 flag: `--to-action-box`, `--to-action-box-margin` (둘 다 기본 꺼짐). 판 2개 추가. 이전 판의 argv·기록 키는 불변(test).
- 재생산이 필요한 산출물: 없음. 옛 기록과 호환: 깨지지 않는다(꺼짐이면 키 하나 없음).
- 판정 3 의 "기제 확인(쥐는 중·쥔 뒤 실행 action 포화 ≤ 0.08)" 은 제약된 행이 실행 5 행이라 실행 action 에 대해서만 보장한다. 꼬리 5 행(실행 안 됨)은 포화할 수 있고 `panda/conversion.saturated_rows` 에는 찍힌다 — 실행 행(index < 5)만 세어야 한다.
- 위반(`violated`) 비율과 HOLD 가 늘 수 있다(위 주의). 상자 `active_rows`, `max_excess` 와 함께 볼 것.
- 모드 C 는 clip 이 없을 때만 A 와 같다. 상자 안에서는 같지만, 상자가 못 막은 초과(`max_excess > margin`)는 C 의 clip 이 일부를 잃는다.

## 한계 · 남은 위험
1. **EE 만 본다.** 상자는 EE(grip_site) 경로의 Dy 로만 정의된다. 팔꿈치·손목 null space 움직임은 OSC action 으로 표현되지 않아(adapter 의 기존 한계) 이 제약 밖이다. 팔 link 충돌을 피하려는 null space 수정은 상자와 무관하게 로봇에서 실현되지 않는다.
2. 실행 5 행만 제약. 꼬리는 자유라서 다음 chunk 가 다시 푼다.
3. QP 가 느려졌다(위). 시간 예산(`time_budget_ms`)은 min_iterations=3 이후에만 검사하므로 반복 수는 같다 — 결과는 시간에 안 흔들리지만 chunk 당 지연은 늘고, 독점 GPU run 의 wall time 이 길어진다.
4. 선형화가 2차 오차를 가지므로 상자 안 여유 `margin` 이 완충이다. margin 0 이면 clip 을 약간 넘을 수 있다(merit 은 clip 초과만 벌한다).
5. multi-seed·GPU seed 와는 같이 못 쓴다(거절). look-ahead gate 는 지원.
6. 이 제약이 만든 `violated` 가 SafePolicy 에서 HOLD 로 이어지는지, 몇 %인지는 측정하지 않았다(closed loop).
