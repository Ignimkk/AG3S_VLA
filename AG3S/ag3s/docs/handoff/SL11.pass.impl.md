## 무엇을 했나 (평이한 요약 먼저)
장애물 없는 LIBERO 실패의 원인 두 개(pb2 문턱 누락, smoothness가 계획 경로에 걸림)와 진단용 관찰 판을 기본 꺼짐 flag로 넣고 판 세 개를 등록했다.
- `…-pc-mi10`: 기존 `--minimal-intervention-mm 10` 만 더한 판. 새 코드 없음. pb2 문턱이 열리면 refiner가 정책 chunk 그대로(float32 bit 동일)를 내고, 변환 C의 `unchanged = Qs == Qr` 경로가 정책 action을 bit 그대로 낸다 — 합성 chunk로 끝까지 확인했다(post-processing 수정 불필요).
- `…-pc-mi10-sdev`: mi10 + `--smooth-on-deviation`. smoothness를 `w_smooth·ΣD2(Q − Q_ref)²` 에 건다(`CostConfig.smooth_on_deviation`). 문턱이 닫힌 call(가까운 chunk)에서도 자유 공간이면 SQP가 정책 chunk를 그대로 돌려준다.
- `…-pc-observe`: pc + `--observe-only`(Panda만). 서버는 AG3S · TO · verdict를 지금처럼 계산 · 기록하지만 client로 가는 `actions`는 정책 chunk bit 그대로, `safe`는 언제나 True(HOLD 없음).
