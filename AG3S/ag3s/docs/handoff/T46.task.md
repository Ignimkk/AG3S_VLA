## 왜 지금 이것인가
`T45TF.verify.json` (D-TF) 과 `T44e-CLA.verify.json` (CL-A) 이 같은 병목을 가리킨다: **권한 손이 읽는 target-free fine 층에 target 과일 표면이 남는다.**
- C1a 기록 grasp 직전 충돌 chunk 17 개 · HOLD 14 개가 행 수 · 깊이까지 이 잔여로 설명된다 (14/14).
- C2′ 에서 권한 손가락 행 821 건이 이 잔여에 obstacle margin 10 mm 를 받아 손을 target 밖에 둔다.
- 주 경로: `ball_owned` 분류에서 **ambiguous seed 보존** (`curobo_builder.py:444-448`) — ambiguous 2,555 개 중 1,785 개는 "non-target 근거" 로 쓰인 가장 가까운 점이 실제 target (GT) 표면 위다.
  그 근거 점은 17/17 chunk 에서 `proximity` 로 골라졌고 (`pipeline.py:2712-2728`, 반경 = fine voxel 5 mm), target 위 cloud 점 667 개 중 280 개가 non-target 으로 남았다.

```
depth → self-filter → attention lifting → target grounding (target points)
      → non-target evidence = cloud − target points   ← F1
      → ball_owned split: target / nontarget / ambiguous / unowned → removed   ← F2
      → target-free fine layer → 권한 행 질의 → TO / verdict
```

## A11 — 구현 (implementer, Opus)

### F1 — non-target 근거에서 target 자신의 점 빼기 (기본 off)
`_nontarget_evidence` (`AG3S/ag3s/runtime/pipeline.py` ≈2690-2730) 의 `proximity` 경로가 target 표면의 cloud 점을 non-target 근거로 남긴다.
- **GT 를 쓰지 않는** 방법으로 target 자신의 cloud 점을 더 걸러낸다. 후보 (구현자가 근거와 함께 하나 이상 골라 option 값으로):
  (a) 반경을 config 로 (fine voxel × k), (b) target 점에서 시작한 cloud 의 연결 성분 (거리 임계 · 법선/색 없이 기하만) 확장, 단 ball 밖 · support 면은 넘지 않음,
  (c) 현재 frame 의 target indices 가 있으면 그것을 우선 (이미 `indices` 경로) — `proximity` 로 떨어지는 이유를 trace 에 남긴다.
- 이웃 과일 점을 target 으로 잘못 흡수하지 않도록 보호 규칙을 둔다 (예: 다른 attention cluster / 이웃 evidence 와의 거리 비교). 보호 규칙의 근거를 impl.md 에.
- config 필드 + CLI (예: `--nontarget-evidence {proximity,…}` 기본 = 현재 동작). off 에서 bit-identical.

### F2 — ambiguous seed 도 지우기 (기본 off)
`_ball_owned_split` (`AG3S/ag3s/fields/curobo_builder.py:420-455`) 의 `removed` 에 ambiguous 를 포함하는 option (예: `--owned-ambiguous {keep,remove}` 기본 keep). off 에서 bit-identical.
- trace (`stats["target_free"]`) 에 ambiguous 제거 수를 남긴다.
