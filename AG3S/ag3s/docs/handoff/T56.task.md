## 왜 지금 이것인가

T51 의 self label (`self_identity`) 에는 네 가지 문제가 있었다.
- 상위 9 cell 이 모두 1.0 으로 **포화** 했다 (rank-1 tie rate 1.0). 그래서 순위는 2D lift tie-break 가 정했다.
- label 이 **grasp 이전 frame 에만** 있었다. 그 frame 에서는 GT 로 재도 상위 cell 이 모두 1.0 이었다.
- grasp event 가 없는 record 가 10 개 중 4 개였다.
- event 로 sim 의 `both_contact` 를 썼다. 실물에서 쓸 수 있는 `grasp_latch` HELD 는 쓰지 않았다.

이 STEP 의 목표는 **실물에서 head · 설정을 고를 때 self 점수가 GT 품질 순위를 따라가도록** 개선하는 것이다. runtime 실패 예측은 범위 밖이며 별도 과제로 남긴다.

## 사전 고정 1 — 예측 대상 (사용자 판정 1)

- **cell 선택** 과 **T54 arm 선택** 을 **각각** 평가한다.
  - cell 후보 = T51 · T51b 의 3D 후보 집합 (action Ω forced 포함 · 명사 Ω). T53 attention npz 에서 같은 cell 을 읽는다.
  - arm 후보 = T54 의 8 arm.
- GT 품질 (T53 GT cache, T54 와 같은 정의) 은 **합치지 않는다.**
  - **주 기준**: `identity_correct` 순위와 선택 regret.
  - **보조 기준**: purity · coverage 순위와 선택 후 손실 (purity 는 `no_target` 비율과 함께 본다).
- 재생 조건은 T54 와 같다. 현재 frame 이 주 조건이고, 유지 포함은 보고만 한다. T54 arm 은 T54 의 test 행을 다시 쓴다.
- phase: **전체 phase 가 주** 이고, pre-grasp · held · placed (T53 `grasp_state`) 로 나눠서도 본다. grasp 이후만 잘 맞는 점수가 전체 설정 선택에 유효한지 확인하기 위해서다.

## 사전 고정 2 — self 점수 변형 (사용자 판정 2, 세부는 dev 에서 고정)

| 변형 | 내용 | 지위 |
|---|---|---|
| **S0** (기존) | T51 `self_identity`: `both_contact` event, fingertip pad 중점 ball 안이 엄격한 과반인 frame 비율, grasp 이전 frame | 비교 기준 |
| **S1** (주) | **연속 점수** + **HELD event**. 0/1 과반 대신 chosen cluster 의 ball 안 점 비율 (포함 비율) 과 ball coverage 를 쓴다. 큰 ball 이나 큰 cluster 가 무조건 유리해지지 않도록 **둘을 함께 보고**, 정규화 · 결합식은 dev 에서 고정한다. event 는 `grasp_latch` 의 HELD 다 | 채택 후보 |
| **S2** (보조) | S1 + **grasp 이후 확장**. 손 근처라는 이유만으로 양성 label 을 계속 주지 않는다. **손과 함께 움직이는 근거가 있는 점** 만 쓴다. slip · release 뒤에는 갱신을 멈춘다. 그 규칙은 dev 에서 고정한다 | 보조 변형 |

- **HELD 는 label 을 만드는 계기일 뿐 정답 인증이 아니다.** empty grasp · wrong-object 에서도 HELD 가 날 수 있다. HELD event 중 label 이 GT target 과 맞지 않는 비율을 보고한다 (T53 자연 사례 + T55 재시뮬이 있으면 그것도).
- 이웃 음성 label (끝까지 손이 닿지 않은 물체 = 비대상) 은 **쓰지 않는다.** 실패한 target 도 그 안에 들어가 잘못된 음성을 만들기 쉽다.
- HELD 가 기록에 없는 dev record 는 기록된 실행 feedback 으로 `grasp_latch` 를 offline 실행해 얻는다. 어느 쪽으로 얻었는지 record 마다 적는다.
- event 가 없는 episode (T53 에서 `held` 0 frame 인 episode 가 4 개) 는 self 점수가 없다. 그 수를 보고하고, 선택은 event 가 있는 episode 로만 한다 (빼는 episode 를 GT 로 고르지 않는다).

## 사전 고정 3 — 선택 · tie-break · 지표

- **선택** = self 점수 (episode 평균 → episode 들의 평균) 가 가장 큰 후보.
- **tie-break (실제 선택에 쓰는 것, 미리 고정)**: 점수 차가 dev 에서 정한 해상도 이하이면 동률로 본다. 동률이면 (1) 보조 self 성분 (S1 의 coverage 성분) 이 큰 후보, (2) 그래도 같으면 후보 이름의 사전순 첫째를 고른다. **2D lift 는 tie-break 로 쓰지 않는다.**
- **regret (주)** = GT 최선 후보의 `identity_correct` − 선택 후보의 `identity_correct` (episode 평균). 두 가지로 보고한다: tie-break 로 고른 하나의 regret, 그리고 **동률 집합 평균 regret**. 동률 비율과 동률 집합 크기도 함께 낸다.
- **Kendall τ-b (진단)**: episode 마다 후보들의 self 점수와 GT `identity_correct` 사이에서 계산한다. 동률은 허용한다. **self 점수가 전부 동률이라 τ-b 가 정의되지 않으면 '정의 안 됨' 으로 적는다. 0 으로 바꿔 개선량을 만들지 않는다.** 그 경우 비교는 regret 중심으로 한다.
- 보조: purity · coverage 의 τ-b 와 선택 후 손실 (GT 최선 − 선택).

## 사전 고정 4 — 판단 (사용자 판정 3)

regret 이 주 판단 기준이고, τ-b 는 순위 전반의 진단 지표다. S1 (그리고 S2 는 보조로) 에 대해 다음을 본다.

1. S1 로 선택한 설정의 GT regret 이 **사전 허용폭** 안에 드는가. 허용폭은 dev 에서 고정한다.
2. S0 보다 regret 이 줄고, 순위 일치도 (τ-b) 도 개선되는가.
3. 선택된 설정의 purity · coverage 가 과도하게 나빠지지 않는가. 허용 악화폭은 dev 에서 고정한다.

- episode 별 paired bootstrap CI (B = 10000, seed 5607, percentile 95 %) 는 보고한다. 그러나 **유의한 τ-b 개선 하나만을 통과 조건으로 삼지 않는다.**
- **선택 결과 (regret) 가 좋아지지 않았다면 동률 감소만으로 개선을 주장하지 않는다.**
- 표기:
  - GT 를 보고 지표 · 가중치 · 임계값을 정한 변형 (S1 · S2 모두 해당) 은 **"GT 로 개발하고 추론 시 GT 를 쓰지 않는 방법"** 으로 적는다.
  - 물리 상수만 들어갔더라도 GT 결과를 보고 설계를 골랐다면 **완전 label-free 가 아니다.**
  - 사람 annotation 대체 비교는 이번 범위에 넣지 않는다.
