# T78 — target 표면 추출 (point / depth 연속성) 을 최종 구성에 넣는다: 실패 보정 + GPU (결과 전 고정)

> writer: lead (세션 A) · 작성: 2026-10-31 KST · 상태: **사전 고정.** 구현: ag3s-implementer 2 개 (아래 두 갈래, 동시) · 재생 · closed-loop · 집계: 세션 A.

## 0. 사용자 판정 (2026-10-31)

- "ATS 과정 자체가 우리의 컨트리뷰션이기에 공으로 지우는 건 좋은 방법론이 아닙니다. 객체가 공 모양이 아니면 더욱 곤란해집니다. 물체가 붙어 있는 상황을 제외한다면 point 연속성으로 표면을 추출하는 과정을 사용할 수 있다. GPU 연산으로 실시간성 개선. **반드시 최종 구성에 포함.**"
- 세부 판정:
  - 맞닿은 물체: 합쳐진 표면 영역을 attention 분할로 한 번 더 잘라 사과 쪽만 남긴다. 그래도 못 자르면 논문 한계로 둔다.
  - 기권 · 엉뚱한 물체: 직전에 맞게 고른 표면 영역을 유지한다. 처음부터 없으면 지우지 않는다. 공으로 대신하지 않는다.
  - TrajOpt: T74 Q1 (E0 + 쥐기 전 꺾임 변화율 · 연속성 끔).

## 1. 근거 — T76 (고정 입력 재생, `outputs/2026-10-30_T76_depth연속경계_대_공방식_재생비교/`)

| 문제 | T76 측정 |
|---|---|
| 맞닿은 물체 합침 | 간격 1–2 mm 장면 (회귀 211 · 954, 허들 211 · 954). 고른 영역 최대 145–183 mm (사과 약 68 mm). 이웃 과일 34,933 voxel 지움 |
| 엉뚱한 물체 | 지운 voxel 에 사과가 거의 없는 요청 57 개 (회귀 954 · 허들 954). 바구니 29,191 voxel |
| 쥔 뒤에도 고름 | 쥔 뒤 구간에서 바구니 8,204 voxel (공 방식 0) |
| 시간 | 표면 선택 중앙 697 ms · p95 768 ms. graph 만들기만 약 600 ms (CPU numpy) |
| 공이 남은 곳 | 표면 방식에서도 거친 target-free 계층 · 권한 창 · ball 은 `--target-exclusion` (공) 그대로 |
| 떨어진 이웃 | 간격 17–22 mm run 3 개에서 공 방식 12–25 voxel → 표면 0 (표면 방식이 나은 경우) |

- 참고 (세션 dev-53, T75): 회귀 211 쥐기 실패의 원인은 ATS 시간 추적이었다. 사과가 밀린 뒤 target 점이 옛 자리에 남았다 (`outputs/2026-10-30_T75_ATS_HSR_LTE_프레임별진단_closedloop/`).
  - 그래서 "ATS target 과 겹침" 검사의 기준 점은 오래된 target 점에 의존하지 않게 한다 (§2 A2).

## 2. 구현 (새 기능은 모두 기본 꺼짐 flag, 꺼짐 = 지금 동작과 bit 동일)

### 갈래 A — 실패 보정 (`runtime/pipeline.py` · `runtime/attention_surface.py` 의 선택 뒤 단계 · `fields/curobo_builder.py` 등)

1. **A1 맞닿은 물체 자르기:** 고른 표면 영역 안의 점을 기존 attention 분할 규칙으로 다시 나눈다. 규칙은 `stages/attention_split.split_by_attention` (12 mm 재군집 + raw attention 비율 2.0) 이다. target 쪽 성분만 남긴다. 분할이 성립하지 않으면 영역을 그대로 둔다.
2. **A2 target 겹침 검사:** 고른 영역 (A1 뒤) 이 이번 요청의 ATS target (grounding 이 고른 target cluster 점) 과 겹치지 않으면 그 요청은 기권으로 본다.
   - 겹침 기준은 implementer 가 T76 기록으로 정해 impl.md 에 근거와 함께 적는다.
   - target 점이 오래된 경우 (T75) 에 맞는 영역을 버리지 않는지 확인한다.
3. **A3 기권 시 직전 영역 유지:** 기권 · 겹침 실패 요청에서는 직전에 맞게 고른 영역의 code (target sample memory) 를 그대로 쓴다. 처음부터 없으면 손 층에서 아무것도 지우지 않는다. 공 방식으로 대신하지 않는다.
4. **A4 쥔 뒤 고정:** grasp latch 가 closing · held 이면 표면 선택을 새로 하지 않는다. 마지막 영역 또는 쥔 물체 기하를 그대로 쓴다. T76 의 쥔 뒤 바구니 지움을 없앤다.
5. **A5 공 제거:** 거친 target-free 계층 · 손가락 권한 창 · 공 대신 표면 영역 (A1–A4 결과) 에서 만든 범위를 쓴다.
   - 범위 정의 (예: 영역 점 + 여유 voxel) 는 implementer 가 정해 impl.md 에 적는다.
   - 이것이 커서 이번 범위에 못 넣으면 impl.md 에 이유를 적고 멈춘다 (lead 판단).
- 엉뚱한 물체 57 요청은 attention seed 가 어디 떨어졌는지 먼저 확인해 impl.md 에 적는다 (T76 기록, `SURF/*/server_constraints` 의 `attention_surface_codes_*` 와 summary `seed_patches`).

### 갈래 B — GPU (`runtime/attention_surface_gpu.py` 새 파일 + 선택 함수의 device 선택)

- `ifg_graph.build_geometry` + `ifg_round_ns.g_and_top1` (+ code 영상) 를 torch CUDA 로 옮긴다. flag 예: `--attention-surface-device cuda`.
- **동등성 (통과 조건):** 같은 입력에서 CPU 와 GPU 의 결과를 비교한다.
  - 선택 node 집합 IoU 중앙 ≥ 0.99 · 최소 ≥ 0.95.
  - code 영상 pixel 일치 ≥ 0.99.
  - 입력은 T76 표면 방식이 기록한 요청을 쓴다. 기록 code 영상 대 재계산 비교, 또는 CPU · GPU 를 같은 프로세스에서 동시에 실행한다.
- **시간 목표:** 표면 선택 p95 ≤ 150 ms (CPU 768 ms). GPU memory 증가분을 함께 보고한다.
- 갈래 A 와 파일이 겹치지 않게 한다. 선택 함수 진입점의 device 분기 한 줄만 공유한다. 겹치면 서로 SendMessage 로 조율한다.

## 3. 평가 (결과 전 고정)

### 3.1 재생 (T76 도구 · 같은 487 요청, 공 방식 기록은 T76 BALL 재사용)

- 구성 S2 = T76 표면 방식 + A1–A5 + GPU. 통과 조건 (모두):
  1. **떨어진 이웃 run** (가림 121 · 122, 허들 119 · 850 · 1345, 회귀 119): 쥐기 전 경계 오류 ≤ 공 방식 (= 56 voxel 이하).
  2. **엉뚱한 물체 요청** (지운 voxel 중 사과 계열 < 20 %, 경계 오류 > 0) = 0.
  3. **쥔 뒤 구간** 경계 오류 ≤ 공 방식 (134 voxel).
  4. **맞닿은 run** (회귀 211 · 954, 허들 211 · 954): 쥐기 전 경계 오류 ≤ T76 표면 방식의 50 % (≤ 32,062). 공 방식 (7,939) 이하는 요구하지 않는다 (한계로 보고).
  5. 사과 남김 비율 중앙 ≤ 공 방식 + 0.05 (≤ 0.276).
  6. 표면 선택 시간 p95 ≤ 150 ms.
- 미통과 항목이 있으면 숫자와 함께 사용자에게 보고하고 멈춘다.
- **변경 기록 (2026-10-31 19:58 KST, 재생 결과 전):**
  - 6 의 시간은 표면 선택만이 아니라 서버의 표면 단계 전체로 잰다 (`profile_ms.attention_surface`, A1–A4 후처리 포함). 더 엄격한 쪽이다. 선택만의 시간 (`attention_surface.ms.total`) 은 함께 보고한다.
  - 재생은 독점 lock 으로 돌리고, pod CPU throttle 계수를 앞뒤로 남긴다 (T78B 권고).
  - 코드는 `$RUN/snapshot_t78` 이다 (작업 트리 복사, `snapshot_t78_head.txt`). 같은 snapshot 의 공 방식을 회귀 119 흔들림 1 에서 재생해 T76 공 방식과 지운 voxel 수가 같은지 먼저 확인한다.
  - 2 (엉뚱한 물체 요청 = 0) 는 모든 단계의 요청에 적용한다 (더 엄격한 쪽). 쥐기 전만 센 값도 함께 보고한다.
  - 5 는 쥐기 전 요청 중 공 방식과 짝이 있는 요청의 중앙으로 비교한다: S2 중앙 ≤ 공 방식 중앙 + 0.05.
  - 거친 target-free 계층은 T76 · Q1 서버 인자에 없어 이번 구성에 영향이 없다 (T78A 미완 1). A5 는 `--surface-no-ball` 로 본다.
