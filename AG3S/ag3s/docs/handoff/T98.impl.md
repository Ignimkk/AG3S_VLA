# T98 — 구현

> writer: ag3s-implementer · 읽는 쪽: verifier, scribe, lead · 2026-11-04 (코드 변경, 커밋 안 함)

## 무엇을 했나 (평이한 요약 먼저)

기본 꺼짐 flag `--surface-do-support {include,exclude}` 를 넣었다 (기본 `include` = 지금 그대로).
`exclude` 이면 손 층 표면 · 띠 길이 쓰는 "가장 가까운 비 target 표본 거리 `d_o`" 에서, `z_floor` 를 만든 받침면의
inlier 표본 (`|n·p − offset| ≤ support_surface.distance_threshold`) 을 뺀다.
사과 바닥은 카메라에 안 보여서 바닥 근처 voxel 은 target 표본이 멀고 바로 아래 탁자 표본 (6–9 mm) 이 더 가까웠다.
그 탓에 `d_t < d_o` 가 깨져 target seed 가 남았다 (T98 진단 820 voxel). 탁자 표본이 경쟁에서 빠지므로 이 seed 가 지워진다.
`z_floor` 아래는 guard 가 그대로 지킨다. 평면 밖 이웃 표본 (탁자 위 8 mm 넘게 뜬 것) 은 계속 경쟁한다.
여유 길 (T78f) · hull (T78b) · solid (T96) · 부호 교정 (T96e) 은 건드리지 않았다. solid 의 `d_N` (τ 보호) 도 그대로
모든 표본을 본다 (T96b 가 따로 뺄 때만 빠진다).

  재생 서버가 T94q 를 import 해도 기본 인자에서는 경로가 달라지지 않는다. 순수 T98 snapshot 이 필요하면 CBF hunk 를 뺀 사본으로 해야 한다 (구현자는 그 hunk 를 건드리지 않았다).
- 재생산이 필요한 산출물: 없음 (재생은 verifier 가 한다).
- 옛 기록과 호환이 깨지는가: 없음. 꺼짐이면 `target_exclusion.oracle` · `oracle_split` 에 새 키가 없다.
- 기록 키 읽는 법: `do_support.n_excluded` 는 후보 영역 근처 (target 표본 AABB ± (2·max_dist + 1 voxel)) 표본 중 inlier 수이고 요청마다의 값이다.
  `t98_guard_diag` 와 같은 분해를 하려면 `oracle_split.n_do_support_dropped` 가 아니라 voxel 별 소유 판정을 다시 재생해야 한다 (trace 키는 추가하지 않았다).

  합성 장면 (비 target 표본 13,600 · 후보 20,000, 다른 부하 없이 7 회 중앙값) 에서 `oracle_visible_split` 이 241 ms → 270 ms (+29 ms, +12 %).
  실제 요청은 후보가 더 적어 이보다 작을 것이다. 실제 값은 verifier 의 재생 기록 (`classify_ms`) 으로 확인해야 한다.
  꺼짐이면 추가 비용 없음 (분기 하나).
