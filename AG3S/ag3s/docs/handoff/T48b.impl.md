## 무엇을 했나 (평이한 요약 먼저)

HSR (Hidden-state Sub-task Recognition: frozen VLA prefix feature 위의 `kv_L4_v1` linear probe 로 pick / place / home 을 읽는 것) 이
image 에서 "쥠 상태" 를 읽는지 "팔 자세" 를 읽는지 가르는 counterfactual 을 돌릴 수 있게 만들었다.
16D recorded run 의 qpos 에서 **대상 과일의 free joint 와 쓰는 손의 finger joint 만** 바꾸고, policy image 규약 그대로 MuJoCo 로 다시 그리고,
state 를 `build_obs("rby1_16d")` 와 같게 다시 만든다. 물리 predicate (contact) 로 host frame 을 고르고 편집 결과를 판정하며,
관통이 기준을 넘는 편집은 제외한다. CLI 는 `render` (CPU) · `extract` (GPU, verifier) · `score` (CPU) 세 단계다.

**parity smoke (CPU):** re-render 는 기록 RGB 와 **bit-identical** 이다 (MAD 0 · max 0, state 차이 0.0). 핵심은 렌더 자세다 —
기록의 qpos 는 마지막 `mj_step` 뒤의 값인데 camera 가 본 kinematics 는 그 step **앞** 의 것이라, `mj_integratePos(qpos, qvel, −dt)` 로 한 step 되돌려야 맞는다.
(되돌리지 않으면 움직이는 link 의 가장자리가 MAD ≤ 0.40 · max ≤ 111 gray level 만큼 다르다.)

## 4. 물리 predicate · host frame · closed_loop_gt 대조

렌더 자세에서 `mj_forward` 한 contact 로 과일의 상태를 정한다 (`classify`):

| 상태 | 정의 | class |
|---|---|---|
| `held` | 한 손의 finger body **둘 다** 와 접촉, table · crate 와 비접촉 | place |
| `grasping` | finger 둘 다 + table 또는 crate 접촉 (닫는 중 / 내려놓는 중) | 모호 (−1) |
| `in_crate` | held 아님, 과일 중심이 crate 내부 부피 안 (crate frame, floor top −0.052 ~ wall top 0.06, \|x\| ≤ 0.082, \|y\| ≤ 0.142 — crate box 에서 계산) | home |
| `on_table` | table 접촉 (finger 하나는 닿아도 됨) | pick |
| `other` | 어느 것도 아님 (공중) | 모호 (−1) |

- **held host** (E1 · E1s · E1z · E2): 쓰는 손 (`randomized_episodes.jsonl` `used_arm`, 7 run 모두 left) 에 `held`.
- **reach host** (E3): 쓰는 손 gripper 가 처음 닫히기 (< 0.9) **전** record 중, 과일 `on_table` 이고 gripper ≥ 0.9. ("파지 전" = 첫 파지 시도 전)
