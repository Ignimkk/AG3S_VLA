## 무엇을 했나 (평이한 요약 먼저)

1. **학습 없는 5 단계 상태 기계 `phase_machine.py`.** 입력은 요청마다 gripper 개도 (측정, 로봇별로 처음 3 요청의 최대 = 1 로 정규화) · 쥐는 손 EE site 위치 · ATS target 중심 (+ 이번 요청에 실제로 보였는지) · ATS 목적지 중심 · VLA chunk 의 gripper 열 앞 16 행. 출력은 approach / grasp / carry / place / retreat. 2. **offline 평가 `t91_phase_eval.py`.** T77 기록 (427 run 중 허들211 10 run 제외) 에서 입력을 만들어 (`extract`), **train 장면 210 run 으로만** 문턱을 고르고 (`select`), 고정된 문턱으로 test 장면 지표 · 판정 json 을 낸다 (`evaluate`). 비교 (A) = T77 `kv_L4` 기록 예측 (`probe/t77_probe.json` `test_predictions`, 다시 계산하지 않음), (B) = 이 상태 기계, (C) = 기록된 grasp latch 상태만.
3. **발견 하나 (설계에 영향):** RBY1 기록에서 정답 carry · place 요청의 **98.8 % (train 1,685/1,706) 는 ATS target 이 `occluded`** (사과가 손에 가려져 centroid 가 마지막 값에 멈춤). task 문장 그대로의 "보이는 target 이 손을 따라감" (co-motion) 은 최종 문턱에서 B 가 carry/place 로 낸 1,912 요청 중 5 건에서만 발동한다 (나머지 1,907 건은 가림 규칙). 그래서 carry 의 시작은 **가림 규칙** (target 이 닫을 때 가까웠고 · 지금은 손에 가려져 있고 · 닫힘이 막혀 있고 · 손이 닫힌 자리에서 ≥ 20 mm 움직임; `occluded_bootstrap`) 이 담당한다. co-motion 은 주로 **거부권** 으로 쓰인다: 보이는 target 이 따라오지 않으면 닫혀 있어도 carry 가 아니다 (빈손 방지). `occluded_bootstrap=False` (task 문장 그대로) 는 train 정확도 58.8 % (가림 규칙 켬 79.6 %) 라 쓸 수 없다.

## 단계 규칙 (코드 그대로, `phase_machine.py` docstring 에도 있음)

- **closed** = 정규화 개도 ≤ `closed_thr` (0.85), **open** = ≥ `open_thr` (0.90). **stalled** = |개도 변화/요청| ≤ 0.03. **blocked** = closed ∧ 개도 ≥ `blocked_min_open` (0.10, 즉 완전히 닫힌 빈 손은 아님) ∧ stalled.
- **carry** = closed ∧ co-motion ≠ False ∧ 다음 중 하나: (a) co-motion True (최근 `comotion_window`=4 요청 안에서 **실제로 보인** target 중심 변위 / 손 변위 ≥ 0.4, 방향 cos ≥ 0.8, 손이 ≥ 15 mm 움직였을 때만 판정), (b) 직전 단계가 carry/place ∧ blocked (가려졌거나 손이 멈춰 판정 불가), (c) `occluded_bootstrap`: 닫기 시작 때 target 이 ≤ `d_near` ∧ 지금 안 보임 ∧ blocked ∧ 손이 닫힌 자리에서 ≥ `bootstrap_hand_mm` (20).
- **place** = carry ∧ (손–목적지 xy 거리 ≤ `d_dest` (0.12 m) ∨ chunk 앞 16 행에 엶 명령 (> 0.90, 이미 carry 였을 때)); 한 번 place 면 retreat 까지 유지.
- **retreat** = 한 번이라도 carry 였던 뒤 carry 조건이 깨짐 (열림 · 미끄러짐 · target 이 남음).
- **grasp** = (target 중심–손 ≤ `d_near` (0.06 m), 또는 닫을 때 가까웠고 지금 가려짐) ∧ (chunk 에 닫기 명령 < 0.85 ∨ 개도 감소 ≥ 0.02/요청 ∨ closed) ∧ carry 아님. 그 밖은 approach.
- 정규화: chunk 명령은 정책 고정 척도 (열림 1.0 · 닫힘 0.0, 설정) 로 0..1; 측정 개도는 `GripperScale`. 로봇 이름은 어디에도 없고, 열 번호는 `PhaseConfig.chunk_gripper_column` (RBY1: left 7, right 15 = `ChunkLayout.rby1` 의 gripper 열; test 로 확인).

A 의 위험은 거의 전부 "approach 를 retreat 으로 봄" (3,160) 이라 task 정의에서는 보이지 않는다. B 는 train 에서 T77 정의 8.8 % (scene-mean) 로 A 의 test 33 % 보다 낮다. §2 판정 문장은 task 정의를 쓰므로 두 정의를 모두 json 에 둔다.
  2. 성공 run = 정답이 `place` 에 닿은 run (프록시; client 의 episode 성공이 아님). `success_runs` / `failed_runs` 는 그 기준.
  3. B 의 가림 규칙은 이 데이터의 사실 (carry 중 사과 98.8 % 가려짐) 에 기댄다. 다른 benchmark (예: 손목 카메라로 물체가 계속 보임) 에서는 co-motion (a) 이 주력이 되고 가림 규칙 (c) 은 드물게 발동할 것이다 (추정) — 이 평가는 그 경우를 시험하지 못한다 (§3, 다음 STEP).
  4. B 는 grasp 정확도가 낮다 (train recall 67 %; grasp → approach 316): grasp 를 가까움 · 닫음 · 닫기 의도로만 보는데 정답은 "손바닥–사과 ≤ 60 mm" (손 위치 기준) 이다.
  5. B 의 위험한 오판은 실패 run 에 몰려 있다 (train 3.3 % vs 성공 run 0.23 %): 가림 규칙이 "닫힌 채 막힌 손이 20 mm 이상 움직임" 을 carry 로 보는데, 사과를 집은 척 못 든 경우 (정답 grasp) 가 여기에 걸린다.
