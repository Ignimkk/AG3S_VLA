# SL15 — 구현: 명령 변환 D (`lag_steady`) 와 E (`lag_steady_deadband`)

> writer: ag3s-implementer · 읽는 쪽: verifier, scribe, lead · 2026-11-05 · worktree branch `wip/sl15-convD` (base feature/panda-benchmark 2d3a736c)
> 새 `--conversion` 값 D · E. 기본 꺼짐: A · B · C 의 출력 · 기록 key 는 이전과 bit 동일(test).

## 무엇을 했나 (평이한 요약 먼저)

**D.** 고친 경로의 row별 EE 변화 `Dy_k`(B 와 같은 정의, 같은 `unchanged` 통과 규칙)를 정상상태 역이득으로만 되돌린다: `Dx_k = Dy_k (1 − α) / β`
(위치 · 회전 따로; 위치 이득 4.01, 회전 4.03). action 보정은 `corr = [dxp/0.05, dxr/0.5]`. 보정 후 `a_pol + s·corr` 의 모든 축이 |·| ≤ 1 이 되는
가장 큰 `s ∈ [0,1]` 을 쓴다(방향 보존; 축별 clip 아님). `s < 1` 이면 `saturated_rows` 에 적는다. 누적 추적 · 부족분 이월 없음.
기록(`panda/conversion`): `mode "D"`, `mode_name "lag_steady"`, `gain_pos`, `gain_rot`, `min_scale_s`(보정한 row 의 최소 s, 없으면 1.0).

**E.** D + 무시 구간. 바뀐 row 가 (자기 변화 `|dyp|` < 0.5 mm, `|dyr|` < 0.3°) 이고 (그 row 까지 누적 `Σdyp`, `Σdyr` 의 norm 이 < 1 mm, < 0.5°) 이면
정책 bit 그대로 통과한다(`passthrough_rows` 와 `deadband_rows` 에 적음). 아니면 D. 임계값은 module 상수
(`DEADBAND_POS_M`, `DEADBAND_ROT_RAD`, `DEADBAND_CUM_POS_M`, `DEADBAND_CUM_ROT_RAD`). 누적은 chunk 시작부터, `unchanged` 통과 row 는 0 으로 더한다.

## action box (`--to-action-box`) 와 D · E

`action_box_from_conversion` 의 D · E 는 B 와 같은 구조에 D 의 이득이다: `alpha_box = 0`, `beta_box = β/(1−α)` → `g = (1−α)/(β·scale)`.
box 의 행(`|a + corr| ≤ 1 − margin`, 축별)은 D 의 방향 보존 scale 이 1 이 되기 위한 충분조건이라 box 안에서는 scale-back 이 필요 없다. E 의 deadband 는
box 에 넣지 않았다(deadband row 는 정책 bit 이라 box 안이다). 현재 `--to-action-box` 는 D · E 와 같이 쓰는 계획이 없다.

## mode 가 server 의 역변환에 닿는 길 (`--conversion D`)

`launch_libero_paired.main`/`launch_libero_safety_paired.main` (`--conversion` choices) → `run_mode` 가 server 프로세스 env 에
`AG3S_PANDA_CONVERSION=<mode>` 를 넣는다(`launch_libero_paired.py:330`; 유일한 채널, safety launcher 는 같은 `lp.run_mode` 를 쓴다) →
`server.conversion_mode()` (`pa.CONVERSION_MODES` 로 검증, 기본 A) → `build_safe_server` 의 `mode` → `PandaSafeServer(mode=mode)` →
`pa.joint_chunk_to_delta_chunk(..., mode=self.mode)` → `response["panda/conversion"] = {**conv.record(), **rec}` (`rec["mode"] == "D"`) →
client 가 call 기록의 `conversion` 으로 쓴다. 이미 이 길에 mode 문자열을 가르는 곳은 없어서 server · client 의 다른 곳은 고치지 않았다.
manifest 의 `panda_conversion_mode` 도 `D`. (D 의 `info["conversion_mode"]`, `recorder_meta.conversion` 도 `CONVERSION_MODES[mode]` 로 D 이름이 나온다.)
