# T50 — HSR 의 instruction 둔감은 fine-tuning 탓인가: probe 학습 · representation · fine-tuning 의 분리

> writer: lead (A0) · 2026-10-12 KST · 읽는 쪽: implementer, verifier · 로그: `AG3S_T47_LOG.md`
> 사용자 판정 (2026-10-12): **T50a (CPU, 지금) + T50b (GPU, T46 CL3 종료 후)** 진행.
> 승인 범위: offline GPU prefix pass (server 없음) — `pi05_base` 와 16D LoRA checkpoint. CL3 와 GPU 를 겹치지 않는다 (TO wall-clock, `T49.task.md` 판정).
> 공통 규칙: env.sh, `.venv-openpi-live` (GPU) / `.venv-ag3s` (CPU), 새 output 은 `$AG3S_RUN_DIR`, CPU worker ≤ 2, 다른 세션 process 금지, 커밋은 lead.

## 왜 지금 이것인가

T48a (`T48.verify.json`) 에서 phase probe (`kv_L4_v1`) 는 다음과 같이 반응했다.
- image 는 따른다: C2s · C2i 에서 image 쪽을 따른 비율 0.979.
- **instruction target 교체에는 거의 반응하지 않는다:** C1 에서 원래 place 인 frame 이 `pick` 으로 바뀐 비율 0.040, home 은 0.000.

사용자 질문: **이것이 우리 fine-tuning (16D LoRA) 때문인가?** 원인 후보는 셋이다.

| 후보 | 내용 | fine-tuning 탓인가 |
|---|---|---|
| (a) probe 학습 | probe 는 prompt 와 장면이 항상 맞는 frame 으로만 학습했다 → 언어를 쓸 이유가 없다. Bhardwaj et al. 의 일반 probe 도 target 교체에 둔감했다 | 아님 |
| (b) representation | L4 V feature 에 "지시된 물체의 진행 상태" 가 선형으로 들어 있지 않다 | 일부일 수 있음 |
| (c) fine-tuning data | 2000 episode 가 모두 성공한 scripted 시연, target 1 + distractor 3. 언어는 처음에 과일을 고를 때만 필요하다 | 그렇다면 base 와 차이가 난다 |

**`pi05_base` (우리 LoRA 의 초기 weight) 가 로컬에 있다:** `$AG3S_STORAGE_ROOT/cache/rby1/openpi/openpi-assets/checkpoints/pi05_base` (12 GB).
따라서 같은 feature 정의 · 같은 입력 변형을 base 와 LoRA 에 똑같이 적용해 비교할 수 있다.

```
같은 입력 (image ×3 · state · prompt 변형 C0/C1/C1p/C2*) → [pi05_base | 16D LoRA] prefix → kv_L4 feature (512D = text 평균 | image 평균)
   → ① feature 가 prompt 교체에 얼마나 움직이나   ② 선형으로 "instruction 기준 phase" 를 읽을 수 있나
```

## 사전 고정 (결과 보기 전)

| 항목 | 정의 |
|---|---|
| data | T48a 와 같은 val split (episode 1600–1799 의 4 번째마다 50 개, SUBTASK-b sampling) · 같은 C0/C1/C1p/C2g/C2s/C2i 변형. probe 학습용 train split 은 SUBTASK-b 와 같다 (episode 0–1599 의 8 번째마다 200 개) |
| ① feature 민감도 | frame 마다 정규화 L2 거리 `d(C0, C1)` 를 `d(C0, C1p)` (표현만 바꿈) 와 비교한다. 비 `r = d(C0,C1) / d(C0,C1p)`. **text 평균 절반 · image 평균 절반을 따로** 낸다 (bidirectional prefix 라 image token 도 text 를 본다). 기준선으로 같은 episode 의 인접 frame 거리도 낸다 |
| ② counterfactual probe (primary) | 같은 512D feature 위에 multinomial LogReg 를 학습하되, **학습 data 에 C1 변형 (distractor 지시 → 정답 `pick`) 을 포함**한다. 비율은 원본 : C1 = 1 : 1, 원본 정답은 그대로 둔다. episode 단위 GroupKFold 로 C 를 고르고 val episode 에서 평가한다. 지표: **C0 정확도** 와 **C1 instruction-기준 정확도** (원래 place/home frame 의 `pick` 비율) — 둘 다 높아야 "정보가 있다" |
| ②′ 통제 | 같은 학습을 **text 절반만 · image 절반만** 으로 반복한다. 그리고 **label 을 섞은 통제** (C1 의 label 을 무작위로) 도 돌린다 |
| 판정 규칙 | LoRA 에서 ② 가 C0 ≥ 0.95 이고 C1 instruction-기준 ≥ 0.80 이면 "representation 에 있음 → 원인은 (a) probe 학습". 아니면 (b) 또는 (c). **(b) 와 (c) 의 구분은 T50b 의 base 결과로 한다**: base 에서 기준을 넘고 LoRA 에서 넘지 못하면 (c) fine-tuning 탓. 둘 다 넘지 못하면 fine-tuning 탓이 아니다 |
| 원 probe | 기존 `kv_L4_v1` 은 바꾸지 않는다 (비교 기준) |

- **판정에 쓰는 값 (lead, T50.impl.md 확인 후 · 결과 전 고정):** 0.95 · 0.80 은 **episode 별 정확도의 median** 에 적용한다. frame 합산 값은 함께 보고만 하고 판정에 쓰지 않는다. 근거는 위의 "episode 단위로 집계" 원칙이다.
- probe 재구현: sklearn 이 없어 SUBTASK-b probe (scaling + LogReg) 를 numpy/scipy 로 다시 구현했다. `kv_L4_v1` 의 val 정확도 0.9807766 을 그대로 재현하고, 확률 차이는 최대 2e-5 다 (impl.md).
- 0.95 · 0.80 은 결과를 보기 전에 lead 가 정한 값이다. 근거: C0 은 원 probe 0.98 에서 크게 떨어지지 않아야 하고, C1 은 우연 (3 class 중 하나) 보다 확실히 높아야 한다.
- frame 이 아니라 episode 단위로 집계한다 (median · IQR 과 합산).

## 이 STEP 이 답하는 질문
**phase probe 가 instruction target 교체에 둔감한 원인은 probe 학습 방식인가, VLA representation 인가, 그리고 representation 이라면 우리 16D LoRA fine-tuning 이 만든 것인가?**

## 되돌아올 지점
- (a) 이면: probe 를 counterfactual-aware 로 다시 학습하는 STEP 을 제안한다 (Bhardwaj et al. 의 contrastive objective 와 비교).
- (c) 이면: fine-tuning data 에 instruction 교체 · 실패 · retry 를 넣는 방향은 학습 설계 판단이다. 사용자 판정으로 넘긴다. 이 STEP 에서 재학습하지 않는다.
- base 가 16D 입력 변환과 맞지 않아 feature 가 무의미하다고 판명되면: 비교를 멈추고 이유를 보고한다.
