# SL13 — 구현: 정답 target 부피 지우기 (`--oracle-target-volume`, -pc-oraclevol / -pc-mi10-oraclevol)

> writer: ag3s-implementer · 읽는 쪽: verifier, scribe, lead · 2026-11-05 · worktree `wip/sl13-oraclevol` (base feature/panda-benchmark 8a7ba963)
> 진단 전용, 기본 꺼짐. 채택 후보가 아니다. task 문서 `SL13.task.md` 의 규칙은 바꾸지 않았다.

## 무엇을 했나 (평이한 요약 먼저)

SL12 에서는 탁자에 닿는 bowl 아래쪽 seed 가 "가장 가까운 표본이 탁자" 라서 지워지지 않았다. 이제 서버 flag `--oracle-target-volume` 을 켜면
(`--target-extent oracle-visible` 일 때만) 기존 oracle-visible 지우기 **뒤에** 정답 target 부피 안의 seed 를 **주인과 상관없이 전부** 미세
target-free 층에서 지운다. 부피 = 이 episode 의 code-1 표본 xy 볼록 껍질을 미세 voxel 1칸 팽창 × z 가 `z_floor` 부터 code-1 최고 z + 1칸.
code-1 표본이 없으면 아무것도 더하지 않는다. 서버 구조상 가능해서 task 의 대안 (client 가 target AABB 를 보냄) 은 쓰지 않았다 —
client 는 그대로이고 wire 도 바뀌지 않았다.

## 지우는 단위 (정확히)

**미세 target-free 층의 seed = `site_index >= 0` 인 fine voxel (5 mm)**. `_oracle_exclusion` 이 지우는 것과 같은 단위이고 같은 `_clear_seeds` 를 쓴다.
부피 안 모든 voxel (seed 여부 무관) 은 hull fill (T78b) 과 똑같이 부호 교정 집합 (`sign_idx`) 에도 들어간다 — 안 그러면 seed 를 지워도 bowl 안쪽의
TSDF 음수가 남는다. `_force_sign_on_pure_voxels` 는 "무언가 1.5 voxel 안에 남아 있는" voxel 은 건드리지 않으므로 이웃 물체 곁은 보수적이다.
voxel 포함 판정은 중심점: 중심 xy 가 hull 을 `vs` 만큼 민 안 (모든 facet `n·x + b <= vs`) ∧ `z_floor <= z <= max z + vs` (경계 `1e-9` 허용).
hull 이 점/직선이면 (`scipy` ConvexHull 불가) xy AABB ± vs 로 대신하고 `degenerate_hull` True 로 기록한다. `z_floor` 가 None 이면 (공이 없는 경우)
code-1 최저 z − vs 부터.

## call 마다 기록되는 것 (`panda/oracle.field`, 켰을 때만)

`volume_applied` (bool: code-1 표본이 있어 부피를 정했고 evidence 가 적용된 call), `volume_n_removed` (**더 지운 seed 수**), `volume_n_voxels` (부피 안 voxel),
`volume_n_seeds` (부피 안 남아 있던 seed = 지운 수와 같다), `volume_degenerate_hull`, `volume_bbox_lo` / `volume_bbox_hi` ([x, y, z] m, 팽창한 hull 의 AABB × z 범위).
evidence 가 없는 call (표본 없음 · no_target_free_layer 등) 은 `volume_applied` False, `volume_n_removed` 0. 지운 seed 는 기존 `target_free_removed_ijk` trace 에도
합쳐진다 (새 key 를 만들지 않았다: `EXCLUSION_TRACE_KEYS` 를 건드리지 않기 위해). 빌더 쪽 상세는 `stats["target_free"]["target_volume"]`
(`n_target_points`, `n_seeds_in_volume`, `n_extra_removed`, `n_sign_added`, `ms`).

## 위험 · verifier 가 볼 것

1. **hull 이 target 에 닿은 이웃을 같이 덮을 수 있다.** 부피 안의 seed 는 주인과 상관없이 지우므로, bowl xy 껍질 안 (+5 mm) 에 걸치는 이웃 물체 (겹쳐 놓인 plate · 쌓인 bowl) 의 seed 도 같이 지워진다. 스펙대로 추가 논리 없음. task §2 "이웃 보존" 기제 검사가 이것을 잡는다.
2. **code-1 표본의 낱개 이상치가 hull 을 키운다.** SL12 offline 점검에서 정지한 bowl 에도 mesh 에서 24–860 mm 떨어진 낱개 표본이 있었다 (움직이는 가장자리 pixel 의 depth/segmentation 시점 차이, p90 은 1.1–1.4 mm). 볼록 껍질은 이상치 하나에 크게 늘어난다. 방어 로직은 스펙에 없어 넣지 않았다. `volume_bbox_lo/hi` 가 call 마다 기록되므로 bowl 실제 크기 (≈ 150 mm) 와 비교해 이상 call 을 먼저 확인하길 권한다.
3. 쥔 뒤 (`held`) 구간에서는 SL12 보고처럼 memory 에 옛 위치 잔류 code-1 표본이 쌓이면 hull 이 이동 경로 쪽으로 늘어난다 (SL12 판 적용 call 에 그대로 더해지므로 task 규칙 그대로). 기제 판정 구간 (접근 · 닫는 중) 에는 영향이 작다.
4. `z_floor` = 공의 `z_min` (지지면 + pad). 탁자 표면 seed 는 그 아래라 남는다 — 의도. 탁자가 `z_floor` 보다 높게 보이는 voxel (중심 ≥ z_floor) 이 부피 안에 있으면 그것도 지워진다.
5. config dump (`AG3SConfig.to_dict`) 에 `esdf.oracle_target_volume: false` 키가 모든 판에 생긴다 (모든 config flag 가 그렇듯). 서버 argv · version record · 응답 · client 요청은 기존 판에서 그대로다.
6. `-lsfork` 쌍둥이는 SL12 와 같은 이유로 등록하지 않았다.

## 내가 기대하는 결과 (verifier 는 측정 전에 읽지 않는다)

접근 · 닫는 중에 실제 bowl 원기둥 (r 45 mm, ±15 mm) 의 target-free 점유가 0.3 이하로 내려가고, 이웃 원기둥 점유는 같은 call 의 주 ESDF 대비 크게 안 떨어진다. 이웃과 겹쳐 놓인 task 에서는 이웃 점유가 떨어질 수 있다.
