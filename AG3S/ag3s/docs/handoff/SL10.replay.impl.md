## 무엇을 했나 (평이한 요약 먼저)

기록 run(`--record-constraints full`) 하나를 인자로 주면, 쥐는 중 · 쥔 뒤 call 중 TrajOpt 가 VLA reference 에서 0.1 rad 넘게
벗어난 call 을 골라서 (J1) 그 call 의 입력을 그대로 복원해 TrajOpt 를 다시 푸는 (J2) 도구를 만들었다.
다시 풀 때 (a) target 을 field 에서 빼고, (b) 연속성 · 꺾임 변화율 항을 끄고, (c) 부착 구를 끄고, (a+b+c) 를 해 보며 변형마다
편차, 변환 C 뒤 포화 행 수, 계획 − 실현 가능 차이를 잰다. 먼저 `replay` 가 기록의 refined 를 1 mm 안으로 재현하는지 보고, 아니면
`"valid": false` 로 멈춘다. action 한계 제약은 `wip/sl10-actionbox` 의 옵션이 이 checkout 의 `TrajOptConfig` 에 있을 때만 돈다
(없으면 `unavailable`).

**서버 · adapter · 기록기는 하나도 바꾸지 않았다** (새 파일 둘뿐; 테스트가 보호 경로 변경 0 을 확인한다). 도구가 import 하는 것은
읽기뿐이다.

**실제 기록에 돌려 본 적은 없다.** Panda 의 `--record-constraints full` 기록은 이 시점에 아직 없어서(lead 의 기록 run 이 돌고 있다),
기록 형식은 코드(`SafePolicy._record`, `libero_safe_client.save`, `constraint_record.py`)와 SL9 run 의 calls · geom npz 에서 읽은 대로
복원했고, 도구는 같은 형식의 합성 run 으로 시험했다. 첫 실제 기록에서 키 이름이 어긋나면 `prepare_call` / `build_context` 에서 잡힌다

### 출력 JSON (요지)

* `targets` · `target_phases` — J1 · J2 대상 call (`<stem>#<seq>`)과 쥠 구간
* `j1[call]` — `rows`: 위반(`clearance<0`) · margin 안(`--j1-band-mm`, 기본 20 mm)인 (step, sphere) 를 손가락 / 손바닥 / 팔 / 부착 구로 센 것과
  행 목록, `voxel_classes`: 근처 점유 voxel 의 MuJoCo geom class (target / 받침면 · 탁자 / 목적지 / 그 밖 / 잔상(30 mm 안 geom 없음), 그리고 로봇 자신 `robot`)
* `fidelity[call]` — `reference_mm` · `record_clearance_mm` · `replay_mm` · `conversion_reproduced` · `failed` · `within_tolerance`
* `results[call][variant]` — `deviation`(max · p90 · 실행 창 max · p90, 관절별, `exceeds`) · `conversion`(포화 행 · 성분, 계획 − 실현 가능 mm 행별 · max · p90)
  · `status` · `vs_recorded_refined_mm`; 못 돌린 변형은 `{"unavailable": 이유}`
* `instrument_summary[variant]` — §1.3 판정 재료. (편차 > 0.1 rad 인 call 비율)과 같은 call 들의 replay 비율, 비율의 비, `reduces_below_half`
  (**변형 비율 < 0.5 × replay 비율**, 즉 절반 *아래*. 같으면 false. 판정은 lead 가 한다 — 비율을 그대로 적는다)

## 기록 형식에서 빠져 있어 J1 / J2 를 (일부) 못 하는 것

1. **쥔 물체의 부착 구** (`SceneSnapshot.attached_points / radii / parent_link`)와 쥔 물체 `manipulated` 구. 기록기가 싣지 않는다
   (`n_attached_points` 개수만 있다). → **쥠(held) call 의 replay 는 충실도 C 에서 걸러질 가능성이 크고**, (c) 변형은 부착 구를 줘야만 돈다
   (`--attached-spheres-json`; 지금은 없으면 `unavailable`). 쥐는 중(closing, 아직 attach 전) call 은 영향이 없다. 쥠 구간 J2 가 필요하면
   기록기에 `attached` 구(parent 좌표계 `[c, r]`, `parent_link`)를 더하는 것이 가장 짧은 길이다 — 이 worktree 에서는 건드리지 않았다.
2. **MuJoCo 모델.** `*_geom.npz` 에 `sim_state`(상태) · body / geom 이름 · geom→body 는 있지만, **geom 크기 · pose 를 낼 `MjModel` 이 없다**.
   J1 의 voxel class 는 `--geom-snapshot` 이 있어야 돈다. snapshot 은 `geom_snapshot_from_mujoco(model, sim_state_image[obs_index], obs_indices, path)`
   (py3.8 에서도 돈다)로 만든다 — LIBERO env 의 `env.sim.model._model` 을 호출자가 넘겨야 한다. 없으면 `voxel_classes: {"unavailable": …}` 이고
   나머지 J1(sphere 종류별 행 수)은 그대로 나온다. 어느 body 가 target 인지도 기록에 없어 `target_centroid` 에 가장 가까운 물체 body 로 추정한다
   (`--target-body` 로 덮어쓴다); 목적지는 `--destination-body` 로만 안다. mesh geom 은 AABB box 로 근사한다.
3. **`q_now`** 는 기록기에 없다. `<stem>_geom.npz` 의 `robot_state/left_wrist[obs_index]` 로 되살린다(요청의 `panda/robot_state` 와 같은 값). 충실도 A 가 검증한다.
4. **서버가 scene 에 후처리로 붙이는 것**: `neighbour_contact` · `neighbour_palm_contact` · `grasp_contact` · `placement_contact` · HSR6 gate ·
   `held_capture_spheres` · 라벨 층(목적지 마진). 이 항들이 켜진 판(pc 판의 `--neighbour-contact-mm` · `--hsr6-*`)에서 그 항이 해를 바꾼 call 은 C 에서 걸린다.
5. **`manipulated.points`** 는 기록의 `target_points` 로 대신한다 (occluded 때 마지막 관측 형상과 다를 수 있음).
6. **QP warm start**: call 마다 새 solver 로 푼다. 서버는 OSQP 를 call 간에 이어 써서(`--qp-eps 1e-4`) 1 mm 안으로 안 맞는 call 이 있을 수 있다.
   그러면 그 call 은 무효로 기록된다 — 이 경우 episode 를 이어 푸는 `--chain` 이 필요하지만 **구현하지 않았다** (RB-Y1 도구의 `chained_replay` 를 옮기는 것은 후속).
7. **`wip/sl10-actionbox`**: 옵션 이름이 정해지지 않아 `detect_action_box_overrides` 가 `TrajOptConfig` 섹션에서 `action_box` 가 들어간 bool 필드를 찾는다.
   옵션이 들어오면 필요한 context 키를 `action_box_context(prep)` 에 채워야 한다(지금은 `{}`). 이름이 다르거나 context 가 필요하면 그 한 곳만 맞추면 된다.

(a) 의 구현은 **근사**다: 서버의 target-free 계층(seed 제거 + TSDF 부호 재결정) 대신, 저장된 SDF 의 음수 voxel 을 점유로 보고 target 점 2 cm(+1 voxel) 안의
점유를 지운 뒤 EDT 로 거리를 다시 잰다 (`TARGET_REMOVAL_RADIUS_M`). 거친 · 미세 계층 모두에 적용되어 모든 행이 target 없는 장을 본다.
target 아래 받침면 voxel 도 그 반경 안이면 같이 지워진다. 쥠(held) call 에서는 (a) 를 `unavailable` 로 둔다 (쥔 물체는 attached 경로로 이미 파였다).

## action_box 연결 (2026-11-05, `wip/sl10-actionbox` 54b1d2cc merge 뒤)

`action_box` 변형이 이제 실제로 돈다 (`unavailable` 아님). 옛 hook(`detect_action_box_overrides`, `action_box_context() == {}`)은 지우고 정식 진입점을 쓴다.

* **상자**: `AG3S.adapters.panda.action.action_box_from_conversion(prep.conv, margin=…, n_rows=rt.execution_length, mode=prep.conv_mode)`.
  `prep.conv` 는 그 call 의 기록된 입력(정책 chunk · `q_now` · `T_world_base` · `prev_step`)에서 충실도 A 가 검증한 변환이고, mode 는 그 call 의 기록된 변환 mode(C). 서버의 `action_box_kwargs` 와 같은 호출.
* **풀이**: refiner `context["action_box"] = box` (`refiner.py` 가 `solve(action_box=)` 로 넘긴다).
* **QP 예산**: `variant_config` 가 `action_box` 변형에서만 `server.action_box_qp_config(cfg)` (qp.max_iter 30000) 를 건다. 안 쓰면 첫 QP 가 실패해 상자가 조용히 꺼진다. 다른 변형의 config 는 그대로 (test).
* **margin**: CLI `--action-box-margin` (기본 0.05) → `Runtime.action_box_margin`.
* **결과 JSON** (`results[call]["action_box"]`): 기존 `deviation` · `conversion` · `status` … 에 더해
  * `action_box` = 서버 `to.action_box` 와 같은 키: `on`, `n_rows`(= 6 × 실행 행), `active_rows`, `max_pred_abs_action`, `max_excess`, `margin`, `rows`, `mode` (상자가 적용 안 되면 `on:false`, `reason`)
  * `qp` = `{qp_failures, max_iter, max_iter_default}` — `qp_failures > 0` 이거나 `action_box.on == false` 면 그 call 의 상자 결과를 믿지 않는다.
* 포화는 **실행 행(index < 5)** 만 센다: `conversion.n_saturated_rows_exec` · `saturated_components_exec` (꼬리 5 행은 제약 밖이라 포화할 수 있다).

테스트 (`test_sl10_panda_fixed_input.py`, 여전히 20 개): 합성 run 에서 `action_box` 가 available 이고, replay 의 `n_saturated_rows_exec > 0` 이 `action_box` 에서 0 으로 줄며(`saturated_components_exec` 도 0), `on`, `n_rows == 30`, `max_pred_abs_action < 1`, `qp.max_iter == 30000`, `qp_failures == 0`, margin 0.2 가 기록에 반영됨. 변형 config 가 서버의 `action_box_qp_config` 와 같고 다른 변형은 qp 를 안 건드림. 서버 불변 test 는 기준을 `54b1d2cc` (merge 된 action-box 구현)로 바꿨다 — 그 뒤로 이 연결이 보호 경로를 바꾸지 않았음을 본다.
`test_sl10_action_box.py` 18 개 + 위 20 개 = **38 passed** (CPU 단일 process, 모듈 `__file__` 은 worktree).

주의: replay 는 call 간 QP warm start 없이 푼다(기존 한계). 상자 변형은 QP 가 느려(2000–6000 iteration) call 당 수백 ms 이다. 합성 장면은 구 장애물이라 ESDF 장면의 `violated` 잔존(상자 때문에 못 피하는 충돌)은 실제 기록에서 처음 본다 — `status` · `max_violation_m` 를 같이 볼 것.

### 남은 한계 (원리적으로 안 되는 것과 이유)

1. **위반이 큰 call 의 QP 는 재현이 안 된다.** reference 가 장애물을 수십 mm 침범하면(#19–#31: 초기 위반 40–80 mm) 한 SQP 에 QP 가 5000–10000 OSQP iteration 을 돈다 (`qp.max_iter` 에 닿기도 한다). 입력이 9자리까지 같아도(초기 merit 일치, **같은 episode 의 앞 call 들을 이어 풀어 OSQP warm start 까지 맞춘 chain 실험에서도**: #0–#17 은 0.000 mm · QP iteration 수까지 정확히 일치하는데, #18 에서 1.0 mm · #19 에서 10 mm 로 갈라진다) 수렴 허용오차(`--qp-eps 1e-4`) 안의 미세한 차이가 해를 mm–100 mm 단위로 바꾼다. 서버의 OSQP 내부 상태(직전 풀이의 x · y, polish)는 기록에 없다. **이 call 들이 바로 J2 가 보고 싶은 call 이므로**, J2 결과에서 이들의 `replay` 는 기록 refined 와 다른 점을 "서버가 실제로 한 풀이의 mm 단위 재현" 으로 읽으면 안 된다 — 동일 도구가 같은 입력에서 다시 푼 결과로, 변형 간 **상대** 비교(replay vs action_box)로만 읽는다. 충실도 C 는 그래서 이 call 들에서 `valid:false` 를 계속 낸다.

### 읽는 법과 한계

* class 는 점유 voxel 중심에서 **가장 가까운 collision geom 의 body** 로 센다. target body = BDDL target instance 전체(`akita_black_bowl_1_*`), 목적지 = BDDL 목적지 instance, `world` · `table` = 받침면,
  로봇 body = `robot`, 나머지 = 그 밖, 가장 가까운 geom 이 30 mm 보다 멀면 `ghost`. mesh geom 은 AABB box 로 근사한다.
* 행(`rows`)은 `clearance < 0` 인 (step, sphere). 찾는 반경 = 구 반지름 + `esdf_margin` + 2 voxel. 점유 voxel(`d<0`)이 없으면 거친 계층, 그래도 없으면 표면 근처 voxel(`d<1 voxel`).
  **얇은 표면은 음수 voxel 이 없어서 표면 근처 단계가 필요하다.** 단, 접촉 중인 곳(손이 탁자 위 등)에서 표면 voxel 은 가장 가까운 geom 이 둘 중 어느 쪽인지 애매하다 —
  집계에는 `class_occupied_only` 와 `class_surface_fallback` 을 따로 두었다 (특히 `robot` 이 표면 단계에서 크게 늘어난다).
* `clearance` 는 기록의 **로봇 구 뿐**이다. 쥔 물체의 부착 구는 기록 `clearance` 에 없으므로 `verdict_collision`(서버가 `hold` 로 판정한 행 하나씩) 만으로 본다.
* call 당 대표 위반 행은 한 줄이라 쥠 구간 부착 구 위반의 개수(`n_violating`)와 점유 voxel 의 주인은 그 한 점으로만 안다.
