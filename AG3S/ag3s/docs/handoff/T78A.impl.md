## 무엇을 했나 (평이한 요약 먼저)

표면 방식 (`--target-extent attention-surface`) 의 선택 **뒤** 에 다섯 단계를 넣었다. 각 단계는 기본 꺼짐 flag 다.

- A1 · 붙은 이웃 자르기: 고른 영역을 cluster 분할 규칙 (12 mm 재군집 + raw attention 비율 2.0, attention 분할) 으로 한 번 더 자른다.
- A2 · ATS 확인: 영역의 과반이 ATS target 점 10 mm 안에 있어야 채택한다.
- A3 · 직전 영역 유지: 채택하지 못한 요청은 직전 채택 영역의 표본을 지운다. 표본이 없으면 아무것도 지우지 않는다. 공과 점 제외로는 물러나지 않는다.
- A4 · 쥐는 동안 고정: closing · held 동안 선택하지 않는다.
- A5 · 공을 만들지 않음: 지지면 guard 는 영역 아래 지지면에서 구한다.

flag 를 모두 끄면 IFG-CL1 과 호출이 같다. test 가 그것을 보인다.

T76 기록을 다시 읽은 진단 결과는 이렇다.

- 회귀 954 · 허들 954 의 "엉뚱한 물체" 요청 (68 개, 아래 정의) 은 seed 가 바구니에 떨어진 경우가 일부다.
- 더 큰 원인은 둘이다.
  - ① 표면 방식이 영역 없는 frame 과 identity 실패 frame 에서 **공으로 물러난 것**.
  - ② memory 가 쥔 동안 (held) · 잘못 고른 frame 의 바구니 표본을 **계속 쌓은 것**.

## 진단 — 954 의 seed 는 어디에 떨어졌나 (T76 SURF 기록, 결과 전)

방법은 `t78a_diag.py` 다.

- 요청마다 seed patch 5 개의 non-robot pixel 을 같은 요청 depth 로 올려 MuJoCo 정답 (t76_metrics 와 같은 8 mm 최근접) 으로 분류했다.

### A5 범위 정의와 이번에 넣지 않은 것

손 층의 지울 범위는 영역 자체다. 정확히는 memory 의 code-1 표본 + oracle split (`oracle_visible_split`) 의 기존 규칙이다.

- 표본에서 `oracle_max_dist_voxels` 6 voxel (30 mm) 안의 seed 를 지운다.
- 단 다른 표본보다 그 표본에 가까워야 하고 (표면 길), 또는 그 물체 띠에만 있어야 한다 (띠 길).
- 그리고 `z_floor` 위만 지운다.

공이 남아 있던 세 곳은 이렇게 처리했다.

| 곳 | 처리 |
|---|---|
| 손 층의 범위 | A3 · A5 로 공이 사라진다. 이전에는 기권 · identity 실패 frame 이 `ball_owned` 로 물러났다 (허들 954: 23 요청) |
| 지지면 guard | A5: 영역 아래 지지면 + 1 voxel. 같은 평면 · 같은 pad 라 공이 있을 때와 값이 같다 (test) |
| 거친 target-free 계층 | **넣지 않았다.** T76 · T74 Q1 서버 인자에 `--target-free-coarse` 가 없다 (거친 계층을 만들지 않는다). S2 에 영향이 없어 A5 는 그 조합을 거절만 한다. 영역으로 짓는 거친 계층이 필요해지면 따로 STEP 이 필요하다 (builder `_coarse_ball_exclusion` 이 공 전용) |
| 손가락 권한 창 | **공을 쓰지 않는다.** 권한 행은 link 이름 (`authorized_links`), 미세 창 배치는 손 swept AABB + manipulated AABB 다. TrajOpt 의 `target_volume` (공) 은 `--target-volume-exempt` 일 때만 실리는데 T76 서버 인자에 없다. `target_membership = layer_diff` 는 `ball_owned` 방식일 때만이다. 표면 방식의 방식 이름은 `oracle_visible` 이라 둘 다 이 구성에서 읽히지 않는다. 바꿀 것이 없었다 |

## A2 겹침 기준 — 근거 (T76 SURF 487 요청, 결과 전)

규칙은 **영역 쪽 비율**이다. 영역 (pixel 가중) 중 ATS 점 10 mm 안 비율이 ≥ 0.5 이어야 한다.

ATS 쪽 비율 (ATS 점 중 영역 안) 은 쓰지 않았다. ATS cluster 는 여러 카메라를 합친 점이라, wrist 카메라 한 대의 영역에는 ATS 점의 16–50 % 만 든다. 그래서 맞는 영역이 떨어진다.

| 분류 (정답: 영역 pixel 의 사과 비율) | 요청 | 영역 쪽 비율 (node 단위, 구현 그대로) 최소 · 5 % · 중앙 · 95 % · 최대 | ATS 쪽 비율 (쓰지 않음) |
|---|---|---|---|
| 맞는 영역 (≥ 50 % 사과) · ATS 가 사과 위 | 229 | **0.587** · 0.666 · 0.997 · 1.0 · 1.0 | 0.161 · 0.416 · 0.991 · … |
| 틀린 영역 (< 20 % 사과) · ATS 가 사과 위 | 68 | 0 · 0 · 0 · 0.023 · **0.183** | |
| 틀린 영역 · ATS 가 옛 자리 | 75 | 0 · … · **0.037** | |
| 섞인 영역 (20–50 %) · ATS 사과 위 | 11 | 0.364 · … · 0.616 (A1 뒤 11/11 통과) | |
| 맞는 영역 · ATS 가 옛 자리 | 67 | 0 (1 개만 1.0) | |

- 문턱 0.5 는 과반이다 (`instance_of` 의 ≥ ½ 과 같다). 두 분포 사이 (0.183 – 0.587) 에 있다. 0.4–0.5 어디에 두어도 이 기록의 판정은 같다.
- A1 → A2 순서로 구현 함수를 그대로 적용한 결과는 이렇다 (`t78a_a2_nodes.py`, `a2_nodes.json`).
  - 맞는 영역 + ATS 사과 위: **229 / 229 채택**.
  - 틀린 영역: **155 / 156 기각** (A4 고정 밖 기준 29 / 29). 채택된 1 개는 closing 중이라 A4 가 선택을 하지 않는다.

**T75 경우 (target 점이 오래된 경우) 를 확인했다.**

- "맞는 영역 · ATS 옛 자리" 67 요청의 latch 는 closing 38 · held 13 · placed 16 이다. **쥐기 전 (searching · latched) 은 0** 이다.
  - closing · held 는 A4 로 선택 자체를 하지 않는다.
  - placed (놓은 뒤, 사과는 바구니 속) 는 기각이 맞는 결과다. 이 기각이 T76 의 "쥔 뒤 바구니 지움" 을 없애는 길이다.
- ATS 가 occluded (가려져 마지막 관측 기하) 인 채로 쥐기 전인 맞는 영역 13 요청은 13 / 13 통과했다. 물체가 움직이지 않았으면 오래된 점이라도 같은 자리이기 때문이다.
- 떨어지는 경우는 **가려진 동안 물체가 밀린 경우** (T75 회귀 211) 뿐이다.
  - 그때 A2 는 맞는 영역을 기각한다.
  - A3 는 memory 를 carve 한다. 밀려난 옛 자리 표본은 너머가 보여 지워진다. 그 결과 손 층은 거의 아무것도 지우지 않는다.
  - 옛 자리를 지우는 일 (T75 · T76 의 증상) 은 없어진다. 대신 밀린 사과를 면제하지도 못한다.
