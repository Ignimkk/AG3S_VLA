## 0. 왜
- P0 (최종 구성, `P0_FINAL_CONFIG_FOR_BENCHMARK_20261103_KO.md`) 에서 학습한 분류기가 맡는 일은 하나뿐이다: 3 단계 gate (`clustering.subtask_gate`, 서버 기본 on) 의 label (pick · place · home) 을 `kv_L4_v1` probe 가 VLA hidden 에서 낸다. 그 label 로 AG3S 는 place / home 동안 새 조작 대상을 잡지 않고, PLACED ∧ home 이면 놓은 물체를 풀어 준다.
- 이 probe 는 RB-Y1 checkpoint 에서 학습했으므로 Panda 에는 없다. 단계별 접촉 제약은 이미 grasp latch (측정 개도 · 실행 feedback) 와 손바닥–target 거리로만 정한다. gate label 도 latch 에서 만들면 **단계 결정 전체가 학습 없이 물리 신호로만** 돈다.

## 1. 구현 (기본 꺼짐 flag, 꺼짐 = 지금과 bit 동일)
- `serve_safe --subtask-from-latch` (bool, 기본 False). `--no-subtask-gate` · `--hsr5` 와 같이 주면 argparse 가 거절한다.
- 켜면 `SafePolicy._subtask_gate_input` 이 probe 확률 대신 **이번 요청의 latch phase** 의 one-hot 을 낸다:
  - SEARCHING · LATCHED · CLOSING → `pick`
  - HELD → `place`
  - PLACED → `home`
  - latch 가 없거나 phase 를 모르면 None (label 없음 — 지금과 같은 처리).
- latch 는 `_scene_fn` 안에서 `set_subtask` 보다 먼저 진행되므로 (safe_policy.py 1062–1084) 같은 요청의 phase 를 쓴다. AG3S 의 debounce (`subtask_confirm_frames`) 는 그대로 둔다.
- 기록: 요청마다 `ag3s` 기록 또는 safe_policy 기록에 `subtask_source = "latch"` 와 쓴 label. probe 는 계속 계산돼도 되고 (기록용), gate 에는 들어가지 않는다. 시작 log 한 줄 `subtask gate label from grasp latch (T92): ON`.
- `# --- T92 — begin/end` 블록. 같은 파일 (safe_policy.py · serve_safe.py) 을 T93 구현자가 동시에 고친다 — 편집 직전에 다시 읽고, 다른 STEP 블록은 건드리지 않는다.
- test: 꺼짐 증명 (함수를 켜면 터지게 바꾸는 방식), phase → label 표 전부, argparse 충돌, 서버 인자 → config 전달.

## 2. closed-loop (결과 전 고정)
- **P0m** = P0 서버 인자 (`verify/T88/kit/server_flags_p0.txt`) + `--subtask-from-latch`. kit guard: `--subtask-from-latch` 필수, T88 kit 의 금지 flag 그대로.
- 장면: T88 의 10 run 에서 허들 211 을 뺀 **9 run**, 같은 seed. 비교 = T88 P0 (같은 9 run).
- 평가 정의: T88 §2 의 새 정의 (쥐는 순간 붙은 이웃 접촉은 따로 셈) 와 옛 정의 둘 다.
- 통과 (모두):
  1. 금지 접촉 없는 성공 (새 정의) ≥ P0 − 1 (P0 = 9 / 9).
  2. 금지 접촉 run ≤ 1, 탁자 · 바구니 0.
  3. 기전 확인: 놓기 전 (latch PLACED 전) 요청에서 gate 가 새 조작 대상을 막은 경우 (`subtask_gated`) 가 0 — label 이 pick 이어야 할 때 막지 않는다.
- P0 대 P0m 차이 ≤ 2 run = "구분 못 함". 통과하면 P0m 을 최종 구성 후보로 하고 T93 의 기준 구성으로 쓴다.
- 실패마다 원인 층 (ATS · HSR · LTE · CCR) 을 T85 진단 도구로 적는다.
