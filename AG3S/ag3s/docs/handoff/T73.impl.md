## 무엇을 했나 (평이한 요약 먼저)

openpi Gemma 에 기본 꺼짐 flag `return_hidden` 을 넣었다. 켜면 PaliGemma (expert 0) 의 layer 별 residual stream 을 `[19, B, T, 2048]` 로 돌려준다. h_0 은 입력 embedding, h_l 은 block l 의 출력이다 (final norm 전, HF `output_hidden_states` 와 같은 관례). 이 flag 는 `Pi0Config.return_hidden_states` 로 연결된다. 끄면 계산이 이전과 같다: 출력과 KV 가 bit 동일하고, trace 한 jaxpr 문자열도 수정 전 파일과 같다.

그 위에 CPU 전용 추출 도구 `pi05_hidden.py` 를 만들었다. 기록된 관측 frame 을 policy 의 input transform 에 넣고 **prefix pass 만** 돌린다 (denoising · action expert 없음). 요청한 layer · token 의 hidden 을 `.npz` 로 쓰고, frame 마다 "저장한 hidden 으로 V cache 와 prefix 출력을 다시 만들 수 있는가" 를 스스로 검사한다.

실제 16D checkpoint 로 frame 3 개를 돌리는 smoke test 는 두 번째 시도에서 시작됐다. model load 9.2 s, AOT compile 1.9 s 를 거쳐 첫 frame 을 돌던 중 (RSS 15.3 GiB), 다른 세션의 closed-loop (`serve_safe` + `pi05_infer`) 이 시작되면서 pod working set 이 76 GiB 가 됐다. watchdog 이 이 도구만 종료했다. 그 뒤 9 분 넘게 기다렸지만 working set 은 57–63 GiB 로, 64 GiB 상한 아래로 돌아갈 여지 (≤ 48 GiB) 가 없었다. 그래서 frame 당 시간과 파일 크기는 아직 재지 못했다.

## 사용법 (사용자가 직접 돌리는 명령)

```bash
cd /mnt/dev/AG3S_VLA-development
source scripts/setup/env.sh
export AG3S_RUN_DIR="$(.venv-openpi-live/bin/python -m common.run_output)"
MUJOCO_GL=osmesa PYTHONPATH=$PWD .venv-openpi-live/bin/python -m AG3S.ag3s.experiments.sources.pi05_hidden \
  --records <.../ag3s/run_0000  또는  .../policy_records/session_xxx> \
  --frames 0 13 26 --layers all --tokens all --pool none --dtype float16 --threads 16 \
  --out "$AG3S_RUN_DIR/hidden/<이름>.npz"
```

- GPU 를 쓰지 않는다. `main()` 이 JAX import 전에 `JAX_PLATFORMS=cpu`, `CUDA_VISIBLE_DEVICES=""` 를 설정하고, process 를 `--threads` 개 CPU 에 pin 한다 (`sched_setaffinity`. XLA CPU thread pool 이 affinity 를 따른다). backend 가 cpu 가 아니면 멈춘다. GPU lock 은 잡지 않는다.
- 기본값: `--checkpoint` = `$AG3S_STORAGE_ROOT/checkpoints/rby1/pi05_rby1_randomized_pick_place_16d_lora/rby1_randomized_pick_place_16d_30k_xla_retry_20260923/29999` (serve_safe `server_proc.txt` 에서 확인한 것과 같은 step), `--config pi05_rby1_randomized_pick_place_16d_lora`, `--out` = `$AG3S_RUN_DIR/hidden/<record>.npz`. 이미 있는 파일은 덮어쓰지 않는다.
- 입력은 두 형식을 자동으로 구분한다: AG3S record `run_XXXX/` (`meta.json` + `step_*.npz`, `load_run` 과 같은 key 중 `state` · `t_step` · `image_*` 만 읽음) 와 OpenPI `policy_records/session_*/step_N.npy`.
- 옵션: `--layers all | 0 4 10 18`, `--tokens all|image|text`, `--pool none|mean` (카메라별 256 token 평균 · 유효 text token 평균), `--dtype float16|float32`, `--prompt`, `--limit`, `--no-check`.

출력 `.npz` key (F = frame, Ls = 선택 layer, Tsel = 선택 token, D = 2048):

| key | 모양 | 뜻 |
|---|---|---|
| `hidden` | `[F, Ls, Tsel, D]` (`--pool mean`: `[F, Ls, G, D]`) | 기본 float16. 모델 자체는 bf16 |
| `layers` | `[Ls]` | 0 = embedding, 18 = 마지막 block 출력 (final norm 전) |
| `token_index` · `token_group` | `[Tsel]` | prefix 위치 · 0/1/2 = 카메라 (`camera_names` 순서), 3 = text |
| `token_valid` · `prefix_mask` | `[F, Tsel]` · `[F, 968]` | text padding 은 False |
| `camera_names` · `camera_token_ranges` · `text_token_range` | `[3]` · `[3,2]` · `[2]` | `CAMERA_BINDINGS` 그대로 (0-256 / 256-512 / 512-768), text 768-968 |
| `pool_groups` | `[G]` | `--pool mean` 일 때 행 이름 |
| `text_token_ids` · `text_token_pieces` | `[F, 200]` | pi0.5 는 이산화한 state 를 text 에 넣으므로 frame 마다 다르다 |
| `frame_id` · `t_step` · `source_files` · `prompt` | | `frame_id` = `<file stem>@t<t_step>` |
| `checkpoint` · `config` · `code_commit` · `code_dirty` | | `code_dirty` = gemma/pi0/pi0_config/도구 파일에 미commit 변경이 있음 |
| `absmax` | `[F, 19]` | layer 별 최대 \|h\|. float16 상한 (65504) 을 넘으면 inf 를 쓰지 않고 멈춘다 → `--dtype float32` |
| `check_v_relerr` · `check_final_norm_relerr` | `[F, 18]` · `[F]` | 아래 자기 검사 (`--no-check` 이면 NaN) |
| `compile_s` · `frame_s` | `()` · `[F]` | AOT compile 시간, frame 당 prefix 시간 (compile 제외) |

같은 이름의 `.json` sidecar 에 meta · 시간 · peak RSS 를 쓴다.

자기 검사 (frame 마다, `pi05_hidden.py:253-302`):
1. 저장한 h_l 에 block l+1 의 `pre_attention_norm` 과 `kv_einsum` (LoRA 포함, 모델의 module 그대로) 을 적용해 V 를 다시 만들고, KV cache 의 V[l] 과 비교한다 (l = 0 … 17).
2. `final_norm(h_18)` 을 같은 pass 의 prefix 출력과 비교한다.

## verifier 가 알아야 할 것

- 새로 생긴 flag · 기본값: `gemma.Block/Module.return_hidden=False`, `Pi0Config.return_hidden_states=False`. serving 은 이 flag 를 켜지 않는다.
- 재생산이 필요한 산출물: 없음. smoke 출력은 아직 없다 (위 script).
- 옛 기록과 호환이 깨지는가: 없음. 꺼짐 경로는 jaxpr 까지 같다.
- 제한:
  - `recompute_v` 는 multi-query (`kv_einsum`) 구조만 지원한다 (gemma_2b 가 그렇다).
  - 출력 `.npz` 한 파일에 모든 frame 을 담는다 (frame 당 75 MB). 수백 frame 이면 `--layers` · `--pool mean` 으로 줄이거나 나눠서 돌린다.
  - `--threads` 는 CPU affinity 로 실행 core 만 제한한다. OS thread 수 (최대 167) 는 orbax · XLA 의 내부 pool 이다.
  - float16 저장은 \|h\| > 65504 면 멈춘다 (실제 값은 smoke 에서 `absmax` 로 확인 예정).
  - frame 당 시간이 수 분 이상이면 task §4 의 early-exit (scan 길이 줄이기) 를 제안할 자리다. 아직 측정 전이라 판단하지 않았다.
