## 1. 공통 — attention source 를 하나의 지정으로 일반화 (중복 구현 방지)
- 지금 `AG3S/trajopt/attention_policy.py` 는 `_DENOISE_STEP = 0 · _AGG = "last" · _LAYER = 8 · _HEAD = 2` 고정 (action query).
- 기본 off 의 serve_safe flag 하나로 attention source 를 지정한다 (예: `--attention-source SPEC`). SPEC 은 query · aggregation · layer · head 를 담는다:
  - 기본 (flag 없음) = 지금 그대로 (action · last · denoise 0 · L8H2) — **bit-identical**.
  - `noun_target:L10H7` = T57 단계 1 N (prompt 의 target 명사 token 행, prefix pass, raw, σ 0, k 1 — `t54_arms` 의 N 과 같은 정의).
  - `action:mean:L10H7` = T61 의 사전 고정 선택 (B 의 `T61.selection.json`: action query · denoise 0 · mean · L10H7 · k 1). 이번에 구현만 하고, 서빙 채택은 T61 held-out 결과 뒤 사용자 판정.
- 명사 token 위치 찾기는 T49 / `t49_noun_query_extract.lookup` 과 같은 방식, 추출은 서빙 policy 호출과 같은 prefix pass 안에서 (`t53_extract.NounTokenExtractor` 와 parity). 명사를 못 찾으면 attention 은 빈 dict (합성 attention 을 끼워넣지 않는다, 기존 원칙) 와 사유 기록.

## 3. 단계 2 — HELD 중 task-aware 실행 gate (사용자 판정 6, 그대로)
- 연결 위치: **latch 상태와 명사 probe 결과가 준비된 뒤, 최종 실행 verdict 를 확정하기 직전.**
```
task_ready = held and probe_pass
if task_gate_enabled and held and not probe_pass:
    verdict_reasons.add("task_not_ready")
```
- `task_not_ready` 가 있으면 기존 HOLD 경로로 그 chunk 의 실행을 보류한다.
- HELD 가 아닐 때는 이 gate 로 차단하지 않는다 (`not task_ready` 전체를 HOLD 조건으로 쓰지 않는다).
- HOLD 중에도 새 관측과 정책 · prefix · probe · latch 추론은 계속한다 (dev 기록으로 요청마다 새로 계산됐음을 보일 수 있게 기록).
- probe 가 다시 true 이면 그 요청부터 `task_not_ready` 만 제거한다. 다른 HOLD 사유는 그대로.
- attach / detach, TargetConfirm, 외부 Phase 는 바꾸지 않는다.
- probe = T55 prereg 그대로: feature `v5` (target 명사 token 행의 layer 5 V cache, 256 차원, `t55_study.noun_matrix("v5")` 와 같은 정의), `…/20261013T171325+0900_cf38c9dbca7b_2ebfd8a5a43c/verify/T55/noun_probe.npz` (logistic C 0.1), τ = 0.3, 지속 p = 1, `noun_ok` 필요 (명사 못 찾으면 probe_pass = false). flag 기본 off.
- 정의 문구: "운반 · 놓기 단계 전이나 작업 완료를 인증하는 기능이 아니다. **물리적으로 보유 중이지만 지시한 대상을 보유했다는 신호가 부족하면 실행을 보류하는 기능**."
- shadow 모드 (gate off 여도 probe p · task_ready 를 계산해 기록만): 별도 flag. 기록 키 `task_ready` · `probe_p` · `noun_ok` · `latch_state` · `task_gate_applied` (요청마다).
- 보고 구분: flag off 출력 회귀 (bit-identical) 와 shadow 비용 (요청당 ms · p95) 을 따로. "기본 off 라 비용도 같다" 고 쓰지 않는다.
