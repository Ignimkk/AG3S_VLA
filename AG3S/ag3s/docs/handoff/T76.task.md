# T76 — depth 연속 표면 graph 가 target 경계를 공 방식보다 잘 구분하는가 (고정 입력 재생, 결과 전 고정)

> writer: lead (세션 A) · 작성: 2026-10-30 KST · 상태: **사전 고정.** 실행 · 집계: 세션 A.
> 사용자 지시 (2026-10-30): "2번으로 수행해봐. 로봇 제어 측면은 중요하지 않습니다. depth 연속성으로 경계를 잘 구분하는지만 확인해보면 됩니다. 만약 TO를 쓸거면 최근에 가장 성공률이 높았던 방식(목적함수, 제약조건, 규칙 등)을 사용하세요."

## 0. 왜

- 논문 방법 설명 (`paper/METHOD_GUIDE_KO.md` §4.2) 은 target 경계를 depth 연속 표면 graph 가 정한다고 쓴다. 이 기능은 `--target-extent attention-surface` 로 켠다.
- 최종 구성 (A8) 은 이 flag 없이 공 방식 (`--target-exclusion ball-owned`) 을 쓴다.
- 핵심 평가 계획 §3.1 의 공 대 표면 비교는 §0.1 판정으로 대체되어 실행되지 않았다.
- 이전 비교 (IFG-CL3, 2026-10-17, 렌더 mask): 금지 접촉 없는 성공 17 대 19 / 40 이었고 차이를 확인하지 못했다. 경계 자체는 재지 않았다.

## 1. 방법 — 고정 입력 재생 (closed-loop 아님)

- 입력: T74 Q1 의 closed-loop 기록 10 run (`20261030T065754+0900_8ab3c7ef7757_4aea29e44498/verify/T74/S1`). Q1 은 최근 가장 성공률이 높은 구성이다 (8 / 10).
- 도구: `t65_replay_client.py` (T65).
  - 기록된 요청을 차례로 서버에 다시 보낸다. 영상 · 상태 · 실행 feedback 은 기록 그대로이고, depth 는 기록 qpos 로 다시 렌더한다.
  - 서버 응답은 쓰지 않는다. 로봇 궤적은 기록 그대로다.
  - T65 parity: 고른 target 일치 1.0, 점구름 chamfer 중앙 0.1–1.8 mm.
- 두 구성, 같은 입력:
  - **공 방식** = Q1 서버 인자 그대로 (최종 구성 − 여러 초기값 − 쥐기 목표 항 + 쥐기 전 꺾임 변화율 · 연속성 끔).
  - **표면 방식** = 공 방식 + `--target-extent attention-surface`.
    - 로봇 mask 는 채택된 구 mask 다 (A7, 렌더 mask 끔). 그래서 표면 선택은 `top1-only-ns:N` 경로로 간다.
    - 표면 방식이 바꾸는 것은 손 층 (미세 target-free 계층) 에서 지울 범위뿐이다. 공 · 거친 계층 · 권한은 그대로다.
- **변경 기록 (2026-10-30 17:12 KST, 결과 전):** 표면 방식에서는 `--nontarget-evidence surface` 를 뺀다.
  - serve_safe 가 두 flag 를 함께 받지 않는다. 이 flag 는 공 방식 미세 계층 분할에만 걸리므로, 표면 방식에서는 효과가 없다는 이유다.
  - 그래서 표면 방식 = 공 방식 − `--nontarget-evidence surface` + `--target-extent attention-surface` 다.
- 서버 인자 · 코드 · openpi 는 T74 Q1 과 같다.
  - 코드: T67 snapshot.
  - openpi: 회귀는 snapshot, 가림 · 허들은 `$RUN/openpi_wt`.
  - 허들 run 은 `.argv.json` 이 없어서, 쥐는 손 · seed 를 기록 meta 의 client argv 에서 읽는다.
- GPU: 공유 lock. 결과가 벽시계와 무관하다. TrajOpt 출력은 지표에 쓰지 않는다.

## 2. 지표 (요청 단위, `AG3S-CORE-EVAL/module_eval.py` 의 LTE 정의 그대로)

- 손 층에서 지운 voxel 을 MuJoCo 정답 (같은 요청의 qpos) 의 8 mm 안 최근접 물체로 분류한다.
  - target 으로 센다: 사과, 사과 안쪽 (보이는 표면 뒤 TSDF 띠), 사과 꼭지 · 잎.
  - **경계 오류 (주 지표)**: 이웃 과일 · 장애물 (기둥 · 허들 막대) · 탁자 · 바구니로 분류된 voxel.
  - 따로 센다: 로봇, 분류 없음 (8 mm 밖).
- 사과 남김 비율: 보이는 사과 표면 중 손 층에 그대로 남은 비율. 낮을수록 target 을 잘 지운 것이다.
- 표면 방식 기권: 코드 영상을 못 만들어 공 방식 추정으로 돌아간 요청 수와 이유.
- 표면 선택 시간 (ms): 서버 기록.
- 구간: 정답 단계 pick (정답 쥠 전) 을 주 구간으로 본다. 쥔 뒤는 따로 보고한다.

## 3. 판정 (결과 전 고정)

같은 run · 같은 요청 짝으로, pick 구간 전체 합계를 본다.

- **"depth 연속 경계가 더 잘 구분한다"**: 아래 모두를 만족한다.
  1. 경계 오류 voxel 합계: 표면 ≤ 0.5 × 공.
  2. 이웃 과일 voxel 을 지운 요청 수: 표면 ≤ 공.
  3. 사과 남김 비율 중앙값: 표면 − 공 ≤ +0.05.
- 1 · 2 를 만족하고 3 을 못 넘으면 "경계는 좁히지만 target 을 덜 지운다 (교환)" 로 보고한다.
- 공 방식의 경계 오류 합계가 10 voxel 미만이면 "이 장면들에서는 공 방식도 경계 오류가 거의 없어 구분할 차이가 없다" 로 보고한다.
- 장면별 · 이웃 과일이 사과 30 mm 안에 붙은 요청 (경계가 어려운 경우) 을 따로 보고한다.
- 재생 parity 확인: 공 방식 재생과 기록된 Q1 서버 chunk 의 지운 voxel 수를 비교한다. 중앙 차이가 5 % 를 넘으면 그 사실을 결과와 함께 적는다.
