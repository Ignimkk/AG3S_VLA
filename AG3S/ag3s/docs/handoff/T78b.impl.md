## flag 의 정확한 뜻 (둘 다 `--target-extent attention-surface` 에서만, 기본 off)

### `--surface-reattach-hull MM` (`esdf.surface_reattach_hull_mm`, `--surface-split` 필요)

1. A1 (`split_by_attention`) 이 **성립 (split)** 한 요청에서만 돈다. target 덩어리 = `components[0]` 이다.
2. target 덩어리 node (5 mm graph node 중심) 의 convex hull 을 qhull 로 만든다.
3. 다른 덩어리마다 node 중심 평균 c 를 구하고 `d = max_f (n_f · c + b_f)` 를 계산한다.
   - `d ≤ 0` 이면 hull 안이다.
   - `d ≤ MM` 이면 facet 을 MM 만큼 밀어낸 부피 안이다. 이것은 offset polytope 로, 공과의 Minkowski 합보다 꼭짓점에서 조금 크다.
   - `d ≤ MM` 이면 붙인다.
4. 붙인 덩어리의 pixel 은 code 1 로 남는다. 즉 memory 에 target 으로 fold 된다.
5. 한 번만 검사한다. 붙인 뒤 hull 을 다시 키워서 반복하지 않는다.
6. target hull 이 퇴화하면 아무것도 붙이지 않는다. 퇴화는 점 < 4 개이거나 평면인 경우다 (`why = hull_degenerate`).
7. 기록 `t78.split.reattach` 는 다음과 같다.
   - `margin_mm`, `applied`, `target_hull {n_vertices, volume_cm3}`.
   - `components[]` 마다 `n_nodes`, `centroid`, `centroid_to_target_mm`, `hull_dist_mm` (= d), `attached`.
   - `n_attached` · `n_dropped` · `n_nodes_attached`.
   - `n_nodes_after` 는 붙인 뒤의 수다.

### `--surface-hull-fill` (`esdf.surface_hull_fill`, `--surface-keep-last` · `--surface-no-ball` 필요)

1. **hull 저장** (`_surface_hull_store`): A2 까지 통과한 채택 요청마다 영역 (A1 · 붙이기 뒤) node 의 convex hull 을 `self._surface_hull` 에 둔다.
   - 같이 두는 것: 이번 분할이 **버린** 덩어리의 code-1 pixel 을 같은 pinhole 로 올린 점 (`dropped_points`).
   - 채택이 없는 요청 (기권 · A2 기각 · A4 고정) 은 마지막 채택 hull 을 그대로 쓴다.
   - 그래서 A4 고정 중에는 마지막 채택 영역의 hull 이 쓰인다.
   - `reset()` 이 hull 을 지운다.
2. **구간** (`_surface_hull_fill`, `_build_esdf` 의 A3 분기에서 매 요청). 아래 셋 중 하나면 쥐기 직전이다.
   - `set_grasp_latched` (= latch LATCHED · CLOSING, `safe_policy.py:1057`) → `window = latched`.
   - `set_grasp_active` (CLOSING · HELD) → `window = grasp_active`.
   - 쥐는 손바닥 점이 hull 중심 (node 평균) 에서 `surface_hull_fill_palm_mm` (80) 안 → `window = palm_near`.
   - 손바닥 점 정의: 이번 frame 권한이 있는 gripper 마다 두 손가락 link 의 제약 구 중심 평균. 구가 없으면 두 손가락 link 원점의 평균이다. 여러 손이면 최소 거리를 쓴다.
3. **guard**: A5 의 `z_floor` (영역 표본 중심 아래 지지면 + 1 미세 voxel) 를 쓴다. 없으면 hull 중심 아래 지지면 + pad 를 쓴다. 둘 다 없으면 지우지 않는다 (`why = no_support_guard`).
4. **builder** (`_hull_fill_exclusion`, `_oracle_exclusion` 다음):
   - 후보: 격자 voxel 중 중심이 hull facet + 1 미세 voxel (5 mm) 안인 것.
   - 지울 수 있는 voxel (`fill`): `z_floor` 위에 있고, 버린 덩어리 표본이 들지 않은 voxel. 표본이 든 voxel = `round((p − origin)/vs)`.
   - 지우는 것: `fill` 중 oracle 분할 뒤에도 **아직 seed 인 것**.
   - `fill` 전부를 부호 교정 집합에 더한다. `_force_sign_on_pure_voxels` 는 다른 표면이 반 칸보다 가까우면 그대로 두는 보수 규칙이다.
   - memory 의 다른 code-2 표본 (앞선 요청의 "사과 아님" 기억) 은 보호하지 **않는다.** task 원인 2 에서 지워야 할 대상이기 때문이다.
5. 기록은 두 군데다.
   - pipeline `stats.target_free.oracle.hull_fill`: `applied` · `why` (`no_accepted_region` · `outside_window` · `no_support_guard`) · `window` · `latched` · `grasp_active` · `palm_mm` · `palm_source` · `hull_source` (`this_request` / `last_accepted`) · `hull_age_frames` · `volume_cm3` · `z_floor_source` · `ms`.
   - builder `stats.target_free.hull_fill` (= tier `exclusion.hull_fill`): `n_hull_voxels` · `n_below_floor` · `n_protected` · `n_protect_points` · `n_seeds_left_in_hull` · **`n_extra_removed`** · `n_seeds_kept_protected` · `n_seeds_kept_below_floor` · `n_sign_extra` · `pad_mm` · `z_floor_m` · `ms` · window · hull_source · volume_cm3.
   - `n_removed` 와 trace `target_free_removed_ijk` 에는 추가로 지운 것이 **포함**된다. 따라서 `t76/t78_metrics` 의 제거 분류가 그대로 읽는다.
   - `n_target_owned` 는 oracle 분할 몫이다.

## 어디에 걸었나와 이유 — builder 의 oracle 분기 (`curobo_builder._build_tiers` → `_hull_fill_exclusion`), 결정은 `_build_esdf`

| 후보 | 판단 |
|---|---|
| oracle path (`oracle_visible_split` · memory 에 점 추가) | hull 안 voxel 은 seed 가 있는지를 알아야 지울 수 있다. 그 정보 (`site_index`) 는 builder 에만 있다. memory 에 가짜 표본을 넣으면 다음 요청에도 쌓이고 carve 규칙과 섞인다 |
| `_build_esdf` 만 | 손 층 격자 · seed 가 없다. 결정 (구간 · hull · guard · 보호 표본) 만 여기서 한다. robot_state · contact_context · support 가 여기 있기 때문이다 |
| **`curobo_builder` 미세 target-free 계층 (선택)** | oracle 분할이 seed 를 지운 **바로 뒤**, 같은 격자 · 같은 `_seed_mask` / `_clear_seeds` / 부호 교정 계약으로 지운다. 주 계층과 거친 계층은 한 voxel 도 바뀌지 않는다 (`oracle` 은 미세 target-free 계층에만 온다). 추가로 지운 voxel 이 trace 에 실려 기존 집계가 그대로 읽는다 |
