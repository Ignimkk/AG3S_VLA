## 무엇을 했나 (평이한 요약 먼저)

쥐기 전 (latch 가 searching · latched · closing, attach 없음) 매 요청마다 **조작 대상이 마지막으로 서 있던 점들을 이번 요청 depth 에 투영**한다. 점마다 그 pixel 의 관측 depth 와 점 자신의 depth 를 비교해 *비어 있음* (광선이 옛 위치를 지나 뒤에 닿음) · *가려짐* (앞에 무엇이 있거나 로봇 pixel) · *있음* 으로 나누고, 판정 가능한 점이 가장 많은 카메라의 비율로 그 요청을 판단한다. "비어 있음 ≥ p_empty ∧ 있음 ≤ p_present" 가 **연속 2 요청**이면 target 을 놓고 (손 가림 · 쥐는 중 고정 · 잠근 정체 유지 규칙보다 먼저) **같은 요청에서** 다시 고른다 — 옛 중심 200 mm 안의 admissible 후보 중 점수가 가장 높은 것, 없으면 가장 높은 admissible 후보, 그것도 없으면 target 없음 (지우지 않음). 이 다시 고르기는 작업 단계 gate (place · home) 에 막히지 않는다. flag `--target-vacancy-release` (config `clustering.target_vacancy_release`) 는 기본 꺼짐이고, 꺼지면 아무 데서도 읽지 않는다.

측정 도구 (`t81_vacancy.py`) 로 §1 의 5 run 을 요청마다 쟀다: **회귀 211 은 seq 16–17, T80 C 두 run 은 seq 15–16 에서 비어 있음 0.58–0.96 / 있음 ≤ 0.16** 이고, **성공 run 두 개에서 규칙이 적용되는 요청의 비어 있음은 최대 0.26** 이다. 문턱 제안: δ 20 mm, p_empty 0.45, p_present 0.30, M 20, N 200 (아래 §측정).

### 규칙 세부 (구현이 정한 해석 — lead 확인 필요한 것 표시 ▲)

- **옛 위치 (§1.2):** `TargetConfirm._geometry` — 마지막으로 관측된 조작 대상 기하 (visible 이면 그 요청 cluster, occluded 이면 마지막 관측, subset/closing kept anchor 면 그 anchor, IFG-FOLLOW 가 옮겼으면 옮긴 것). 최대 N 개를 배열 순서대로 고르게 뽑는다 (`sample_points`, 결정적).
  - **T78 구성과 공 (ball) 구성에서 같은 점이다.** 규칙은 ATS grounding 이 고른 조작 대상의 cluster 점 (`TargetConfirm` 의 기하) 만 읽는다. T78 의 표면 영역 (`_attention_surface_update_t78`) 과 공은 그 뒤 ESDF 단계에서 이 기하로부터 만들어질 뿐 `TargetConfirm` 으로 돌아오지 않으므로, target extent 가 `attention_surface` (T78) 이든 공이든 옛 위치는 ATS cluster 점이다. 놓으면 그 요청의 `manipulated_geometry` 가 새 target (또는 없음) 이 되므로, T78 A2 (`ats_points`) 도 새 target 과 비교한다. ▲ T78 A3 (`surface_keep_last`) 가 지난 채택 영역의 memory 를 유지하는 규칙이라, 놓은 직후 옛 자리 표면 표본이 memory 에 얼마나 남는지는 T78 쪽 동작이다 — closed-loop 에서 "옛 자리 지운 voxel 이 사라지기까지 요청 수" 로 보인다.
- **판정 (§1.3):** 점을 카메라 좌표로 옮겨 pixel 로 반올림 (`_visible` 과 같은 투영). 이미지 안 ∧ depth > 0 인 점 = valid. valid 중 robot pixel 은 가려짐, 나머지 (= 판정 가능) 는 `관측 − 점 depth` 가 > δ 비어 있음, < −δ 가려짐, 그 외 있음. **카메라 선택과 M 은 판정 가능 (로봇 pixel 아님) 점 수로**, ▲ **비율의 분모는 valid 점 전체 (로봇 pixel = 가려짐)** — 손이 옛 자리 앞에 있으면 비어 있음 비율이 내려가지 올라가지 않게. 두 수 (`n_judged`, `n_robot`, `n_valid`) 가 모두 기록에 있다.
- **robot mask:** 서빙에서는 scene reconstruction 의 self-filter depth mask (T38 B2, 3 카메라 모두, `collision_backend` 가 esdf/both 일 때). 없으면 None (depth 비교만).
- **적용 조건 (§1.1):** 고정 (frozen = grasp active ∨ attach) 이 아니거나, 고정이어도 closing (`note_pre_attach_grasp` ∧ `note_latched` = latch CLOSING ∧ attach 없음) 일 때. HELD (grasp active ∧ latch 가 LATCHED/CLOSING 아님) · attach 중 · ▲ **PLACED 를 본 뒤 (이 episode) 에는 적용하지 않는다** (task 는 HELD 와 attach 만 적었지만, 놓은 뒤의 물체는 옮겨진 것이라 "옛 자리" 질문이 아니고, place 뒤 다시 고르기는 SUBTASK-c B3 의 home 규칙과 겹친다). 기록 `why = placed`.
- **연속 2 요청 (§1.4):** 적용 · 판정 가능 · 조건 만족이 아닌 요청 (가려짐 · 판단 불가 · 있음 · 카메라 없음 · 적용 안 됨) 은 연속 횟수를 0 으로 되돌린다.
- **놓은 뒤 (§1.5):** `_forget_manipulated()` (정체 · 기하 · anchor · 손 가림 근거가 함께 사라짐), 같은 `select()` 에서 다시 고르기. 고정 (closing) 중이어도 다시 고른다 (`_held is None` 분기는 고정을 보지 않는다). ▲ 200 mm 안 후보가 없으면 **가장 높은 admissible 후보** 를 고른다 (task 의 "후보가 없으면 target 없음" 을 admissible 후보가 하나도 없을 때로 읽었다; 이때는 `NO_ADMISSIBLE` 이고 다음 요청에서 다시 고르기가 이어진다). 가까운 후보만 받게 하려면 한 줄이다.
- **작은 이동 (§1.7):** 옛 자리 점이 "있음" 이면 `있음 > p_present` 로 놓지 않는다 → IFG-FOLLOW (`kept_geometry_follow`) 가 그대로 맡는다.
