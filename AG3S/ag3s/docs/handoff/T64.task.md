## 왜

- 지금 HSR 은 pick · place · home 3 단계만 나눈다. 그래서 LTE 가 "들어 올리는 중" 과 "바구니에 내리는 중" 에 다른 접촉 허용을 줄 수 없다.
  - 들어 올릴 때: 쥔 물체와 테이블의 접촉 허용
  - 내릴 때: 쥔 물체와 바구니의 접촉 허용
- 학습 데이터에는 expert 수집기가 frame 마다 기록한 14 단계 phase 가 이미 있다 (`transport_atomic.Phase`). 그래서 새 annotation 없이 다시 묶을 수 있다.
- 지금까지 HSR 은 strong rule (그리퍼 · 접촉 evidence 로 HELD 판정) 대비 추가 가치를 보이지 못했다 (AG3S_T47_LOG "T55": 다른 물체를 쥔 경우 216 → 212 frame).
- 이번에는 rule 이 약한 조건에서 시험한다.
  - **앞서 알기:** 정책의 의도가 물리 증거보다 먼저 드러나는가
  - **놓친 attach:** "T55b" 에서 실제로 쥐었는데 attach 를 놓친 117 frame

## 사전 고정

### 단계 묶음 (expert `phase_index` → 단계)

| 6 단계 | phase_index | 4 단계 (6 단계가 기준 미달일 때) |
|---|---|---|
| approach | 0 시작 대기 · 1 접근 · 2 쥐기 전 정렬 | approach |
| grasp | 3 손가락 닫기 · 4 쥐기 확인 | grasp (3–5) |
| lift | 5 테이블에서 들기 | ↑ grasp 에 포함 |
| transport | 6 운반 | transport |
| placement | 7 바구니로 내리기 · 8 놓기 · 9 놓기 확인 | placement (7–13) |
| retreat | 10 물러나기 · 11 안정 대기 · 12 준비자세 복귀 · 13 종료 대기 | ↑ placement 에 포함 |

- 재시도 phase (20–22) 와 그 밖의 index 는 학습 · 평가에서 뺀다. 그 frame 수는 보고한다.
- **6 → 4 전환 규칙:** 6 단계 probe 의 데이터 val macro-F1 이 0.80 미만이면 4 단계로 바꾼다. 이 규칙은 Part A 결과로만 정하고, Part B 를 본 뒤에는 바꾸지 않는다.

### Part A — 데이터 label 로 학습 · 평가 (CPU)

- data: 기존 HSR 과 같은 feature 파일 `results/workspace/verify/SUBTASK-b/feat/{train,val}`. train 200 episode · val 50 episode, 각 frame 의 `phase_index`.
- feature: `normal__kv_L4` (512 차원). 지금 HSR 과 같아서 서빙에서 추가 forward 가 없다. 다른 layer 는 보지 않는다 (feature 를 고르는 탐색을 하지 않음).
- 모델: 지금 HSR 과 같은 방식 (StandardScaler + 다항 logistic regression). C 는 train 안의 GroupKFold(5) 로 고른다.
- 지표: val 의 단계별 F1, macro-F1, 혼동 행렬, 단계 경계 지연 (frame).

### Part B — closed-loop 기록에서 물리 정답 대비 (CPU)

- data: T55 test 의 원래 prompt 재시뮬 16 episode (T53 기록과 bit 단위로 같음). T55 가 이미 뽑은 `kv_l4` feature 를 쓴다.
- **물리 정답** (MuJoCo, target 기준, 결과 전에 고정):

| 단계 | 정의 |
|---|---|
| approach | target 손가락 접촉이 처음 생기기 전 |
| grasp | 접촉 시작부터, 보유 중 target 이 시작 높이보다 2 cm 오를 때까지 |
| lift | 2 cm 오른 뒤, 수평 이동이 5 cm 미만인 동안 |
| transport | 보유 중이고 수평 이동 ≥ 5 cm, target 이 바구니 xy 범위 밖 |
| placement | target 이 바구니 xy 범위 안 (보유 중이거나 놓은 직후), 놓은 뒤 손이 target 에서 5 cm 멀어질 때까지 |
| retreat | 그 뒤 |

- **비교 rule (같은 6 단계, 서빙에서 쓸 수 있는 신호만):** latch 상태 (재실행 grounding 의 SEARCHING · LATCHED · CLOSING · HELD · PLACED), 손 높이 · 수평 이동 (FK), AG3S destination (바구니) 위치. 경계값은 물리 정답과 같다 (2 cm · 5 cm).
- **주 지표:** episode 평균 macro-F1 (단계 정확도).
- **보조:** 경계별 전환 지연 (frame). **앞서 알기** = 물리 정답 전환보다 먼저 맞힌 frame 수, 경계별 median.
- 불확실성: episode bootstrap B 10000 · seed 6401.
- **보조 data (보고만):** 핵심 평가 round 1 의 요청별 HSR · 물리 정답 기록 (run `20261028T224856+0900_b3b69311f948_8784a1265958` `verify/AG3S-CORE-EVAL/module/core.json`, 세션 A 제공, 읽기만). 현재 채택 config 에서 3 단계 HSR 의 일치도를 6 단계 결과와 나란히 보이는 데만 쓴다. 판정에는 쓰지 않는다.

### Part C — 놓친 attach 보완 (OR 결합)

- 결합: HELD′ = strong rule HELD **OR** (HSR 단계 ∈ {lift, transport, placement} **∧** latch 의 손가락 evidence `closed` · `blocked` 가 참)
  - 4 단계일 때는 {grasp 뒤의 transport, placement}.
- data: T55 test 의 재실행 grounding 기록 (instruction 변경 · 원래 · 빈손 · 미끄러짐 조건).
- **기준 (모두 충족해야 "보완 가치 있음"):**
  1. instruction 변경 조건에서 놓친 117 frame 의 회복 비율 ≥ 50 %
  2. 빈손 · 미끄러짐 조건에서 잘못 세운 HELD 의 증가 0 frame
  3. 원래 조건의 false pass 증가 ≤ +1 %p

### 판정 문구 (결과 전에 고정)

- **"6 단계 HSR 이 rule 보다 단계를 더 잘 나눈다":** Part B macro-F1 차이 (HSR − rule) 의 95 % CI 하한 > 0.
- **"앞서 알기 가치":** transport → placement 또는 approach → grasp 경계에서 HSR 의 median lead ≥ 1 frame 이고, 그 경계 F1 이 rule 보다 0.05 이상 낮지 않다.
- **"보완 가치":** Part C 기준 1–3 을 모두 충족.
- 셋 다 아니면 "이 feature 로는 strong rule 대비 추가 가치가 관측되지 않았다" 로 적는다. HSR 단계가 LTE 에 쓸 만한지는 셋 중 하나라도 충족할 때 closed-loop 실험 (세션 A) 으로 넘긴다.

### 실패 상황의 단계 (확정 2026-10-29)

- **원칙:** 단계는 시간 순서가 아니라 **그 순간 물체의 물리 상태**로 정한다.
  - LTE 가 단계에 따라 허용을 바꾸므로, 쥐지 못한 물체에 "쥔 물체" 용 허용이 남으면 안전 문제가 된다. 예: 테이블 접촉 허용, attach.

| 상황 (물리) | 정답 단계 | 이유 |
|---|---|---|
| 손가락을 닫았는데 물체가 손에 없음 (빈손 쥐기) | 닫는 동안 **grasp**, 손가락이 다시 열리면 **approach** (재시도) | 쥐기 시도는 했지만 보유가 성립하지 않았다. 다음 행동은 다시 접근 |
| 들거나 운반하다 손에서 빠짐, 물체가 바구니 밖 | **failure** (7 번째 label) | 보유 단계 허용을 즉시 끊어야 하는 상태다. 정상 6 단계 어디에도 맞지 않는다 |
| 바구니 위에서 빠짐 (물체가 바구니 안에 떨어짐) | **placement** | 결과적으로 놓기와 같은 물리 상태다 |
| 다른 물체를 쥠 | 쥔 물체 기준 단계 + **task 불일치** 표시 | 단계는 물리, "지시한 물체인가" 는 별도 판단 (지시 물체 확인 gate 의 역할) |

- 학습 데이터의 재시도 phase (20 다시 열기 · 21 물러나기 · 22 다시 접근) 는 approach 로 묶어 학습에 넣는다. 처음 초안은 이를 빼는 것이었다. 빈도와 결과는 따로 보고한다.
- **failure 의 지표:** 정확도 (macro-F1) 에서는 빼고 따로 보고한다.
  - 물체가 빠진 뒤 HSR · rule 이 보유 단계 (lift · transport) 를 벗어나기까지 걸린 frame 수
  - 짧을수록 위험이 작다
- data: T55 의 빈손 쥐기 · 미끄러짐 개입 재시뮬 (기존 기록).

| 판정 문구 | 기준 | 결과 | 판정 |
|---|---|---|---|
| 6 단계 HSR 이 rule 보다 단계를 더 잘 나눈다 | macro-F1 차 (HSR − rule) 95 % CI 하한 > 0 | +0.020 [−0.043, +0.087], 16 episode 중 7 개 높음 · 8 개 낮음 | **미충족** |

- **결론:** 6 단계 HSR 은 단계 구분 정확도와 경계를 먼저 알아채는 것에서는 strong rule 대비 추가 가치가 관측되지 않았다. **strong rule 이 놓친 attach 를 보완하는 데서는 추가 가치가 있다.**
- 단계별로 보면 HSR 은 approach (0.84 vs 0.76) · grasp (0.58 vs 0.29) · retreat (0.95 vs 0.86) 에서 rule 보다 높고, lift (0.67 vs 0.93) · transport (0.29 vs 0.84) 에서 낮다. 이는 아래 closed-loop 후보의 사용 방식 (보유 관련 허용은 HSR ∧ 물리 evidence) 과 맞는다.
- 사전 고정 규칙 ("하나라도 충족하면 closed-loop 실험으로 넘긴다") 에 따라 아래 후보를 세션 A 에 넘긴 것이 그대로 유효하다.

## closed-loop 후보 (사용자 판정 2026-10-29: "HSR 을 사용한다" · 사용 방식 승인) → 세션 A
