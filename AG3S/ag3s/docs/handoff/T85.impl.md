## 무엇을 했나 (평이한 요약 먼저)

서버 flag `--hsr-gt-stage` 와 client flag `--safe-gt-stage` 를 더했다. 켜면 client 가 요청마다 MuJoCo 정답 5 단계
(approach · grasp · carry · place · retreat) 를 계산해 요청에 싣고, 서버는 그것을 분류기 (`--hsr5`) 의 결과와 **같은 모양의
record** (`{"p": 원-핫, "argmax": 단계, "probe": "gt"}`) 로 `SafePolicy._hsr5_start` 에 넣는다. 그 뒤 (새 조작 대상 gate · `--hsr6-*`
네 규칙의 단계 · deflection-rate / continuity after-grasp · closing 풀기) 는 `--hsr5` 와 **같은 코드** 를 그대로 탄다
(`hsr5.py` 의 `SUBTASK3` · `RULE_PHASE6` · `AFTER_GRASP_STAGES` · `CLOSING_KEEP_STAGES` 불변). HSR6 · HSR5 probe 는 이 모드에서 읽지 않는다.

정답 단계의 정의는 T77 `t77_labels` 의 것 (`gt_held` · `phase5_sequence` · `SceneProbe`) 을 복제하지 않고 재사용한다. client 쪽 인과 계산
(`CausalPhase5`) 은 요청마다 (held, 손바닥–target 거리, 바구니 안) 을 열에 더하고 `phase5_sequence` 의 **마지막 항목** 을 낸다 —
정의상 같은 열에서 같은 값이다 (test 로 보임). 측정은 client 가 도는 시뮬레이션의 `qpos` (+ mocap) 를 **private `MjData`** 에 옮겨
`mj_forward` 한 것이라 제어 루프의 `MjData` 는 건드리지 않는다 (test: qpos · qvel · xpos · qacc_warmstart · time 불변).

## 기록 (summary_json.hsr5)

- gt 모드: `hsr5 = {"stage": <단계>, "p": 원-핫, "argmax": <단계>, "probe": "gt", "ms": None, "source": {규칙: "hsr5"/"latch", ...}, "stage_source": "gt"}`.
  **주의 (task §2 의 "`summary_json.hsr5.source = "gt"`" 와 다른 점):** `hsr5.source` 는 이미 "규칙별 단계 출처" dict 라서 (`{"subtask_gate": "hsr5", ...}`),
  거기에 문자열을 덮어쓰지 않고 `probe: "gt"` 와 `stage_source: "gt"` 로 남겼다. 규칙별 `source` 값은 `--hsr5` 와 같다 ("hsr5" = 단계 label, "latch" = label 없음).
- `hsr6.phase` 는 이 모드에서 `None` (HSR6 probe 없음); `hsr6.rule_phase` · `phase_source: "hsr5"` 는 `--hsr5` 와 같이 정답 단계에서 온 값.
- 서버가 단계를 못 받은 요청 (client 가 측정 못함 → 키 없음) = `result["hsr5"]` 없음과 같은 "label 없음" (stage `None`, 규칙은 엄격한 쪽 · latch 규칙).
- client 가 자기 쪽에 남기는 것: 없음 (`GtStageSource.last` 는 메모리에만). 필요하면 lead 가 요청하라.

## 남은 위험

- `hsr5.source` 가 task 문구와 다르다 (위 "기록"). verifier / scribe 는 `hsr5.probe == "gt"` · `hsr5.stage_source == "gt"` 로 읽어야 한다.
- 정답 `held` 는 측정된 MuJoCo 접촉 (target 과 쥔 손의 두 손가락 body) 이다. 쥐는 순간 바구니 · 탁자와의 접촉은 보지 않는다. 손가락 body 이름은 MJCF 이름 (`ee_finger_{l,r}{1,2}`) 이라 URDF 와 좌우 손가락 이름 바뀜 (T43 OC) 과 무관하다 (양쪽 모두 쥔 손의 두 손가락 집합이므로 같은 집합).
- target body 는 randomized episode 의 `target_fruit` 이다 (T77 오프라인 라벨은 항상 `apple`). 사과 장면 (허들 954 등) 에서는 같다. 다른 과일 장면에서는 T77 라벨과 다를 수 있다.
- client 측정은 요청 직전 `_pack` 에서 한 번 (private `MjData` forward 1 회) — 요청당 수 ms 미만. 벽시계에 의존하는 측정이면 이 비용이 client 쪽에 더해진다 (서버 `time_budget_ms` 에는 들어가지 않음).
- 정답 단계는 상한이 아니다 (oracle ≠ 상한). 분류기가 아닌 이유의 실패는 그 층에서 따로 적는다.
