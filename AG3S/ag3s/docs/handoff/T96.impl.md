## flag 의 정확한 뜻

| flag (config) | 기본 | 뜻 |
|---|---|---|
| `--surface-solid-owned` (`esdf.surface_solid_owned`) | 꺼짐 | 손 층 seed 를 지우는 길에 solid 를 더한다. 켜면 τ 보호가 표면 · 띠 길에도 걸린다. 전제 `--target-extent attention-surface --surface-keep-last --surface-no-ball`. `--surface-hull-fill` · `--surface-contact-allowance-mm` · `--surface-memory-target-sticky` 와 같이 주면 시작 거절 |
| `--surface-solid-protect-mm τ` (`surface_solid_protect_mm`) | 5 | 가장 가까운 비 target 표본까지 거리 `d_N ≤ τ` 인 voxel 은 어느 길로도 지우지 않는다 (부호 교정 후보에서도 뺀다). flag 없이 주면 거절 |
| `--surface-solid-dilate-mm δ` (`surface_solid_dilate_mm`) | 0 | solid 길은 S 의 facet 을 δ 밀어낸 부피 (`max_f(n_f·x+b_f) ≤ δ`, voxel 중심 기준) 를 본다. flag 없이 주면 거절 |

- **S:** `R` = 직전 채택 영역의 graph node (5 mm voxel 중심, `region.pos` — A1 · A2 뒤, `_surface_hull_store` 와 같은 영역). `R⊥` = `R` 을 영역 중심 아래 받침면 (`_support_surface_under`, `_support_plane_z` 와 같은 규칙 · 같은 평면, normal 정규화) 에 수직으로 내린 점. `S = conv(R ∪ R⊥)` (`attention_surface_post.convex_hull`, qhull).
- **d_T:** target 표본 (memory code 1) ∪ `R ∪ R⊥` 중 가장 가까운 것 (solid 길이 보는 voxel 에서만 계산). 영역 표본 = memory code 1 표본과 node 둘 다 넣었다 (task 의 "영역 표본 ∪ R⊥").
- **d_N:** `OracleVisibleEvidence.other_points` = 표면 기억의 code ≠ 1 표본 전부. **확인 결과 — 로봇 표본은 빠지고 받침면 표본은 들어 있다.** attention-surface code 영상에서 로봇 pixel 은 code 0 (기억에 안 들어감), 그 밖의 모든 graph pixel (탁자 · 바구니 · 이웃) 이 code 2 (`runtime/attention_surface.py` 표 · `oracle_segmentation.points_from_codes`). 그래서 τ 는 탁자 표본 근처 (guard 위 ~5 mm) 에도 걸리고, `d_T ≤ d_N` 도 탁자 표본과 겨룬다 (아래 "verifier 가 알아야 할 것" 2).
- **z_floor:** 지금의 A5 guard 그대로 (`ev.z_floor` = code 1 표본 중심 아래 받침면 + 1 미세 voxel). guard 가 없으면 solid 를 만들지 않는다.
- **창:** 구간 제한 없음 (손 층은 쥐는 손 권한 행만 본다). A4 (`--surface-grasp-hold`) 동안은 직전 영역 그대로.
- **영역 없음:** solid 없이 τ 만 건 evidence (`why: no_accepted_region`). 받침면 없음 `no_support_plane`, guard 없음 `no_support_guard`, hull 퇴화 `degenerate_hull (…)`.

### 기록 `target_exclusion.attention_surface.solid` (JSON)

`applied` · `why` · `protect_mm` · `dilate_mm` · `region_source` (`this_request` / `last_accepted`) · `region_age_frames` · `n_region_nodes` · `n_projected` (R⊥ 점 수) · `support_surface_id` · `plane_z_at_centroid_m` · `z_floor_m` · `volume_cm3` · `n_vertices` · `ms` (pipeline) · `voxels` = builder 의 `{protect_mm, dilate_mm, has_solid, n_solid_voxels, n_removed_surface, n_removed_band, n_removed_solid, n_removed_dilate, n_removed_total, n_protected_tau (+ _surface · _band · _solid), n_seeds_in_solid, n_sign_fill_nonseed, candidates_ms, split_ms, region_source, volume_cm3}` (builder 가 안 갈랐으면 None). 길별 seed 수는 겹치지 않게 센다 (solid = 표면 · 띠가 안 지운 것 중 S 안, dilate = S⊕δ − S). npz trace `target_free_solid_removed_ijk` · `target_free_solid_protected_ijk`.

## flag 의 정확한 뜻

| flag (config) | 기본 | 뜻 |
|---|---|---|
| `--surface-solid-shadow-mm L` (`esdf.surface_solid_shadow_mm`, mm) | 안 줌 (None) | 직전 채택 영역 요청의 카메라 중 하나에서 `x` 의 가장 가까운 pixel `(round v, round u)` 이 code 1 이고, `0 < z_cam(x) − depth[v,u] ≤ L` (z-depth 비교, depth > 0 · 유한), `z ≥ z_floor`, `d_N > τ` 이면 그 seed 를 지운다. 표면 · 띠 · solid 길이 이미 지운 seed 는 세지 않는다 (`n_removed_shadow` = 그림자만 지운 수). `--surface-solid-owned` 필요. 권장 80 |

- **`d_N` (그림자 길):** 기억의 code ≠ 1 표본 **전체** 를 상자 ± τ 로 자른 것 (T96 의 `ref` AABB 자르기와 별도 — 상자는 그 AABB 를 넘을 수 있다. `d_N ≤ τ` 판정에는 정확하다) 에서 D28 평면 (`dn_plane`, 8 mm) 의 표본을 뺀 것. `n_shadow_dn_support_dropped` 는 그 상자 안에서 뺀 수.
- **카메라:** `_surface_solid_store` 가 영역을 저장한 요청 (`frame_index` 같음) 의 `SurfaceView` 들 중 code-1 pixel 이 있는 것. code 영상은 A1 분할 뒤 (`restrict_codes`) · A2 통과한 것 = 영역 node 를 만든 pixel 과 같다. frame index 가 다르면 `why: camera_frame_mismatch` 로 그림자 없음.
- **상자:** `S.lo − L … S.hi + L` (S 꼭짓점 = `R ∪ R⊥`). 보인 target 표면 ⊂ S 이므로 그림자 (표면 뒤 L 안) 는 이 상자 안에 있다. 상자 안 seed 만 후보에 더한다 (non-seed 는 그림자 길이 보지 않는다).
- **기록:** pipeline `attention_surface.solid.shadow` = `{applied, why?, shadow_mm, cameras {이름: target pixel 수}, box_lo_m, box_hi_m}`, builder `attention_surface.solid.voxels` 에 `shadow_mm · n_removed_shadow · n_removed_shadow_by_camera {이름: 수} (한 seed 가 두 카메라에서 맞으면 둘 다 센다) · n_protected_tau_shadow · n_shadow_looked · n_shadow_hits · n_shadow_box_seeds · n_shadow_candidates_added · n_shadow_dn_support_dropped · shadow_ms · shadow_candidates_ms`. `n_removed_total` 은 그림자를 포함한다. `n_seeds_in_ball` (oracle counts) 은 늘어난 후보의 seed 를 센다 (켬일 때만 뜻이 바뀜). npz `target_free_solid_shadow_removed_ijk` · `target_free_solid_shadow_protected_ijk`.

- **진단:** 재생의 "제거 목록에 있으나 손 층 값 <= 0" voxel 은 **전부 (B0p 1,447 / 1,447 · P0f 1,163 / 1,163) 같은 한 가지 원인** 이다. 지운 seed 바로 옆 (1 voxel 또는 √2 voxel) 에 **남은 seed** 가 있어서, 부호 교정의 순수 판정 (`_force_sign_on_pure_voxels`, `|d| > 1.5 vs` 일 때만 양수로) 이 그 voxel 을 건너뛰고, 거리 변환이 TSDF 에서 읽은 안쪽 부호 (음수) 가 그대로 남았다. 그 남은 이웃 seed 의 95–97 % 는 **사과 자신의 seed** (분할이 "다른 표본이 더 가깝다" 로 남긴 것) 다.

   - 남은 seed 옆 (1.5 vs 안) 이라 꺼짐에서 음수였던 removed seed 가 ≥ 5 개 있고, 켬에서 [vs, 1.5 vs] 의 작은 양수가 된다.
   - 남은 seed (값 0) · 이웃 B 표면 (여유 길은 설계상 B 일부를 지우므로 목록 밖 B) · 탁자는 그대로 0 이다.
   - 기록 수가 직접 센 값과 같고 `oracle_split` 으로 전달된다.
4. `_removed_sign_free` 의 numpy 길과 torch 길이 같다. 값 0 은 `n_zero_left` 로 세고 그대로 둔다. 빈 목록도 처리한다.
5. **server-arg 줄 두 개:** 각각 base 줄 + flag 와 정확히 같다. `build_parser` · `reject_bad_flag_combinations` · `trajopt_config_from_args` · `target_exclusion_section` → `AG3SConfig` 를 통과하고, 기록 meta 키가 있다. P0m_sign 은 hull 채우기 · 여유 10 · solid 없음, Q5 는 solid · ever-target · 그림자 80 이다.

## verifier 가 알아야 할 것 (T96e)

- **새 flag:** `--surface-removed-sign-free` (기본 안 줌). 기존 기본값은 바꾸지 않았다. 꺼짐 = 이전 그대로 (test 2).
- **재생산 필요 산출물:** 없음. **옛 기록 호환:** 깨지지 않는다. 새 키는 켤 때만 생긴다 (`oracle_split.removed_sign_free`).
- 1. **기대 상한:** class 5 는 켬에서 0 이 되어야 한다 (재생 원인이 100 % 순수 판정이었으므로). 그 voxel 들은 사라지지 않고 +5 · +7.07 mm 가 된다. 바로 옆의 남은 사과 seed (분할이 남긴 것, 다른 class 로 셈) 는 그대로 0 이다. 그래서 손가락이 실제로 얻는 여유는 그 자리에서 1 voxel 안팎이다. 남은 사과 seed 자체를 줄이는 것은 T96c · T96d 쪽 (d_N · 기억 라벨) 의 일이다.
- 2. **위험 — 접촉 여유 길 (P0m):** 여유 10 mm 는 설계상 target 표본 10 mm 안의 이웃 seed 도 지운다 (T78f 가정: 쥐는 순간 장애물 없음). 지운 이웃 seed 가 남은 이웃 seed 옆이면, 지금까지는 음수 (이웃 안쪽) 로 남았고 켬에서는 +5 mm 가 된다. 이웃 표면 (남은 seed) 은 그대로지만, 재생의 "freed by class" 에서 이웃 · 탁자 몫이 P0f 대비 늘 수 있다. 회귀211 (붙은 바나나) 을 따로 본다.
- 3. 순수 판정이 지켜 오던 경우 (target 과 다른 표면이 한 voxel 에 함께 있음) 에서 분할이 "지운다" 로 판정했다면, 이제 그 voxel 은 양수가 된다. 그 판정의 책임은 분할 (표면 · 띠 · solid · 여유 규칙) 에 있다. 이 flag 는 분할의 결론을 거리장에 그대로 옮길 뿐이다.
