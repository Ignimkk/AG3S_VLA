HSR (Hidden-state Sub-task Recognition: frozen VLA prefix feature 위의 `kv_L4_v1` linear probe 로 pick / place / home 을 읽는 것) 의
counterfactual 실험을 돌릴 수 있게 만들었다. 한 frame 의 입력 셋 (prompt · 16D state · RGB 3 장) 중 하나만 바꾼 변형 6 종
(C0 원본 · C1 target 명사 → distractor · C1p 다른 phrasing · C2g gripper 값 반전 · C2s state 이식 · C2i image 이식) 을 만들고,
각 변형의 `kv_L4` feature 를 **서빙과 같은 prefix pass** 로 뽑아 cache 하고 (GPU, verifier 가 실행), probe 와 baseline 3 종
(simple rule · strong-rule proxy · frame-index) 의 예측과 지표를 CPU 에서 계산한다.

CPU 에서 확인한 것: val split 재현 (50 episode · 2601 frame · 1000/800/801) 이 SUBTASK-b 저장 feature 파일과 frame · state ·
label · rule 이력 · prompt 까지 51/51 unit 일치, 저장 feature 로 돌린 C0 수치가 rule 0.9423 · frame-index 1.000 · probe 0.98078 을

## 3. state 문자열 경로와 C2g

**변형은 16D float state 배열만 바꾼다.** 문자열은 서빙 transform 이 만든다:
`policy._input_transform` = `InjectDefaultPrompt` → `AlohaInputs(adapt_to_pi=False)` (state 그대로, `third_party/openpi/src/openpi/policies/aloha_policy.py:159-187`) → quantile `Normalize` (`transforms.py:141-145`; `use_quantile_norm` = pi05, `training/config.py:191`; norm stats = checkpoint `assets/local/rby1_randomized_pick_place_16d_v1/norm_stats.json`, `policies/policy_config.py:64, 77-82`) → `ResizeImages` → `TokenizePrompt(discrete_state_input=True)` (`transforms.py:248-266`; `pi0_config.py:43-46`) → `PaligemmaTokenizer.tokenize`: `np.digitize(state, linspace(-1,1,257)[:-1]) - 1`, `"Task: {prompt}, State: {bins};\nAction: "` (`models/tokenizer.py:22-29`) → `PadStatesAndActions` (문자열 뒤라 영향 없음) (`training/config.py:130-141`).

- extract 는 load 된 policy 의 `_input_transform` 을 그대로 쓴다 (`t48_hsr_features.py:69-73`). `discretize_state` (`t48_hsr_core.py:305`) 는 보고용 numpy replica 다.
- **token check (CPU, model 없이 같은 transform 조립, `build_cpu_input_transform`)**: val ep1600 · ep1807 의 18 row 씩 decode 한 prompt 가 replica 와 전부 일치. C0 대비 바뀐 state 숫자 수: **C2g 1 개 (used gripper dim 만)**, C1 · C1p · C2i 0 개, C2s 7–15 개. decode 예: `Task: Place the orange into the basket., State: 187 171 193 18 90 169 136 255 155 90 74 33 135 154 104 255;` → C2g 는 마지막 `255` → `89`. text token 수는 변형마다 1–4 개 달라진다 (예: ep1807 C0 81 · C1p 77 · C2g 80) — 기록은 `plan/token_check.json`, extract 는 `n_text_tokens` 를 unit 마다 저장.
- **used gripper**: `used_arm` left → `state[7]`, right → `state[15]` (val 50/50 에서 실제로 닫히는 dim 과 일치; 26 left · 24 right). C2g 는 이 dim 하나만 바꾸고 쓰지 않는 손의 gripper 는 그대로 둔다.
- **대표값 (train split 에서만)**: 열림 = used gripper ≥ 0.9 인 train frame 의 median = **1.0000** (p1–p99 0.9953–1.0004, n 7001). 닫힘 = used gripper < 0.9 이고 phase 4-8 (쥐고 있는 구간) 인 train frame 의 median = **0.6702** (p5–p95 0.494–0.732, n 3000; 과일별 median apple 0.723 · banana 0.495 · orange 0.667 · pear 0.673). 판정 문턱 0.9 (SUBTASK-b rule, `probe.py:104`): 값 < 0.9 → 1.0, 아니면 → 0.6702 (`flip_gripper`, `t48_hsr_core.py:127-141`). 서빙 bin 으로 열림 255 · 닫힘 89.

## 4. C2s / C2i 쌍

- host frame A 마다 partner B 하나: 같은 unit 안, A 와 **다른 class** 중 하나를 균등하게 고르고 그 class 의 frame 하나를 균등하게 (`sample_pairs`, `t48_hsr_core.py:213-235`).
  RNG = `np.random.default_rng([seed, seed_key])`, `seed_key` = sha256(unit_id) 앞 4 byte (`stable_key`, `t48_hsr_io.py:103`) — unit 순서 · Python hash salt 와 무관. 기본 `--seed 0`.
- 같은 (A, B) 에서 **C2s = image A + state B** (정답 A 의 class = image 쪽), **C2i = image B + state A** (정답 B 의 class = image 쪽). prompt 는 원본.
- val 2601 쌍 · ep1807 75 쌍. 각 row 에 `y_image` · `y_state` 를 기록하고 둘은 항상 다르다.

| baseline | 정의 | 출처 |

**원래 이력 (t 이전)** + 변형의 state (t) 를 보고, frame-index 는 A 의 clock 을 쓴다.

## 7. feature 추출 (GPU stage — 실행하지 않았다)

- model: `pi05_attention.load_policy(config, ckpt)` (`return_attn_probs=True`, 라이브 attention model 과 같은 load) → `AttentionSampler(policy._model)`.
- obs: HWC → CHW, `policy._input_transform`, batch 축, `Observation.from_dict`, `preprocess_observation` 한 번 (`observation_from_step` · `_sample:185` 와 같다).
- prefix: sampler 의 `_jit_prefix` + `_jit_kv_feature` (batch 1 = 서빙 reduction 그대로). suffix · denoise loop 는 돌리지 않는다.
- `--batch N>1`: 같은 reduction 의 batched jit. 첫 batch 를 batch-1 경로로 다시 돌린 차이를 `extract/extract_meta.json` `batch_parity` 에 남긴다.
- cache: `feat/<full|maxN>/<set>/<unit>.npz` = `feature (V,512)`, plan row 전부 (`plan__*`), `plan_digest` (sha256), `decoded_prompt` (model 이 본 문자열), `n_text_tokens`, `state_bins_serving` (decode 해서 읽은 bin), replica 불일치 수, `prefix_s`. 같은 digest 면 건너뛰고 (이어 하기), 다른 digest 면 덮어쓰지 않고 멈춘다.
- 시작 전 `nvidia-smi --query-compute-apps` 에 다른 process 가 있으면 멈춘다 (`--allow-busy-gpu` 는 lead 승인 시만). lock 은 스크립트가 잡지 않는다 — `flock` 으로 감싸서 실행 (안에서 다시 잡으면 교착).

- **GPU 예상 (측정 아님, 추정)**: 근거 = SUBTASK-b 실측 (H200, batch 1, prefix median 24.4 ms; val 5202 forward 를 wall 520 s = forward 당 ~100 ms, 그중 suffix 5 ms · 나머지는 input transform · eager preprocess · decode).
  - `--batch 1` (서빙과 같은 경로, 권장 기본): prefix 24084 × 24.5 ms ≈ 10 분, wall **~25–40 분** (checkpoint load · JIT 1–3 분 포함).
  - `--batch 8`: wall **~15–25 분** 예상; `extract_meta.json` `batch_parity` 를 먼저 본다.
  - GPU memory: bf16 weight ~3.3 B param ≈ 6.6 GB + prefix 중간값 (return_attn_probs 로 prefix attention probs 가 jit 안에서 만들어질 수 있음, sample 당 수백 MB) → **batch 1 ~8–12 GB, batch 8 ~15–25 GB** 예상, `XLA_PYTHON_CLIENT_PREALLOCATE=false`. 실측은 `extract/timing.json` (`per_input_ms_median`, `memory.peak_bytes_in_use`, `wall_s`).
  - CPU 측: video decode (unit 당 3 × ~310 frame) 와 tokenizer — 단일 process, worker 1.
- **baseline 의 C2 해석 주의 (정의상)**: rule · proxy 는 host A 의 이력을, frame-index 는 A 의 clock 을 본다. 그래서 frame-index 는 C2s 에서 image 쪽, C2i 에서 state 쪽과 정의상 같은 class 를 낸다. proxy 도 이력의 영향이 크다. 이 숫자는 위 §5 의 약속에서 나온 것이다.
- **C1 의 baseline 실패는 설계 결과다** (prompt 를 보지 않는다) — task 대로 수치만 보고.
- ep1807 frame-index 는 nearest fallback (549/675 row) 의 확장 정의다. `score/metrics.json` `frame_index_fallback_rows` 에 수가 있다.
- C1 정답 pick 의 전제 (distractor 미접촉) 는 val 최대 14.9 mm 이동 (ep1784 pear) 이 있다 — 위 §2.
