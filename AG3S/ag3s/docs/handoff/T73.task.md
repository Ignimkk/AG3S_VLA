# T73 — VLM (PaliGemma) 중간 layer hidden state 를 GPU 없이 CPU 로 추출 (도구 + smoke test)

> writer: lead (세션 cc) · 작성: 2026-10-30 00:45 KST · 상태: **사전 고정.** 구현 · smoke test: ag3s-implementer.
> 사용자 지시 (2026-10-30 ~00:20 KST): "기본 이미지 feature 가 아니라 VLM 의 중간 layer hidden state" 를 GPU 없이 뽑고 싶다 (사용자가 따로 테스트에 쓴다).

## 0. 왜 · 지금 무엇이 있나

- 지금 도구 `AG3S/ag3s/experiments/sources/pi05_attention.py` 는 prefix pass 의 **KV cache** (`kv_L4` = layer 4 V cache, head 0, 256 차원) 와 attention 확률만 꺼낸다.
  - V cache 는 hidden state 를 RMSNorm 한 뒤 W_v 로 256 차원에 사영한 값이다. hidden state (residual stream, 2048 차원) 자체가 아니다.
- `third_party/openpi/src/openpi/models/gemma.py` 의 `Module` 은 18 개 `Block` 을 `nn.scan` 으로 돌리고 마지막 layer 출력만 돌려준다. 중간 hidden state 는 밖으로 나오지 않는다.
- 같은 방식의 선례: `return_probs` (static dataclass flag, 기본 False, 끄면 byte 동일, checkpoint 그대로).

## 1. 구현에 요청하는 것

1. **openpi gemma 에 기본 꺼짐 static flag `return_hidden`** (`Block` · `Module`, `Pi0Config.return_hidden_states` 로 연결, `return_attn_probs` 와 같은 길).
   - 켜면 scan 출력에 layer 마다 **block 출력 hidden (residual stream, final norm 전)** 을 쌓아 돌려준다. h_0 = 입력 embedding, h_l = block l 출력 (l = 1 … 18) → `[19, B, T, 2048]` (HF `output_hidden_states` 와 같은 관례). PaliGemma expert (expert 0, prefix) 만.
   - 끄면 반환 계약 · 계산 · parameter 가 지금과 같다 (serving 경로 영향 0).
2. **추출 도구** `AG3S/ag3s/experiments/sources/pi05_hidden.py`
   - CPU 강제: `JAX_PLATFORMS=cpu`, `CUDA_VISIBLE_DEVICES=""` 를 도구 안에서 JAX import 전에 설정. GPU lock 을 잡지 않는다.
   - 입력: 기존 기록 (`policy_record.load_run` 이 읽는 형식, 또는 OpenPI `policy_records/session_*/step_N.npy`) 의 관측 frame 들. checkpoint = 16D 30k (`$AG3S_STORAGE_ROOT/checkpoints/rby1/pi05_rby1_randomized_pick_place_16d_lora/...`, config `pi05_rby1_randomized_pick_place_16d_lora`).
   - **prefix pass 만** 돌린다 (denoising · action expert 없음).
   - 출력 (`.npz`, 새 run 의 `$AG3S_RUN_DIR` 아래): 요청한 layer 들의 `hidden [n_layer_sel, T, 2048]` (float16 기본, `--dtype float32` 선택), token 지도 (카메라별 image token 구간 = `CAMERA_BINDINGS`, text token 구간 · 유효 mask), frame id, layer 번호, checkpoint · config · 코드 commit.
   - 옵션: `--layers` (기본 전부 0 … 18), `--tokens all|image|text`, 요약 `--pool none|mean` (카메라별 · text 평균).
   - 사용법을 docstring 에 적는다 (사용자가 직접 돌린다).
3. 손대지 않을 것: serving 코드 (`serve_safe` 등), 기존 `pi05_attention.py` 의 결과.

## 2. 검증 (→ implementer 가 smoke test 까지)

| # | 무엇 | 기준 |
|---|---|---|
| 1 | flag 꺼짐 동등성 (작은 random config 로 unit test) | 출력 · KV bit 동일 |
| 2 | hidden 이 맞는 값인가: 저장한 h_{l} 에서 `pre_attention_norm` + W_v 로 다시 계산한 V 가 layer l+1 의 V cache 와 같다 | 상대 오차 ≤ 1e-2 (bf16) |
| 3 | h_18 에 final norm 을 하면 flag 꺼짐 경로의 prefix 출력과 같다 | 상대 오차 ≤ 1e-2 |
| 4 | 실제 16D checkpoint · 기록 frame 2–3 개로 CPU 실행 | GPU 사용 0 (nvidia-smi 에 이 process 없음) |
| 5 | CPU 비용 | frame 당 시간 (compile 제외 · 포함), 최대 RSS, 파일 크기 |

- 메모리: 시작 전에 pod working set (`memory.current − inactive_file`) 을 보고 추정치를 더해 64 GiB 를 넘지 않을 때만 돈다. 넘으면 멈추고 lead 에게 알린다. thread 는 16 이하.
- 끝나면 process 를 종료하고 `python3 scripts/setup/reclaim_cache.py "$AG3S_RUN_DIR" <checkpoint 경로>` 한 줄을 impl.md 에 남긴다.
- figure: layer 별 hidden norm · 카메라별 image token 평균의 layer 간 cosine 그래프 1 장 + sidecar json (`AG3S/ag3s/docs/figures/t73-hidden-cpu.*`).

## 3. 이 STEP 이 답하는 질문

GPU 없이 16D checkpoint 의 VLM 중간 layer hidden state 를 정확하게 (KV cache 와 맞게) 뽑을 수 있고, frame 당 얼마의 시간 · 메모리가 드는가.

## 4. 되돌아올 지점

- CPU 시간이 frame 당 수 분 이상이면: 요청 layer 까지만 돌리고 멈추는 early-exit (scan 길이 줄이기) 를 제안한다 (구현은 lead 확인 후).
