## 0. 왜
- T91 (학습 없는 상태 기계) 은 사전 기준 미통과: 위험한 오판 8.6 % (분류기 1.4 %). 쥐고 옮기는 정답 요청의 98.8 % 에서 ATS target 이 손에 가려져 "target 이 손을 따라감" 을 볼 수 없었고, 대신 쓴 가림 규칙이 쥐지 못한 닫기 (허들 954) 를 운반으로 봤다.
- 사용자 관찰 (2026-11-01): "쥐는 중에 target 이 손목 카메라에 안 보이면 보통 쥐지 못한 것". 쥔 물체는 손목 카메라에서 손가락 사이 고정된 영역에 크게 보인다. LIBERO 계열에도 손목 카메라 (eye-in-hand) 가 있다.

## 1. 방법
- `phase_machine.py` 에 새 증거 하나 (기본 꺼짐 설정): **손가락 사이 target 증거** = 쥐는 손 손목 카메라 image 에서 손가락 사이 고정 영역 (로봇별 설정: image 안 사각형 또는 손가락 끝 사이를 투영한 영역) 의 pixel 중 target 으로 표시된 비율 ≥ τ_in, 연속 m 요청.
  - target 표시는 벤치마크 공통으로 얻을 수 있는 것만: (a) 그 요청 ATS target 점의 손목 카메라 투영 (가려졌어도 마지막 기하가 있으면 투영), (b) 손목 depth 가 그 영역에서 손가락 사이 거리 (손바닥에서 d_min–d_max) 에 있는 표면의 비율 — 둘 다 내고 (b) 를 주 증거로 한다 (target 인식에 기대지 않음).
  - 운반 판정 = 닫힘 ∧ 손가락 사이 증거. 닫혔는데 손가락 사이가 비어 있으면 운반 아님 (빈손).
- 다른 단계 규칙은 T91 그대로 (문턱 고정 값 재사용), 새 문턱 (영역 · τ_in · m · d 범위) 만 train 에서 고른다.

## 2. 평가 (결과 전 고정)
- RBY1: T91 과 같은 T77 test 207 run (허들 211 제외). 비교 = 채택 5 단계 분류기 (`h4_img3+last`), T91 상태 기계.
- SafeLIBERO (benchmark storage, 읽기만): benchmark-44 가 알려 준 VLA 단독 run `results/benchmark/20261017T151126_38722284e2fa_sl5f-safelibero-LI-dev-LI-vla_only/episodes/` (`<stem>.npz` eef · gripper_qpos · action_chunks 열 6, `_geom.npz` depth · K · T_world_cam). 정답 단계 = 시뮬레이터 재렌더 (`sim_state_image`) 로 손가락–물체 접촉 · 물체 들림 · 목적지 영역 (T77 정의와 같게, 쥐기 = 손바닥 60 mm 안). 분류기는 이 checkpoint 가 아니라 비교 불가 → T91 상태 기계와만 비교.
- 지표: 5 단계 정확도 (장면 평균), 위험한 오판률 (정답 접근 · 쥐기 → 운반 · 놓기), 전환 지연.
- 판정 (RBY1, 장면 평균): T91b 가 "쓸 만하다" = 위험한 오판률 ≤ 분류기 ∧ 정확도 ≥ 분류기 − 5 %p. SafeLIBERO 는 보고 (같은 문턱으로 위험한 오판률 ≤ 2 % 이면 "벤치마크로 옮길 만함" 으로 적는다).

## 3. 구현에 요청하는 것 (→ ag3s-implementer)
1. `AG3S/trajopt/phase_machine.py` 에 손가락 사이 증거 (설정 기본 꺼짐 — 꺼짐 = T91 결과 bit 동일, test 로 고정).
2. `t91_phase_eval.py` 에 손목 image · depth 입력 추출 (RBY1: client step npz 의 손목 카메라 depth · K · T; SafeLIBERO: `_geom.npz`) 과 SafeLIBERO 정답 단계 · 입력 어댑터 (`--dataset safelibero`, 새 파일로 분리해도 됨, benchmark storage 는 읽기만).
3. train 문턱 고르기 (RBY1 train 장면만), test 판정 json 은 lead 가 돌린다. SafeLIBERO 는 문턱을 다시 고르지 않고 RBY1 문턱 그대로 (로봇별 설정 — 손가락 사이 영역 · gripper 정규화 0.04 m · 열 6 — 만 바꿈).

5. 새 파일 / 기존 T91 파일만. serving 은 고치지 않는다 (세션 e1 의 T92 가 `_subtask_gate_input` 을 고치는 중).
