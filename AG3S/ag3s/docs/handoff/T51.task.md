# T51 — attention head 선택 protocol 공식화: filter → calibration → bootstrap 안정성 → held-out → ablation (RB-Y1 sim + LIBERO)

> writer: lead (A0) · 2026-10-12 KST · 읽는 쪽: implementer, verifier · 로그: `AG3S_T47_LOG.md`
> 사용자 판정 (2026-10-12):
> - head · layer 를 하나로 고정해 쓰려면 **선택의 당위성** 이 있어야 하고, **실물 로봇 · LIBERO 에서도 같은 절차로 고를 수 있어야** 한다. 리뷰어가 납득할 수 있게 공식화한다.
> - 범위: **RB-Y1 sim protocol + 실물용 grasp-event 자기 label 검증 + LIBERO.**
> - primary 선택 지표 = **3D `identity_correct`**. 2D lift 는 depth 가 없는 플랫폼용 보조 지표다.
> 공통 규칙: env.sh, 새 output 은 `$AG3S_RUN_DIR`, CPU worker ≤ 2, 다른 세션 process 금지, 커밋은 lead.
> GPU 는 T46 CL3 와 겹치지 않는다. LIBERO 실행은 다른 checkout (`AG3S_VLA-benchmark`) 의 LIBERO 작업과 조율한 뒤에 한다.

## 왜 지금 이것인가

- 서빙 cell `L8H2` (denoise 0 · agg last) 는 **14D · `cam_high` 1 대 · 28 frame** 에서 `peak_on_target` 하나로 골랐다. 절차로 설명되지 않는다.
- T47: 논문 (Kang et al.) 의 label-free 기준 (attention sum + spatial entropy) 은 action-token query 에서 **sink head 와 넓게 퍼진 map** 을 골랐다. 3D `on_target` 0/30 으로 실패했다.
- T47b: 시험한 변형 중 **raw L8H2 (smoothing 없음)** 의 `identity_correct` 가 가장 높았다 (held-out 26/30 · 28/30). 그러나 이것은 사후 비교이지 선택 규칙이 아니다.
- KNOWS 재현 (`Baseline/knows_vla/docs/08-p0b-results.md`, `pi05_libero`): (8,2) 0.700, 최고 (12,4) 0.715 — 다른 모델에서도 L8H2 부근이 상위권이었다. **보조 근거일 뿐 공식 절차는 아니다.**

**목표:** "이 규칙을 따르면 어느 모델 · 로봇에서도 같은 방식으로 cell 이 정해지고, 그 선택이 얼마나 안정적인지 수치로 말할 수 있다." 그 결과로 L8H2 가 다시 뽑히는지 확인한다. 다른 cell 이 뽑히면 서빙 반영은 별도 판정이다.

## Protocol (사전 고정 — 결과 보기 전)

후보 Ω = {(query, layer, head)}. query = action token (denoise 0 · agg ∈ {last, mean, first}). T49 결과가 나오면 명사 token 행도 같은 Ω 에 추가한다. layer 는 L2–17 (L0 · L1 제외).

| 단계 | 정의 | label 필요 |
|---|---|---|
| **P1 filter** (label-free) | calibration set 전체에서 cell × camera 마다 계산한다 (T47b #5 와 같은 정의). **제외** 조건: (i) image mass median < 0.01, (ii) **고정 patch sink** = 최빈 argmax patch 의 frame 비율 > 0.5 **이고** top-1 patch mass 몫 > 0.4, (iii) **넓게 퍼진 map** = top-1 patch mass 몫 < 0.03 **이고** 최대 component 면적 > grid 의 15 %. 한 camera 라도 해당하면 그 camera 에서 제외 (공통 cell 이면 cell 제외) | 아니오 |
| **P2 calibration 점수** | calibration episode 에서 cell 마다 primary **3D `identity_correct` 비율** (T47b 정의, raw · σ=0) 을 계산한다. 보조로 2D lift · `peak_on_target` · `nontarget_seed_loss` 도 낸다. 3D 계산 비용 때문에, **2D lift 상위 16 cell + L8H2 + T47b oracle 3 cell** 에만 3D 를 돌린다 (2D → 3D 2 단계 선별, 기준을 미리 고정) | 예 (GT 또는 자기 label) |
| **P3 안정성** | episode bootstrap B = 1000. 각 resample 에서 P2 1 위 cell 을 기록하고 **cell 별 1 위 확률 · top-3 포함 확률** 과 primary 점수의 95 % CI 를 낸다 | 예 |
| **P4 k 선택** | k ∈ {1, 2, 3} (상위 cell raw 합) 을 **episode 단위 nested CV** 로 고른다. 차이가 CI 안이면 **더 작은 k** 를 쓴다 (단순성 원칙, 사전 고정) | 예 |
| **P5 held-out** | calibration 에 쓰지 않은 record 로 평가한다. split 은 T47 과 같다: selection = `long` · `t2` · `ep1807` / held-out = same-scene `headfix` · `ep1800`, new-scene `ep1850` · `ep1900` | 예 |
| **P6 ablation** | 같은 held-out 에서 비교한다: 논문 label-free top-3 (T47) · head 평균 · **무작위 cell 20 개의 분포** · GT-oracle (상한) · 현재 L8H2 | 예 |

- 선택 결과의 **단일 head 고정 여부는 P4 가 정한다.** "하나로 고정" 이 데이터가 내린 결론이 되게 한다.
- 모든 threshold (0.01 · 0.5 · 0.4 · 0.03 · 15 % · 상위 16) 는 lead 가 결과를 보기 전에 정했다. T47b 에서 관찰한 sink (L14H5: top-1 0.669, 최빈 0.96) 와 넓은 map (L4H1 · L2H0: top-1 0.012–0.028, 최대 component 17–24 %) 을 걸러내는 최소 조건이다.
  **이 값들로 L8H2 (top-1 0.26–0.34, 최빈 0.09–0.33, 최대 component 4.5–7.2 %) 가 제외되지 않는지는 결과에서 보고만 한다.** 값을 다시 맞추지 않는다.

## 플랫폼별 label

| 플랫폼 | label | 이 STEP 에서 |
|---|---|---|
| RB-Y1 sim | MuJoCo segmentation GT (T47 GT cache) | P1–P6 전부 |
| **실물 로봇** | **grasp-event 자기 label**: gripper 가 물체를 쥔 시점 (sim 에서는 물리 predicate; 실물에서는 `grasp_latch` 의 HELD) 의 fingertip 중심 3D 위치를 **그 전 frame** 들의 camera 로 투영한다 → 물체가 쥐기 전에 정지해 있다는 가정에서 target pixel 위치를 얻는다. 사람 annotation 이 필요 없다 | **sim 에서 자기 label 을 GT 대신 써서 P2–P5 를 다시 돌리고, GT 로 고른 결과와 일치하는지** 확인한다. 지표: 자기 label 의 투영 오차 (GT target 중심까지 px), 고른 cell 의 일치 여부, held-out `identity_correct` 차이 |
| LIBERO | robosuite (MuJoCo) segmentation GT | **L1** 아래 참조 |

### LIBERO 단계
- **L0 조사 (CPU):** KNOWS P0b 수집물 (`Baseline/knows_vla/collect_p0b.py` · `probe_p0b.py` · `docs/08-p0b-results.md`) 이 cell 별 attention 과 GT (seg / bbox) 를 storage 에 남겼는지 찾는다. **있으면 그것으로 P1–P3 를 CPU 로 돌린다** (`pi05_libero`). 3D 지표가 불가능하면 2D primary 로 하고 그 사실을 명시한다.
- **L1 (필요하면):** 수집물이 없거나 부족하면 LIBERO 환경과 GPU 로 새로 수집해야 한다. 이 checkout 에는 LIBERO venv 가 없다 (`.venv-libero` 는 benchmark checkout 에만 있다). → **이 경우 여기서 멈추고 필요한 것 (환경 · GPU 시간 · benchmark checkout 과의 조율) 을 보고한다.** 사용자 판정 후 진행한다.

## 판정 보완 (사용자 2026-10-12, T51.impl.md 확인 후 · 결과 전)

- **LIBERO L1 승인 (KNOWS 재현 확인 없이).** KNOWS P0b 수집물 (`$AG3S_STORAGE_ROOT/datasets/workspace/knows_p0b/`, 40 episode · 1,479 step, frame · state · GT seg · depth) 에는 cell 별 attention 이 없다.
  → 저장 frame 에 `pi05_libero` attention pass 를 **이 checkout 의 `.venv-openpi-live` + `checkpoints/panda/pi05_libero`** 로 한 번 돌린다 (CL3 종료 후, GPU lock). 새 LIBERO rollout 은 하지 않는다.
  LIBERO primary = **2D lift** (3D `identity_correct` 는 불가). P1–P3 를 이 2D primary 로 돌린다.
- **RB-Y1 calibration 확장 승인.** calibration 이 3 episode (그중 `long` · `t2` 는 같은 scene) 뿐이라 bootstrap 의 서로 다른 resample 이 10 개뿐이고, P4 의 inner CV 가 episode 1 개로 학습한다.
  → 기록된 VLA 학습 episode run **`ep0` · `ep500` · `ep1200`** (`results/workspace/live_test/20260925_train/`) 을 calibration 에 추가한다. 이 run 들에 대해 GPU attention 추출 (T47 npz 와 같은 축 · 같은 checkpoint) 과 GT cache 생성 (CPU) 을 한다.
  **VLA 학습에 쓰인 episode 라는 점을 결과에 명시한다.** held-out (same-scene 2 · new-scene 2) 은 그대로 둔다.
  calibration 의 서로 다른 scene: episode 1800 (`long` · `t2`), 1807, 0, 500, 1200 → 5 개. bootstrap 은 **scene 단위** 로 다시 뽑는다 (같은 scene 의 run 은 함께 뽑는다).

- **집계 단위 (lead, T51.impl.md 확장 확인 후 · 결과 전 고정):** P2 의 점 추정은 **scene 평균** 이다 — 같은 scene 의 run 들을 먼저 평균한 뒤 scene 끼리 평균한다. record 평균은 보고만 한다. LIBERO 의 bootstrap 과 점 추정은 **task 단위** 로 묶는다. 근거: scene 단위 bootstrap 과 같은 원칙이다.

- **집계 단위 수정 (lead, 2026-10-12, verifier 발견).** 처음 코드는 P2 · P3 · P4 의 순위를 **record 평균** 으로 매겼다. 그래서 scene 1800 (`long` · `t2`) 이 6 개 중 2 개의 가중을 받았고, 사전 고정 (scene 평균) 과 어긋났다. GT 1 위가 record 평균에서는 `mean:L12H4`, scene 평균에서는 `last:L12H4` 로 달라졌다.
  → `--aggregate scene` 을 추가했다 (`T51.impl.md` "집계 단위 수정"). **scene 평균 결과가 primary** 다. record 평균 결과는 "사전 고정과 다른 방식" 으로 표시해 보고만 한다.
  held-out 비교 (P5 · P6 ablation) 도 **held-out scene 평균** 으로 낸다 (`headfix` · `ep1800` 은 같은 scene 1800). record 값은 함께 보고한다. LIBERO 는 `--aggregate task` 다.

## 이 STEP 이 답하는 질문
**사전에 고정한 filter → calibration → bootstrap → nested-CV 절차를 따르면 어떤 cell (과 k) 이 선택되고, 그 선택은 얼마나 안정적이며, 사람 label 없는 자기 label 로도 같은 결과가 나오는가?**

## 되돌아올 지점
- 선택이 불안정하면 (1 위 확률 < 0.5): "단일 head 고정" 을 주장하지 않는다. k > 1 또는 명사 query (T49) 를 Ω 에 넣어 다시 돌린다.
- 자기 label 의 결과가 GT 와 다르면: 실물 적용에는 소량 사람 annotation 이 필요하다고 명시한다 (필요한 frame 수를 bootstrap 으로 추정).
- LIBERO 수집물이 없으면 L1 판정을 요청한다.
- 서빙 반영은 이 STEP 에서 하지 않는다.
