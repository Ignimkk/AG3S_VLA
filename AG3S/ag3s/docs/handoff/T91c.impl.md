## §3.1 확인: 서버가 손목 depth 를 받는가 — 받는다 (client 변경 없음)
- 요청에는 카메라마다 `ag3s/depth/<cam>` (uint16 mm), `ag3s/K/<cam>`, `ag3s/T_base_cam/<cam>`, `ag3s/robot_state/<cam>`, `ag3s/stamp/<cam>` 가 실린다
  (`wire.pack_request`, `AG3S/trajopt/wire.py:441–490`; 서버는 `strip_request` 로 `ag3s/` 접두를 떼어 `scene["depth/wrist_cam_l"]` 로 읽는다).
  `wire.DEFAULT_CAMERAS = ("zed_left", "wrist_cam_l", "wrist_cam_r")` (`wire.py:406`) 이므로 손목 카메라 둘이 기본으로 실린다.
- 서버는 이 손목 카메라들을 이미 AG3S 관측으로 쓴다 (`wire.unpack_camera_observations`, `wire.py:594–620`: `depth/<cam>` 이 없으면 그 카메라를 버린다).
- T92 P0m closed-loop 의 client 기록에 같은 값이 있다: `step_*.npz` 의 `depth_wrist_cam_l|r` (480×640 uint16 mm), `K_wrist_cam_l|r`, `T_base_cam_wrist_cam_l|r`
  (`policy_record.py:217` 이 요청에 실은 것과 같은 양자화로 쓴다). 그래서 재생은 기록된 실제 요청 값을 쓴다.
- 서버 쪽은 `scene.get("depth/wrist_cam_<l|r>")` 만 읽고 (`safe_policy.py:1458`), 쥐는 손의 것을 고른다. 카메라 목록에 손목 카메라가 없는 client (예: `--cameras zed_left`)
  이면 `finger_gap=None` 이 되어 T91 규칙 (co-motion · 가림) 으로 내려간다 — 기록 `phase_machine.inputs.wrist_depth=false` 로 보인다.
- 필요한 client key 는 새로 없다. (K · T 는 이 flag 가 읽지 않는다: 손가락 사이 비율은 depth 의 고정 ROI 만 쓴다.)

2. **동시 사용 거절:** `--subtask-from-latch` · `--hsr5` (인자 있는 것도) · `--hsr-gt-stage` · `--no-subtask-gate`, 그리고 `--no-safe` · `--no-attention` · `--no-perception`. `SafePolicy` 생성자도 두 출처를 거절.
3. **빈손 닫기 → place 안 나옴:** 목표에서 멀리서 닫고 (손목 depth 가 탁자 / 없음) 35 cm 이동해도 carry · place 단계가 한 번도 없음. 서버 경로 (요청 dict → `_subtask_gate_input`) 로도 같음.
4. **손가락 사이 표면 + 닫힘 → place:** 목표에 접근해 쥐고 40 mm 들면 마지막 label 이 place (단계 carry). 표면이 없으면 pick 유지, 열린 손은 carry 아님.
5. **run 사이 reset:** reset 뒤 첫 걸음이 `n=0`, 개도 기준을 새로 배움 (reset 안 하면 0.5 로 읽힐 값이 1.0), 이전 run 을 돌렸어도 새 gate 와 label 이 같음, 쥐는 손이 바뀌면 새 machine.
6. **5→3 대응:** approach · grasp → pick, carry · place → place, retreat → home (표 + gate 가 machine 단계마다 그 one-hot 을 냄).
7. 서버 경로 == 단독 `PhaseGate` (같은 입력에서 같은 (label, stage) 열), 한 요청에 한 번만 걸음, 오른손 열 · 손목 카메라, 오류 = label 없음 (요청은 안 죽음), 개도 없음 = label 없음, T91 `thresholds.json` 의 `params` 가 gate 설정과 일치,

## verifier 가 알아야 할 것
- 새로 생긴 플래그·기본값 변경: `--subtask-from-phase-machine` 새로 생김, 기본 꺼짐. 기본값 변경 없음.
- 재생산이 필요한 산출물(npz 등): 없음 (재생 json 은 lead 가 생성).
- 옛 기록과 호환이 깨지는가: 없음. 꺼짐이면 기록 key · gate 입력이 이전과 같고, 켜면 `summary_json` 에 `subtask_source` / `phase_machine`, 서버 record 의 `subtask.source` 가 더해진다.
- 알려 둘 한계: (1) 서버 경로의 `ee` 는 URDF FK(`hold_site_position`), 재생의 `ee` 는 MuJoCo `<side>_ee` site 다 — 같은 점이라는 것은 A6 의 test 로 고정돼 있으나 이 STEP 에서 두 값을 직접 대조하지는 않았다.
  (2) 서버의 `chunk_gripper` 는 `_pending["chunk"]` (정책 chunk), 재생은 기록의 `reference_chunk` — 같은 것이다. (3) 손목 카메라를 안 보내는 client 에서는 T91 규칙으로 내려간다 (`inputs.wrist_depth=false`).
