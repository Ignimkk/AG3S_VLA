## 무엇을 했나 (평이한 요약 먼저)

1. **hidden 추출 도구 확장 (`pi05_hidden.py --pool patches`).** 새 option 세 개 — `--cameras` (3 카메라 image token), `--prompt-override` (같은 image 를 다른 prompt 로 한 번 더 forward), `--noun-attention [L:H]` (같은 forward 에서 명사 token 행의 attention, 기본 10:7). 셋 중 하나라도 주면 T86 파일 배치로, 하나도 안 주면 T79 도구 그대로다 (parser 기본값 · routing test 로 고정, T73 / T77 / T79 test 는 고치지 않고 통과). 명사 행은 **그 forward 의 prompt** 로 `attention_source.noun_lookup` 을 다시 불러 찾으므로 prompt 를 바꾸면 행이 따라간다 (실제 tokenizer 로 확인: 사과 행 773, 바나나·오렌지·배 행 774).
2. **`t86_labels.py` (새).** T77 spec · 라벨 위에서 (a) 쥐기 전 (접근 · 쥐기) 요청을 run 마다 seeded 균등 표본, (b) 요청 qpos 로 MuJoCo **segmentation** 을 VLA 입력과 같은 기하 (299 × 224 render → 224 격자 → `t79_events.patch_of_policy_pixel`) 로 3 카메라 모두 렌더해 token 마다 class 비율을 저장 (`frac [N, 3, 256, 8]`), (c) 라벨 target / other / background, (d) counterfactual 과일 선택 + prompt. 렌더 포즈는 RGB 와 맞춰 검증: **표본 전체 (773 요청 × 3 카메라) 에서 기록된 policy image 와의 평균 절대 차이가 정확히 0.0 gray level** (bit 동일, 장애물 장면 포함). `survey` 부명령은 모든 쥐기 전 요청의 head 카메라 사과 token 수를 문턱 0.30 / 0.20 / 0.10 / 0.05 별로 센다.
3. **`t86_probe.py` (새).** train 장면만으로 layer {4, 8, 12, 16} × C 를 GroupKFold(장면) 교차 검증해 고르고 (raw B 와 frame 평균 뺀 B'), test 장면에서 기준 A (명사 attention) 와 같은 평가 함수로 top-1 · 물체 선택 · AUROC · counterfactual 따라가기를 잰다. **판정 수치는 장면 평균** (장면마다 같은 무게, target token 이 있는 요청이 20 개 미만인 장면은 평균에서 빼고 표에 `included: false` · `excluded` 로 표시). 요청 가중 (pooled) 수치는 참고로 json 에 남는다. 카메라마다 프로세스 하나 (`--jobs ≤ 3`), 손목 카메라도 같은 문턱.
