# T55 — 작업 의도와 실제 grasp 상태의 분리: phase feature 대 `grasp_latch` strong rule (정답 = 물리 predicate)

> writer: lead (A0) · 2026-10-13 KST · 읽는 쪽: implementer, verifier · 로그: `AG3S_T47_LOG.md`
> 근거: `T52-T57.plan.task.md` 사용자 판정 4 · 6 · 7, T55 사용자 판정 (2026-10-13, 아래 사전 고정 1–5).
> **strong rule 을 정답으로 쓰지 않는다. 정답은 물리 predicate 다.** 잡은 뒤에도 apple 을 찾는 것은 grounding 성능이지 basket 단계 전환의 증거가 아니다.
> 공통 규칙: 새 output 은 새 `$AG3S_RUN_DIR`. CPU worker ≤ 4. GPU 는 offline feature 추출만 하고 lock 을 잡는다. closed-loop 은 하지 않는다. 기존 파일의 동작은 바꾸지 않는다 (새 `t55_*.py` 만). `clustering.placed_no_seed_certify` 는 모든 조건에서 같은 값 (off) 으로 둔다.

## 왜 지금 이것인가

T48a · T48b · T50 은 HSR (`kv_L4_v1`) 을 **offline strong-rule proxy** 와만 비교했다. 실제 strong rule (`AG3S/trajopt/grasp_latch.py` + 실행 feedback) 과는 비교하지 않았다 (재측정 대기 5 · 12).
strong rule 은 "무엇인가를 쥐었다" 만 안다. phase feature 는 "지시된 물체를 쥐었다" 를 읽는 것이 목적이다. 그래서 정답을 둘로 나누고, feature 가 strong rule 을 대체하는지가 아니라 **task gate 를 보완하는지** 를 본다.

## 사전 고정 1 — 정답 (물리 predicate, 사용자 판정 1)

| predicate | 정의 | instruction 을 바꾸면 |
|---|---|---|
| **P_grasp** | 활성 손 (episode 의 used arm) 이 **어떤 물체든** 실제로 보유한다. 한 손의 두 finger body 가 모두 그 물체와 접촉하고, 그 물체가 table · crate 와 비접촉이다 (`t48b_scene.classify` 의 `held` 를 물체 전체로 확장) | 바뀌지 않음 |
| **P_task** | 활성 손이 **지시된 target** 을 보유한다 (P_grasp 이고 그 물체 = prompt 의 target) | 바뀜 |

- 상태는 넷이다: 빈손 (P_grasp F) · **wrong-object grasp (P_grasp T ∧ P_task F)** · target 보유 (P_task T) · placed. **다른 물체를 쥔 상태를 "pick 상태" 와 같은 것으로 판정하지 않는다.** wrong-object grasp 는 빈손과 구분해 따로 집계한다.
- **지속 조건**: 순간적으로 스친 접촉은 보유로 세지 않는다. predicate 는 연속 `K` policy frame 동안 성립할 때 참이 된다. 모든 source 와 조건에 같은 `K` 를 쓴다. `K` 는 dev 에서 고정한다 (아래 dev 단계). 해제 쪽에도 같은 `K` 를 쓴다.
- 자세 = camera 가 본 자세 (`render_qpos`). T53 `gt/<key>.grasp.npz` 와 같은 규약이다.

## 사전 고정 2 — source

| source | 출력 | 채점 |
|---|---|---|
| **strong rule** | `grasp_latch` 의 `HELD` (실행 feedback: `applied_gripper` · 측정 개도 멈춤 · revoke) | 본래 역할은 **P_grasp** 로 평가한다. P_task 로도 채점한다 |
| **HSR** (`kv_L4_v1`, 재학습 없음) | `place` 예측 = feature_target_held | P_task · P_grasp 둘 다 |
| **명사 token probe** (새로 학습) | target 명사 token feature (T53 `t53_extract` 의 `noun_v` layer 별 · `noun_hidden_final`) 위 선형 probe → feature_target_held | P_task · P_grasp 둘 다 |

- 명사 probe 의 layer · C · 분류 임계값은 **episode 단위 dev CV** 로 고정한다. 같은 episode 의 원본 frame 과 변형 frame 은 같은 fold 에 둔다. **T53 은 학습 · 선택에 쓰지 않는다.**
- T50 counterfactual probe 는 넣지 않는다.

## 사전 고정 3 — 조건 (사용자 판정 2)

| 조건 | 만드는 법 | 정답 변화 |
|---|---|---|
| **instruction 변경** | 같은 image · state 에서 prompt 의 target 명사를 scene 의 다른 과일로 바꾼다 (T48a C1 방식). 원래 target 을 쥔 frame 은 wrong-object grasp 가 된다. feature 는 바뀐 prompt 로 다시 추출한다 (GPU) | P_task 만 바뀜 |
| **물체 보유 여부 변경 (empty grasp)** | **물리 재시뮬.** T53 (test) · dev record 의 기록 동작 (executed actions) 을 MuJoCo 에서 처음부터 실행한다. 닫힘 시작 전 개입 시점에 target 을 제거하고, 같은 기록 동작을 계속 실행한다. **기록 qpos 를 매 순간 덮어쓰는 재생은 쓰지 않는다.** 그래야 실제 개도 · 접촉 · `applied_gripper` 와 image 가 물체 유무에 따라 반응한다 | P_grasp · P_task 둘 다 F (팔 자세는 비슷함) |
| **slip** | 같은 재시뮬에서, 보유가 성립한 뒤 개입 시점에 물체를 손에서 떼어낸다 | 개입 뒤 P_grasp · P_task F |
| **자연 발생** | T53 16 episode 에서 실제로 생긴 empty grasp · slip · wrong-object 접촉 · 재시도 (`grasp_state` 와 접촉 replay 로 식별) | 기록 그대로 |

- **재시뮬 parity (E0)**: 개입 없이 재시뮬한 궤적이 기록과 같아야 한다 (qpos · image · `applied_gripper`). 통과하지 못하면 거기서 멈추고 보고한다. 이때 기록 qpos 덮어쓰기로 대신하지 않는다.
- 개입 시점과 제거 · 분리 방법 (예: 물체를 작업 공간 밖으로 옮김, 아래로 떨어뜨림) 은 **dev 에서 고정한다.** T53 자연 사례와 인위적 개입 사례는 **나눠 보고한다.**
- 재시뮬 image 로 feature (kv_L4 · 명사 token) 를 추출한다 (GPU lock). strong rule 은 재시뮬의 실행 feedback 으로 offline 실행한다. 개입 전 latch 상태 (SEARCHING / LATCHED) 는 기록과 같아야 한다 (parity).

## 사전 고정 4 — 결합 규칙과 판단 (사용자 판정 4)

- 물리 grasp latch (strong rule) 는 그대로 유지한다. feature 는 **target 보유 확인을 보완** 하는 데만 쓴다.

```
task_ready = physical_grasp (strong rule HELD) ∧ feature_target_held
```

- **task_ready 가 false 여도 물리적으로 쥔 상태 · attached 처리를 해제하지 않는다.** feature 는 attach / detach 에 관여하지 않는다.
- 기준 arm = strong rule 단독 (`task_ready = HELD`). 비교 arm = HSR 결합 · 명사 probe 결합.
- 오류 정의 (P_task 기준):

| 오류 | 정의 |
|---|---|
| **false pass** | `task_ready ∧ ¬P_task`. wrong-object · empty · slip 을 task 성공 상태로 잘못 통과시킴. **조건 별로** 센다 |
| **false reject** | `¬task_ready ∧ P_task`. 올바른 target 보유를 거부함 |
| **검출 지연** | P_task 가 참이 된 frame 부터 task_ready 가 참이 될 때까지의 policy frame 수 (event 단위) |

- **채택 근거 두 가지**: (1) wrong-object 를 task 성공 상태로 잘못 통과시키는 오류가 줄어드는가, (2) 올바른 target 보유를 거부하는 오류와 검출 지연이 과도하게 늘지 않는가.
- **결합 규칙의 세부 (feature 임계값 · 지속 frame) 와 허용 악화폭 (false reject 증가 · 지연 증가의 상한) 은 dev 에서 고정한다.** T53 을 열기 전에 `T55.prereg.json` 으로 남기고 lead 가 사용자 확인을 받는다.
- 모든 조건에서 오류가 한 건도 늘지 않아야 한다는 기준은 두지 않는다.
- 결과: 보완 효과가 있으면 **T57 후보** (task gate) 로 둔다. 없으면 HSR 은 **보조 기록용** 으로 둔다. 어느 쪽이든 "HSR 이 instruction 기반 단계 판단을 한다" 고 주장하지 않는다 (plan 판정 1).
- strong rule 의 P_grasp 성능 (오류 · 지연, 조건 별) 은 독립된 결과로 따로 보고한다.

## 추가 사전 고정 (사용자 판정 2026-10-13, 구현 후 · 측정 전)

`T55.impl.md` 의 E0 결과를 보고 내린 판정이다. T53 test record 는 재시뮬이 bit 단위로 같다 (ep1804). dev record 8 개는 실행 동작이 float32 로만 저장되어 grasp 이후 오차가 커진다.

1. **dev E0 = 개입 없는 재시뮬.**
   - dev 에서는 기준 조건과 개입 조건을 모두 같은 재생 방식으로 실행한다. image · feature · predicate 는 재시뮬에서 다시 만든다.
   - 원 기록과의 차이는 수치로 보고하되, 완벽한 일치는 요구하지 않는다.
   - **비개입 재시뮬에서 이미 grasp 에 실패한 사례는 slip 평가 대상으로 삼지 않는다.** 개입 효과를 비교할 기준 상태가 없기 때문이다.
2. **perception = 재시뮬 관측에서 AG3S 를 다시 실행한다.**
   - 개입 뒤의 실제 image · depth 에 고정된 서빙 L8H2 grounding 을 돌린다. perception history 도 그 관측으로 갱신한다. 비개입 조건에도 똑같이 적용한다.
   - 이를 위해 재시뮬 frame 의 action attention (L8H2) 을 GPU 로 추출해야 한다 (lock).
   - 기록 perception 은 오래된 입력에 대한 **민감도**, oracle (MuJoCo 참값 reach) 은 perception 오류를 분리하는 **보조 진단** 으로만 쓴다.
   - instruction 변경 조건에서도, 바뀐 prompt 로 추출한 attention 으로 grounding 을 다시 실행하는 것을 원칙으로 한다. 구현이 불가능하면 lead 에게 보고한다.
3. **허용 악화폭 (strong rule 단독 대비, 사전 고정)**:
   - false reject 증가 ≤ 5 %p
   - 평균 검출 지연 증가 ≤ 1 frame
   - 보유 시작 사건의 추가 미검출 = 0 건
   - dev 의 변동 폭은 허용폭으로 쓰지 않는다. dev 분포는 기준을 달성할 수 있는지와 측정 불확실성을 확인하는 데만 쓴다.

## 사용자 판정 (2026-10-14, dev prereg 확인 · test 전)

- **허용폭은 합산 기준을 유지한다.** dev false reject 증가는 합산 +4.92 %p 로 통과다. 자연 발생 조건만 보면 +5.66 %p 로 허용폭을 넘는다.
  - 결과를 본 뒤에 조건별 필수 기준으로 바꿔 결합을 기각하지 않는다.
  - 보고 문구: **"합산 허용폭 충족, 자연 조건에서는 초과"**.
  - 지연 · 미검출 기준까지 충족한 경우에만 결합 후보로 유지한다.
  - 합산 분모 확인 (lead, `t55_study.py:364-383`): trace 별 count 를 먼저 더한 뒤 나눈다. false reject 의 분모는 P_task=True frame 수다. empty · slip 의 음성은 분모에 들어가지 않는다. 양성이 없는 조건은 분자와 분모에 0 을 더할 뿐, 오류율 0 으로 평균 내지 않는다.
- **slip 은 ghost · park 를 둘 다 유지하고 따로 보고한다.**
  - ghost = 물체가 시각적으로 남아도 접촉 상실을 감지하는가. park = 물체가 손에서 사라졌을 때 보유 해제를 감지하는가.
  - 둘 다 인위적 개입이며 실제 slip 의 재현이 아니다. **접촉 제거 · 물체 이동에 대한 진단 조건** 으로 표현한다.
  - 판정은 prereg 의 합산 방식과 가중치를 유지한다. 한 방식에서만 좋은 결과를 전체 slip 대응 성능으로 일반화하지 않는다.
- **T60 종료 구간 mask (P · H) 는 보조 분석으로만 쓴다.**
  - 주 판정은 전체 구간이다. mask 는 e4 의 T60 정의를 분석 전에 고정해 모든 arm 에 같게 적용한다.
  - 결과가 잘 나오는 창을 골라 주 판정으로 바꾸지 않는다.
- (사용자 판정, e4 세션 경유 2026-10-14) **T55 는 기존 정의 · P · H 결과를 나란히 보고한다.** T55 는 복귀 · 해제 이후의 동작도 평가한다. 그래서 placement 에서 자른 결과가 전체 기능 평가를 대신하면 안 된다.
