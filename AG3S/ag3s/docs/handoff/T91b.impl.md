# T91b — 구현 (손목 카메라 "손가락 사이 target" 운반 판정, offline · RBY1 + SafeLIBERO)

> writer: ag3s-implementer · 읽는 쪽: lead, verifier, scribe · 작성: 2026-11-03 KST
> 범위: `T91b.task.md` §3 (phase machine 증거 · 입력 추출 · SafeLIBERO adapter · train 문턱 · test). serving 코드는 건드리지 않았다.
> **RBY1 test 판정은 하지 않았다** (lead). SafeLIBERO 는 아래 "SafeLIBERO" 절에 어떻게 다뤘는지 적었다 (전 episode 에 어댑터를 한 번 돌렸다).

## 무엇을 했나 (평이한 요약 먼저)

1. **새 증거 하나 (기본 꺼짐).** 쥐는 손의 손목 카메라 image 에서 손가락 끝 사이 영역(ROI) 을 잡고, 그 안에서 *손바닥에서 d_min–d_max 거리에 표면이 있는 pixel 의 비율* (주 증거, depth 만 씀: target 인식 불필요) 과 *ATS target 점을 손목 카메라로 투영한 pixel 의 비율* (참고 증거) 을 요청마다 낸다. `phase_machine.py` 는 이 숫자만 받는다 (`finger_gap_mode="on"` 일 때). 운반 = 닫힘 ∧ 완전히 닫힌 빈 손 아님 ∧ 손가락 사이 증거 (진입 `gap_m` 연속, 이탈은 `gap_m` 연속 miss) ∧ (이미 운반 중 ∨ 닫힌 자리에서 손이 ≥20 mm 이동). 닫혔는데 손가락 사이가 비면 운반이 아니다. 다른 단계 (grasp · place · retreat) 와 T91 문턱은 그대로.
2. **꺼짐 = T91 bit 동일.** 증거 숫자를 넣어도 mode 가 off 면 stage 와 evidence dict 가 같다. 옛 `phase_machine.py` (T91) 와 새 것을 RBY1 train 210 run 8,882 요청 + test 207 run 11,606 요청 전부에서 나란히 돌려 **stage 불일치 0 · evidence dict 불일치 0** (손목 숫자 0.9 를 일부러 넣고도). test feature 는 이 동일성 확인에만 읽었다 (지표 계산 없음).
3. **입력 추출.** RBY1: client step npz 의 `depth_wrist_cam_{l|r}` · `K_wrist_cam_*` · `T_base_cam_wrist_cam_*` (손 쪽 = 그 run 의 `side`) 와 server chunk npz 의 `target_points` (base frame). 손목 depth 는 stride 4 (120×160 uint16 mm), target 점은 손목 카메라 (u, v, z) 로 미리 투영해 저장. SafeLIBERO: `_geom.npz` 의 `depth_mm/left_wrist` · `K` · `T_base_cam` · `T_world_base`.
4. **train 문턱** (RBY1 train 210 run 만): 새 문턱 = ROI · 깊이 창 · τ_in · m. depth arm 이 train 에서 정확도 82.0 % → **87.8 %**, 위험한 오판 0.81 % → **0.30 %** (장면 평균; T91 상태 기계 대비).
5. **SafeLIBERO.** benchmark 에는 이 run 의 시뮬레이터 정답 단계가 없어서, 새 py3.8 스크립트로 물리를 다시 렌더해 만들었다 (아래). 문턱은 다시 고르지 않고 RBY1 값 그대로. 결과 (VLA 단독 20 episode, 796 요청): **위험한 오판률 4.2 % (요청) / 4.25 % (장면 평균) > 2 %** → task §2 의 "벤치마크로 옮길 만함" 기준 미달. T91 상태 기계 (gap 꺼짐) 는 5.6 % / 7.1 %.

## SafeLIBERO adapter

**방식 결정과 사용한 것 (벤치마크 checkout 은 읽기만).** 이 run (`20261017T151126_..._sl5f-...vla_only`, LI, 20 episode = task 0–3 × e0–4) 에는 시뮬레이터 정답 단계 파일이 없어서 (benchmark 의 `phase_*.npz` 는 다른 LIBERO run) 물리를 다시 렌더해야 했다. robosuite/LIBERO 는 `.venv-ag3s` 에 없고 benchmark checkout 의 `.venv-libero` (py3.8) 에만 있다. 설치하지 않고 **그 인터프리터를 그대로 썼다**: `/mnt/dev/AG3S_VLA-benchmark/.venv-libero/bin/python AG3S/ag3s/experiments/studies/t91b_safelibero_export.py` — 이 스크립트가 benchmark 의 `libero_pi05_client` · `libero_safe_client` · `task_target` · `client_env` module 과 SafeLIBERO fork 를 import (읽기), 출력은 새 run 폴더에만 쓴다. 쓰기: benchmark checkout 에 쓰지 않았다 (확인: 수정된 파일 없음; 처음에 `.venv-libero-safety` 로 robosuite import 가 되는지 한 번 확인할 때 `PYTHONDONTWRITEBYTECODE` 를 안 줘서 `benchmark/LIBERO-Safety/third_party/robosuite-1.4/robosuite/renderers/context/__pycache__/egl_context.cpython-310.pyc` 하나가 생겼다 — byte-code cache 일 뿐, 필요하면 지워도 된다). env history 는 rollout 과 같게 (task 별 env 하나, episode 마다 `start_episode`), **정책 호출 frame 마다 두 카메라 RGB 재렌더가 기록과 bit 동일해야** 통과 (20 episode 모두 통과, `report.json`). 시간: episode 당 약 10–25 s (1 core, nice 10).

**입력 (호출 c, frame f = `chunk_t[c]`):** `gripper_raw = |gripper_qpos[f,0]|` (finger joint 1) — `PhaseConfig.panda` 가 1 = 0.04 m, 닫힘 0 점 0 으로 정규화 (`gripper_calibration.json` `normalisation`); `ee_pos` = `obs_robot0_eef_pos[f]` 를 `T_world_base[f]` 로 **base frame 으로 옮긴 것** (ATS centroid · 점은 base frame, 물리 정답은 world — 처음엔 섞여 있어서 ee–centroid 거리 350 mm 가 나왔고 base 로 옮겨 100 mm 로 맞췄다); `target_pos` / `target_fresh` = ATS replay (`ats-physical`) 의 `frames.jsonl` centroid · `manipulated_state=="visible"`; `chunk_gripper = action_chunks[c,:,6]` (+1 닫기, −1 열기: `chunk_closed_value=+1, chunk_open_value=−1`); `finger_gap` = `depth_mm/left_wrist[f]` 의 ROI 표면 비율; `finger_gap_proj` = replay `clouds/<stem>.npz` 의 target 점을 `K` · `T_base_cam` 으로 투영. `destination_pos` = **None** (replay 가 목적지를 기록하지 않음) → place 는 VLA 의 열기 명령으로만 도달. 변형 "destination oracle" = BDDL plate body 위치 (GT 입력; headline 아님, 따로 보고). replay 가 덮는 호출만 채점 (20 episode 796 호출 중 796).

**로봇별 설정 (task §3.3: 손가락 사이 영역 · gripper 정규화 0.04 m · 열 6 만):** `PANDA_ROBOT` = chunk 열 6 · 값 +1/−1 · `open_ref_value=0.04` · `blocked_min_open=0.025325` (benchmark 의 calibrated `empty_below`: 빈 닫힘 0.0125, 얇은 테두리 쥠 ≥0.038 정규화 — T91 의 0.10 은 얇은 그릇 테두리를 빈손으로 오판하므로 로봇 설정으로 바꿈; `panda()` 는 이 값들을 `kw` 로 덮어쓰지 못하게 함); 나머지 T91 문턱 · 새 문턱 (τ 0.3 · m 1 · d 0.03–0.09) 은 RBY1 train 값 그대로. **ROI (Panda, 결과 전에 고정)** u 0.38–0.62 · v 0.62–0.76: grip site 가 모든 frame 에서 pixel (127.5, 213.5) · 0.097 m 에 투영되고 (kinematics), 손가락 패드 geom 이 행 195–212 에 있다 (손목 segmentation 으로 확인, 하드웨어 기하) → site 열을 중심으로 패드 바로 위 행. 패드를 ROI 에 넣으면 닫힌 손의 패드가 "표면" 이 되어 닫힘만으로 증거가 켜진다 (아래 민감도 `roi_low_incl_pads`). 깊이 창은 site 깊이가 두 로봇에서 같은 0.1 m 이므로 RBY1 값을 그대로 옮겼다.

**정답 단계 (T77 정의를 재렌더 물리에 적용, headline = 사양 그대로):** `held` = target 에 **두 손가락 body** 가 모두 접촉 ∧ target body z ≥ 첫 호출 z + 20 mm; `place` = held ∧ target xy 가 plate 충돌 geom AABB xy 안; `carry` = held ∧ not place; `retreat` = held 였다가 not held; `grasp` = never held ∧ |eef − target body 중심| ≤ 60 mm (사양); 그 밖은 approach. 민감도 `grasp_or_touch` (손가락 접촉만 있어도 grasp) 도 json 에 있다 (그릇 테두리를 쥐면 eef 가 중심에서 60 mm 보다 멀 수 있음). 정답 호출 수: approach 508 · grasp 62 · carry 89 · place 64 · retreat 73.

- **이 숫자는 내가 한 번 봤다.** adapter 가 맞는지 (frame · 좌표계 · 정렬) 확인하려고 20 episode 전체에 한 번 돌렸고, 그 뒤로 문턱 · ROI · 깊이 창 · 규칙을 바꾸지 않았다 (민감도는 따로 보고). 버그로 고친 것은 하나: ee 를 base frame 으로 옮긴 것 (위 입력 설명) — 그 수정은 headline 숫자를 보기 전에 centroid 와의 거리로 확인해 넣었다. lead 도 이 어댑터를 한 번 돌린 것으로 보인다 (run 폴더에 내가 만들지 않은 `safelibero_t91b.json`, `wrist_test_SMOKE6/` 가 있다).
