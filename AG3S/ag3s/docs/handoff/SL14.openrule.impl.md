# SL14 §6 (KS) -- 구현: 개도 · 명령만 쓰는 단순 attach 규칙 (`--grasp-opening-rule`)

> writer: ag3s-implementer · 읽는 쪽: verifier, scribe, lead · 2026-11-05 · branch `wip/sl14-openrule` (base `wip/sl14-oraclelatch` 066e4b33)
> 배포 가능(정답을 쓰지 않음). 기본 꺼짐, Panda 서버만.

## 무엇을 했나 (평이한 요약)

`--grasp-opening-rule` 을 켜면 grasp latch(`GraspLatch.observe_grasp`)가 증거 검사 대신 아래 규칙만 쓴다.

- **attach**: CLOSING · LATCHED · PLACED (또는 대상 잠금이 있는 SEARCHING)에서 아래 넷이 모두 참이면 HELD.
  마지막 **실행** gripper 명령이 닫힘(`< gripper_closed_below` 0.85) · `settled`(직전 요청과 개도 차 < 0.02) · 측정 개도 ≥ 0.03 ·
  reach(손 - target ≤ 120 mm, 기존 `reach` 값). `blocked` · `not_empty` · `dropped` · `manipulated` 는 묻지 않는다.
  attach 는 평소 경로 그대로다(`LatchEvent.attach` -> `SafePolicy` 가 `manip.geometry` 로 `AG3S.attach`), 그래서 쥔 물체가 거리장에서 빠지고,
  `AG3S.attach` 의 마지막 관문(reach · 사용 가능 기하)이 거절하면 평소처럼 `revert_attach` -> CLOSING 이다.
- **detach**: HELD 에서 (마지막 실행 명령이 열림 `>= 0.85` ∧ 개도 > attach 개도 + 0.02) ∨ 개도 < 0.02(빈손). detach 뒤는 **LATCHED**(PLACED 아님)라 다시 쥘 수 있다.
  T34 회수(`attach_revoked`) · 열림 놓기(`release_frames`) · 성공 판정 · slip 은 이 규칙에서 돌지 않는다.
- 마지막 실행 명령은 `GraspLatch._rule_command` 가 기억한다(HOLD 청크는 `last_command=None` 이라 갱신 없음; detach · 재쥠에도 유지).
- LATCHED -> CLOSING(닫힘 명령 실행), CLOSING -> LATCHED(다시 열림) 전이는 평소와 같이 둬서 `closing` 에 의존하는 다른 곳(continuity off 등)은 그대로다.
- 기록: 켰을 때만 call 마다 `panda/grasp.opening_rule = {applied, decision: "attach"|"detach"|null, opening, last_command, reach_mm}`.
  피드백이 없는 call 은 `applied: false`. 개별 검사 값은 `grasp.evidence.checks = {closed_command, settled, opening_min, reach}`.

## verifier 가 알아야 할 것

- 새 flag `--grasp-opening-rule`(serve_safe, 기본 꺼짐, Panda). 꺼짐이면 서버 argv · `LatchConfig` · 호출 기록 키가 이전과 같다. client 변화 없음(정답을 쓰지 않는다).
- 이 규칙은 증거 검사(`attach_revoked`, slip, 열림 놓기, `placed`)를 **대체**한다. 그래서 `release_frames` 로 놓이는 일이 없고 PLACED 로도 가지 않는다 -- 놓음은 "열림 명령 + 개도 상승"으로만 잡힌다.
  손이 천천히 열려 개도가 attach 개도보다 0.02 넘게 커지지 않으면 물체를 쥔 상태로 남는다(개도 > attach + 0.02 는 Panda 에서 곧 닿는다고 보지만 측정으로 확인할 일).
- HELD 에서 대상 잠금은 그대로다. detach 직후 같은 call 에 다시 attach 하지 않는다.
- `AG3S.attach` 가 거절하면(`rejected`) latch 는 CLOSING 으로 돌아가 다음 call 에 같은 조건으로 다시 시도한다.
- 개도 척도는 pc판의 latch 개도(`gripper_gap_opening` 아님)로 가정했다. `--gripper-gap-opening` 과 같이 쓰면 0.03 · 0.02 문턱의 척도가 달라진다(이 판은 쓰지 않는다).

## 위험

1. 실행 명령이 닫힘이고 개도 ≥ 0.03 이 정지돼 있고 대상이 12 cm 안인 모든 call 이 attach 다 -- 물체를 안 쥐고 대상 근처에서 손가락이 다른 것(테이블 모서리 등)에 막혀 0.03 이상에서 멈추면 거짓 attach 이며 이를 회수하는 장치가 이 규칙에는 없다(개도 < 0.02 로 닫히거나 열려야만 풀린다).
2. 판단 근거는 기록 재생 수치(LIBERO 1.00 · LIBERO-Safety 0.99)이고, 실제 server 로 측정하지 않았다. CPU 단위 test 만 했다.
