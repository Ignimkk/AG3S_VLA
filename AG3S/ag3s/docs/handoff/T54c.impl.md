## 무엇을 했나 (평이한 요약 먼저)

T54c 의 새 16 episode 를 **metadata 와 사용 흔적만 보고** 골라 `t54c_records.py` 에 고정했다. 결과 data 는 열지 않았다. 고르는 규칙은 다음과 같다.
- test split 의 layout slot 0–15 마다, 사용 흔적이 없고 예약되지 않은 episode 중 index 가 가장 작은 것을 고른다.
- 사용 흔적은 storage 의 `results/` · `recordings/` (경로 이름 + text 내용) 와 `assets/` 경로 이름, `AG3S/ag3s/docs/**/*.md`, `handoff/` 의 모든 text, `doc/**/*.md` 에서 찾는다.
- 제외 근거는 표로 남겼다 (아래).

이 registry 를 기존 코드에 연결한 방식은 다음과 같다.
- `t53_records` 는 고치지 않았다. 그 코드를 **별개의 module 객체로 한 번 더 실행** 한 뒤 registry 와 출력 경로 (`<run>/verify/T54c`) 만 바꿨다 (`records()`).
- `t54c_extract` 는 `t53_extract` 를 그 registry 로 돌리는 얇은 wrapper 다.
- `t54_study --registry t54c --records-run <T54c run>` 이 같은 replay · 분석을 새 registry 로 돌린다. bootstrap seed 기본값은 5417 이고, N · B 진입 표와 방향 행이 붙는다.

rollout launcher 는 repo 코드가 아니다. `t54c_rollout` 이 T53 run 의 `p/` 를 읽어 **새 run 의 `verify/T54c/p/`** 에 생성한다. port 는 8292 · 8293, seed 는 `<N>1` 이다. run dir 을 상수로 두지 않는다.
