## 무엇을 했나 (평이한 요약 먼저)

기본 꺼짐 flag 두 개를 표면 선택 (`--target-extent attention-surface`) 의 CPU · GPU 경로에 넣었다.

- `--surface-crease-cut`: 표면 graph 를 2.5 mm node 로 만든다. seed 관심 영역 (150 mm) 안에서 두 node 의 표면이 오목하게 20° 이상 꺾이면 그 edge 를 끊는다. 그 뒤 선택은 지금과 같다 (seed 질량이 가장 큰 연결 영역, m ≥ 0.5).
- `--surface-crease-reattach-ratio R`: 선택 뒤, 끊긴 edge 로만 선택 영역과 이웃한 성분 (지지면 아님) 의 node 수가 선택 영역의 R 배 이하이면 그 성분 전체를 붙인다. 한 번만 한다.

결과는 이렇다.
- **동등성:** CPU · GPU 경로 모두 study `run_variant(0.0025, cut=True)` 와 487 요청 전부에서 선택 node 집합 IoU 1.0 · code 영상 일치 1.0 이다 (최소도 1.0).
- **시간:** GPU 경로 표면 단계 p95 **116 ms** (중앙 45 ms) 로 150 ms 안이다. 같은 run 의 꺼짐 (T78 B) 은 p95 63 ms 다.
  - 처음 그대로 옮기면 host `spsolve` 만 50–110 ms 여서 p95 를 넘을 뻔했다. 그래서 켜짐에서만 linear solve 를 GPU PCG 로 옮겼다. 0.5 문턱이 뒤집힌 node 는 487 요청 전체에서 **0 개** 다.
- **꺼짐:** 지금과 bit 동일하다. crease 함수를 부르면 터지게 바꾸고 돌린 test 가 이것을 보인다.

## flag 의 정확한 뜻 (모두 `--target-extent attention-surface` 에서만, 기본 꺼짐)

| CLI | config (`esdf.*`) | 기본 | 뜻 |
|---|---|---|---|
| `--surface-crease-cut` | `surface_crease_cut: bool` | False | 위 표의 2.5 mm graph + 오목 끊기 |
| `--surface-crease-voxel-mm MM` | `surface_crease_voxel_mm: float` | 2.5 | node 크기 (`--surface-crease-cut` 필요) |
| `--surface-crease-angle-deg DEG` | `surface_crease_angle_deg: float` | 20 | 끊는 각 (`--surface-crease-cut` 필요) |
| `--surface-crease-reattach-ratio R` | `surface_crease_reattach_ratio: Optional[float]` | None | 다시 붙이기 (`--surface-crease-cut` 필요). 권장 0.25 |

다시 붙이기 규칙 (`attention_surface_crease.reattach`):
1. ROI 의 끊은 graph 에서 지지면 node 를 뺀 연결 성분을 구한다.
2. 후보: 선택 node 를 하나도 갖지 않고, 선택 node 와 **끊긴 edge** 로 이어진 성분. 끊기지 않은 edge 로 이어진 부분은 이미 선택 영역의 성분이라 후보가 아니다.
3. 후보의 node 수 ≤ R × 선택 node 수 이면 그 성분 전체를 붙인다. m ≥ 0.5 문턱은 다시 걸지 않는다. 한 번만 한다.
4. **한계:** 선택 영역의 R 배보다 작은 맞닿은 이웃은 붙는다. 예: R = 0.25 에서 사과 영역 1,000 node 면 250 node 이하의 맞닿은 이웃은 붙는다. 맞닿은 바나나 (사과의 약 0.6 배) 는 붙지 않는다.
