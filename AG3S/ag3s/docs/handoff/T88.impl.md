### 통과 규칙 (`sqp.py:_clear_passthrough`)

통과는 다음이 모두 참일 때만이다. 먼저 실패한 사유가 `reason` 에 남는다.

1. `collision.enabled` (꺼진 판에서는 최적화기가 충돌을 재지 않으므로 "clear" 가 뜻이 없다) — 아니면 `collision off`
2. `safety.require_certified_geometry` 인데 `geometry_certified` 가 아니면 통과하지 않는다 (`_finish` 가 VIOLATED 로 바꿀 chunk 를 OPTIMAL 로 내지 않기 위해) — `geometry not certified`
3. `reference_violation <= 0` (lookahead 면 실행 구간, 아니면 chunk 전체; 요구 clearance 포함) — 아니면 `collision`
4. path rows 가 켜져 있으면 (`reduction.sweep_check` / `limits.servo_model`) waypoint 사이 위반도 0 — 아니면 `path`
5. `_limit_overshoot(reference)` (position · velocity · acceleration · step-0 anchor, rest-start envelope 포함) ≤ 1e-6 — 아니면 `limit`

통과하면 `_finish(reference.copy(), iterations=0)` 를 부른다. 그래서 결과는 최적화된 chunk 와 같은 metrics 키 (`clearance_m`, `limit_overshoot`, `lookahead`, `neighbour_palm_contact` …) 를 갖고, status OPTIMAL, `reference_deviation` 0, `max_violation` 은 측정값 (≤ 0 위반), `_previous` · `frame_index` 는 풀었을 때처럼 갱신된다. (기존 `_passthrough` 는 status UNCONSTRAINED 라 `safe_policy` 가 `unverified` 사유로 HOLD 시킬 수 있고 measured 키도 없어서 재사용하지 않고 `_finish` 를 썼다. task 는 `_passthrough` 재사용을 말했지만 이 이유로 다르게 했다 — lead 확인 필요.)

기록 `to.metrics.passthrough_clear` (켰을 때만; 꺼짐이면 키 자체가 없다. `constraint_record.py:290` 이 `to.metrics` 전체를 `_scalar` 로 싣는다):
- 통과: `{"applied": true, "reference_violation_m": 0.0, "reason": "clear", "previous_plan_seam_rad": float|null}`
- 최적화: `{"applied": false, "reference_violation_m": <m, ≥0>, "reason": "collision"|"path"|"limit"|"geometry not certified"|"collision off"}`
- `previous_plan_seam_rad` = 통과한 chunk 의 step 0 과 앞 chunk 계획 (refiner 가 실행 step 수만큼 정렬해 준 continuity reference) 의 step 0 의 최대 관절 차이 (rad). **재기만 하고 막지 않는다** (task §1). 앞 계획이 없으면 null. 기존 `plan_join_discontinuity_rad` (refiner) 는 한 chunk 안의 "다듬은 창 끝과 reference 꼬리" 차이이고 통과 chunk 에서는 0 이라 이음매를 보지 못한다 — 그래서 새 키를 따로 두었다.

### lookahead

- gate 열림 (`_solve` 본체): `reference_violation` 이 실행 구간 `step_clearances[:k]` 의 최소이므로 **꼬리에만 위반이 있어도 통과한다** (꼬리는 원래도 인증하지 않고 `_finish` 의 `tail_violation_m` 에 기록된다). test `test_lookahead_open_gate_the_window_decides`.
- gate 닫힘 (`_solve_window`): 창 최적화기 (`window_optimizer`) 가 같은 `_solve` 를 같은 config 로 실행하므로 같은 규칙이 창 `[:k]` 에 적용되고, 통과하면 창 = reference, 꼬리 = reference (`_solve_window` 가 이어 붙이는 그대로). 기록은 창 결과의 `passthrough_clear` 가 유지된다 (`dataclasses.replace` 가 metrics 를 보존). 창 최적화기는 `full_violation` (창 행 전부), 외부는 `step_clearances[:k]` — 같은 행 집합이다.

### 다른 flag 와의 구성 (T88 구성은 둘 다 끔)
- **`--to-multi-seed N`**: 통과한 chunk 는 `max_violation = 0` 이므로 E2 가 "standard solve within tolerance" 로 `triggered False` 를 적고 seed 를 풀지 않는다. 위반 chunk 는 지금과 같이 seed 를 푼다. seed 풀이 (`initial_iterate` 가 있는 `_solve`) 에는 통과 규칙을 적용하지 않는다.
- **grasp anchor (`--grasp-anchor`, G1 등 `grasp_anchor` 가 chunk 에 붙은 경우)**: 규칙은 anchor 를 보지 않는다. reference 가 clear 이면 anchor 가 끌어당겼을 goal / palm 항 없이 reference 가 그대로 나간다 (anchor 의 `_solve_standard` 후처리 기록은 그대로 계산된다). 즉 anchor 와 함께 켜면 "충돌 없는 chunk 에서는 anchor 가 작동하지 않는다" 는 뜻이다. 의도가 다르면 (anchor 가 있으면 통과 금지 등) 알려 달라. T72 reach box (`reach_constraint`) 도 clear reference 에서는 box 를 강제하지 않는다.
- **path rows**: 켜져 있으면 waypoint 사이 위반도 0 이어야 통과.
- **rest start / servo**: step-0 anchor · envelope 는 `_limit_overshoot` 에 이미 포함되어 있어 VLA 의 첫 step 이 `max_step` 을 넘으면 통과하지 못한다 (한계 초과로 취급).
