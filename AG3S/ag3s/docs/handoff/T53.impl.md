### 명사 token feature 의 정의 (T55 후보, 이 파일이 고정한다)

prefix = `[cam_high 0:256 | cam_left_wrist 256:512 | cam_right_wrist 512:768 | text 768:]`. query token 의 prefix row = `768 + text index`
(`t49_noun_query_extract.lookup`: 명사 piece 가 valid text token 중 **정확히 한 번**, 아니면 그 frame 은 `noun_ok=False`, 값 0).

| 배열 | shape | 정의 |
|---|---|---|
| `noun_v` | (F, Q=3, nL, 256) float32 | V cache `kv[1][layer, batch 0, row, kv head 0, :]` (gemma_2b 는 kv head 1 개). V_l = W_V^l · RMSNorm_l(x_l) — layer l 의 residual stream 을 그 layer 의 value 행렬로 투영한 것. kv_L4 가 평균하는 바로 그 tensor. layer 목록 `--noun-layers` (기본 0–17 전부) |
| `noun_hidden_final` | (F, Q, 2048) float32 | `PaliGemma.llm` prefix 출력의 final RMSNorm 뒤 값 (`normed[0]`), 같은 row |
| `noun_token_index` · `noun_prefix_row` · `noun_token_id` · `noun_ok` · `noun_error` | (F, Q) / (F,) | 위치와 실패 사유 |
| `kv_l4` | (F, 512) float32 | T48 / SUBTASK-b 의 kv_L4 (`[text mean | image mean]` of V, layer 4, head 0) |

Q 순서 = (`target`, `basket`, `last_text`). 같은 model load (`load_policy`, `return_attn_probs=True`), 같은 전처리 observation (`FeatureExtractor._obs`).
중간 layer 의 hidden 자체는 `PaliGemma.llm` 이 돌려주지 않아 넣지 않았다 (넣으려면 openpi 를 고쳐야 한다 — 하지 않음). K 는 RoPE 위치에 묶여 제외.

### 물리 grasp 상태 (T48b predicate 재사용)

`t48b_scene.classify` — 대상이 **한 손의 두 finger body 모두** 와 접촉하고 table · crate 와 비접촉이면 `held`. MJCF body 이름만 쓰고 한 손의 두 손가락을
둘 다 요구하므로 **T43 왼손 MJCF/URDF 이름 swap 은 생기지 않는다** (URDF 이름을 쓰지 않음). 자세 = camera 가 본 자세
(`render_qpos`, 한 physics step 뒤로; `--warmup-steps` > 0 이면 0 번 frame 도) 와 기록된 qpos 둘 다 계산.

| `grasp_state` | 뜻 |
|---|---|
| `held` | episode 의 used arm 이 held |
| `placed` | held 아님, 대상 중심이 crate 내부 부피 안 (`in_crate`) |
| `pre` | 첫 `held` 이전, placed 아님 (table 위 · closing · 밀림) |
| `post` | 첫 `held` 이후, held 도 placed 도 아님 (내려놓는 중 · 떨어뜨림) |
| `held_other_hand` | 다른 팔이 held |

함께 저장: `phys_state`/`phys_hand` (render 자세), `*_qpos` (기록 qpos), `finger_contact_lr`, `touching`, `penetration_m`, `target_pos_world`,
`crate_pos_world`, `used_gripper`, SUBTASK-b `closed_loop_gt` (T48 label). 이것은 **policy step (step npz) 단위** 다. control 600 행 접촉 replay
(`replay_contacts.py`, 생성 5) 는 verifier 의 CL3 script 그대로이고 여기서 만들지 않았다.

## 내가 기대하는 결과

(verifier 는 측정이 끝나기 전에 이 절을 읽지 않는다.)

- `layout`: 16 episode 모두 problem 0, 75 planning 행 = 75 step npz, seed 가 manifest · trajectory 에서 같음.
- `attention_parity` / `noun_parity`: T51 · T51b 와 같은 수준 (bitwise 는 아닐 수 있음, argmax 일치 높음).
- `feat_parity`: kv_L4 rel L2 작음 (SUBTASK-b 대비), `noun_v_vs_sampler_cache_max_abs` = 0 또는 bf16 반올림 수준, deterministic True.
- `noun` · `feat`: 16 개 prompt 템플릿 3 종 모두 명사가 정확히 한 번 → 실패 frame 0.
- `grasp`: 성공 episode 는 pre → held → placed 순, held frame 에서 used arm 의 두 손가락 접촉.
