## 0. 왜
- 지금 5 단계 분류기 (T77 · T82) 는 이 VLA checkpoint 의 hidden 공간과 이 시뮬레이터 정답에 묶여 있다 (ADOPTED A9.2 한계). 벤치마크 (Franka Panda · LIBERO 계열 · 다른 checkpoint) 로 가면 다시 학습해야 한다.

## 1. 방법 (학습 없음, 로봇 · 벤치마크 공통 입력만)
모듈 `AG3S/trajopt/phase_machine.py` (새, 순수 Python · 상태 기계). 입력은 요청마다:
- gripper 개도 (측정) → 로봇별 정규화 (처음 N 요청의 최대 = 열림, 설정의 닫힘 한계 = 0) — 로봇 독립.
- 쥐는 손 끝 (EE site) 위치 · 속도.
- target 3D 중심 (ATS `manipulated.centroid`, 없으면 결측) · 목적지 3D 위치 (ATS destination, 없으면 결측).
- VLA action chunk 의 gripper 명령 열 (앞 K 행) — "곧 닫음 / 곧 엶" 의도.

단계 (5 단계, T77 과 같은 이름: approach · grasp · carry · place · retreat) 와 판정:
1. **approach:** 열림 ∧ (target 거리 > d_near 또는 chunk 안에 닫기 명령 없음).
2. **grasp:** target 거리 ≤ d_near ∧ (chunk 안에 닫기 명령 있음 또는 개도가 줄고 있음) ∧ 아직 붙지 않음.
3. **carry (붙어 움직임):** 닫힘 ∧ **co-motion** — 최근 W 요청 동안 target 중심 변위가 손끝 변위를 따라감 (변위 비 ≥ ρ, 방향 cos ≥ c) 또는 target 이 손에 가려져 안 보이지만 직전까지 co-motion 이었고 개도가 닫힌 채 막힘. **닫혔는데 target 이 따라오지 않으면 carry 가 아니다** (빈손을 쥔 것으로 보는 위험한 오판 방지).
4. **place:** carry 이고 목적지 거리 ≤ d_dest 또는 chunk 안에 엶 명령.
5. **retreat:** carry / place 뒤 개도가 열림 ∧ target 이 손을 따라오지 않음.
- 문턱 (d_near · d_dest · W · ρ · c · K) 은 **train 장면 (T77 나누기) 에서만** 고르고, 고른 값을 결과 전에 `T91.impl.md` 에 고정한다.

## 2. offline 평가 (RBY1 기록, 결과 전 고정)
- 데이터: T77 spec · 라벨 (closed-loop 427 run, 요청마다 MuJoCo 정답 5 단계 `gt.phase5`), test = T77 test 장면 (211 · 954 · 122 · 119), 허들 211 은 제외 (사용자 2026-11-03).
- 비교: (A) 지금 5 단계 분류기 (T77 hidden L4, 기록된 serving 값 또는 offline 재계산), (B) T91 상태 기계, (C) 기록된 grasp latch 상태만 (참고).
- 지표: 5 단계 정확도 (요청 · 장면 평균), **위험한 오판률 = 정답이 approach / grasp 인데 carry / place 로 본 비율**, 단계 전환 지연 (정답 전환 대비 요청 수), 성공 run 과 실패 run 따로.
- 판정 (test, 장면 평균): B 가 "쓸 만하다" = 위험한 오판률 ≤ A 이고 정확도 ≥ A − 5 %p. B 는 학습이 없으므로 같은 수준이면 범용성 때문에 B 를 고른다 (사용자 원칙: 비슷하면 원리적 방식).
