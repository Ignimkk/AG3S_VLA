# T59 — 16D 에서 phase 별 attention 사용: phase 를 나누지 않은 grounding 대 현재 serving (offline, T53 16 episode)

> writer: lead (A0, 세션 "ppt자료(HSR,Attention)") · 2026-10-13 KST · 읽는 쪽: verifier, scribe
> STEP 번호 T59 는 dev-70 (T58) · development 세션에 알렸고 둘 다 충돌 없음을 확인했다.

## 왜 지금 이것인가

HSR · phase 설계의 근거로 쓰던 "phase 를 나누지 않으면 들고 가는 동안 target 이 crate 로 넘어간다" 는 그림
(`archive/14d-era-20260923/figures/target-latch-evidence.png`, F11 · F17) 은 **14D 시기 · latch 도입 전** 기록이다.
사용자가 16D 로 새로 관측하라고 요청했다.

**사용자 판정 (2026-10-13):**
1. 16D 재관측은 **T53 기록 offline** 으로 한다 (새 rollout · GPU 없음).
2. HSR 실험 (HSR 대 grasp_latch, 물리 predicate 정답) 은 **T55 결과를 쓴다.** 이 STEP 에서 하지 않는다.
3. phase 를 나누지 않았을 때의 attention 실험은 **offline 먼저.** closed loop 은 하지 않는다.
4. 그래프는 **place 이후 · home 으로 돌아온 이후를 자르고** 보인다 (필요 없는 구간).

```
카메라 depth → 로봇 마스크 → [attention lifting → target grounding → TargetConfirm(latch · freeze · HSR gate)] → TSDF/ESDF
```
이 STEP 은 괄호 안에서 "TargetConfirm 이전 (현재 frame 만)" 과 "serving 이 실제로 쓴 것" 을 phase 별로 나란히 놓는다.

## 분석 창 (사용자 판정 4, 결과 전 고정)

- **창 = frame 0 → 첫 `placed` frame (포함).** 첫 `placed` 이후와, 그 전이라도 **S 의 HSR 확정 label 이 `home` 이 된 뒤** 의 frame 은 주 그림 · 주 표에서 뺀다 (두 조건 중 이른 쪽에서 자른다).

## 이 STEP 이 답하는 질문

**16D 현재 serving 기록에서, phase 를 나누지 않은 grounding (현재 frame 의 attention 만) 은 쥐기 전 · 들고 가는 중 · 내려놓는 중에 각각 무엇을 target 으로 고르며, 같은 frame 에서 phase 를 나눈 serving 은 무엇을 쓰고 있었는가?**

## 되돌아올 지점

- 16D closed loop 에서 latch · freeze 를 끈 미분할 arm (사용자 판정 3 으로 보류). 전환 신호: 이 offline 결과에서 held 의 U ≠ target 이 크고, 그것이 실제 접촉 · 성공에 이어지는지 확인이 필요해질 때.
- HSR 대 strong rule 은 T55 (진행 중) 결과를 기다린다.
- U 의 cluster 로 가상 field 를 지어 "잘못 carving 했을 양" 을 재는 것 (이번에는 표시만).
