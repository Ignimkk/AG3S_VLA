## 1. 문제 (숫자로 확인된 것만)

| 사실 | 값 |
|---|---|
| 가림 장면 케이스 3의 "쥐지 못함" 다수는 손목 camera에서 사과가 **화면 밖**으로 나간 뒤 VLA가 공중에서 닫는 것 | 손바닥–사과 166–284 mm에서 닫음 (DX) |
| 가려짐이 아니라 화면 밖 | 장애물을 치워도 손목 화면에 사과 0 pixel. "가려짐"(보이는 비율 < 10 %) 1 요청뿐 |
| 이탈 시점 · 각도 | t 72–152부터, 손목 광축–사과 각 52–56°에서 시작해 61–73°까지 (화각 절반 ≈ 45°) |
| head camera | 모든 요청에서 사과가 화면 안, 부분 가림(보이는 비율 46–77 %) — AG3S의 target 추정(서버 target 오차 16–18 mm)은 유지됨 |
| TrajOpt 수정량 | 그 run들의 닫기 전 요청당 0.8–2.0° (312만 39.5°) — 수정이 크지 않은데도 경로가 VLA 단독과 갈라짐 |
| 비교 한계 | VLA 단독은 막대 접촉으로 일찍 끝나(t 64–136) 같은 시각 비교는 321 · 322만 가능(AG3S 45° 초과 시 VLA 34°) |

**①(DX3)과의 관계:** 케이스 1 단계 2에서는 연속성 항이 첫 수정을 만들고 그 뒤 정책 경로가 갈라졌다. 케이스 3의 화면 밖 이탈도 같은 "작은 수정 → 정책 경로 이탈" 경로일 수 있다. 그래서 VW 구현 전에 **DX3 최소 변경(`--w-continuity 0`)을 케이스 3 단계 1 · 2 여섯 run에 돌려 이탈이 줄어드는지**를 먼저 보는 것이 순서다(새 코드 없음, 기존 flag).

## 2. 설계 후보 (완화 가능한 것 = 비용 · 조건부 동작, 강제 제약 아님)

| 후보 | 무엇을 하나 | 어디 (층) | 장점 | 위험 |
|---|---|---|---|---|
| V1 시야 유지 비용 | TrajOpt 비용에 hinge 항: 쥐기 전(`latched`)이고 target이 있을 때, 실행 행의 손목 광축–target 중심 각이 θ0(예 40°)를 넘는 만큼 제곱 벌점. 무게는 VLA 추종 대비 작게(완화) | CCR (TrajOpt 비용) | 회피 수정이 손목을 돌릴 때 시야를 덜 잃게 한다. 장애물 제약을 깨지 않음(비용) | VLA가 원래 손목을 돌리는 경우와 싸움(추종 오차 증가) · 손목 camera 외부 파라미터(link 기준 자세)를 로봇 모델에 넣어야 함 · 각 미분(선형화) 필요 |
| V2 이탈 감지 → 재관측 | 서버가 요청마다 "target이 손목 화면 밖으로 나갈 예상"(계획 행의 광축–target 각 > 화각)이면, 그 chunk만 손목 회전 관절을 target 쪽으로 되돌리는 작은 보정(또는 그 관절만 VLA 대비 변화 상한) | CCR (조건부) | 평소엔 꺼져 있음(발동 조건) · 구현 범위가 작음 | 발동 경계에서 덜컥거림 · 손목 관절만 바꾸면 손 위치도 바뀜(장애물 여유 재검사 필요) |
| V3 재관측 HOLD | target이 손목 화면 밖으로 나간 상태에서 VLA가 닫기를 계획하면(정책 chunk의 gripper 닫힘 행) 닫기를 늦추고 손목을 target 쪽으로 돌릴 때까지 대기 | HSR · CCR (쥐기 단계 판단) | 공중에서 닫는 실패를 직접 막음 | HOLD 증가 ≠ 보호(규칙) — 성공으로 이어지지 않으면 의미 없음 · VLA 입력이 바뀌어 다른 행동이 나올 수 있음 |
| V4 head 기반 target 유지(관측) | 손목 화면 밖일 때 VLA 입력에는 손대지 않고, AG3S target(head camera 기반)을 유지 — 이미 됨 | ATS | 추가 구현 없음 | 문제(VLA가 공중에서 닫음)를 해결하지 않음 — 참고용 |

권장 순서: (0) DX3 최소 변경을 케이스 3 단계 1 · 2에 → 이탈이 남으면 (1) V1(완화 비용) offline → (2) V1 closed-loop. V3는 V1이 부족할 때만(HOLD 지표 함정).

## 3. V1 구현 시 필요한 것 (구현 전 확인 목록)

- 손목 camera 자세: MJCF `wrist_cam_l`의 부모 body · 상대 자세를 TrajOpt 로봇 모델 FK에 추가(구가 아닌 frame 하나).
- 비용: `w_view · max(0, angle(row) − θ0)²`, 실행 행 0–7만, `latched`이고 target 중심이 있을 때만. 기본 꺼짐 flag(`--view-keep-weight W --view-keep-deg θ0`), 꺼지면 bit 동일.
- 선형화: 각의 관절 미분(FK Jacobian으로) — 기존 grasp anchor 항(`grasp_anchor.py`, link 점 FK · Jacobian)과 같은 방식.
- 기록: `to.metrics.view_keep`(행별 각, 벌점, 발동 여부).

## 4. 시험 방법 (고정은 구현 판정 때)

- offline: E3 가림 기록의 이탈 run(311 · 313 · 321 · 322 · 323 · 332)에서 같은 입력으로 V1을 풀어, 계획 행의 광축–target 각과 VLA 추종 오차 · 장애물 여유 변화를 잰다(같은 입력이라 다음 VLA 행동 변화는 못 봄).
- closed-loop: 케이스 3 단계 1 · 2 여섯 run + 회귀 18장면. 주 지표 = 금지 접촉 없는 성공, 보조 = 닫기 전 손목 화면 밖 요청 수 · 닫는 순간 손바닥–사과 거리 · HOLD 수(증가만으로 보호로 보지 않음).

## 5. 열린 질문 (사용자 판정)

1. VW 구현 전에 DX3 최소 변경을 케이스 3 단계 1 · 2에 돌려 볼지 (권장).
2. V1(완화 비용)을 첫 후보로 할지, V2(조건부 재관측)를 먼저 할지.
3. θ0(시야 유지 시작 각) — 손목 화각 절반 ≈ 45° 기준으로 40°를 제안.
