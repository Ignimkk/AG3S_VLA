# T46d — DX-04 선행 확인: LTE 대 global exclusion 비교가 성립하는 최소 비허용 link 집합

> writer: lead (A0) · 2026-10-12 KST · 읽는 쪽: verifier (Opus)
> 사용자 판정 (2026-10-12): 추천안 — W1 은 모든 Ablation arm 에 on, DX-04 는 최소 비허용 link 범위부터, 표본 18 쌍 유지.
> 방향: `doc/plans/develope_PLAN.md` §0.10.1-1 ("먼저 비교의 성립을 확인한다 … wrist 등 관련 비허용 link 를 최소 범위로 추가, whole-body 는 기본 과제 아님"),
> §11 실행 순서 1 (DX-00 · DX-04 선행 확인), DX-04 "선행 확인" 문단. 로그: `AG3S_T47_LOG.md`.

## 왜 지금 이것인가
- DX-04 (link-specific exemption, DT-05A) 는 **query set 에 허용 link 와 비허용 link 가 함께 있고, 진단 장면에서 비허용 link 가 target 에 접근해야** 성립한다.
- 현재 기본 `--links gripper` (손바닥 2 + 손가락 4) 는 active hand 전체가 허용 집합이라 LTE 와 global exclusion 이 같은 결과를 낸다 (퇴화 — 측정으로 확인할 것).
- `--links arms` (양팔 14 link + 손가락, 422 구) 는 C2′ 에서 task 1/18, 비권한 `link_*_arm_5` 가 binding (CL-A), TO median 502 ms.
- 그 중간 (wrist 등) 이 없다. 계획서는 최소 범위를 요구한다 — 어떤 link 를 넣어야 비교가 성립하면서 비용이 작은지를 **기록으로** 정한다.

## 측정 (verifier, Opus) — 코드 수정 없음, CPU offline
입력 (읽기 전용): CL3 (`results/development/20261012T155130+0900_218229ac6464_5fb5ff542c33/verify/T46/CL3/`, C1a · C1aF1 각 18 run, gripper scope), CL2 C2′ (`results/development/20261012T040647+0900_f14ae3e6b62b_d600316277ef/verify/T44/CL2/runs/C2p`, arms scope), CL-A 결과 (`T44e-CLA.verify.json`), snapshot code.
1. **퇴화 확인:** gripper scope 에서 grasp 직전 (pre8 + close) · lift · carry window 의 query 행 중 target 근처 (target 표면에서 margin 50 mm 안) 에 있는 행이 모두 권한 행인가. LTE 와 global exclusion 이 다른 판정을 내는 행 수 (= 비권한 행이 target 근처에 있는 수) — 0 이면 퇴화.
2. **link 별 target 접근:** CL3 C1aF1 의 실행 궤적 (기록 qpos, FK) 에서 양팔 각 link (`link_*_arm_1..6`, wrist/flange 계열, 손바닥 · 손가락) 의 target 및 이웃 과일까지 최소 거리 분포 (GT MuJoCo geom, 같은 phase window). arms-scope 구 모델 (C2′ 와 같은 `--capsule-radius-scale` 등) 의 구 기준.
   — "target 에 접근하는 비권한 link" 의 사전 고정 기준: window 안에서 구 표면–target 표면 거리 ≤ 50 mm 인 chunk 가 run 의 ≥ 1 개.
3. **후보 집합과 비용:** 2 의 결과로 최소 후보 (예: `link_*_arm_6` 만 · `arm_5–6` · `arm_4–6`) 를 만들고, 각 후보의 구 수 · ESDF 질의 행 수와, C2′ 기록에서 그 link 들이 binding / 최악 행이었던 chunk 수 (CL-A 대조) 를 표로. TO 시간은 재풀이 없이 행 수 비례 추정만 (추정이라고 표시) — 정확한 시간은 closed-loop 에서.
4. **세 field policy 의 offline 차이 (가능하면):** 후보 집합 1–2 개에서 no exemption / global exclusion / LTE 를 같은 chunk 에 재조회해 판정이 갈리는 chunk 수 · 그 행의 link. 코드 수정 없이 가능한 범위 (기존 `--target-field-policy` · `--links` · `--exclude-links` 조합) 에서만.
5. 결론: 비교가 성립하는 최소 link 집합 (또는 "성립 안 함 → link-specific 효과 주장 축소" — 계획서의 판정 규칙) + 그 집합을 쓰는 데 필요한 구현 (새 `--links` 값 등) 서술.

## 중단 기준 (측정 전 고정)
