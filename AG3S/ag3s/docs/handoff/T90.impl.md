## 무엇을 했나 (평이한 요약 먼저)

1. **asset.** T86 이 train 교차 검증으로 고른 설정 (head L8 · 왼손목 L12 · 오른손목 L8, 셋 다 raw, C 0.01) 을 train 전체
   (508 forward) 로 다시 맞춰 카메라별 표준화 (평균 · 표준편차) · 계수 · 절편을 `AG3S/ag3s/asset/target_probe/t86_hidden_probe.npz`
   (+ `.json`) 로 저장했다. 다시 맞춘 모델이 T86 이 보고한 모델과 같다는 것은 **T86 test 장면의 hidden 으로 T86 test 지도 (B) 를
   재현** 해서 확인했다: 카메라마다 무작위 60 forward 에서 최대 확률 차이 3e-8 (float32 반올림 수준).
2. **serving.** `--attention-source hidden_probe[:NPZ]` 는 지금 `noun_target:L10H7` 이 들어가는 `result["attention"]` 자리에
   카메라 3 대의 16 × 16 지도를 넣는다. 지도 값은 `p(target) = sigmoid(logit)` 이고, logit 은 카메라별 layer 의 image token hidden
   (2048-d) 을 표준화해 `coef[1] − coef[0]` 에 사영한 것이다. **같은 prefix forward 에서** 나오며 (gemma `return_hidden` 을 그 pass 에만
   켜는 T82 의 경로 `llm_with_hidden` 재사용, 추가 forward 없음) 점수는 device 에서 계산해 `[3, 256]` logit 만 host 로 온다.
   `--hsr5` 와 함께 주면 같은 hidden stack 에서 HSR5 feature (h_4) 도 나온다 (한 pass).
3. **prompt 는 hidden 으로만 본다.** probe 는 prompt 문장을 읽지 않는다 (model 이 prompt 를 읽은 결과가 hidden 에 담길 뿐).
   명사 lookup 은 "prompt 에 target 과일 단어가 정확히 하나 있는가" 만 정한다: 없으면 지금과 같게 **target 없음 (빈 attention + 사유)**.
4. **기록.** `summary_json.attention_source` (요청마다) 에 `spec = hidden_probe`, 카메라별 `layers`, `asset_md5`, `ms`,
   `max_score` (카메라별) · `max` · `argmax_patch`, 그리고 `prompt_use` 문장.

### 정한 것 (⚑ = lead 확인)

| 항목 | 값 | 근거 |
|---|---|---|
| 지도 값 | **확률** `sigmoid(logit)` (logit 아님) | ATS (`ifg_s1.top_k`) 는 768 patch 전체에서 점수 > 0 인 상위 5 개를 가중치 `score / sum` 으로 쓴다. 음수 logit 은 가중치가 될 수 없고, 확률은 카메라 사이에 비교가 된다 (카메라마다 따로 학습). ⚑ 확률이 포화 (≈ 1) 하면 상위 5 개가 거의 같은 무게가 된다 — noun attention 은 봉우리가 뾰족했다. host 에서 float64 로 sigmoid 해 logit < 36 에서는 동점이 안 생긴다 |
| 점수 계산 위치 | device float32 (표준화 후 사영), sigmoid 는 host float64 | `[3, 256]` 만 복사. offline float64 와 차이는 test 로 고정 |
| hidden 정밀도 | serving 은 float32 hidden, asset 은 float16 으로 저장된 train hidden 에서 학습 | T86 과 같다 (T86 이 hidden 을 float16 으로 저장). 차이는 smoke 에서 측정 |
| `--hsr5` 와 함께 | 한 pass 에서 둘 다, `hsr5_ms` = `probe_ms` (같은 pass) | `--hsr5` 가 있으면 h_4 feature 도 나온다 |
| `ms` | prefix pass (hidden stack · 점수 · host 복사) 의 벽시계. `noun_target` 쪽은 지금 이 값을 기록하지 않는다 | 요청당 추가 시간은 smoke 에서 두 source 를 같은 요청으로 비교 |
