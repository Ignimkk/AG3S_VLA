# T44b I2b — 구현: carry 권한 = 쥔 손의 gripper + gripper 바로 위 link

> writer: ag3s-implementer (A3) · 읽는 쪽: verifier, scribe, lead · 2026-10-10 UTC
> task: `T44b.task.md` §A3 (사용자 판정 3). 선행: `T44I2.impl.md`, `T44I2.verify.json` (V-I2-3).

## 무엇을 했나 (평이한 요약 먼저)

I2 strict 에서 쥐고 있을 때 (carry) 는 `manipulated_link_margin` 이 모든 link 에서 같아 권한 행이 0 개였다.
그래서 strict 가 쥔 손의 손가락까지 held 잔상에 대해 검사했다 (V-I2-3: 바뀐 행 43 chunk 가 전부 held).
이제 strict 이고 쥐고 있으면 권한 행 = **쥔 손의 contact link (손바닥 + 손가락 둘)** + **그 손의 URDF chain 에서
gripper 위로 N 개 link** (`collision.held_permission_parent_links`, 기본 1) 이다. 반대 손 · forearm · 나머지는 검사한다.
"어느 손이 쥐었나" 와 "chain" 은 AG3S (`to_adapter`) 가 robot model 과 `ContactConfig` 로 행마다 `depth` 로 기록하고,
trajopt 는 `0 ≤ depth ≤ N` 으로 읽는다. strict off · 쥐기 전 (approach) · relax 의 동작은 그대로다.

**찾은 parent link: `link_left_arm_6` / `link_right_arm_6`.** URDF 의 바로 위 parent 는 `FT_sensor_L/R` (fixed joint,
제약 모델에 구가 없음) 이라 행이 없으므로 건너뛰고, 구를 가진 첫 link 를 센다.

## 남은 결함 · 판정이 필요한 것

1. **"gripper 바로 이전 link" 의 해석.** URDF 의 직속 parent `FT_sensor_L/R` 은 fixed joint 의 센서 frame 이고 제약 모델에 구가 없다 (행 0).
   그래서 "구를 가진 link 만 센다" 로 구현했고 N=1 = `link_<side>_arm_6` (손목 · 카메라 bracket, 15 구, gripper 와 **fixed joint 로 강체 연결**).
   사용자가 의도한 것이 첫 **회전 관절 너머** link (forearm `link_<side>_arm_5`) 였다면 N=2 로 같은 결과를 얻는다 (forearm 은 5 구).
2. **CLI 없음.** `serve_safe.py` 는 이번 소유 밖이라 `--held-permission-parent-links` 를 넣지 않았다. 기본 1 = 사용자 판정이므로 strict 로
   돌리는 closed-loop 에는 영향이 없지만, 0/2 를 서버에서 시험하려면 I2 block 에 한 줄이 필요하다.
3. **relax 의 한계 (그대로 둠, task 4).** mask 없음 + 쥐지 않음 (`relax`) 에서 권한 = `manipulated_link_margin < max − 1e-12`. 모든 구가
   권한 link 이거나 TRANSIT (`margin_scale` 1.0) 이면 아무 행도 권한이 없어 strict 에서 target 예외가 0 이다. phase 가 margin 을 줄이는
   APPROACH/GRASP 에서만 손 행이 권한을 받는다 — phase 규칙에 묶인 간접 권한이고, ContactConfig 의 측을 직접 읽지 않는다.
4. **측 판정의 근거는 hold link 이름 하나.** hold link 가 어느 `ContactConfig.contact_links` 측에도 없으면 (예: 다른 `--hold-links`) fail closed
   (권한 행 0 → strict 가 쥔 손도 검사) 이다. 양손 파지 (attachment 둘) 는 지금 구조 (attached 하나) 에서 다루지 않는다.
5. held 잔상에 대한 권한이 gripper + arm_6 에 생기면서, strict 에서 **그 행들이 held 잔상 근처에서 look-ahead drop · obstacle margin 면제 ·
   sweep 제외를 다시 받는다** — I2 strict 보다는 느슨하고 strict off 보다는 엄격하다. arm_6 행이 잔상 아닌 장애물 근처에서 우연히 E1 test
   (`|d − d_object| ≤ voxel`) 를 통과하는 경우가 있는지는 재생으로만 보인다.
