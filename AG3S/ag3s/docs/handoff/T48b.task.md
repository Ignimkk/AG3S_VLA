# T48b — HSR counterfactual (b): empty grasp · slip · phantom hold 로 probe 가 "쥠 상태" 를 읽는지 "팔 자세" 를 읽는지 가른다

> writer: lead (A0) · 2026-10-12 KST · 읽는 쪽: implementer, verifier
> 사용자 판정 (2026-10-12, T48a 결과 후): **T48b 진행.** 16D policy 이미지 re-render parity 를 먼저 확인하고, 통과하지 못하면 거기서 멈춰 보고한다. GPU 추출은 T46 의 CL3 가 끝난 뒤에 한다 (TO wall-clock 마감 때문 — `T49.task.md` 의 판정과 같다).
> 승인 범위: MuJoCo replay (osmesa, CPU) · offline GPU prefix pass (server 없음).
> 공통 규칙: env.sh, `.venv-openpi-live` (GPU) / `.venv-ag3s` (CPU test), 새 output 은 `$AG3S_RUN_DIR`, CPU worker ≤ 2, 다른 세션 process 금지, 커밋은 lead.

## 왜 지금 이것인가

T48a (`T48.verify.json`) 결과:
- probe 는 **state 문자열이 아니라 image 를 따른다.** C2s · C2i 에서 image 쪽을 따른 비율이 0.979 이고, gripper 값을 뒤집으면 예측이 0.005 만 바뀐다.
- probe 는 **instruction 의 target 교체에 거의 반응하지 않는다.** C1 에서 원래 place 인 frame 이 `pick` 으로 바뀐 비율은 0.040 이다.

남은 질문: probe 가 image 에서 읽는 것이 **"물체를 쥐고 있다"는 작업 상태** 인가, **"팔이 이 자세에 있다"는 시간·자세 순서** 인가.
dataset 은 실패 · retry 가 없는 scripted 시연이다 (frame index 만으로 val 1.000). 그래서 자세와 쥠 상태가 항상 같이 움직이고, 지금 data 로는 둘을 가를 수 없다.
→ 같은 팔 자세에서 **물체의 유무 · 위치만** 바꾼 image 를 만든다.

```
recorded 16D step (qpos · 224 RGB ×3 · state)
  → qpos 편집 (물체 자유 관절 · finger 관절) → MuJoCo re-render (policy image 규약) → state 재구성
  → VLA prefix (frozen) → kv_L4 feature → probe → pick / place / home
```

## Counterfactual 설계

정답은 **물리 predicate** 로 정한다. 대상 물체가 gripper 안에 있고 table · basket 에 닿아 있지 않으면 `held` 다. gripper rule 로 정답을 만들지 않는다.

| ID | 출발 frame | 편집 | 정답 | 묻는 것 |
|---|---|---|---|---|
| **E0** | 모든 사용 frame | 편집 없음, re-render 만 | 원래 정답 | **parity**: re-render image 의 예측이 기록 image 의 예측과 같은가 |
| **E1** empty grasp | `held` frame (파지 후 · 놓기 전) | 쥔 과일을 **초기 table 위치** 로 옮기고, finger 를 물체 없이 닫힌 위치로 둔다. state 의 gripper 값도 그에 맞춘다 | **pick** | 손은 닫혔고 팔은 운반 자세인데 물체가 없다 |
| **E1s** empty grasp (state 고정) | 같음 | 과일만 옮기고 finger 와 state 는 그대로 둔다 | **pick** | E1 에서 finger image · state 효과를 뺀다 |
| **E2** slip | `held` frame | 쥔 과일을 gripper **바로 아래 table 위** 에 놓는다 (손에서 떨어진 위치). finger · state 는 E1 과 같게 한다 | **pick** | 물체가 손 근처에 보이지만 쥐어져 있지 않다 |
| **E3** phantom hold | 파지 **전** 접근 frame (`reach`) | 대상 과일을 **finger 사이** 에 놓고 finger 를 과일 폭에 맞춘다. state 도 맞춘다 | **place** (물리적으로 쥐어짐) | 팔은 접근 자세인데 물체는 손에 있다 — E1 의 대칭 |

- 편집 뒤에는 `mj_forward` 만 한다. 접촉이 맞지 않는 (관통) 배치는 rendering 이 그럴듯한지 sidecar 에 기록하고, 관통 깊이가 기준 (impl 이 정하고 근거를 적는다) 을 넘는 frame 은 제외한다.
- 비교 대상: probe · 단순 rule · offline strong-rule proxy · frame-index. 정의는 T48a 와 같다. proxy 는 measured opening (finger 개도) 을 쓰므로, E1 (빈 손이라 완전히 닫힘) 은 proxy 가 잡아낼 수 있는 경우다.

## 이 STEP 이 답하는 질문
**같은 팔 자세에서 물체의 유무만 바꾸면 phase probe 의 예측이 바뀌는가? — 바뀌면 "쥠 상태" 를 읽는 것이고, 안 바뀌면 "자세 순서" 를 읽는 것이다.**

## 되돌아올 지점
- E0 parity 미달 → 이후 진행 없음. re-render 와 기록 image 의 차이부터 찾는다 (camera 규약 · 조명 · 해상도).
- E1 · E2 에서 probe 가 `place` 를 유지하면 probe 는 자세 순서를 읽는다. 그러면 HSR 은 empty grasp · slip 에서 strong rule (measured opening) 보다 못하다. → 검토 문서 §6 기준대로 HSR 을 보조 구성 요소로 둔다.
- E1 · E2 · E3 에서 probe 가 물체를 따라가면 image 의 쥠 상태를 읽는 것이다. → 실험 4 (phase source ablation) 의 HSR arm 근거가 된다.
