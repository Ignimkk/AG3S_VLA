# T65 — target 찾기 attention 신호 3 가지를 같은 입력으로 비교 (고정 입력 재생, 사전 고정)

> writer: lead (세션 B) · 2026-10-29 KST · 상태: **사전 고정 — 결과 전.**
> 근거: 사용자 판정 (2026-10-29 01:50 KST, 세션 A 경유, `AG3S-CORE-EVALUATION.task.md` §0.1-2)
> - ATS 비교의 주 지표는 성공률이 아니라 **ATS 고유 지표를 고정 입력에서** 잰다
> - closed-loop 성공은 안전 확인으로만 쓴다
> - 고정 입력 재생은 세션 B 가 맡는다

## 왜

- ATS 의 일은 두 가지다. target 물체의 표면을 나누는 것 (segmentation), 그리고 거리장에 줄 입력 (무엇을 지우고 남길지) 이다.
- closed-loop 성공률에는 TrajOpt · HSR · 정책 변동이 섞인다. 같은 config 에서도 1–2 run 이 우연으로 흔들린다.
- 또 closed-loop 에서는 구성마다 로봇이 다르게 움직여 ATS 가 보는 장면이 달라진다.
- 그래서 **같은 관측을 그대로 두고 attention 신호만 바꿔** ATS 출력을 비교한다.

## 사전 고정

### 비교 구성 (바꾸는 것은 attention 신호 하나)

| 구성 | `--attention-source` | 지위 |
|---|---|---|
| 명사 | `noun_target:L10H7` | 현 구성 (핵심 평가 채택 config) |
| 관행 head | `action:last:L8H2` | 비교 |
| 절차 선택 head | `action:mean:L10H7` | 비교 (T61 사전 고정 절차의 선택, `T61.selection.json` sha `c3f3b60f`) |

- 나머지 서버 설정은 핵심 평가 round 1 서버의 실제 cmdline 그대로다 (`server_proc.txt`, code = `$RUN/snapshot_core`).

### 입력 (고정)

- 핵심 평가 round 1 (명사 구성) 의 기록 18 run.
  - run: `RUN=/mnt/dev/AG3S_VLA-storage/results/development/20261028T224856+0900_b3b69311f948_8784a1265958`, `V=$RUN/verify/AG3S-CORE-EVAL`
  - 회귀 6 장면 × 2 회: `$V/REG_k{0,1}`
  - 가림 기둥 3 장면 × 2 회: `$V/OCC/k{0,1}`
- 요청마다 기록된 관측을 그대로 쓴다: 224 이미지 3 장 · depth · K · T · qpos · state · prompt · 실행 feedback. 로봇 궤적은 기록 그대로다.
- AG3S 상태 (latch · TargetConfirm) 는 각 구성에서 처음부터 다시 진행한다. attention 이 바뀌어 latch 판단이 바뀌는 것은 ATS 의 영향으로 측정에 포함한다.

### 실행

1. **attention 추출 (GPU, 공유 lock):** 기록 요청의 이미지 · prompt · state 로 VLA prefix pass 를 다시 돌려 세 신호의 map 을 뽑는다. 결과가 벽시계에 의존하지 않으므로 공유 lock 으로 돌린다.
   - **명사 구성도 다시 뽑는다.** 세 구성을 같은 경로로 처리하기 위해서다.
2. **AG3S 재생 (CPU, worker ≤ 4):** 서버 cmdline 그대로 만든 `SafePolicy` 에 요청을 순서대로 넣는다 (T55 `t55_perception` 방식).
   - 정책 출력은 기록 chunk 로 대신하고, TrajOpt 는 돌리지 않는다 (perception-only).
   - 출력은 서버와 같은 형식의 chunk (`target_points` · `summary_json` · target-free 계층) 이다.
3. **ATS 지표:** 세션 A 의 정의를 그대로 쓴다 (`$V/make_spec.py` · `module_eval.py` · `ats_extra.py` · `ats_only.py`). closed-loop ATS 수치와 바로 비교할 수 있게 하기 위해서다.

### parity gate (비교 전 필수)

- 명사 구성 재생이 기록된 서버 chunk 를 재현해야 한다.
  - 요청별 target 선택 (manipulated id · grounding status) 일치 ≥ 99 %
  - target 점 집합 일치 (median Chamfer ≤ 1 voxel = 5 mm)
- 미달이면 비교하지 않고 원인을 보고한다.

### 지표 (A 의 정의, 쥐기 전 요청 = 첫 두 손가락 접촉 또는 20 mm 상승 전까지)

| 지표 | 정의 (`ats_only.py`) |
|---|---|
| **target identity** | 고른 점의 다수 물체 (10 mm) 가 정답 사과인 요청 비율 |
| **precision** | target 점 중 정답 사과 표면 5 mm 안 비율 |
| **다른 물체 선택** | 고른 점의 다수 물체가 다른 물체인 요청 비율 |
| 보이는 표면 recall | 보이는 정답 사과 표면 중 target 점 5 mm 안 비율 |
| 중심 오차 | 보이는 표면 중심 대비 mm |
| target 없음 | target 이 없는 요청 비율 |
| 거리장 입력: **남은 target** (`apple_left_frac`) | GT 사과 충돌 표면 표본 (`gt.at(qpos)`, apple geom 만) 을 가장 가까운 voxel 로 fine main field `esdf_*` 와 target-free field `esdf_free_*` 에서 읽는다. seen = \|main\| ≤ 1 voxel (5 mm), left = seen ∧ \|target-free\| ≤ 1 voxel, **left_frac = left / seen**. target-free 계층이 있는 요청만 |
| 거리장 입력: **잘못 지운 영역** (`removed_by_class`) | `target_free_removed_ijk` voxel 중심 (`target_free_trace_origin + (ijk + 0.5) · target_free_trace_voxel_size`) 을 가장 가까운 표면 label 로 분류한다 (cKDTree, 8 mm). label = GT 비로봇 표본 (apple · fruit · obstacle · table · crate) · 로봇 표면 · 사과 꼭지 · 잎 visual mesh · 사과 중심의 충돌 반경 안 (`apple_inside`) · 그 밖 `none`. **잘못 지운 것 = fruit (사과가 아닌 과일) + obstacle + table + crate.** apple · apple_inside · 꼭지 · 잎 · robot · none 은 오류가 아니다 |

- 거리장 두 지표는 세션 A `module_eval.py` main() LTE 블록 (89–107 행) 의 정의를 T65 코드에 그대로 옮겨 쓴다 (2026-10-29 세션 A 전달, 결과 전). A 의 run 디렉터리는 고치지 않는다.
- 창: 쥐기 전 요청 (첫 두 손가락 접촉 또는 20 mm 상승 전, `ats_only.py` 규칙).

- 집계: 장면 (9) 마다 2 회 평균 → 장면 평균.

#### 집계 세부 (2026-10-29 03:00 KST, 재생 진행 중 · 비교 결과 전에 고정)

- **실행 방식 변경 기록:** 재생은 perception-only `SafePolicy` 대신 **기록 서버 cmdline 그대로의 `serve_safe` 에 기록 요청을 순서대로 다시 보내는 방식**으로 한다 (`t65_run.py` · `t65_replay_client.py`). 카메라 이미지 · depth 는 기록 qpos 로 MuJoCo 에서 다시 렌더한다. 정책 · TrajOpt 도 돈다. 로봇 궤적은 기록 그대로라 ATS 지표에는 영향이 없다. 명사 smoke 15 요청 parity: 선택 15/15 · attention 차 0 · Chamfer median 2.4 mm.
- 요청 j 의 재생 chunk ↔ 기록 client step j (같은 qpos) 로 정답을 만든다 (A `module_eval.py` 와 같은 대응).
- **분모:** 쥐기 전 요청 전체.
  - identity = 다수 물체 `apple` 인 요청 / 전체
  - 다른 물체 선택 = 다수 물체가 `apple` 도 `none` 도 아닌 요청 / 전체 (`none` = 점이 어떤 물체 10 mm 안에도 없음, 따로 보고)
  - target 없음 = target 점 0 인 요청 / 전체
  - precision · recall · 중심 오차 = 그 값이 있는 요청 평균
  - 남은 target = target-free 계층이 있는 쥐기 전 요청의 `apple_left_frac` 평균
  - 잘못 지운 영역 = run 의 쥐기 전 요청 전체에서 지운 voxel 중 오류 class 비율 (개수도 보고)
- **좋은 방향:** identity · precision · recall ↑, 다른 물체 · `none` · target 없음 · 중심 오차 · 남은 target · 잘못 지운 비율 ↓.
- **"2 %p 이상 개선":** 장면 평균 차이 (다른 구성 − 명사) 가 좋은 방향으로 ≥ 0.02.
- **"악화 없음":** 나머지 지표의 장면 평균 차이가 나쁜 방향으로 0 을 넘지 않음 (점 추정, 허용오차 없음). 크기는 함께 보고한다.
- **"9 장면 중 5 이상 같은 방향":** 주 지표 셋 각각에서, 좋은 방향으로 0 보다 큰 차이가 난 장면이 5 개 이상 (동률은 세지 않음).
- 값이 없는 장면 (예: target 이 한 번도 없어 precision 없음) 은 그 지표의 장면 수에서 빠진다. 빠진 수를 보고한다.

### 판정 규칙 (사용자 판정 2026-10-29 01:50 KST, 바꾸지 않는다)

- 명사에서 다른 구성으로 바꾸는 조건 (모두 충족):
  1. identity · precision · 다른 물체 선택이 **각각 2 %p 이상 개선**
  2. 나머지 ATS 지표 악화 없음
  3. 개선 방향이 **9 장면 중 5 장면 이상**에서 같음
  4. closed-loop 안전 확인 통과 (세션 A 집계): 접촉 없는 성공이 명사보다 4 run 넘게 적지 않고, 비허용 접촉 run 이 늘지 않음
- 아니면 **명사 유지** (성공률이 비슷하면 원리적인 방식).
- closed-loop 실패 run 마다 원인 층 (ATS · HSR · LTE · CCR) 을 적는다. 실패 시점의 ATS 지표가 틀렸을 때만 ATS 실패로 센다 (세션 A 와 함께).
