# T44 — Target exclusion 첫 작업 묶음: I0 trace · I1 `ball_owned` exclusion · I2 permission 일관성

> writer: lead (A0) · 읽는 쪽: implementer (A1 = I0+I1, A2 = I2), verifier
> 작성 2026-10-09 UTC. 근거 문서: `benchmark/docs/AG3S_PHASE_DENOISING_PLAN.md` (PROPOSED) §2.2–2.4, §8.1–8.2.
> 사용자 지시: I0 → I1 → I2 를 첫 묶음으로. 기존 ball 을 비교 기준으로 보존. HSR · denoising · L1/L2 는 이번 범위 밖.

## 왜 지금 이것인가

목표: **올바르게 선택한 target 의 필요한 contact 는 허용하고, 주변 obstacle 과 non-contact link 의 보호는 유지한다.**

```
카메라 depth → 로봇 마스크 → [attention lifting → target grounding] → TSDF/ESDF (main + fine_no_target)
            → 거리장 어댑터 (link 별 main / target-free) → SQP 선형화 · look-ahead · sweep → QP 해 · verdict
```

현재 baseline V11AB (benchmark tag `v2`, `498f713`) 는 target 을 `_target_ball` (fitted sphere + pad, 예: fit 33.5 mm → ball 54.4 mm)
로 target-free fine layer 에서 지운다. 이 layer 는 authorized link (ee + fingers) 만 조회한다.

코드로 확인한 것 (실행 영향은 **미측정** — 확정 bug 로 다루지 않는다):

| ID | 무엇 | 위치 |
|---|---|---|
| P1 | `PathChecker._target_rows` 가 E1 test (`\|d−d_object\|≤voxel`) 와 `in_target_volume` 으로 path 행을 제외하는데 authorized link 와 교집합이 없다. `&= ~free` 때문에 오히려 **authorized 행은 E1 제외에서 빠지고 non-authorized 행이 target 근처에서 빠진다** | `trajopt/sweep.py:427-460` |
| P2 | `_lookahead_keep` (tail 행 drop) · `_obstacle_rows` (obstacle_margin 면제) 도 같은 판정을 link 필터 없이 쓴다 | `trajopt/linearize.py:1021-1024, 1084-1089` |
| P3 | `obstacle_margin > 0` 이면 `obstacle = dict(...)` 로 다시 만들어 앞서 넣은 `target_volume` 이 사라진다 | `trajopt/linearize.py:1969-1982` |
| P4 | builder 는 target `(M,3)` 점과 ball 만 받는다. ball 안 seed 가 target 것인지 이웃 물체 것인지 가를 정보가 없다 | `ag3s/runtime/pipeline.py:2607-2630`, `ag3s/fields/curobo_builder.py:1277` |

V11AB 는 `sweep_check` · `servo_model` off (PathChecker 없음), `target_volume_exempt` off, `--lookahead obstacles` on 이다.
그래서 V11AB 에서 P1·P3 는 비활성이고, P2 (look-ahead tail 행) 만 살아 있을 수 있다.

### I1 — `ball_owned`: ball ∖ non-target-owned seeds
- **왜 이 방식인가:** ball 은 sparse-point exclusion 에서 target seed 가 남는 문제를 고치려고 도입됐다. ball 을 *외곽 상한* 으로 유지하면
  그 recall 을 잃지 않고, ball 안에서 **관측된 non-target 표면에 더 가까운 seed 만 보존**하면 이웃 물체 문제만 고친다. support guard ·
  sign correction · fine window 경로를 그대로 재사용한다.
- Config (`EsdfConfig`): `target_exclusion: str = "ball"` (`"ball"|"ball_owned"`), `owned_tie_voxels: float` (기본 1.0),
  `owned_max_dist_voxels: float` (기본 2.0), `unowned: str = "remove"` (`"remove"|"keep"`). validation 포함.
  CLI: `--target-exclusion {ball,ball-owned}`, `--owned-tie-voxels`, `--owned-max-dist-voxels`, `--owned-unowned {remove,keep}`.
- Evidence: `_run` 에서 **non-target 점** = fused cloud − `target.point_indices` − `support_mask` (robot 은 이미 self-filter 됨) 를 builder 로
  넘긴다 (`update(..., nontarget_points=...)`; `ball` 모드에서는 넘기지 않거나 무시 — bit-identical). target 점은 기존 `target.points`.
- 분류 (ball 안, `c_z ≥ z_min` 인 seed voxel centre `c` 마다): `d_t` = 가장 가까운 target 점 거리, `d_o` = 가장 가까운 non-target 점 거리.
  - `min(d_t, d_o) > owned_max_dist_voxels·vs` → **unowned** (`unowned` 설정대로 제거/보존)
  - `|d_t − d_o| ≤ owned_tie_voxels·vs` → **ambiguous** → 보존, 기록
  - `d_t < d_o` → target_owned → 제거; `d_o < d_t` → nontarget_owned → 보존
- 이웃 탐색은 기존 helper (`_SeedIndex` 등) 나 scipy cKDTree 를 재사용. GPU tensor 경로가 있으면 그 경로를 따른다.
  sign correction (`_force_sign_on_pure_voxels`) 은 **실제로 제거된** index 에만 적용.
- 모호/결측에서 ball 로 넓혀 fallback 하지 않는다 (ball 이 이미 상한이다). 원인은 stats 로 남긴다.

### 구현
1. Config `collision.target_permission_strict: bool = False` + CLI `--target-permission-strict`. TrajOptConfig 왕복.
2. `scene_from_constraint_set`: snapshot 에 `target_contact_rows` (robot sphere 행별 bool) 를 싣는다.
   - `exclude_authorized`: `target_free_mask` · `exclude_all`: `target_free_exempt` · `relax`/mask 없음: `manipulated_link_margin < max − 1e-12`.
   - 아무것도 manipulated 가 아니면 `None`.
3. **P3 수정 (flag 무관):** `obstacle = dict(...)` → 기존 dict 에 `update`. `target_volume_exempt` off 인 V11AB 에서는 bit-identical 임을 test 로.

   `& target_contact_rows` 를 적용한다 (held 행은 기존대로).
5. `ball_owned` 대비 (A1 의 `stats["target_free"]["exclusion_method"] == "ball_owned"` 일 때, flag on): `in_target_volume` 의 ball 판정 대신
   target membership = `d_free − d_main > voxel` (target-free layer 에서만 사라진 표면) 로 판정. 같은 helper 를 세 소비자가 쓴다.
   stats 키가 없으면 기존 ball 판정.

## 이 STEP 이 답하는 질문
같은 correct identity 에서 `ball_owned` 가 target 제거를 유지하면서 ball 보다 이웃 물체를 더 보존하는가, 그리고 non-contact link 는
모든 검사 경로 (waypoint · look-ahead · sweep · verdict) 에서 target 예외를 받지 않는가.
