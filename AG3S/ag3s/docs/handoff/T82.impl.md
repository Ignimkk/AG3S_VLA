## 무엇을 했나 (평이한 요약 먼저)

1. **5 단계 분류기를 serving 에 넣었다 (flag `--hsr5`, 기본 꺼짐).** attention 복사본이 이미 돌리는 noun prefix pass 하나에서, 그 pass 에만 openpi `return_hidden` 을 켜서 hidden layer 4 를 꺼낸다. 추가 forward 는 없다. 꺼낸 값은 [cam_high · left_wrist · right_wrist image token 평균, 마지막 유효 text token] 8192 차원이고, T77 의 `h4_img3+last` 분류기 (asset 으로 복사, md5 `985be918…`) 가 요청마다 raw argmax 로 단계를 낸다 → `result["hsr5"]`.
2. **T77 추출 도구와 같은 feature 다.** T77 smoke 의 회귀 211 기록 8 frame 에서, serving 코드가 낸 feature 와 T77 `pi05_hidden --pool summary` 값의 상대 오차가 **0.0 (bit 동일)** 이었다. argmax 8/8 일치. flag 를 켜도 attention row 와 3 단계 subtask 확률은 바뀌지 않았다 (차 0.0). prefix pass 시간은 중앙 70.7 → 72.3 ms (+1.6 ms) 다.
3. **`--hsr5` 를 켜면 단계 입력이 5 단계로 바뀐다.** 규칙 코드는 그대로 두고 입력만 바꿨다. 새 조작 대상 gate, HSR6 네 규칙 (①–④), 쥔 뒤 꺾임 변화율 · 연속성 항, 그리고 새 규칙 **closing 풀기** 가 대상이다. closing 풀기: latch 가 closing 인데 단계가 운반 · 놓기가 아니고, 실행된 gripper 명령이 닫힘 문턱 0.85 이상인 요청이 2 번 연속이면 latched 로 되돌린다. latched 가 되면 ATS 고정이 풀린다.

### closing 풀기 세부

- **세는 요청:** latch 가 CLOSING 인 요청 중 (LATCHED → CLOSING 으로 바뀐 그 요청도 포함) 기존 "다시 열림" 규칙 (`reopened` = 명령 ≥ 0.85 ∧ 측정 개도 ≥ 0.85, 1 요청) 이 발동하지 않은 요청만 센다. 기존 규칙이 먼저다.
- **연속 수 +1 조건 (모두):** 단계가 있다 ∧ 단계 ∉ {carry, place} ∧ 이번 피드백에 실행된 step 이 있다 (`n_exec > 0`) ∧ 마지막 실행 명령 ≥ 0.85.
- **연속 수 0 으로:** 단계 없음 · carry · place · 실행 명령 없음 (HOLD chunk) · 명령 < 0.85. 이유는 `evidence.closing_release.reset` 에 남는다. 새 닫힘 시도 (LATCHED → CLOSING) 도 0 에서 시작한다.
- **2 에 닿으면:** LATCHED 로 간다. attach · detach 는 없고, 대상 잠금은 유지한다. `_reset_grasp(keep_opening=True)` 를 부르는데, 이것은 기존 "시도 포기" 와 같은 처리다. 그 요청에서는 attach 검사를 하지 않는다. `SafePolicy` 가 매 요청 `set_grasp_active(phase ∈ {CLOSING, HELD})` 를 부르므로 그 요청부터 ATS 의 쥐기 고정 (frozen) 이 풀린다.
- **기록:** `grasp.evidence.closing_release = {stage, command, threshold, streak, frames, released[, reset]}`, `summary_json.hsr5.source.closing_release = "hsr5"`.
- ⚑ **"닫기 시작 개도" 의 해석.** `gripper_closed_below` (0.85) 로 읽었다. latch 가 "닫힘 명령" 으로 세는 문턱, 곧 닫기가 시작됐다고 보는 값이다. 다른 해석은 닫기 직전 측정 개도 (`opening_before`) 다. 그러나 이 값은 기록에서 ≈ 1.01 이고 실행 명령의 최대는 ≈ 1.00 이라, 그렇게 읽으면 거의 발동하지 않는다. 바꿀 곳은 `grasp_latch._closing_release_check` 의 `thr` 한 줄이다.
- ⚑ **회귀 211 (T71 R0) 기록에서는 이 규칙이 발동하지 않는다.** 빈손 닫기 (요청 20) 뒤 실행 명령이 끝 (요청 75) 까지 0.27–0.46 에 머물렀다 (`server_8292_20261029T154310` chunk 의 `grasp.evidence.last_command`). VLA 가 gripper 를 다시 열지 않았다는 뜻이다. 계획 chunk 50 행 중 뒤쪽에는 0.9–1.0 이 자주 나오지만, 실행되는 앞 8 행에는 나오지 않는다. task 머리말의 "211 에서 latch 가 closing 에 묶임" 은 이 규칙으로 풀리지 않는다. 이것은 test `test_the_211_pattern_command_never_reopens_keeps_closing` 로 고정했다. 결과 판정이 아니라 규칙 정의에서 나오는 사실이다.
