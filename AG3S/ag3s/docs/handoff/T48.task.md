## 왜 지금 이것인가

HSR (Hidden-state Sub-task Recognition) 은 frozen VLA feature 위의 linear probe 로 `pick / place / home` 을 읽는다.
이 phase 는 target grounding 의 gate 에 쓰인다 (`TargetConfirm`, `target_grounding.py:945, 959-968, 1124-1135, 1204-1209`; `config.py:342-360` `subtask_gate=True`).

지금 근거는 이렇다 (`paper/notes/SUBTASK_FACTS.md`):

| 사실 | 의미 |
|---|---|
| val accuracy 0.9808 | 높다 |
| **frame index 만으로 val 1.000** (250 episode 중 248 이 같은 phase 순서) | 위 정확도가 *작업 상태* 를 읽은 것인지 *시간 · 자세 순서* 를 읽은 것인지 가릴 수 없다 |
| L0 ~ L17 전부 ≈ 0.98 | 어디서나 읽힌다 — 강한 근거가 아니다 |
| gripper 값을 가려도 0.98 · 단순 rule (gripper + ever-closed) 0.9423 | proprio 하나로 설명되지는 않는다 |
| 완전 held-out episode 는 ep1807 하나 | 일반화 근거가 얇다 |
| gate on/off 48 쌍: 성공 28 vs 29 | 실행상 이득은 입증되지 않았다 |

feature 는 prefix KV cache 의 **V, layer 4, KV head 0** 이다. 512D = `[valid text token 평균 | 768 image token 평균]` (`subtask_probe.py:10-15, 54-76`).
**text 평균 안에는 discretize 된 16D state 문자열 (gripper · joint 숫자) 이 들어 있다.** 그래서 probe 가 이미지 대신 state 문자열을 읽을 수 있다.

검토 문서의 구분 (Bhardwaj et al.):
**weak decodability** (feature 에서 label 이 읽힌다 — 지금 있는 근거) ≠ **strong decodability** (관련 입력이 바뀌면 올바르게 반응한다 — T48 이 처음 재는 것).

```
RGB ×3 + state 문자열 + prompt → VLA prefix (frozen) → KV V L4 h0 → [text 평균 | image 평균] 512D
   → LogReg (kv_L4_v1) → pick/place/home → SubtaskDebounce → TargetConfirm gate
         ↑ T48a 는 여기 입력을 하나씩 바꾼다 (prompt · state · image)
```

## Counterfactual 설계 (T48a)

data 의 성질: dataset 의 모든 episode 는 **target 1 + distractor 3** 이고, 모두 `place_one`, 성공, retry 0 이다. **distractor 는 episode 내내 건드려지지 않는다.**
→ prompt 를 distractor 로 바꾸면 그 instruction 기준 정답은 **모든 frame 에서 `pick`** 이다 (아직 안 잡았고 basket 에도 없다). 사용자 판정과 일치한다.

| ID | 바꾸는 것 | 고정 | 정답 | 무엇을 묻나 |
|---|---|---|---|---|
| **C0** | 없음 (원본) | — | dataset `phase_index` → class (`kv_L4_v1.json` 의 `class_from_phase_index`: pick 0-3 · place 4-8 · home 9-13) | 재현 점검 (val 0.9808 이 나와야 한다) |
| **C1** | prompt 의 target 명사 → 같은 scene 의 distractor 과일 3 개 각각 | image · state | **`pick` (모든 frame)** | language 민감도: 원래 place/home frame 에서 `pick` 으로 바뀌는가 |
| **C1p** | 같은 target, **다른 phrasing** (dataset 의 3 template 중 나머지) | image · state | 원본 정답 | 통제: 말만 바꿨을 때 흔들리지 않는가 |
| **C2g** | state 의 **gripper 값만** 반대로 (열림 ↔ 닫힘, 범위는 dataset 실제 분포의 열림/닫힘 대표값) | image · prompt | 원본 정답 (이미지가 보여 주는 실제 상태) | gripper 숫자에 끌려가는가 |
| **C2s** | **state 전체** 를 같은 episode 의 **다른 class frame** 에서 이식 | image · prompt | 원본 정답 (image 쪽) | state 문자열이 phase 를 결정하는가 |
| **C2i** | **image 3 장** 을 같은 episode 의 **다른 class frame** 에서 이식 | state · prompt | 이식된 image 의 class (state 쪽 원본과 다름) | image 가 phase 를 결정하는가 |

- C2s 와 C2i 는 대칭이다. 같은 (frame A, frame B) 쌍에서 둘 다 만든다. 예측이 state 를 따르는지 image 를 따르는지 쌍마다 센다.
- 이식 쌍은 class 가 다른 frame 끼리, 같은 episode 안에서, 무작위 seed 고정으로 고른다.

### 비교 대상 (같은 frame · 같은 입력 변형)
- **probe** (`kv_L4_v1`, 그대로).
- **simple rule** — SUBTASK-b `probe.py:101-104` (gripper + ever-closed). prompt 를 보지 않는다.
- **offline strong-rule proxy** — state 의 gripper 값 (= 측정 finger 개도, `|qpos(gripper_finger_l1)|/0.045`) + 이력 (닫힘 지속, 열림 전환). `grasp_latch.py` 는 실행 feedback 이 필요해 offline 으로 못 돌리므로 **proxy 이며 실제 strong rule 이 아니라고 표기**한다.
- **frame-index baseline** — SUBTASK-b controls 의 정의.
- rule 들은 prompt 를 보지 않으므로 C1 에서 원래 phase 를 그대로 낸다. 그 실패는 rule 의 설계에서 오는 것이다. 이를 그대로 보고하되 해석은 하지 않는다.

## 이 STEP 이 답하는 질문
**phase probe 는 instruction 과 이미지가 바뀌면 그에 맞게 반응하는가 (strong decodability), 아니면 state 문자열과 시간 순서에 기대는가?**

## 되돌아올 지점
- C1 에서 place/home frame 의 `pick` 전환이 거의 없으면 probe 는 instruction 을 반영하지 못한다. 이때 HSR 은 "wrong-object" 상황에서 strong rule 보다 나을 근거가 없다. → 검토 문서 §6 채택 기준대로 **보조 구성 요소** 로 둔다. language 민감 probe (원문의 contrastive objective) 는 별도 판정한다.
- C2 에서 예측이 state 를 따르면 HSR 은 사실상 proprio rule 이다. → feature 에서 state token 을 뺀 변형 (image 평균만, 또는 state 를 뺀 text) 을 T48 후속으로 제안한다.
- C0 가 재현되지 않으면 T48 전체를 멈추고 feature 경로 차이부터 찾는다.
- T48b (empty grasp · slip, 16D policy-image re-render parity 필요) 는 T48a 결과를 보고 판정한다.
