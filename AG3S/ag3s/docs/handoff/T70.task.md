> 사용자 판정 (2026-10-29 ~19:40 KST): "목적함수 ablation 으로 단계별로 해치는 항 · 돕는 항을 찾자. 최대한 빨리, run 수는 적당히."

## 0. 왜

- 최종 구성이 쥐지 못한 8 run 에서, VLA 계획이 실행 구간에서 위반이 없는데도 TrajOpt 가 손을 5 mm 이상 옮긴 요청이 마지막 60 mm 의 25 % (쥔 run 15 %) 였다. 예: 회귀 954 t16–18 (위반 0–1.7 mm, 밀림 5–7 mm), 회귀 211 t16–17 (위반 0, 밀림 20 · 11 mm).
- 후보: (가) 꺾임 변화율 항 (`--w-deflection-rate 20`, 직전 실행 꺾임을 이어감) · 연속성 항 (`w_continuity 0.5`, 직전 계획 꼬리에 맞춤) 이 밀림을 다음 요청으로 끌고 감. (나) 실행 구간 뒤 계획 (8–15 행) 의 위반 (look-ahead).
- IFG-TOB 가 954 에서 (가) 를 이미 관찰했다 (회피 꺾임이 다섯 chunk 이어짐). 그 옵션 (`--deflection-rate-after-grasp`) 은 최종 구성에서 쓰지 않는다.

## 1. 구성 (기존 flag 만 — 구현 없음)

| 구성 | 최종 구성 서버 인자에 더하는 것 | 의미 |
|---|---|---|
| 기준 | — (기존 기록 재사용) | 최종 구성 |
| **E1** | `--deflection-rate-after-grasp` | 꺾임 변화율 항을 쥐기 전 (searching · latched · closing) 에는 빼고, 쥔 뒤부터 둔다 |
| **E2** | `--continuity-after-grasp` | 연속성 항을 쥐기 전에는 빼고, 쥔 뒤부터 둔다 |
| **E3** | 두 flag 모두 | 쥐기 전에는 VLA 추종 · 부드러움 · 충돌만 |

- 쥔 뒤 (운반 · 놓기) 의 목적함수는 그대로다 → 허들 회피 동작은 바뀌지 않는다.
- 쥐기 목표 항 · 기하 보정은 최종 구성에서 0 요청이므로 따로 다루지 않는다 (T68).

## 3. 판정 (결과 전 고정)

- 기준값 (최종 구성, 이 8 run): 금지 접촉 없는 성공 **2 / 8**, 금지 접촉 run **1**.
- **통과:** 금지 접촉 없는 성공 ≥ **5 / 8** · 금지 접촉 run ≤ **1** · 성공 2 run 이 둘 다 성공 유지.
- 여럿 통과하면 성공이 많은 쪽, 차이 ≤ 1 이면 바꾼 것이 적은 쪽 (E1 · E2 > E3), 그래도 같으면 E1.
- 통과한 구성은 전체 32 run 으로 확인한다. 채택 (모두 충족): ≥ 23 / 32 · 금지 접촉 run ≤ 3 · 탁자 · 바구니 접촉 0 · 9 장면 ≥ 14 · 허들 ≥ 6.
- 아무것도 통과하지 못하면 32 run 은 돌리지 않는다.
- 주 지표 · 접촉 정의는 T67 §4 와 같다.

## 4. 기전 지표 (보고만, B)

- `t67_mech.py`: 마지막 60 mm 손바닥 밀림 · 닫기 시작 거리 · 위반 없는 밀림 (VLA 계획 실행 구간 위반 ≤ 2 mm 인데 ≥ 5 mm) 요청 수.
- B 병렬 offline: 최종 구성 기록의 "위반 없는 밀림" 32 요청을 꺾임 변화율 끔 · 연속성 끔 · look-ahead 끔으로 재풀이해, (가) · (나) 중 무엇이 밀림을 만드는지 가른다.
