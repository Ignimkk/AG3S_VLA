# T63 — cuRobo v2 TrajectoryOptimizer vs 우리 TO (CCR) 비교 (lead task, 2026-10-20 KST)

STEP 번호 T63 은 2026-10-20 에 peer 세션 3 곳 (development-38 · -f5 · -22) 에 알려 예약했다 (충돌 없음 회신).

## 목적

cuRobo v2 의 trajectory optimization 을 우리 입력 (VLA chunk · AG3S target-excluded ESDF) 위에서 돌렸을 때
어떤 궤적이 나오는지 보고, 우리 목적함수 · 제약을 1–2 개씩 더해 가며 우리 TO (CCR: Constrained Chunk
Refinement, `AG3S/trajopt`) 와 같은 입력 · 같은 지표로 비교한다. 어느 쪽이 낫다고 미리 정하지 않는다.

lead 가 기본 처리로 정하고 사용자에게 알린 것 (이의 없음):
- `esdf_free` 가 없는 chunk (232 / 750) 는 그 chunk 의 main fine layer (+ 상자 밖 coarse) 로 대신하고 따로 집계한다.
- `exclusion.grasp_active` chunk 는 pre-grasp / post-grasp 로 나눠 보고한다 (attached 질의점이 있는 chunk 는 0 개라 skip 0).
- 손가락 열림: 최적화는 chunk 당 한 값 (B0 – B4 공통 한계로 보고). **평가기는 모든 비교 대상에 step 별 served 열림 값을 똑같이 쓴다.**
- self-collision 은 끈다 (우리 TO 에도 robot-robot 행이 없다).

## 사용자 판정 3 (2026-10-21 KST, 단계 2 결과 `T63.impl.md` "단계 2" 를 본 뒤)

| 항목 | 판정 |
|---|---|
| 가중치 scale | **우리 항 전체 (track · continuity · deflection-rate, 그리고 B4 의 target margin 은 제외) 에 같은 배율 λ 를 곱해 λ ∈ {1, 100, 10⁴} 세 값을 돌린다.** λ 는 결과 전에 이 세 값으로 고정한다. λ = 1 은 "baseline 가중치 그대로" 결과다. cuRobo 자체 c-space 정규화 · collision 가중치는 기본값 유지 |
| B4 target 제외 mask | **server record 의 mask** (`--b4-mask record`). 비교 대상인 우리 TO 기록이 실제로 쓴 값 |

lead 기본 처리 (사용자에게 알림):
- 항의 행 범위: cuRobo 가 최적화하는 50 row 전부 (`--term-window chunk`).
- `esdf_free` 가 없는 chunk 의 상자 안 층: "fine 단독" → **우리 TO 와 같은 `min(coarse, fine)`** 으로 바꾼다 (상자 안 row 2.1 % 에서 2.5 mm 넘게 달랐다).
- B4 margin 규칙이 우리 TO 보다 보수적인 점 (target 이 최근접 표면이 아니어도 margin 요구) 은 한계로 보고한다.
- B3 · B4 의 계산 시간이 66.7 ms 를 넘는 것은 offline 비교에서는 보고만 한다 (closed-loop 진입 판정 때 다룬다).

## 단계

### 0. 준비와 parity (gate — 실패하면 1 이후 진행하지 않고 보고)

1. RB-Y1 16D 모델의 cuRobo v2 robot config: **AG3S 가 쓰는 같은 URDF · 같은 collision sphere** (record 의
   `sphere_radii` 270 개와 일치해야 함; cuRobo sphere fit 사용 금지). 최적화 joint 는 우리 TO 와 같게.
2. AG3S ESDF (record 의 `esdf_*` 배열) → cuRobo voxel/SDF world. 기본 cuRobo 에는 **target-excluded 층 하나**
   (`esdf_free_*`) 를 모든 sphere 에 준다 (프로젝트 목적의 "target 제외 ESDF → cuRobo" 와 같은 뜻).
   링크별 층 선택 (LTE) 은 단계 2 의 항목이다.
3. Parity: record 의 `refined_chunk` 를 cuRobo FK · cuRobo collision 으로 재서
   - sphere centre vs record `sphere_centres`: 최대 오차 (mm)
   - sphere 별 signed distance vs record `clearance`: 오차 분포 (median · p95 · max, mm). 허용오차는 그 층의
     `voxel_size / 2` 로 사전 고정하고, 넘는 비율을 보고한다.

### 1. 기본 cuRobo (B0)

- start = 그 chunk 의 `q_now`, goal = `reference_chunk[-1]` (cspace), seed = `reference_chunk`, 그 외 cuRobo
  기본값. 우리 chunk 격자 (15 Hz, 50 step) 로 내보내야 하므로 dt 를 1/15 로 고정할 수 있으면 고정하고,
  안 되면 cuRobo 출력을 15 Hz 로 재샘플한다. **기본값에서 바꾼 설정은 전부 목록으로 남긴다.**

### 2. 우리 항을 1–2 개씩 누적 추가 (B1 → B4)

| 변형 | 추가 항 | 우리 TO 의 대응 |
|---|---|---|
| B1 | step 별 VLA chunk tracking (custom cost; cuRobo cspace cost 는 target 1 개만 받음) | `w_track` |
| B2 | B1 + 이전 refined chunk continuity | `w_continuity` |
| B3 | B2 + deflection-rate · servo accel | `w_deflection_rate`, servo accel rows |
| B4 | B3 + 링크별 거리장 (LTE: Link-specific Target Exemption) · clearance margin | contact policy (`target_field_exclude`, `manipulated_link_margin`) |

가중치는 snapshot `f0d8046` 의 C1aN 시작 로그 (`TO objective`) 값을 그대로 옮긴다. 조정하지 않는다
(조정이 필요하면 멈추고 보고).

### 3. 비교 (offline, 같은 chunk · 같은 평가기)

비교 대상: reference (VLA 원본) · 우리 TO 기록 `refined_chunk` · 우리 TO 재풀이 (`fixed_input_ablation` 경로,
재현 오차 보고) · B0 – B4. **모든 대상을 같은 평가기 (우리 full-resolution field, record 의 contact policy)
로 잰다.** 지표 (사전 고정):

| 지표 | 정의 |
|---|---|
| 명령 궤적 최소 clearance | 실행 구간 (앞 8 step) · plan window 별, mm. 관통 (< 0) chunk 수 |
| VLA 대비 변경량 | TCP 위치 차 mean · max (mm), 실행 구간 · plan window |
| goal error | chunk 끝 joint 차 (rad) · TCP 차 (mm) |
| 운동학 | 속도 · 가속 한계 위반 step 수, jerk (3 차 차분) RMS |
| 계산 시간 | chunk 당 solve ms (cold · warm 분리), 66.7 ms 주기 초과 비율. GPU 시간은 CPU 시간과 따로 적는다 |
| 실패 | solver 실패 · NaN · infeasible 수 |

offline 은 명령 궤적만 잴 수 있다. 실제 궤적 (measured_qpos) 기준 contact 는 closed-loop 단계의 주 지표다.
