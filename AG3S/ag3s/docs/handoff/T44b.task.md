## A3 — I2b: carry 권한 = 쥔 손의 contact link + gripper 바로 이전 link (implementer)

**소유 파일:** `trajopt/linearize.py` (`target_contact_rows_of` 와 그 호출부), 필요하면 `ag3s/constraints/to_adapter.py` 의 권한 기록 부분,
`tests/trajopt/test_t44_target_permission.py` (확장). 다른 파일은 읽기만.

**현재:** `target_contact_rows_of` (`linearize.py:1958`) 는 mask 가 없으면 (relax 또는 **쥐고 있을 때**) `manipulated_link_margin < max` 로
권한을 정한다. carry 에서는 margin 이 모두 같아 권한 행이 0 → strict 가 쥔 손의 행까지 held 잔상에 대해 검사한다 (V-I2-3: 바뀐 행 전부 carry chunk).

**구현:**
1. 쥐고 있을 때 (`attached` 가 있을 때) 의 권한 행 = **쥔 손 (attachment 의 hold link / 측) 의 contact link** (`ContactConfig.contact_links` 의 그 측:
   `ee_<side>`, `ee_finger_<side>1/2`) **+ 그 hold chain 에서 gripper 바로 이전 link** (URDF 에서 `ee_<side>` 의 parent link 를 코드로 찾는다 —
   이름을 하드코딩하지 말고 robot model / URDF 의 parent 관계로. 찾은 이름을 impl.md 에 적는다).
   반대쪽 손 · 나머지 팔 link 는 권한 없음.
2. config: `collision.held_permission_parent_links: int = 1` (gripper 위로 몇 link 까지 허용할지, 0 = gripper 만). 사용자 판정은 1.
3. 이 규칙은 `target_permission_strict` on 에서만 효력 (off bit-identical 유지). 쥐기 전 (approach) 의 권한은 지금 그대로 (`exclude_authorized` mask).
4. relax 모드 (mask 없음, 쥐지 않음) 의 `margin < max` 규칙은 그대로 두되, impl.md 에 그 한계를 다시 적는다.
5. trajopt 쪽에서 "어느 손이 쥐었나" 를 무엇으로 아는지 (snapshot 의 attached 정보 / AG3S summary / `ContactPolicyContext`) 근거 `파일:줄` 을 impl.md 에.

**Unit tests:** 왼손 · 오른손 각각 carry 에서 쥔 손 gripper 행 + parent link 행만 예외, 반대손 finger 와 forearm 은 held 잔상에 대해 검사 · parent 0/1 설정 ·
쥐기 전 동작 불변 · off bit-identical · 왼손 finger 이름 MJCF/URDF 혼동 없음 (URDF 이름 기준).

**산출물:** `T44I2b.impl.md`. 전체 pytest passed 수.

## D-sign — `owned_max_dist_voxels` 3 · 4 재측정 + target-free 내부 부호 진단 (verifier, Opus)

**재측정 (판정 1):** `T44E2.verify.json` 과 **같은 frame 목록** (`outputs/verify/T44/E2/e2_demo_frames.json` 64 frame, `e2_frames.json` fallback 48 frame),
같은 identity mode 두 개, 같은 margin (10 mm) · 같은 고정 기준 ①–④. `ball_owned_remove` 를 `owned_max_dist_voxels` ∈ {2 (재현), 3, 4} 로.
`owned_tie_voxels` 는 1.0 고정. 추가로 잰다: unowned 로 분류된 distractor seed 의 "가장 가까운 관측점 거리" 분포 (fused cloud 기준) 와,
같은 seed 에서 **per-camera (fusion 전) 점** 까지의 거리 분포 — `fusion_voxel_size` (실행 설정값을 확인해 기록) 가 unowned 의 원인인지 가르기 위해.
build ms 는 단독 timing pass 로 (V-E2 와 같은 방식).

**부호 진단 (판정 4):** target-free layer 에서 distractor 내부 voxel 의 음수 비율 0.27 (main 0.80) 의 원인을 가른다. 수정하지 않는다.
- 같은 frame 에서 main fine tier · target-free fine tier · coarse 의 distractor 내부 voxel 부호를 비교. 비율을 다음으로 분해:
  (a) TSDF 관측 상태 (unknown / observed) (b) sign correction (`_force_sign_on_pure_voxels`) 이 건드린 voxel 인가 (c) target-free 조회 합성
  (`curobo_field.target_free_distance` 의 `min(f, max(d, b))`, window 경계) (d) ball 안/밖 (e) seed 제거와 무관하게 tier 를 다시 만드는 과정 (`only="fine"`) 의 차이.
- oracle (GT target seed 만 제거) 도 0.27 이므로 ball/owned 고유 문제가 아닐 가능성이 크다 — 이를 확인하거나 반박.
- **안전 영향:** authorized link (finger) 구 중심을 distractor 내부 몇 점에 둘 때 target-free query 가 양수를 돌려주는가 (main 은?). 몇 건 / 몇 frame.
- skill `curobo-esdf` (함정 5 개) 먼저.

**산출물:** `T44E2b.verify.json`, `figures/t44/t44e2b-*` (실제 scene · graph · table + sidecar), raw `outputs/verify/T44/E2b/`.

## D-merge — 붐비는 장면 cluster merge 원인 진단 (verifier, Opus)

**대상:** E2-demo 64 frame 중 pipeline cluster 가 target 과 다른 과일을 합친 34 frame (+ 합치지 않은 30 frame 을 대조로).
**주의:** E2 harness 의 `gt` 모드 attention 은 **GT Gaussian 합성 attention** 이다 (A1 impl.md). 실제 VLA attention 과 다를 수 있다.

1. 기존 경로를 재사용해 단계별로 어디서 합쳐지는지 가른다: `ground_target` (`target_grounding.py:1611`) 의 cluster grow (connectivity ·
   fusion voxel 12 mm), `split_by_attention` (`attention_split.py:164`) 의 trigger 조건 (어떤 값이 임계 못 넘었나), admissibility.
   frame 별 표: 두 과일 표면 사이 최소 gap (GT mesh), cluster 의 target 비율, split trigger 값과 임계, split 결과.
2. attention 출처 영향: 가능하면 같은 frame 에서 **실제 VLA attention** 으로도 grounding (렌더 RGB 로 `AttentionPolicy` 의 attention pass —
   GPU 1 개 model, 서버 띄우지 않고 offline 호출이 가능하면). 불가능하면 이유를 적고 GT attention 만으로.
3. 원인이 gap < voxel (물리적으로 닿음) 인지, trigger 임계 / connectivity 설정인지, attention 이 두 과일에 걸치는지 분해.
4. **알고리즘 후보 (판정 2):** 진단 결과에 근거해 (a) 기존 split 의 설정/trigger 조정으로 충분한가 (b) 새 분할이 필요한가.
   (b) 이면 후보를 비교 표로 — 예: depth discontinuity / surface normal convexity 기반 분할 (LCCP 류), RGB 색 차이 region split,
   알려진 크기 prior 의 sphere/ellipsoid fitting 분할, attention-weighted min-cut. 각 후보에 대해 이 64 frame 에서의 **간단한 offline 시험값**
   (target 비율 · recall) 을 붙일 수 있으면 붙인다 (코드는 `outputs/verify/T44/merge/` 의 실험 스크립트로만, benchmark 코드 수정 금지).
   실제 pipeline 은 외부 segmenter 를 쓰지 않는다는 전제 (simulator GT 는 평가에만).

**산출물:** `T44M.verify.json`, `figures/t44/t44m-*` (실제 scene: 합쳐진 cluster 와 GT · graph · table + sidecar), raw `outputs/verify/T44/merge/`.
