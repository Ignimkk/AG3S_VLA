## 무엇을 했나 (평이한 요약 먼저)

target-free 계층의 공 제외에 **trace** 를 붙였다 (I0): 공 안 seed 수 · 실제로 지운 seed 의 voxel ijk · 그 프레임이 어느
request 와 어느 target 점 집합으로 지어졌는지 · 행별 권한 vector 가 stats · chunk npz · summary 에 남는다. 그리고
**`ball_owned`** (I1) 를 flag 로 더했다: 공은 외곽 상한으로 두고, 공 안 seed 마다 가장 가까운 target 점과 non-target
관측점의 거리를 비교해 **이웃 물체 쪽 seed 를 보존**한다. 기본 (`ball`) 은 값이 비트 동일하다 (실제 cuRobo 로 HEAD 와 대조).
offline E2 harness (`exclusion_e2.py`) 는 기록 frame · demonstration 자세 · posed-frame JSON 에서 같은 integrator 로
ball / ball_owned(remove·keep) / oracle 네 계층을 만들어 seed · query · 시간을 잰다.

## verifier 가 알아야 할 것

- 새로 생긴 플래그·기본값 변경: 기본값 변경 없음. 새 config `esdf.target_exclusion` (`ball`) · `owned_tie_voxels` (1.0) ·
  `owned_max_dist_voxels` (2.0) · `owned_unowned` (`remove`). 새 CLI `--target-exclusion {ball,ball-owned}` · `--owned-tie-voxels` ·
  `--owned-max-dist-voxels` · `--owned-unowned {remove,keep}` (ball-owned 는 `--target-field-policy exclude-*` 와 함께만).
- 기본 (`ball`) 에서 바뀌는 것은 **기록뿐**: `stats["target_free"]` 새 키 (`exclusion_method` …, `geometry_version`, `classify_ms`),
  `field.exclusion_trace`, `metrics["target_permission"]`, chunk npz 의 `target_free_*` 키, summary `target_exclusion` ·
  `target_permission`. 필드 값 · 행 · verdict 는 같다 (위 GPU 대조 + 단위 test).
- 재생산이 필요한 산출물: 없음 (옛 기록은 새 키가 없을 뿐).
- 옛 기록과 호환이 깨지는가: 없음.
- harness 의 시간: pod 가 붐비면 수백 ms 로 튄다 — `--repeats` 의 각 값이 json 에 있다. V-E2-3 은 조용한 시점에.
- harness oracle 의 정의: GT target 라벨 seed 만 지운다. GT 가 설명하지 못하는 seed (`unlabelled`, 공 안 frame 당 12–27 개 — 어느 물체
  표면에서도 7.5 mm 밖이고 과일 hull 밖) 는 oracle 이 **장애물로 둔다**. 그래서 "oracle 대비 overestimation" 의 일부는 ball 이 이
  유령 seed 까지 지운 몫이다 (ep 677 authorized 구 최대 25–28 mm 가 ball 과 ball_owned_remove 에서 같고 keep 에서 작다).
- harness 의 attention: GT Gaussian 을 **target 을 보는 카메라에만** 싣는다. 모든 카메라에 실으면 target 이 화면 밖인 카메라의 map 이
  정규화로 전부 ≈ 1 이 되어 그 카메라 점 전체가 seed 가 된다 (ep 677 wrist_cam_r → pear/banana 쪽 600 mm).
- 판정이 필요한 설계 둘 (lead · 사용자):
  1. **부호 교정 집합.** task 문구는 "실제로 제거된 index 에만" 인데, `ball` 의 교정 집합은 공 안 voxel **전부** (seed 아닌 target 내부
     포함) 다. 제거된 seed 에만 걸면 target 내부 (TSDF < 0, seed 아님) 가 "다음 표면까지의 음수 거리" 로 남아 손가락이 target 안에서
     큰 음수를 본다. 그래서 `ball_owned` 의 교정 집합 = 제거된 seed ∪ **target 쪽이 확실한 non-seed** (`d_t < d_o − tie`) 로 두었다
     (`_ball_owned_split` docstring). 이웃 물체 내부는 교정하지 않는다 (단위 test 가 음수 유지를 본다).
  2. **`ball_owned` 는 identity 의 완전성에 민감하다.** target 점 집합에서 빠진 관측 target 점은 non-target 증거가 되어 그 근처 seed 를
     보존한다 (LB s128: 완전성 0.83 → recall 0.84 → 0.67). E2 를 `--identity gt` (task 문구: 가장 가까운 cluster) 로 잴지
     `--identity gt_label` (완전) 로 잴지, 또는 둘 다 낼지 정해야 한다.

## 내가 기대하는 결과

<**verifier 는 측정이 끝나기 전에 이 절을 읽지 않는다.**>

붐비는 demo 장면에서 `ball_owned_remove` 가 ball 의 distractor seed 손실을 70–90 % 줄이고 recall 은 1–3 pp 낮출 것 (identity 가

완전한 identity 면 ball 과 같고, cluster 가 target 을 쪼개면 recall 이 크게 떨어질 것. build 시간 증가는 2–5 ms (분류 2–3 ms).
