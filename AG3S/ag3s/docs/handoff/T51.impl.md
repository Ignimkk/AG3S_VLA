## 무엇을 했나 (평이한 요약 먼저)

head 선택을 **사전 고정된 절차** 로 돌리는 study 를 새 파일 다섯 개로 만들었다. 절차는 P1 filter (label 없이 sink · 넓은 map ·
낮은 mass 를 거른다) → P2 calibration (2D lift 로 후보를 줄이고, 줄인 후보만 3D `identity_correct` 로 순위) → P3 episode
bootstrap (1 위 확률 · CI) → P4 nested CV 로 k ∈ {1,2,3} 선택 (차이가 CI 안이면 작은 k) → P5 held-out → P6 ablation 이다.
같은 절차를 **GT label** 과 **grasp-event 자기 label** (쥔 순간의 fingertip 중심을 이전 frame 의 camera 로 투영한 label) 로
각각 돌리고, 두 선택을 비교하는 stage 를 따로 두었다. 3D row 는 (record, source) 마다 cache 되어 모든 stage 와 두 label 이
공유한다 (resumable). **기존 파일은 하나도 고치지 않았다.** GPU 는 쓰지 않았다. MuJoCo 는 smoke 만 돌렸다 (아래).

**LIBERO L0 결론:** KNOWS P0b 수집물은 storage 에 있다 (`datasets/workspace/knows_p0b/`, 40 episode). frame · state · action ·
agent-view GT segmentation · depth 를 담고 있다. 그러나 **cell 별 attention 은 저장되어 있지 않다.** `probe_p0b.py` 는 attention 을
그때그때 계산해 hit rate 만 출력했다. 따라서 **P1–P3 를 storage 만으로 CPU 에서 돌릴 수 없다 → 여기서 멈추고 L1 판정을 요청한다.**
필요한 것은 새 LIBERO rollout 이 아니다. 저장된 frame 위에서 `pi05_libero` 의 attention forward 를 한 번 돌리면 된다 (GPU, 아래
"LIBERO" 절). 그 extraction adapter 와 CPU 쪽 (GT loader, P1–P3 2D) 은 구현했다. GPU 쪽은 실행하지 않았다.

## Stage 정의 (사전 고정 값)

공통: Ω = {query × L2–17 × head 0–7}. query = action token, denoise 0, agg ∈ {`last`, `mean`, `first`} → **384 cell**
(`--t49-dir` 를 주면 `noun_target` 이 더해져 512). L0 · L1 제외. calibration = T47 selection record (`long` · `t2` · `ep1807`),
held-out = `headfix` · `ep1800` (same-scene) · `ep1850` · `ep1900` (new-scene). **episode = record.** `long` 과 `t2` 는 같은 초기
scene (episode 1800) 에서 출발한다 — 독립 episode 가 사실상 2.5 개다.

### P1 filter (`--stage filter`, label 없음, MuJoCo 없음)

calibration 3 record 의 **모든 frame 을 pooled** 하고, cell × camera 마다 계산한다. 정의는 T47b #5 와 같다.
`t47b_sink.map_stats` → `summarize_cells` 를 그대로 호출한다.

| 사유 | 조건 (부등호는 task 표 그대로 strict) | 통계 |
|---|---|---|
| `low_mass` | `mass_median < 0.01` | frame 별 `S_cam` (16×16 합) 의 median |
| `fixed_patch_sink` | `modal_fraction > 0.5` **and** `top1_share_mean > 0.4` | 최빈 argmax patch 의 frame 비율 · max patch / `S_cam` 의 frame 평균 |
| `broad_map` | `top1_share_mean < 0.03` **and** `largest_share_of_grid_mean > 0.15` | 평균 기준 binarize 후 8-connected 최대 component / 256 의 frame 평균 |

- 한 camera 라도 사유가 있으면 그 cell 은 **제외** 다 (P2 는 3 camera 공통 cell 만 쓰기 때문이다).
- NaN 통계는 어떤 사유도 켜지 않는다. 모든 map 이 0 인 cell 은 `top1` 이 NaN 이지만 `low_mass` 로 걸린다.
- 출력: `filter/filter.json` (`eligible` 목록, `excluded[cell][camera] = [사유]`, 사유별 · camera 별 개수, `marked` = L8H2 · T47 oracle3 ·
  논문 top-3 의 camera 별 4 통계와 판정), `filter/filter_arrays.npz` (`<query>__<통계>` (16, 8, 3), `<query>__reason__*`, `<query>__eligible` (16, 8)).
- **L8H2 가 제외되는지는 결과에 나온다 (`marked.l8h2`).** threshold 는 다시 맞추지 않는다.

### P2 calibration (`--stage score2d --label {gt,self}` → `--stage score3d`)

**2D (score2d):** cell 마다 record 안의 kept (frame, camera) sample 에서 T47 `map_scores` 의 `lift` · `peak_on_target` · `target_mass`
평균을 낸다. 그다음 record 사이의 **가중 없는 평균** 을 낸다.
- `gt`: T47 GT cache 의 `class_cov`. keep = target ≥ 200 px (480×640, T47 관례).
- `self`: 자기 label disc coverage `[self, 1−self]`. keep = grasp 이전 frame **이고** 투영 disc 의 image 안 면적 ≥ 200 px.

**2D → 3D 선별 규칙 (`preselect`, 사전 고정):**
1. P1 eligible cell 을 calibration 2D lift 내림차순으로 정렬한다. 동점이면 2D `peak_on_target` 내림차순, 그다음 Ω index 순이다.
2. **상위 16 개** 를 고른다.
3. **forced** = `last:L8H2` + T47 oracle top-3 (`last:L8H3` · `last:L10H7` · `last:L12H4`, T47 `validate/oracle.json` d0_last 에서 읽음) 를 더한다.
4. 3D 를 돌리는 집합은 `top ∪ forced` 다. 순위를 다투는 집합 (`ranked_set`) 은 `top ∪ (P1 을 통과한 forced)` 다.
   P1 에 걸린 forced cell 은 3D 점수만 보고하고 순위에는 넣지 않는다.
   forced 가 이미 top-16 안에 있어도 채워 넣지 않는다. 그래서 집합은 20 개 이하다.
5. **누수 방지:** P4 의 모든 training set (outer LOEO 3 개 + inner 3 개 = 6 개) 마다 **그 training record 만으로** 같은 선별을 다시 한다 (`folds`).
   3D 후보 `candidates_3d` = global ∪ 모든 fold 선별의 합집합이다. smoke 로 확인한 gt 후보 수는 25 개다 (cell 이름은 보지 않았다).

**3D (score3d):** 후보 cell 마다 raw (σ=0) 단일 cell map 을 3 camera 에 붙인다. 그리고 live 서빙 경로 그대로 grounding 한다
(T47b 와 같은 loop, `serve_safe.build_ag3s` 기본값, subtask gate off, legacy ESDF, source 마다 별개 AG3S).
row 에는 T47 field, `frame_b2` (ball 없음), 자기 label field 가 들어간다.

| 지표 | 정의 (record 안 frame pooled → record 가중 없는 평균) |
|---|---|
| **primary (gt)** `gt_identity` | `identity_correct` (T47b: chosen cluster 의 label 있는 점 중 엄격한 다수 class 가 target) 의 비율, **모든 frame** |
| **primary (self)** `self_identity` | `self_identity_correct` 비율, **자기 label 이 있는 frame (grasp 이전) 만** |
| 비교용 `gt_identity_on_self_frames` | GT identity 를 자기 label frame 에서만. label 잡음과 frame 부분집합 효과를 가르는 데 쓴다 |
| 보조 | `on_target` · `purity_mean` · `nontarget_seed_loss_per_frame` · `other_object_loss_per_frame` · 2D `lift` · 2D `peak_on_target` |

순위 (`ranking_3d`): primary 내림차순 → 동점이면 calibration 2D lift → Ω index.
출력: `<label>/score2d/{score2d.json, score2d_arrays.npz}` (2D heatmap 용 `(E, Q, 16, 8)`), `<label>/score3d/{score3d.json, score3d_arrays.npz}`.

### P3 안정성 (`--stage bootstrap --label`)

- 단위 = **record (episode)**. E = 3 이다. `numpy.random.default_rng(5103).integers(0, E, (1000, E))` 로 resample 한다.
  resample 마다 cell 별 평균 (NaN episode 는 건너뛴다) 을 내고 `rank_order` 로 순위를 매긴다 (동점은 그 resample 의 2D lift 평균, 그다음 Ω index).
- 출력: cell 별 `p_rank1`, `p_top3`, 95 % percentile CI, full-sample 순위, `rank1_tied_rate`.
  `stable_single_cell` = full-sample 1 위의 `p_rank1 ≥ 0.5` 다 (task 되돌아올 지점의 기준).
- **episode 가 3 개라서 distinct resample 은 10 개뿐이다.** B = 1000 Monte-Carlo 는 이 작은 이산 분포에서 뽑은 것이다.
  그래서 **27 개 ordered resample 전부의 exact 확률** (`exact_p_rank1` · `exact_p_top3`) 을 함께 낸다.
- exploratory: `--unit block:N` 은 record 안의 연속 N frame 을 한 단위로 본다. 사전 고정이 아니므로 판정에 쓰지 않는다.
  출력은 `bootstrap__blockN.json` 이다.

### P4 k 선택 (`--stage ksel --label`)

- `cv_scores`: LOEO 다. test record 마다 나머지로 순위를 매긴다 (그 fold 의 2D 선별 ∪ forced, 3D primary 평균).
  top-k cell 을 **raw 합** 한 map 으로 test record 의 primary 를 잰다. k>1 합은 필요한 것만 replay 한다.
  `required_pairs` 가 실행 전에 목록을 확정한다 (outer 3 fold × k 2 개 + inner 6 fold × k 2 개, 중복 제거 후 18 개 이하).
- `choose_k` (사전 고정 단순성 규칙):
  1. best = CV 평균이 가장 큰 k 다 (동점이면 작은 k).
  2. 작은 k 부터 차례로, 쌍 차이 `score[best] − score[k]` (같은 test record 끼리) 의 bootstrap 95 % CI 를 잰다 (seed 5104, B=1000).
  3. CI 하한 ≤ 0 인 첫 k 를 고른다. 없으면 best 를 쓴다.
- `nested_cv`: outer test record 마다 나머지 2 record 안에서 inner LOEO 와 `choose_k` 로 `k_inner` 를 정한다.
  outer 점수 = 그 outer fold 의 top-`k_inner` 를 test 에서 잰 값이다 (`nested_mean`). fold 별 `k_inner` 도 낸다.
  inner fold 는 1 record 로 순위를 매기고 1 record 로 평가한다 (E = 3 의 한계).
- **최종 선택** = 전체 calibration 순위의 top-k\* 다 (`selected.combo`). `single_head_fixed` = (k\* == 1) 이다. `cv_mean_ci95` 에 k 별 CV 평균 CI 를 낸다.
- 누수 없음은 unit test 로 확인했다. test unit 의 점수를 뒤집어도 그 fold 의 선택이 같다. 모든 순위 호출은 test unit 을 포함하지 않는다.

### P5 held-out (`--stage heldout`) · P6 ablation (`--stage ablation`) · 비교 (`--stage compare`)

- P5: `last:L8H2` 와 label 별 선택 combo 를 held-out 4 record 에서 잰다. **항상 GT identity 로 채점한다** (자기 label 로 고른 cell 도 GT 로 잰다).
  record 별 값, same/new scene 평균, `t47b_metrics.summarize` (scene × phase strata) 를 낸다.
  **parity**: T51 `last:L8H2` row 와 T47b `e2e/rows__<key>__s0.jsonl` 의 `l8h2` row 를 field 별로 대조한다.
- P6 (held-out, GT) 비교 대상:
  - `paper3_s0` (T47 공통 top-3 L4H1·L2H0·L14H5 raw 합 σ=0)
  - `paper3_s1` (같은 head set, σ=1 = T47 사전 고정 primary)
  - `headavg` (last, L2–17 128 cell 평균)
  - `oracle3_t47` (T47 GT-oracle top-3 raw 합)
  - **무작위 20 개**: P1 eligible cell 에서 k\*(gt) 개씩, seed 5106 으로 뽑는다. k\*=1 이면 단일 cell 이다.
  - **restricted oracle**: GT 3D 후보 (global 선별 ∪ forced) 중 held-out 에서 가장 좋은 단일 cell 이다.
    held-out 에서 고른 것이므로 상한 참고값이다. 384 cell 전부를 held-out 에서 돌리면 약 6 시간이라 이 정의를 택했다.
  - L8H2, 선택 (gt), 선택 (self)
- compare:
  - P2 top-1 일치, top-3 겹침
  - 서로의 1 위에 대한 bootstrap `p_rank1`
  - k\* 와 combo 의 일치
  - held-out GT identity 의 record 별 차이 (self 선택 − gt 선택)
  - 자기 label 투영 오차 요약
  - GT top-3 의 `gt_identity` · `gt_identity_on_self_frames` · `self_identity`
- annotate (되돌아올 지점, exploratory): GT 3D row 에서 calibration frame n 개 (5 · 10 · 20 · 40 · 80 · 120 · 전부) 를 비복원으로 뽑는다 (B=1000).
  뽑은 frame 으로 다시 순위를 매겨 full-data 1 위와 같을 확률, 1 위가 full top-3 안일 확률을 낸다.

## 자기 label 생성기 (`t51_selflabel.build_selflabel`)

| 단계 | 정의 |
|---|---|
| pose | T47 replay 와 같은 `policy_record.pose_scene` (기록 qpos · qvel → `mj_forward`). render 는 하지 않는다 |
| 접촉 | target body 와 접촉한 body 집합이다 (`data.contact`). `both_contact` = 한 손의 finger body 둘 (MJCF `ee_finger_{l,r}{1,2}`) 이 모두 닿음. `held` = `both_contact` 이고 table · crate 가 닿지 않음 (T48b predicate, `t48b_scene.py:40-44, 330-343` 와 같은 정의를 **독립 구현** — T48b 파일은 아직 작성 중이라 import 하지 않았다) |
| **grasp 시점** (기본 `both_contact`) | 한 손의 두 finger 가 처음 target 에 닿은 frame. **단 그 손이 이후 `held` 상태가 되는 경우만** 센다 (실제로 들어 올린 grasp). 변형 `--event held` = 첫 `held` frame (들어 올린 뒤라 latch HELD 에 가깝다) |
| fingertip 중심 | 그 frame 에서 그 손 두 pad 의 중점이다 (pad = finger body 의 가장 큰 collision geom, `t48b_scene.pad_midpoint` `:571` 과 같은 정의). 두 finger 를 대칭으로 쓰므로 MJCF/URDF 왼손가락 이름 swap (T43 OC) 은 무관하다 |
| 물체 반지름 | `0.5 × pad 중심 간격 − pad 두께의 반` (pad geom size 의 최솟값), [1.5, 6] cm 로 clip 한다. 실물에서는 gripper 개도에 해당한다 |
| labeled frame | grasp frame **이전** frame 전부다 (`labeled[:g] = True`) |
| 투영 | world 점 → frame 마다 base (base 는 움직일 수 있다) → camera. `TransportScene.intrinsics` · `T_base_cam` (OpenCV, 480×640 = GT cache · attention lifting 과 같은 frame) 을 쓴다. 반지름 px = `f r / z`. `z ≤ 2 cm` 면 투영하지 않는다 |
| 16×16 label | 반지름 px 의 disc 를 stride 2 (240×320) 로 rasterize 하고, patch (15×20 sample) 마다 평균해 `self_cov` 를 만든다. `self_px` = image 안 disc 면적 (480×640 px) |
| 3D label | labeled frame 의 base 좌표 grasp 점, ball 반지름 `r_obj + 0.02 m`. `self_identity_correct` = chosen cluster 점 중 ball 안이 **엄격한 과반** 이다 (자기 label 은 target / 비target 두 class 뿐이라 plurality 대신 과반을 쓴다) |
| **GT 점검 (sim)** | `proj_err_px` = 투영점과 GT target pixel 중심 (T47 GT cache `label_small`, target ≥ 200 px 일 때) 사이 거리 (480×640 px). `hit_pixel` = 투영점이 GT target pixel 위인가. `hit_patch` = 그 patch 의 GT target coverage > 0.05 인가 |

> writer: implementer (A1) · 원인: T51 verifier 보고 — `T51.task.md` "판정 보완 → 집계 단위" 는 P2 점 추정을 **scene 평균** (같은 scene 의 run 을 먼저 평균한 뒤 scene 끼리 평균) 으로 사전 고정했는데,

**평이한 요약.** 새 CLI 옵션 `--aggregate {record,scene}` 을 넣었다. **기본값은 `record` 이고, 기본 동작과 출력은 바뀌지 않는다** (지금 돌고 있는 T51 verifier 의 stage 와 같은 결과).

3D row cache (`rows/`) 는 집계와 무관하므로 공유한다.

### verifier 가 다시 돌릴 명령 (`--aggregate scene`, T51 run 에서, 현재 record 실행이 끝난 뒤)

```bash
cd /mnt/dev/AG3S_VLA-development
source scripts/setup/env.sh
export AG3S_RUN_DIR=<T51 run>          # 예: /mnt/dev/AG3S_VLA-storage/results/development/20261012T180318+0900_28b981600bf7_852011fdcae0
T51="env MUJOCO_GL=osmesa PYTHONPATH=${AG3S_PROJECT_ROOT} ${AG3S_PROJECT_ROOT}/.venv-ag3s/bin/python -m AG3S.ag3s.experiments.studies.t51_study"
Lc="env PYTHONPATH=${AG3S_PROJECT_ROOT} ${AG3S_PROJECT_ROOT}/.venv-ag3s/bin/python -m AG3S.ag3s.experiments.studies.t51_libero"

# P2a: 2D 선별 (global + scene fold) 을 scene 평균으로 → gt|self/score2d/score2d__scene.json
$T51 --stage score2d --label gt --aggregate scene;  $T51 --stage score2d --label self --aggregate scene
# P2b: 새 후보만 replay (record 실행의 rows/ 는 그대로 재사용) → score3d__scene.json
$T51 --stage score3d --aggregate scene --workers 2
# P3 (--unit scene 이 기본, 필수) → bootstrap__scene.json
$T51 --stage bootstrap --label gt --aggregate scene;  $T51 --stage bootstrap --label self --aggregate scene
# P4 → ksel__scene.json (scene 선택이 다르면 새 combo 를 replay 한다)
$T51 --stage ksel --label gt --aggregate scene --workers 2;  $T51 --stage ksel --label self --aggregate scene --workers 2
# P5 · P6 → heldout__scene.json · ablation__scene.json
$T51 --stage heldout --aggregate scene --workers 2
$T51 --stage ablation --aggregate scene --workers 2
$T51 --stage compare --aggregate scene;  $T51 --stage annotate --aggregate scene
# LIBERO (task 단위 점 추정 · bootstrap) → libero/score2d__task.json · score2d_arrays__task.npz · bootstrap__task.json
$Lc --stage score2d --aggregate task;  $Lc --stage bootstrap --aggregate task
```

- record 실행과 같은 run 에서 돌려도 된다: 모든 출력 이름이 다르다 (`__scene`). 순서 의존은 record 와 같다 (`score2d` → `score3d` → `bootstrap`/`ksel` → `heldout`/`ablation` → `compare`).
- **MuJoCo replay 가 늘 수 있다:** scene 평균 2D 선별이 record 선별과 다르면 `score3d` 가 새 후보를, scene fold ranker 가 다른 combo 를 고르면 `ksel` 이 새 (combo, record) 를 replay 한다. 이미 있는 row 는 다시 돌지 않는다.
- `--aggregate scene --unit record|block:N` 은 CLI 가 거절한다 (scene 평균은 scene resample 과만 짝이 맞다).

### lead 확인이 필요한 것

- 앞 절의 "lead 확인 1" (P2 = record 평균) 은 이 수정으로 바뀐다: 사전 고정 정의는 `--aggregate scene` 이다. **판정에 어느 출력을 쓸지 (scene) 는 lead 가 정한다.** 기본값은 진행 중인 verifier 때문에 `record` 로 두었다.
- `ablation__scene` 의 무작위 분포 · restricted oracle 을 held-out scene 평균으로 바꾼 것은 구현자가 정했다 (P2 와 같은 원칙). held-out 은 record 단위 표 (task #5) 도 계속 낸다.
