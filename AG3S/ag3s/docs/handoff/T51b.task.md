# T51b — head 선택 protocol 에 명사 query 행을 추가: action query 와 같은 기준으로 비교

> writer: lead (A0) · 2026-10-12 KST · 읽는 쪽: implementer, verifier · 로그: `AG3S_T47_LOG.md`
> 사용자 판정 (2026-10-12, T49 결과 후): **T51b 로 추가.** 진행 중인 T51 (action query) 은 그대로 끝낸다. 같은 protocol (`T51.task.md` 의 P1–P6 · threshold · scene 단위 집계) 을 **명사 query 행** 에 돌려 두 query 를 같은 기준으로 비교한다.
> 승인 범위: offline GPU prefix pass (server 없음, GPU lock) — 추가 calibration run 의 명사 attention 추출.

## 왜 지금 이것인가

- T49: 명사 query 는 instruction 을 따르고, 잡은 뒤에도 target 에 머물고, target 과 목적지를 따로 준다. 단 3D `identity_correct` 는 L8H2 보다 낮았다 (T49b 가 σ · k 를 확인 중).
- T51 의 후보 Ω 는 지금 action query 만 담고 있다. `T51.task.md` 는 "T49 결과가 나오면 명사 token 행도 같은 Ω 에 추가한다" 고 예고했다.
- `t51_study.py` 는 `--t49-dir` 로 명사 행을 받는다 (`t51_study.py:122-149`). 그러나 **추가 calibration run (ep0 · ep500 · ep1200) 에는 명사 attention 이 없다** (`:142` 에서 막힌다).

## 구현 (→ implementer, Opus)

- T49 의 명사 추출 (`t49_noun_query_extract`) 을 **ep0 · ep500 · ep1200** 에 돌릴 수 있게 한다. T51 확장의 record 정의 (`t51_records.py`) 를 쓰고, 출력은 T51 run dir 의 `verify/T51b/noun_extract/` 에 둔다.
- `t51_study` 가 T47 record 의 명사 행 (T49 run dir) 과 추가 run 의 명사 행 (T51b 출력) 을 함께 읽도록 한다.
- **고칠 수 있는 파일:** `t51_*.py` · `tests/ag3s/test_t51_*` (T51 소유, uncommitted) 와 새 `t51b_*.py`.
  **T51 verifier 가 지금 `t51_*` 를 실행 중이다** → 기존 함수의 동작을 바꾸지 않는다. 새 인자 · 새 파일로만 추가한다.
  `t49_*` 는 읽기만 한다.
- GPU 는 쓰지 않는다 (추출은 verifier 가 한다). unit test 는 합성 data 로 한다.

## lead 판정 (T51b.impl.md ★ 두 항목 · 결과 전 고정, 2026-10-12)

- **명사 단독 Ω 의 3D 강제 포함 cell** = T49 primary 명사 cell **L8H6 · L5H4 · L4H2**. T51 이 서빙 L8H2 와 oracle 3 개를 강제 포함한 것과 같은 원칙으로, 비교 기준이 되는 cell 을 넣는다. 합친 Ω 에서는 T51 의 강제 cell 에 이 3 개를 더한다.
- **(c) 비교의 통계:** primary 는 **scene 단위 paired 차이** (scene 평균 `identity_correct` 의 차) 와 scene bootstrap 95 % CI 다. frame 단위 McNemar 는 frame 을 독립으로 세므로 **참고값으로만** 보고한다.
