## 무엇을 했나 (평이한 요약 먼저)

`serve_safe --fm-guide` (기본 꺼짐) 를 넣었다. 켜면 요청마다 VLA 를 지금처럼 한 번 샘플링하고, TrajOpt 가 reference (VLA chunk) 의 위반 `reference_violation` 을 재서 **위반 > 0 일 때만** VLA 를 같은 관측 · 같은 noise 로 다시 샘플링한다. 다시 샘플링할 때 flow 단계마다 x0 예측 (`x_t − t·v_t`) 의 충돌 비용 (TrajOpt 가 이 요청에 쓰는 같은 linearizer · scene · 행의 `½ Σ max(0, −clearance)²`) gradient 로 `x_next` 를 민다. 유도한 chunk 의 위반이 원래보다 낮으면 그것을 TrajOpt reference 로 쓰고, 아니면 원래 chunk 를 쓴다. TrajOpt · HOLD 판정 · gripper 열 (사실은 TrajOpt 가 소유하지 않는 모든 열) 은 그대로다. 위반 ≤ 0 인 요청은 켠 서버에서도 꺼진 서버와 bit 동일하다.

**task 와 다르게 한 것 두 가지 (lead 확인 필요)**
1. 첫 샘플링에 `policy.infer(obs, noise=…)` 를 **넘기지 않는다.** noise 를 넘기면 값은 같아도 컴파일되는 그래프 (noise 를 그래프 안에서 뽑느냐 입력으로 받느냐) 가 달라 수치가 미세하게 바뀔 수 있다. 대신 `infer` 직전에 정책 key 에서 그 요청의 noise 를 **읽기만** 한다 (`fm_guide.peek_noise`: `Policy.infer` 가 `split` 해서 쓰는 바로 그 sample key 로 `jax.random.normal`). `infer` 호출은 꺼짐과 글자 그대로 같다. GPU smoke 에서 확인: 유도 scale 0 으로 다시 샘플링한 chunk 가 원래 chunk 와 **0.0 rad 차이** (noise 와 loop 구현이 모두 맞다는 뜻), 위반 없는 앞 20 chunk 의 `reference_chunk` 가 T88 P0 (같은 장면 · 같은 seed) 와 max|Δ| = 0.0.
2. 배선을 `sqp.py` 가 아니라 **`TrajOptChunkRefiner.refine`** 에 뒀다 (`sqp.py` 는 안 건드렸다). 이유: reference 를 바꾸는 일이라 lookahead gate (`_lookahead_gate`) · `_solve_window` · IFG-TOA anchor · multi-seed 가 **모두 같은 (유도된) reference 를 보려면** `solve` 진입 전에 바꿔야 한다. refine 은 `scene_fn` 직후라 scene · q_now · finger path · 형상이 TrajOpt 가 곧 쓸 것과 같고, 위반 정의는 `sqp._solve` 944–947 줄의 두 호출을 그대로 옮겼다 (lookahead 면 `step_clearances[:lookahead_from].min`, 아니면 `full_violation`). window 최적화기는 유도 hook 을 받지 않는다 (바깥에서 한 번).

### 비용 · gradient · 갱신 (`fm_guide.py`)
- 비용 `C = ½ Σ_rows max(0, −value)²`, 행 = `CollisionLinearizer.linearize(trajectory, q_now, scene, optimizer.config)` 이 고른 행 (접촉 허용 · 바닥 띠 · 쥔 물체 · lookahead 규칙은 linearizer 안에 있다). gradient `dC/dq = −Σ max(0,−value)·∂value/∂q`, 열 배치는 `layout.action_columns` (그 밖 열 · planned 밖 스텝은 0).
- 사상: 정책의 실제 output transform (unnormalize → delta→absolute → 16 slice) 을 `x=0`, `x=1`, 무작위 `x` 에서 평가해 `offset + scale·x` 로 놓고 **무작위 x 잔차가 1e-4 이하인지, 행마다 scale 이 같은지를 요청마다 검사**한다 (아니면 `FmGuideError` → 해당 요청은 유도 없음 + 기록 `error`). test 에서 중심차분으로 대각 scale 과 일치함을 보였다 (`test_output_affine_diagonal_scale_matches_finite_difference`).
- 한 flow 단계: `x̂0 = x_t − t·v_t` → 물리 chunk → 오라클 gradient `g_phys` → `g_x = scale ⊙ g_phys` → `dx = −λ·g_x` → 물리 변화 `scale⊙dx` 를 열마다 ±`max_step_rad` 로 clip → `x_next += dx`. 적용 단계 = 마지막 `steps` 개.
- 결정 (`guide_reference`): 위반 ≤ 0 → 반환 chunk 는 **같은 객체**. 위반 > 0 → 재샘플, **`layout.action_columns` 열만** 받고 (gripper · 고정 관절 · padding 은 원래 chunk 값), 위반이 낮으면 사용. 재샘플이 예외를 내면 원래 chunk + 기록 `error`.
- 오라클은 context manager: `esdf_host_mirror` 를 `_solve_standard` 처럼 하고, `linearize._CLEARANCE_SIDE_ATTRS` (linearizer 가 호출마다 남기는 기록 속성) 를 끝에서 복원한다. 그래서 곧 도는 solve 는 유도 없는 서버와 같은 상태에서 시작한다.

## 구현 방식: Python loop vs pure_callback — 측정과 선택

둘 다 구현했다 (`GuidedSampler` = loop, `CallbackSampler` = `Pi0.sample_actions(guidance_xv_fn)` + `jax.pure_callback`). 같은 요청에서 같은 설정으로 (GPU smoke, H200, **공유 lock 에서 잰 값이라 절댓값은 거칠다**):

| 요청 (t_step) | loop (ms) | pure_callback (ms) | chunk 차이 |
|---|---|---|---|
| 20 | 512 | 735 | 0.0 rad |
| 26 | 346 | 364 | 0.0 |
| 27 | 336 | 357 | 0.0 |
| 32 | 349 | 489 | 0.0 |

**loop 를 골랐다.** 항상 같거나 빠르고 (+0 ~ +44 %), 두 구현의 결과가 비트 단위로 같다. 이유: callback 은 compiled while 안에서 매 단계 device 동기화를 하고, 요청마다 달라지는 closure 를 공유 holder 로 전달해야 해서 (재컴파일을 피하려고) 상태가 숨는다. loop 는 단계마다 필요한 `(x_t, v_t)` 만 host 로 가고, 앞쪽 `first_guided` 단계는 host 일을 아예 건너뛰며, 요청별 closure 를 그대로 쓴다.

지연 (loop, 공유 lock): 10 단계 유도 요청 ≈ 330–510 ms (대부분 단계당 ≈ 30 ms 의 오라클: FK + Jacobian + ESDF 질의 + 한 단계 VLA suffix pass), **마지막 5 단계만 유도 ≈ 220–300 ms.** 켠 서버는 위반 여부와 상관없이 **모든 요청에 위반 검사 1 회**를 더한다: `check_ms` 중앙값 28 ms (18–81, n = 36). 정확한 지연 중앙값은 lead 가 독점 lock 에서 잴 것 (task §4-4).
