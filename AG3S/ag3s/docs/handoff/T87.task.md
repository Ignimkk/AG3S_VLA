- "판정 대기 중인 것은 그 기능 자체가 성능이 안 좋은 건지, 다른 모듈이 간섭해서 성능이 안 좋은 건지 비교할 수가 없어서 판정을 못 하고 있던 것."
- 지금까지 기록 (T78 · T80 · T83 · T84 · T84 강한 규칙) 은 모두 옛 3 단계 gate + HSR6 단계 판정으로 돌았다 (`--hsr5` 를 넣지 않음 — lead 실수). 채택한 HSR 은 5 단계 (`--hsr5`, T77 · T82) 다.
- 알려진 간섭원:
  1. HSR 단계 오판 → 규칙 ② · ④ 가 엉뚱한 때 켜지고 꺼짐 (T85: 허들 954 손 밀림은 분류기 오판이 원인).
  2. 기하 grasp 보정 (G1): 단계가 grasp 로 맞게 들어가면 작동해, 충돌 위반 0 인 요청에서 팔을 8–11° 꺾어 쥐기 실패 (세션 ce, T85 기록 허들 850 · 119). 최종 구성에서는 ④ 때문에 작동 0 이었다.
  3. closed-loop 민감도: 0.55° 차이로 VLA 재시도가 갈림 (회귀 954 진단) → run 1 회 성공 수로는 기능 효과를 못 가름.

## 1. 구성 (모두 같은 snapshot `snapshot_t84`, 같은 10 장면 · seed = T84 kit k0)

- **기준 B0** = T84 꺼짐 서버 인자 − `--surface-hull-fill --surface-memory-target-sticky` − G1 (`--geo-grasp --geo-goal-mode correct --geo-track-scale 0.25 --geo-continuity-off`) + `--hsr5` (`--hsr6-*` 4 flag 는 규칙 스위치로 둔다 — `--hsr5` 가 그 단계 입력을 5 단계로 바꾼다, T82 §2).
  - 즉 표면 추출 (overlap 검사 · 직전 영역 유지 · 쥔 뒤 고정 · 공 없음 · GPU) + 5 단계 HSR + 규칙 ①–④ + E0 TrajOpt (쥔 뒤 꺾임 · 연속성) + 이웃 접촉 허용 (손가락 20 · 손바닥 10).
- **한 기능씩 더하기:** B0+H (`--surface-hull-fill`) · B0+S (`--surface-memory-target-sticky`) · B0+A (`--surface-contact-allowance-mm 10`) · B0+V (`--target-vacancy-release` + T81 값: δ 20 mm · p_empty 0.45 · p_present 0.30 · min 20 · samples 200) · B0+HS (= T84 꺼짐 − G1 + `--hsr5`).
- G1 은 이번 비교에서 끈다 (간섭원 2). G1 을 켠 효과는 따로 잰다 (이 STEP 밖).

## 2. 두 층의 측정

### 2.1 closed-loop (exclusive lock, 서버 1 개)

- 6 구성 × 10 run (seed k0). 그 뒤 seed k1 (끝자리 4) 을 같은 6 구성으로 이어 돌린다 (총 120 run).
- 주 지표: 금지 접촉 없는 성공 (실제 MuJoCo, T84 outcome 도구 그대로).
- **실패 첫 사건 분류 (기능 탓 대 다른 모듈 탓):** 실패 run 마다 MuJoCo 재생으로 처음 일어난 사건 하나를 고른다.
  - (a) 닫기 시도 없음 / 손바닥–사과 60 mm 밖에서 닫음 → VLA 쥐기 시도
  - (b) 닫았는데 사과가 안 들림 (두 손가락 접촉 없거나 상승 < 20 mm) → VLA 쥐기 시도 · 손 위치
  - (c) 쥐기 창에서 서버 HOLD 가 3 요청 이상 연속 → HOLD 이유의 점이 정답 target 표면이면 "target 못 지움" (LTE 기능 몫), 로봇 · 이웃 · 장애물이면 다른 원인
  - (d) 쥔 뒤 금지 접촉 → 접촉 link · 상대
- 기능 몫 지표 (closed-loop 안): 쥐기 창의 남은 target voxel 비율 (바닥 띠 제외) · 잘못 지운 voxel (정답 이웃 · 탁자 · 바구니) 수 · 쥐기 창 HOLD 요청 수.

### 2.2 고정 입력 재생 (shared lock) — 다른 모듈 간섭 없는 기능 자체 효과

- B0 closed-loop 기록 (k0) 의 입력 (`--record-inputs`) 을 그대로 서버에 다시 넣어, 요청마다 B0 · +H · +S · +A · +V 의 거리장 · TrajOpt 결과를 계산한다 (T78c 재생 harness `t78de_run.py` 방식). 입력이 같으므로 차이는 그 기능 하나 때문이다.
- 지표: (1) 쥐기 창 남은 target voxel 비율 (바닥 띠 제외) 과 손가락 접촉 부분의 남은 voxel, (2) 기능이 추가로 지운 voxel 의 정답 분류 (사과 · 이웃 · 탁자 · 바구니 · 빈 곳), (3) TrajOpt 결과 차 (손바닥 위치 · 관절), (4) verdict 가 HOLD ↔ 실행으로 바뀐 요청.
- V 는 거리장 기능이 아니므로 재생 대신 T81 의 이동 기록 (T8182 r2 의 앞 · 뒤 이동 run) 으로 따라가기 지연 · 잘못 놓음을 다시 잰다 (이번 HSR 5 단계 closed-loop 의 V 결과와 함께 보고).

## 3. 판정 (결과 전 고정)

- **기능 자체가 좋다:** 재생에서 (1) 쥐기 창 남은 target voxel 중앙값이 B0 대비 줄고 (2) 추가로 지운 voxel 중 이웃 · 탁자 · 바구니 ≤ 5 %.
- **closed-loop 에서 기능이 해롭다:** 그 구성의 실패 중 첫 사건이 (c) "target 못 지움" 또는 기능이 지운 voxel 과 관련된 (d) 인 run 이 B0 보다 늘었다.
- **다른 모듈 간섭:** 실패 첫 사건이 (a) · (b) · (c 의 비 target) 이면 기능 몫이 아니다 — 그 층 (VLA · CCR · HSR) 을 적는다.
- 성공 수는 20 run (k0 + k1) 으로 보고하되, 차이 ≤ 2 run 은 "구분 못 함" 으로 적는다.
- 채택 여부는 결과를 보고 사용자가 정한다.

### 3.1 결과 전 변경 (2026-11-02 KST, 집계 전 — 사용자 판정을 세션 ce 가 전달)

- G1 (기하 grasp 보정) 은 이후 모든 단계에서 끈다 → 이 STEP 은 처음부터 끔 (변경 없음).
- **평가 정의:** 쥐는 순간 쥐는 손 (손가락 · 손바닥 body) 이 target 에 붙은 이웃에 닿는 것은 금지 접촉 (실패) 으로 세지 않고 따로 센다.
  - 창 = 정답 쥠 (두 손가락이 사과에 닿고 사과가 첫 요청 대비 20 mm 이상 상승) 이 처음 성립하기 전 step 이고 쥐는 손 손바닥 site – 사과 중심 ≤ 60 mm.
  - 붙은 이웃 = 그 step 에 MuJoCo 표면 표본이 사과 표면 표본에서 10 mm 안에 있는 이웃 물체.
  - 표에는 "쥐는 순간 붙은 이웃 접촉 (실패로 안 셈)" 열로 run 수 · step 수를 낸다. 이 창 밖의 이웃 접촉 · 쥐는 손이 아닌 링크의 접촉은 그대로 금지 접촉이다.
  - 창 · 거리 값은 세션 ce 의 다음 task 정의와 다르면 그쪽 값으로 다시 내고 차이를 적는다.
  - **2026-11-03 변경 (집계 전, 세션 ce 판정 D2 — 사용자 위임, 사용자 검토 대기):** "붙은 이웃" 거리 조건 (10 mm) 을 뺀다. 창 안에서 쥐는 손이 **이웃 과일** 에 닿는 접촉은 거리와 상관없이 실패로 세지 않는다. 장애물 (기둥 · 허들) 접촉은 그대로 금지. 이유: 같은 문지름이 간격 10 / 11 mm 로 갈림 (T84 강한 규칙 run 회귀 954 검증). 코드: `agg/grasp_contact.py` (`T87_ATT_MM` 기본 inf, 10 이면 앞 정의).
