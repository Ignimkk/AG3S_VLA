## 범위 변경 (사용자 판정 2026-10-12, T47 결과 확인 후) — 아래 원문보다 우선한다

T47 결과: primary 공통 top-3 (L4H1 · L2H0 · L14H5) 는 target mass 0.012–0.017, 3D `on_target` 0/30 로 실패. **L8H2 유지.**
1. **B1 의 비교 대상 교체.** 합산 방식 (`raw_sum` / `mass_norm_joint` / `mass_norm_per_camera`) 을 **GT-oracle top-3 (L8H3 · L10H7 · L12H4) · camera 별 top-3 · head-average** 에 적용한다. 공통 top-3 는 `raw_sum` 1 줄만 참고로 남긴다. head set 은 T47 의 select / oracle 출력 파일에서 읽는다. `mass_norm_joint` 의 "사전 선언 secondary" 지위는 **oracle top-3** 로 옮긴다. head-average 는 모든 head 의 mass 가 같아지도록 정규화한 평균이다.
2. **B2 · B3 는 그대로.**
3. **측정 #5 추가 — sink 진단 (사용자 판정: 정식 기록).** 128 cell (L2–17 × 8 head) × camera 마다 다음을 잰다. denoise 0 · agg last 이고, 전 record 와 frame 을 쓴다.
   - (a) 최빈 argmax patch 가 나온 frame 비율, (b) top-1 patch mass 의 평균 (camera mass 대비), (c) 평균 기준 binarize 후 component 수와 최대 component 의 면적 비율, (d) spatial entropy, (e) `S_cam`.
   - T47 의 공통 top-3 와 L8H2 · oracle top-3 를 이 축 위에 표시한다. 선택된 head 가 "고정 patch sink" 인지, "넓게 퍼졌지만 한 덩어리" 인지 수치로 구분한다.
   - figure: (b) 대 (c) 최대 component 면적의 scatter (cell 마다 한 점, 선택 · L8H2 · oracle 강조) + 대표 map.
   - lead 의 빠른 점검 (기록 아님): L14H5 `cam_high` 는 최빈 patch (r1, c11) 가 frame 의 96 %, top-1 mass 0.67 이었다. L2H0 · L4H1 은 top-1 mass 가 약 0.02 였다. verifier 가 이것을 독립적으로 다시 잰다.

4. **사전 고정과 다른 점 보정 (lead, T47b.impl.md 확인 후).** T47 의 e2e 와 class mass 는 **σ = 0** 으로 돌았다 (`summary__heldout.json` `args.sigma=0.0`). T47 사전 고정 primary 는 **σ = 1** 이었다.

   - HEAD: T46 이 `218229ac` 로 commit 했다. 기록하는 md5 가 T46 검증 때와 같으면 HEAD 를 `218229ac` 로 적는다.

## 왜 지금 이것인가

T47 은 논문 그대로 **raw 합** 으로 top-3 를 합친다. 검토 문서가 지적한 세 가지가 T47 설계에 빠져 있다.

1. **합산이 head 간 가중을 바꾼다.** 같은 head set 의 합과 평균은 상수배 차이일 뿐이다.
   downstream 은 camera 별 percentile 정규화 (`attention_lifting.py:240-283`), raw argmax peak, camera 간 raw max fusion (`multiview.py:384`), split 의 raw ratio (`target_grounding.py:1729`) 를 쓰므로 상수배에는 둔감하다.
   그러나 **head 마다 image mass 가 다르면** raw 합은 mass 가 큰 head 하나가 지배한다. camera 간 상대 크기도 바뀌어 max fusion 의 camera 선택이 달라질 수 있다.
   → **head 별 mass 정규화 후 합산** 을 비교한다.
2. **10 cm centroid (`on_target`) 만으로는 작은 이웃 과일과의 오분리를 못 가린다.** label 기반 지표가 필요하다.
3. 상수배에 둔감하다는 위 주장은 **코드 점검으로 확인해야** 한다. raw attention 에 절대값 threshold 가 하나라도 있으면 성립하지 않는다.

```
attention npz (cell 별 16×16 × 3 camera) → [head set 합산 방식]  ← 1
   → lifting (percentile 정규화 · raw peak) → multi-view raw max fusion → grounding (split raw ratio)  ← 3
   → chosen cluster vs GT label  ← 2
```

### B1 — 합산 방식 변형
- `raw_sum` : T47 과 같다 (기준).
- `mass_norm_joint` : head 마다 **3 camera 768 token 전체 mass 로 나눈 뒤** 합산한다. camera 간 비율은 보존된다. → **사전 선언된 secondary 비교** (T47 primary 와 나란히 보고).
- `mass_norm_per_camera` : head · camera 마다 16×16 mass 로 나눈 뒤 합산한다. camera 간 비율은 사라진다. → exploratory.
- head set · k=3 · σ=1 · denoise 0 · agg last 는 **T47 사전 고정과 같다.** head set 은 T47 `select` 결과 파일에서 읽으며, 새로 고르지 않는다.

### B2 — 3D 오분리 지표 (e2e 에 추가, GT seg label 사용)
- `identity_correct` : chosen cluster 점의 GT label 다수결이 target 인가. `on_target` 과 나란히 보고한다.
- `chosen_cluster_purity` : target 점 ÷ cluster 점. 그리고 **cluster 에 섞인 non-target 점 수 · class 별 분해** (other_object / destination / robot / table).
- `target_residual` : GT target 의 관측 점 중 target seed 로 잡히지 않아 obstacle 로 남는 수와 비율.
- `nontarget_seed_loss` : GT non-target (특히 other_object) 점 중 target seed 로 잡혀 **obstacle 에서 빠지는** 수. T44 의 distractor seed loss 와 같은 정의인지 impl.md 에 대조한다.
- 모든 지표는 frame 별 raw 로 남기고 **record (episode) 단위로 집계** 한다. frame 을 독립 trial 로 세지 않는다.

### B3 — raw amplitude 의존 점검 (코드 읽기 + 작은 수치 시험)
- attention 이 lifting 에서 grounding 까지 가는 경로에서 **raw (정규화 전) 값에 절대값 비교** 를 하는 곳을 전부 찾아 file:line 표로 만든다.
  출발점: `attention_lifting.py:240-342`, `multiview.py:350-404`, `target_grounding.py` (seed percentile, score, split ratio, `TargetConfirm` score ≥ 0.1), `config.py` 의 attention 관련 필드.
- 각 지점이 상수배 (×k) 와 head 간 가중 변화에 **불변 / 가변** 인지 판정한다. 판정 근거는 코드 줄이다.
- 같은 frame 에서 attention 입력을 ×3 해 grounding 결과가 bit-identical 인지 확인하는 **수치 시험** 을 unit test 또는 study 함수로 둔다. 실행은 verifier 가 한다.

- `identity_correct` 와 `on_target` 이 자주 갈리면, 이후 모든 grounding 평가의 주 지표를 label 기반으로 바꾸는 것을 제안한다.
