## 0. 왜

- **우선순위 5:** `--target-vacancy-release` (T81) 는 옛 target 자리가 depth 로 비어 보이면 target 을 놓고 다시 고르는 기능이다. 기능 후보로 남아 있고 최종에는 편입되지 않았다.
  - T81 r2 (T78 바탕): 사과를 60 mm 옮긴 2 run 에서 새 사과로 가기까지 1 요청이 걸렸다 (끔 48–49). 회귀 · 가림 4 run 에서 잘못 놓음은 0 이었다.
  - 하지만 성공은 2/6 → 2/6 으로 같았다. P0m (latch 단계 · hull · 접촉 여유) 위에서는 재지 않았다.
- **T98:** 재생에서 통과했을 때만 이 STEP 에 넣는다 (T98 §4). → **미통과 (2026-11-05 01:3x KST). 이 STEP 은 V 만 본다.**

## 2. 장면

1. **9 run** (k0, 허들 211 제외, `verify/T96/kit/items9.txt`) — 회귀 · 가림 · 허들. 기능이 켜져도 성공을 깨지 않는지 (회귀 확인) 본다.

## 3. 지표 · 판정 (결과 전 고정)

- **주 지표:** 금지 접촉 없는 성공 (실제 MuJoCo; 사과 50 mm 들림 + 끝에 바구니 안, 금지 = 이웃 과일 · 손 아닌 로봇 부위 ↔ 사과 · 장애물). 탁자 · 바구니 접촉은 따로 센다. 집계는 T92 kinematic replay 규칙 (T96e 와 같은 도구).
- **V 판정:**
  - 9 run 에서 P0m 대비 성공이 줄지 않아야 한다.
  - 금지 접촉 · 탁자 접촉이 늘지 않아야 한다.
  - 잘못 놓음 (옛 자리가 아닌데 target 을 놓음) = 0.
  - 옮김 2 run: target 이 새 사과 20 mm 안까지 오는 데 걸린 요청 수와 성공을 적는다. VLA 단독이 성공한 run 에서는 V 가 P0m 보다 낫거나 같아야 한다.
- **D 판정** (돌린 경우): 9 run 에서 성공이 줄지 않아야 한다. 탁자 접촉 = 0. 금지 접촉이 늘지 않아야 한다.
- 실패마다 원인 층 (ATS · HSR · LTE · CCR) 을 적는다.
- 결과가 P0m 보다 좋아도 **채택은 사용자 판정**이다. 사전 기준 계산을 보고에 적는다.
