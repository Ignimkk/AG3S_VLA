## 무엇을 했나 (평이한 요약 먼저)

1. **hidden 추출 도구에 head 카메라 patch 저장을 넣었다.** `pi05_hidden.py --pool patches` (기본 꺼짐) 는 요청마다 head 카메라 (`cam_high` = `zed_left`) image token 256 개의 hidden 을 지정 layer 만 float32 `[L, 256, 2048]` 로 저장한다. 자르기는 jit 안에서 하고, `--requests` 로 준 요청 (사건 · 평상 표본 · 그 참조 요청) 만 뽑는다. 요청 번호 j = t_step 으로 정렬한 j 번째 client step (T77 짝짓기 그대로). 이 option 을 주지 않으면 T73 / T77 경로는 그대로다.
2. **사건 · 정답 표 `t79_events.py`.** T77 spec · 라벨 위에서 쥐기 전 요청마다 MuJoCo 정답 (사과 중심, head 카메라에 보이는 사과 표면 중심), 기록된 ATS (target 상태 · 중심 · 정밀도 · 다수 물체), 참조 요청 (그 전의 마지막 ATS 정답 요청), 사건 종류 (a 밀림 / b 가려짐 / ab / normal / no_ref) 를 쓴다. 채점할 요청 (사건 전부 + run 당 평상 4 개 표본) 은 head depth 를 **patch 별 표 (점 수 · 좌표 합 · 정답 class 수)** 로 미리 만들어 둔다. 그래서 다음 단계는 MuJoCo 없이 돈다.
3. **재탐색 · 판정 `t79_track.py`.** §1 그대로 (참조 요청의 target patch hidden 평균 → cosine 유사도 지도 → τ 이상 · 4-연결 가장 큰 덩어리 → 그 patch 의 depth 점 중심), §3 지표 (찾음 ≤ 20 mm, 잘못 찾음 > 50 mm 또는 다른 물체), layer · τ 는 **train 장면에서만** 고르고 test 장면에서 판정한다. 참고 두 줄 (판정 없음): noun attention (L10H7) 지도, 그리고 frame 평균을 뺀 hidden.

발견 (구현 중):
- **raw cosine 은 모든 patch 에서 0.90–0.99 다** (smoke, 회귀211 요청 3 · 15 · 25 · 40; layer 4 중앙값 0.97, layer 16 중앙값 0.90). 이 residual stream 에는 모든 patch 가 공유하는 큰 성분이 있다. 그래서 τ 격자를 0.01 이 아니라 **0.001 간격 [0, 1)** 로 했다 (격자는 범위 전체를 고르게 덮는다; 값의 위치는 test 장면 smoke 에서 봤지만 격자 자체는 결과와 무관하게 균일하다 — ⚑ lead 확인).
- **224 이미지와 640 × 480 depth 의 관계:** `image_cam_high` 는 같은 `zed_left` 카메라를 4:3 (299 × 224) 로 그린 뒤 **잘라내거나 채우지 않고 224 × 224 로 늘린 것** 이다 (`rby1_manipulation/data/recording.py:47` `resize_policy_image`, `integration/rby1/bringup/pi05_infer.py:1441-1450`). depth · K 는 같은 카메라의 640 × 480 (fx = fy = 240, cx = 320, cy = 240). SigLIP So400m/14 는 224 이미지를 14 × 14 px patch 로 행 우선 (token k = 행 k // 16, 열 k % 16) 으로 자른다 (`third_party/openpi/src/openpi/models/siglip.py:216-226`). 따라서 **head token k ↔ depth 화소 u ∈ [40c, 40c+40), v ∈ [30r, 30r+30)** — 1 patch = 224² 에서 14 × 14 px = 640 × 480 에서 40 × 30 px. 이것은 serving ATS 의 대응 (`ifg_graph._cam_pixels:102`, `(v·16//H)·16 + u·16//W`) 과 같다. test 3 개로 고정했다.
- 사과는 head 카메라에서 지름 약 23 px (fx 240, 거리 약 0.7 m) 이라 **patch 하나 안팎** 이다. 그래서 patch 의 depth 점에는 탁자 · 손이 섞인다. 중심을 낼 때 **기록된 로봇 구 (`sphere_centres/radii` + 5 mm) 안의 점과 기록된 지지면 점 (`raw_cloud[support_mask]`) 10 mm 안의 점을 뺀다** — 둘 다 같은 요청의 server chunk 에 있는 serving 정보다 (정답 아님). ⚑ task 문장 ("그 patch 의 depth 점 → 중심") 에 없는 거르기다.

- 재생산이 필요한 산출물: 없음 (새 산출물만).
- 옛 기록과 호환이 깨지는가: 없음. serving 은 이 도구를 쓰지 않는다.
- 제한:
  - 회귀211 smoke 의 `track_smoke/t79_track.json` 은 train 장면이 없어 **고정 설정 (layer 8, τ 0.975, 임의)** 으로 돌린 배선 확인일 뿐이다. 거기의 hidden 숫자는 결과가 아니다.
