# T61 — 사전 고정 알고리즘으로 attention head 를 고르고 실행 중 고정한다 (사전 고정)

> writer: lead (e4 세션). 상태: **사전 고정 (2026-10-14 KST, 사용자 판정 3 반영). 선택 · held-out 결과를 보기 전.**
> 근거: 사용자 판정 ③ (2026-10-14, [`T60.task.md`](T60.task.md) "사용자 판정 2") 과 T61 판정 (2026-10-14, 아래 "사용자 판정 3").
> 참고 논문 (Kang et al., arXiv 2503.06287) 처럼 **선택 규칙을 먼저 고정하고, 고른 head 는 실행 중 바꾸지 않는다.**

## 왜 지금 이것인가

T47 · T51 은 같은 질문 ("head 를 하나로 고정해도 되는가") 을 다뤘지만 T60 에서 **완료 이후 frame 이 선택을 바꿨다**
(T51 GT 선택 `last:L12H4` → P `mean:L10H7` · H `mean:L12H4`). L8H2 를 관행으로 유지하지 않고, 결과를 보기 전에 고정한
절차가 내놓는 구성을 serving 에 고정한다. L8H2 는 기준선으로 보존한다. **선택 구성이 L8H2 보다 반드시 나을 필요는 없다** —
재현 가능한 절차로 비슷한 성능을 내는 것도 결과다.

## 사용자 판정 3 (2026-10-14 KST, 이 문서의 모든 규칙의 근거)

1. **held-out = 새 평가 집합.** 기존 4 record (`headfix` · `ep1800` · `ep1850` · `ep1900`) 는 개발 · 참고 자료. 아직 선택 · 개발에 쓰지 않은 기존 기록이 없으면 새 rollout · attention 추출. T53 규모 16 episode, 과일 · 사용 팔 · 배치 분산. **평가 대상 목록과 규칙을 먼저 고정하고, 선택 결과를 저장한 뒤 평가한다.**
2. **calibration 의 ep0 · ep500 · ep1200 유지** (VLA 학습 episode — 일반화 평가로 주장하지 않는다). **`long` 은 T56 에서 입력 배선 문제 (X2 수정 전 head 0 녹화, cam_high 가 벽을 봄) 로 제외한 기록이므로 calibration 에서도 제외한다.** 성능이 낮아서 빼는 것과 입력이 잘못된 것을 구분한다.
3. **강제 후보 없음.** T47 GT-oracle top-3 과 L8H2 모두 일반 선별 규칙을 통과해야 후보가 된다. L8H2 의 강제 포함은 **기준선 평가에만** 쓴다. T51 에서 L8H2 가 P1 filter 로 빠졌다면 다시 뽑으려고 threshold 를 바꾸지 않는다.
4. **명사 query 포함.** action 과 명사 query 를 같은 downstream 조건에서 비교한다. 2D 사전 선별의 후보 수와 query 별 배분을 미리 고정하고, 결과에 전체 선택과 query 별 결과를 함께 남긴다. **선택 단위 = query · denoise · aggregation · layer · head 전체.** 예: `mean:L10H7` 이 선택되면 serving 도 mean 을 구현한다 (기존 last 로 대체하지 않는다).
5. **k 선택:** CV 최고 평균 구성의 **표준오차 1 개 이내** 인 구성 중 가장 작은 k. 후보 순위는 각 CV 학습 fold 안에서 계산한다.
6. **안정성:** bootstrap 은 보고 지표로만 둔다. "1 위 확률 < 0.5 이면 L8H2 로 복귀" 는 없다. 최종 구성을 정하는 규칙은 calibration CV 하나다.
7. commit: 공유 로그는 세 세션 확인 후 한 세션이 한 번에. 각 세션의 코드 · 테스트 · 산출물은 소유 범위별로 분리.

## 사전 고정 — 선택 (calibration)

| 항목 | 고정 내용 |
|---|---|
| **calibration record** | `t2` (scene 1800) · `ep1807` · `ep0` · `ep500` · `ep1200` — **5 record · 5 scene**. `long` 제외 (판정 2). ep0 · ep500 · ep1200 은 VLA 학습 episode |
| **평가 창** | **P** (T60 규칙, inference frame `t_step ≤ t_P`, 미도달 record 는 전체). record mask = T60 `step3/records/<key>.npz` 의 `keep_frames_P` |
| **후보 집합 Ω** | action query `last` · `mean` · `first` (denoise 0) × L2–17 × 8 head = 384 cell + 명사 query `noun_target` (prompt 의 target 명사 token, denoise 0) × L2–17 × 8 = 128 cell → **512 cell** (T51b combined Ω 와 같다) |
| **전처리** | raw map (σ 0), 3 camera 배선, 조합은 cell map 의 합 (T51 `sum[...]`). 3D replay 옵션은 T51 그대로 (voxel 0.020, legacy ESDF, gripper links, on_target 0.10 m, label 0.003 m, membership T51 기본) |
| **P1 filter** | T51 `FILTER_THRESHOLDS` 그대로, P 창의 calibration frame 으로 계산 (label 을 쓰지 않는다). 결과가 어떻든 threshold 를 바꾸지 않는다 |
| **2D 사전 선별 (query 별 고정 배분)** | P1 통과 cell 중 **query 마다 2D lift (scene 평균) 상위 6 개** (동률: 2D peak_on_target, 그다음 Ω 순서) → 4 query × 6 = **24 cell**. P1 통과 cell 이 6 개보다 적은 query 는 통과한 만큼만. **강제 후보 없음** |
| **주 기준 (3D)** | calibration **scene 평균 GT `identity_correct`** (P 창) |
| **동률 규칙** | 주 기준이 같으면 (차이 ≤ 1e-9) → (1) scene 평균 `chosen_cluster_purity` (대상 frame = `has_target`) 높은 쪽 → (2) scene 평균 coverage = `chosen__target / n_target_obs` (출력 없는 frame 은 0, `n_target_obs = 0` frame 은 제외) 높은 쪽 → (3) Ω 순서 (query `last` → `mean` → `first` → `noun_target`, 그다음 layer, head) 앞쪽 |
| **조합 k** | k ∈ {1, 2, 3}. k 구성 = 그 학습 fold 순위의 상위 k cell 합 |
| **CV** | **leave-one-scene-out** (5 fold). 각 fold 에서 2D 사전 선별 · 3D 순위 · 동률 처리를 **학습 scene 만으로** 다시 계산하고, 상위 k 구성을 test scene 에서 잰다 (test scene 점수 = 그 scene 의 GT identity, P 창) |
| **k 선택 (one-SE)** | k 마다 CV 평균 m_k 와 표준오차 SE_k = sd(5 scene 점수, ddof 1) / √5. best = m_k 최대 (동률 → 작은 k). **m_k ≥ m_best − SE_best 인 k 중 가장 작은 k** 를 고른다 |
| **최종 구성** | 5 scene 전체로 다시 계산한 순위의 상위 k* cell 합. nested CV (바깥 fold 마다 안쪽 one-SE) 점수는 절차 전체의 추정으로 **보고만** 한다 |
| **보고만 (선택에 쓰지 않음)** | scene bootstrap (B 10000, seed 6101) 의 1 위 확률, query 별 최선 (action 만 · 명사만 으로 같은 절차를 돌린 결과), label-free · self label 선택 |
| **고정 시점** | 선택 결과를 `T61.selection.json` 으로 저장하고 sha256 을 이 문서와 verify 에 적은 **뒤에** held-out 을 연다. 이후 규칙 · 창 · 후보 · 배분을 바꾸지 않는다 |

## serving 고정 (선택 뒤, 별도 STEP)

선택 단위 전체 (query · denoise · aggregation · layer · head) 를 serving 에 구현한다. 현재 serving 은 `last` action query 만 쓰므로 `mean` · `first` · 명사 query 가 선택되면 그 경로를 구현하고, 선택 전 offline map 과의 parity 를 확인한 뒤 closed loop 로 간다. 진행 중 실험 (T54c · T55 · T56) 의 설정은 바꾸지 않는다.

## 되돌아올 지점

- calibration 이 5 scene 이라 CV 의 SE 가 크다. one-SE 가 k = 1 을 고르는 경향이 있다는 것을 결과와 함께 보고한다 (규칙은 바꾸지 않는다).
- held-out 의 (apple, left) 가 비어 있다 — 결과를 과일 × 팔로 일반화하지 않는다.

### 서빙 구현 요청 (사용자 판정 2026-10-14 B 작업 5: held-out 보고 직후 A 에 전달)

- **선택 단위 전체:** action query (suffix 의 action token), denoise step 0, **aggregation = mean** (action token 축 평균, `pi05_attention.AGGREGATIONS["mean"]`), layer 10, head 7, k = 1, raw σ0, 3 camera. T57-A 의 `attention_source` spec 으로는 `action:mean:L10H7`.
- **추출 경로:** 서빙 prefix pass 의 같은 attention 에서 last 대신 mean 을 취한다. T57 단계 1 (명사 `noun_target:L10H7`) 과 같은 `attention_source` 일반화 경로를 쓴다 (공통).
- **후보 경로 구현과 기본 교체를 구분한다.** 이번 요청은 후보 경로 (기본 off) 와 parity 다.
  - parity: T61 held-out 기록 몇 frame 에서 서버가 낸 map 이 offline `t56_cells.cell_maps(["mean:L10H7"])` 와 같아야 한다. AG3S 행이 `t61_heldout` replay 행과 같아야 한다.
  - flag off 회귀: 단계 1 과 같다.
- 기본 서빙 교체는 parity 와 closed-loop 결과를 보고 사용자가 판정한다. L8H2 대비 유의한 개선은 구현 요청의 필수 조건이 아니다 (재현 가능한 선택 절차 자체가 결과다).
- 추가 비용: 같은 prefix pass 의 aggregation 만 바뀌므로 추가 pass 는 없을 것으로 본다. 서버 attention 처리 시간은 측정하지 않았다 (parity 때 함께 잰다).
