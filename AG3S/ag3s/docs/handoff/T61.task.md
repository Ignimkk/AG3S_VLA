# T61 — 사전 고정 알고리즘으로 attention head 를 고르고 실행 중 고정한다 (초안, 실행 전)

> writer: lead (e4 세션). 상태: **초안 — 실행하지 않았다.** 아래 "판정 필요" 를 받은 뒤 사전 고정 (pre-registration) 으로 확정한다.
> 근거: 사용자 판정 ③ (2026-10-14, [`T60.task.md`](T60.task.md) "사용자 판정 2"): L8H2 를 관행적으로 유지하지 않고, 참고 논문
> (Kang et al., arXiv 2503.06287) 처럼 사전에 고정한 알고리즘으로 head 를 고르고 실행 중에는 고정한다.

## 왜 지금 이것인가

T47 · T51 은 같은 질문 ("head 를 하나로 고정해도 되는가") 을 다뤘지만, T60 에서 **완료 이후 frame 이 선택을 바꿨다**
(T51 GT 선택 `last:L12H4` → P `mean:L10H7` · H `mean:L12H4`, T47 label-free 공통 top-3 변경). 선택 규칙 · 평가 창 ·
동률 규칙이 결과를 본 뒤 정해진 부분이 없는지 다시 고정하고, 그 절차가 내놓는 head 를 serving 에 고정한다.
L8H2 는 기존 기준선으로 보존한다. 선택 head 가 L8H2 보다 반드시 나을 필요는 없다 — 재현 가능한 절차로 비슷한 성능을
내는 것도 결과다.

## 사전 고정 (안)

| 항목 | 고정 내용 |
|---|---|
| **calibration 데이터** | 평가와 분리된 record. 현재 후보 = T51 calibration 6 record · 5 scene (`long` · `t2` · `ep1807` · `ep0` · `ep500` · `ep1200`; ep0 · ep500 · ep1200 은 VLA 학습 episode 임을 함께 보고) |
| **평가 창** | **P** (T60 규칙: 안정 placement 까지, inference frame `t_step ≤ t_P`; 미도달 record 는 전체). `endpoints_sampled` 의 record mask 를 그대로 쓴다 |
| **후보 집합 Ω** | T51 과 같다: action query (denoise 0 × last · mean · first) × L2–17 × 8 head, P1 filter (T51 threshold) 통과 cell. 명사 query 를 넣을지는 T60c 결과 뒤 판정 |
| **전처리** | raw map (σ 0), 3 camera 배선, T51 replay 옵션 (voxel 0.020, legacy ESDF, gripper links, on_target 0.10 m, label 0.003 m) |
| **주 기준** | calibration **scene 평균** GT 3D `identity_correct` (P 창) |
| **동률 규칙** | 주 기준 차이 < 1 frame 분 (= scene 평균에서 1 / (그 scene 의 P 창 frame 수) 의 평균) 이면 동률. 동률이면 (1) scene 평균 `chosen_cluster_purity` 높은 쪽, (2) scene 평균 coverage (`chosen__target / n_target_obs`, 출력 없는 frame 은 0) 높은 쪽, (3) Ω 순서 (query → layer → head) 앞쪽 |
| **2D → 3D 사전 선별** | T51 P2 그대로 (calibration 2D lift 상위 N + forced). forced 는 L8H2 만 (T47 oracle 은 같은 calibration 에서 GT 로 고른 것이라 forced 에서 뺀다 — 판정 필요) |
| **조합 크기 k** | k ∈ {1, 2, 3}, calibration 내부 **scene 단위 leave-one-scene-out CV** (T51 P4 nested CV). 규칙: 가장 작은 k 중 best k 와의 paired 차이 CI 하한 ≤ 0 인 것 |
| **안정성 보고** | scene bootstrap (B 10000, seed T51) 의 1 위 확률. 선택을 바꾸는 데 쓰지 않고 보고만 |
| **고정 시점** | 선택 결과를 파일 (`T61.selection.json`, sha) 로 고정한 **뒤에** held-out 을 연다. 이후 규칙 · 창 · 후보를 바꾸지 않는다 |
| **L8H2 를 다시 고르도록 조정 금지** | 어떤 규칙도 L8H2 를 결과로 보고 바꾸지 않는다 |
| **self label 경로** | T56 self-label 선택은 검증 후 annotation 대체 경로로 따로 판단. T61 의 공식 경로는 calibration GT |
| **진행 중 실험** | T54–T56 의 설정은 소급 변경하지 않는다 |

## 판정 필요 (실행 전)

1. **held-out 이 이미 열렸다.** T60 에서 같은 calibration · P 창으로 T51 chain 을 돌려 held-out (4 record · 60 frame) 결과를 이미 보았다
   (`mean:L10H7` 0.900, L8H2 0.911). T61 의 규칙 (동률 규칙 · forced 후보) 이 그 chain 과 다르더라도 같은 held-out 으로 평가하면
   "held-out 을 보기 전에 고정" 을 만족하지 못한다. 선택지: (a) **새 held-out** (아직 어떤 선택 · 개발에도 쓰지 않은 episode 의
   16D rollout 기록 + attention 추출, GPU 필요) 을 만든다, (b) 기존 held-out 을 쓰고 오염을 명시한다.
2. calibration 에 VLA 학습 episode (ep0 · ep500 · ep1200) 를 그대로 둘지.
3. T47 GT-oracle top-3 을 forced 후보에서 뺄지 (위 초안은 뺀다).
4. 명사 query 를 Ω 에 넣을지 (T60c 결과 뒤).
5. serving 에 고정할 때 action query 의 denoise · aggregation 을 cell 정의에 포함 (예: `mean:L10H7`) 하는 것 — 현재 serving 은 `last` 만 쓴다.

## 되돌아올 지점

- 선택이 calibration scene 하나에 크게 좌우되면 (bootstrap 1 위 확률 < 0.5) 단일 head 대신 k ≥ 2 조합 또는 L8H2 기준선 유지로 돌아온다.
