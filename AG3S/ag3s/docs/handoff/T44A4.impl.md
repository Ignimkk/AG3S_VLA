## 무엇을 했나 (평이한 요약 먼저)

attention split 의 ratio gate (target 후보의 평균 attention ÷ 다른 성분의 최대 평균 ≥ 2.0) 가 읽는 값을 고를 수 있게 했다.
`clustering.attention_split_ratio_source = "raw"` 이면 **정규화 전** attention (`AttentionPointCloud.raw_attention`) 으로 비율을 계산한다.
**target 후보 선택은 두 모드 모두 정규화 attention 질량 그대로**다 — raw 는 gate 만 바꾼다 (D-merge `merge_analyze.py` 의
`"A: recluster12 + ratio2 (raw att)"` 와 같은 정의: `evaluate(..., ratio_raw=True)` 는 성분 선택 `att` 질량, gate `raw` 평균).
기본 `"normalized"` 는 HEAD 와 bit-identical (64 frame 실측, 아래). split radius 는 기존 config 키를 CLI 로 바꿀 수 있게만 했다 (기본 15 mm 그대로).
`serve_safe.py` 에 `--attention-split-radius-mm`, `--attention-split-ratio-source`, 그리고 A3 (I2b) 에서 빠진 `--held-permission-parent-links` 를 넣었다.

## verifier 가 알아야 할 것

- 새로 생긴 플래그·기본값 변경: `clustering.attention_split_ratio_source` (기본 `"normalized"`). CLI `--attention-split-radius-mm MM`
  (`clustering.attention_split_radius` = MM/1000; 안 주면 0.015), `--attention-split-ratio-source {normalized,raw}`, `--held-permission-parent-links N`
  (strict 와 함께만). 기본값 변경 없음. T44M 권고 설정은 `--attention-split-radius-mm 12 --attention-split-ratio-source raw`.
- 새 기록 키 (raw 일 때만): split decision record `ratio_source`, component `mean_ratio_attention`, frame split record `ratio_source`.
- 재생산이 필요한 산출물(npz 등): 없음.
- 옛 기록과 호환이 깨지는가: 없음 (기본 record 는 키까지 같다).
- 위 smoke 는 grounding 단계만이다. AG3S 전체 (`process_multi_debug`, cuRobo field) 와 closed-loop 는 돌리지 않았다.

## 남은 결함 · 판정이 필요한 것

1. **release split (T32b S2) 은 정규화 attention 그대로.** `split_anchor_on_release` 는 `TargetConfirm` 이 저장한 geometry 의 정규화 attention
   (`observe(..., attention=)`) 만 갖고 있다. raw 로 맞추려면 `observe` 가 raw 도 저장해야 하는데, 이는 "split 호출부만" 소유 범위 밖이다.
   raw 모드에서 frame split 과 release split 의 gate 가 다른 값을 읽는다 — 맞출지 판정 필요.
2. **raw gate 의 문턱 2.0 은 정규화 기준으로 정한 값이다.** raw 는 카메라 간 max fusion 값이라 scale 이 frame 마다 다르지만 비율이라 무관하다.
   다만 raw 2.0 의 근거는 T44M 64 frame (demo pose, offline VLA attention) 뿐이다 — closed-loop / E3 replay (T31b 의 근거 집합) 로는 재지 않았다.
3. **12 mm radius 와 단일 사과의 분할.** T31b 의 "단일 사과는 15 mm 에서 둘로 안 나뉜다 (MST 최장 간선 95 pct 17 mm)" 근거는 15 mm 기준이다.
   12 mm 에서 단일 과일이 둘로 쪼개지는가는 이 smoke 의 non-merged 30/30 외에 확인하지 않았다 (`test_attention_split_e3_replay.py` 는 15 mm 고정).
4. `.venv-ag3s` interpreter 의 NFS page 멈춤 (위) — 환경 문제로 보고만 한다.
