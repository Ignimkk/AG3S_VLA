# T54b — T54 유지 포함 재생 수정: 기록된 latch · attach / detach 를 모든 arm 에 똑같이 넣는다

> writer: lead (A0) · 2026-10-13 KST · 읽는 쪽: implementer, verifier · 로그: `AG3S_T47_LOG.md`
> 근거: 사용자 판정 (2026-10-13, T54 결과 보고 후) "기록된 latch · attach 를 넣어 다시". T54 의 주 조건 (현재 frame) 결과는 바뀌지 않는다.

## 왜

T54 의 유지 포함 (`hold`) 재생은 attach / detach 를 재현하지 않았다 (`T54.verify.json` deviation 5). 그 결과 두 가지가 나왔다.
- 모든 arm 이 post · placed phase 에서 identity 0.0 이다.
- N · B 가 모든 episode 에서 L8H2 와 identity · purity · no_target 이 정확히 같다.

그래서 "실제 사용 조건에서 개선이 사라지거나 역전되는가" 를 확인하지 못했다. 이 확인은 T54c (N · B 후속 확인) 에도 필요하다.

## 고칠 것 (→ implementer)

- `hold` 조건에서 **서빙 chunk 기록의 grasp latch 상태 (SEARCHING / LATCHED / CLOSING / HELD / PLACED), attach / detach 시점, freeze 상태** 를 frame 마다 모든 arm 의 AG3S 에 똑같이 넣는다. 이 값은 grounding 이 아니라 robot feedback 에서 나온다 (T54 사전 고정 2).
- 각 arm 은 계속 **자기 예측으로 자기 grounding history 를 쌓는다.** L8H2 가 기록한 geometry 를 다른 arm 에 넣지 않는다.
- 새 파일 또는 `t54_*` 의 새 option 으로 넣는다. 기존 `hold` 동작은 옵션으로 남긴다 (T54 결과 재현용). 서빙 코드는 바꾸지 않는다.
- test (synthetic):
  - 주입된 attach 가 모든 arm 에 같음
  - arm 별 history 분리
  - 기존 `hold` 모드의 결과가 바뀌지 않음
- **점검 (verifier):** L8H2 arm 의 수정된 `hold` 재생이 T53 서빙 기록의 grounding 결과 (chosen target · manipulated identity) 와 얼마나 일치하는지 수치로 낸다. 이 일치도가 재생의 충실도다.
