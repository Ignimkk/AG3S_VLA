# SL13 — 진단: 정답 target의 부피 전체(탁자 맞닿는 띠 포함)를 지우면 개입이 줄고 성공이 돌아오나 (결과 전 고정, 채택 없음)

> writer: lead (benchmark checkout), 2026-11-05 13:4x KST, 자율 판정 시간(사용자 연장 16:00 KST, 결정 문서 E39).
> 근거: `outputs/2026-11-05_SL12_정답target진단/`
> - SL12 정답 target 판(`--target-extent oracle-visible --oracle-extent-identity gt`)은 identity가 정답(1.00)이다.
> - 그런데 탁자 위 bowl episode(t0–t3 · t8)에서는 실제 bowl 원기둥(원점 ±15 mm) 안 target-free 칸을 **하나도 지우지 않는다**(지운 비율 0, 점유 0.92–0.99).
> - 지운 칸은 bowl 원점보다 약 40 mm 위(테두리)에 있다. 탁자에 닿는 아래쪽 seed는 "가장 가까운 표본이 target이 아님"(탁자)으로 남는다.
> - 그래서 SL12는 "target 인식 · 지우기가 완벽하면"이라는 질문에 답하지 못했다(기제 미달).

## 1. 변경 (진단 전용, 기본 꺼짐)

- 새 서버 flag `--oracle-target-volume`(Panda 서버만, `--target-extent oracle-visible`과 함께만, 기본 꺼짐)을 둔다. 켜면 기존 oracle-visible 지우기에 더해 **정답 target 부피 안의 seed를 주인 판정과 상관없이 모두** 미세 target-free 층에서 지운다.
- 정답 target 부피:
  - xy: 이 episode의 code-1(target) 표본 xy 볼록 껍질을 미세 voxel 1칸 팽창한 것
  - z: `z_floor_m`(서버가 이미 기록하는 탁자 높이)부터 code-1 표본 최고 z + 미세 voxel 1칸까지
  - target 표본이 없으면(못 봤으면) 아무것도 더하지 않는다. 몇 칸을 더 지웠는지는 call마다 기록한다(`oracle.field.volume_*`).
- 손에 쥔 뒤(`held`)와 다른 latch 상태의 처리는 SL12 판 그대로다. `--oracle-target-volume`은 SL12에서 지우기가 적용되던 call에만 더해진다.
- 대체 구현: 위 정의가 서버 구조상 불가능하다고 판단되면, implementer가 MuJoCo 정답 geom 부피(client가 target geom의 world AABB를 보냄)를 대안으로 쓸 수 있다. 그 경우 이유를 `SL13.impl.md`에 적는다.
- 판:
  - `AG3S-final-panda-v3-e0to-pc-oraclevol` = `-pc-oraclegt` + `--oracle-target-volume`
  - `…-pc-mi10-oraclevol` = `-pc-mi10-oraclegt` + `--oracle-target-volume`
- 기존 판의 server argv는 bit 동일해야 한다(테스트).

## 2. 기록할 숫자 · 판정 (결과 전 고정)

- **기제 (필수):** 아래 측정은 `outputs/2026-11-05_SL12_정답target진단/scripts/tfc_control_ep.py`의 정의 그대로다(원기둥 r 45 mm, 원점 ±15 mm, 5 mm voxel, 접근 · 닫는 중, 손에 들기 전).
  - LIBERO 9에서 실제 bowl 원기둥의 target-free 층 점유 중앙값이 ≤ 0.3이어야 한다.
  - 탁자 위 bowl episode 각각의 중앙값도 ≤ 0.5여야 한다.
  - **이웃 보존:** target이 아닌 이웃 물체(다른 bowl · plate · ramekin · cookies)의 같은 원기둥 점유가, 같은 call의 주 ESDF 점유 대비 0.1 넘게 떨어지면 안 된다(이웃을 지우면 안 된다).
  - 아니면 "의도대로 동작하지 않음"으로 보고하고 멈춘다.
- **진단 숫자 (판정 아님):**
  - LIBERO 9 · LIBERO-Safety 10 성공을 VLA 단독 · pc판 · 무개입 · SL12와 비교한다.
  - 통과 문턱이 열리는 비율(mi10 판의 찾는 중 + 접근 call 중 실행 = 정책 bit 동일)을 본다.
  - 구간별 표(`phase_map.py`)를 낸다.
- **읽는 법 (결과 전 고정, SL12와 같다; 기제를 통과했을 때만 적용):**
  - 두 판 중 하나라도 LIBERO 성공이 VLA 단독 −1 이내(≥ 8/9)로 돌아오면 → 다음 작업 우선순위는 target 지우기(LTE: 맞닿은 경계 주인 판정)와 인식(ATS)이다.
  - 두 판 모두 ≤ 7/9면 → TO · latch(HSR · CCR)가 우선이다.
  - SL12 규칙의 "pc판 +2 이하"(≤ 8)와 겹치는 8/9는 "ATS · LTE 우선"으로 읽는다.
