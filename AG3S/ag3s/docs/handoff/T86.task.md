## 0. 왜

- 지금 ATS 의 target 신호는 prompt target 명사 token 의 prefix attention (layer 10 head 7) 이다. 이 신호는 T80 A 재실행에서 "left / right" 같은 위치 표현을 반영하지 못했고 (ATS-03), T79 에서 가려진 뒤 다시 찾기 0.12 / 0.40 였다.
- T79 은 hidden patch 의 **비지도 cosine** 이 화면 전체 0.85–0.95 로 갈리지 않음을 보였다 (모든 patch 가 공유하는 큰 성분). 그러나 PaliGemma prefix 는 image · text token 이 서로 보는 구조라 깊은 layer 의 image patch hidden 에 prompt 정보가 섞일 수 있다.
- 질문: **지도 학습한 선형 probe 가 hidden image patch 에서 "prompt 가 말한 물체의 patch" 를 명사 attention 보다 잘 찾는가, 그리고 prompt 를 바꾸면 따라가는가.**

## 1. 방법 (비교 대상, 결과 전 고정)

- **기준 A (지금):** 같은 forward 의 명사 attention (`noun_target:L10H7`) patch 지도 (카메라마다 16 × 16).
- **새 B (hidden probe):** 카메라 patch 마다 layer l 의 hidden (2048 차원) → 표준화 + 로지스틱 회귀 → p(target). 변형 B' = 같은 frame 256 patch 평균을 뺀 hidden (T79 의 공통 성분 제거).
  - layer l ∈ {4, 8, 12, 16}, 규제 강도 C 는 **train 장면 교차 검증만으로** 고른다.
- 두 지도 모두 같은 평가 함수로 잰다 (아래 §3).

## 2. 데이터 (결과 전 고정)

- 기록: T77 이 쓴 closed-loop 기록 (spec · 라벨 그대로), 장면 나누기도 T77 과 같다 (test = 211 · 954 · 122 · 119, 나머지 train).
- 요청: 정답 held 전 (접근 · 쥐기) 요청에서 run 마다 균등 표본. 저장 상한 20 GB 안에서 implementer 가 표본 수를 정해 `T86.impl.md` 에 적는다 (전체 실행 전 고정).
- 카메라: head · 왼손목 · 오른손목 3 대 (VLA 입력 224 px, 16 × 16 patch).
- **정답 patch 라벨:** 그 요청 qpos 로 MuJoCo segmentation 을 VLA 입력과 같은 투영 (T79 `patch_of_policy_pixel`) 으로 렌더해, patch pixel 의 30 % 이상이 prompt target body (visual geom 포함) 이면 target, 다른 물체 30 % 이상이면 other, 나머지 background.
- **prompt 바꾸기 (counterfactual):** 같은 image 에서 다른 과일 (banana · orange · pear 중 그 frame 에 target patch 가 1 개 이상 보이는 것) 을 목적어로 한 prompt (`Pick up the <fruit> and place it in the basket.`) 로 forward 를 한 번 더 한다. 정답 = 그 과일. train 장면에서는 학습에도 쓴다 ("늘 사과" 로 외우지 않게), test 에서는 평가만.

### 2.1 결과 전 변경 (2026-11-03 KST, lead — probe 결과를 보기 전, 라벨 통계만 본 뒤)

- 이유: head 카메라에서 사과는 지름 약 23 px 로 token (14 × 14 px) 1–2 개라, "pixel 30 % 이상" 규칙이면 쥐기 전 요청 중 8.1 % 만 target patch 가 있고 test 217 run 중 37 run 만 남는다 (test 요청 227 개 중 174 개가 장면 211, 장면 119 · 허들 954 · 반기둥 122 는 0 개) — 한 장면이 판정을 정한다 (implementer 조사 `t86_survey.json`).
- 변경: target / other patch 문턱을 **20 %** 로 내린다 (쥐기 전 요청의 45 %, test 173 run). 저장 상한 20 GB 를 지키도록 run 당 표본 수를 줄인다 (값은 `T86.impl.md`).
- 판정 보강: test 지표는 장면별로도 내고, 판정은 **장면 평균** (장면마다 같은 무게) 으로 한다. target patch 가 있는 요청이 20 개 미만인 장면은 평균에서 빼고 표에 적는다.

## 3. 지표와 판정 (결과 전 고정)

요청 · 카메라마다 (정답 target patch 가 1 개 이상인 것만):
1. top-1 patch 적중 (가장 높은 patch 가 target patch).
2. 물체 선택 정확도: 지도 상위 patch 의 4-연결 가장 큰 덩어리 (상위 k = 정답 target patch 수) 의 다수 라벨이 target.
3. AUROC (target 대 나머지).
4. counterfactual 따라가기: 바꾼 prompt 에서 2 의 덩어리가 바꾼 과일로 옮겨 간 비율.

**판정 (test, head 카메라 주 · 손목은 보고):** B (또는 B') 가 "낫다" = 물체 선택 정확도 ≥ A + 10 %p **이고** counterfactual 따라가기 ≥ 0.8 **이고** ≥ A. 미통과면 숫자를 보고하고 멈춘다 (serving 연결은 통과 뒤 사용자 판정).
