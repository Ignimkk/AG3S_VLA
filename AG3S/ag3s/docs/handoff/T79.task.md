# T79 — ATS 시간 추적: VLM hidden patch 특징으로 밀리거나 가려진 target 다시 찾기 (offline, 결과 전 고정)

> writer: lead (세션 dev-53) · 작성: 2026-10-31 · 상태: **사전 고정.** 구현: ag3s-implementer. 실행 · 판정: lead.
> 사용자 지시 (2026-10-31): hidden state 실험 순서 = HSR (T77, 채택 → ADOPTED A9) → **ATS 시간 추적 (이 STEP)** → ATS target 찾기 → 쥐기 의도.
> STEP 번호 T79 는 다른 세션에 알림. **T78 (세션 A, attention 표면 추출 + GPU, 최종 구성 반영 예정) 의 파일은 건드리지 않는다** (`runtime/attention_surface*.py` · `runtime/pipeline.py` · `fields/curobo_builder.py` · `runtime/oracle_segmentation.py`). serving 반영은 T78 이 들어간 뒤 그 위에서 따로.

## 0. 왜

- T75 (최종 구성 프레임별 진단): 회귀 211 은 요청 12–14 에 손가락이 사과를 약 10 cm 밀었고, 요청 15 부터 target 이 "가려짐" 이 되어 **target 점이 사과의 옛 자리에 끝까지 남았다** (정답과 90–116 mm). 그래서 LTE 가 빈 자리를 지우고 진짜 사과는 손 층에 100 % 장애물로 남아 쥐지 못했다.
- 지금 ATS 의 시간 추적은 3D 위치 · 소유 규칙 기반이다. 사과가 보이는데도 (head 카메라에 사과가 있음) 옛 자리를 유지했다.
- 질문: VLM hidden 의 image patch 특징 (사과의 외형) 으로, target 이 밀리거나 가려진 뒤 **진짜 사과 위치를 다시 찾을 수 있는가.**

## 1. 방법 (비교 대상, 결과 전 고정)

- **기준 (지금 ATS):** 기록된 target 중심 (`manipulated.centroid`) · target 점.
- **hidden 재탐색 (새):**
  1. 참조: run 안에서 ATS 가 정답과 맞던 마지막 요청 (target 점 정밀도 ≥ 0.8 ∧ 다수 물체 = 사과 — T75 판정 그대로) 에서, target 점이 투영되는 head 카메라 patch 들의 hidden 평균 = 사과 외형 벡터 a (layer l).
  2. 이후 요청마다 head 카메라 patch 256 개의 hidden 과 a 의 cosine 유사도 → 상위 patch (유사도 ≥ τ, 연결된 가장 큰 덩어리) → 그 patch 의 depth 점을 3D 로 → 그 중심 = 재탐색 target 중심.
  3. 유사도가 τ 넘는 patch 가 없으면 "못 찾음" (기권).
  - layer l ∈ {4, 8, 12, 16} 과 τ 는 **train 장면에서만** 고른다 (T77 과 같은 장면 나누기: test = 211 · 954 · 122 · 119).
- 참고 (판정 없음): 같은 방법을 VLA 의 noun attention (layer 10 head 7) 상위 patch 로 했을 때.

## 2. 평가 요청 (결과 전 고정)

- **사건 요청:** 쥐기 전 (정답 held 이전) 이고 다음 중 하나:
  - (a) 정답 사과 중심이 참조 요청 때보다 20 mm 이상 움직였다 (밀림),
  - (b) 기록 target 상태가 "가려짐" 이고 head 카메라에 정답 사과 보이는 표면이 있다.
- **평상 요청:** 쥐기 전, 사건이 아닌 요청 (재탐색이 평소에 망치지 않는지).
- 정답: 같은 요청 MuJoCo 상태의 사과 중심 · head 카메라에 보이는 사과 표면 (T75 `ats_extra` 와 같은 방식).

## 3. 지표와 판정

- **찾음:** 재탐색 중심 (또는 기준 target 중심) 과 정답 사과 **보이는 표면 중심** 의 거리 ≤ 20 mm.
- **잘못 찾음:** 중심이 다른 물체 (정답 class 8 mm) 쪽이거나 50 mm 넘게 떨어짐.
- **"hidden 재탐색이 낫다" (모두 충족, test 장면):** 사건 요청 찾음 비율이 기준보다 30 %p 이상 높음 ∧ 사건 요청 잘못 찾음 ≤ 10 % ∧ 평상 요청 찾음 비율이 기준보다 5 %p 넘게 낮지 않음.
- 회귀 211 (T71 R0 기록) 요청 15–74 의 결과는 따로 표로 낸다 (실제 씬 그림 포함).

## 4. 구현에 요청하는 것 (→ ag3s-implementer)

1. `pi05_hidden.py` 에 `--pool patches` (기본 꺼짐): 지정 layer 의 head 카메라 image token 256 개 hidden (float32, [L, 256, 2048]) 을 요청마다 저장. 대상 요청만 (사건 · 평상 표본, spec 의 요청 목록) 으로 크기를 줄인다. 기존 option 결과 bit 동일.

5. smoke: run 1 개 (T71 R0 회귀 211) GPU 공유 lock, 크기 · 시간 보고. 전체 실행은 lead.

## 6. 결과 전 보완 (lead 2026-10-31, 구현 smoke 뒤 · 전체 실행 전)

- **기준 위치 = 기록된 target 점들의 평균** (T75 의 ATS 중심 정의와 같음). 공 중심 (`manipulated.centroid`) 은 ATS 가 맞을 때도 보이는 표면 중심과 20–28 mm 떨어져 (smoke) 기준을 부당하게 낮추므로 참고로만 적는다 (`baseline_ball_centre`).
- 재탐색 점에서 기록된 로봇 구 (+5 mm) 안 · 지지면 점 10 mm 안을 뺀다 (같은 요청 serving 정보, 구현 제안 수용).
- "잘못 찾음 — 다른 물체" = 중심을 만든 점들의 8 mm 정답 class 다수가 사과가 아님 (로봇 포함).
- raw cosine 이 모든 patch 에서 0.90–0.99 라 τ 는 0.001 간격으로 고른다 (train 에서만).
- 저장은 float16 (layer 4–16 head token |h| 최대 3.0e3, float16 범위 안). 사건 표본은 줄이지 않는다.

## 7. 결과 (2026-10-31, lead) — "hidden 재탐색이 낫다" 아님

- train 에서 허용 조건을 만족하는 (layer, τ) 0 개 → 선택 설정은 test 사건 98 % 기권 (찾음 0). 어떤 설정도 train 사건 찾음 ≤ 5 %. head patch hidden 과 사과 외형 cosine 이 화면 전체 0.85–0.95.
