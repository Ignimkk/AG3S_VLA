# T46f — DX-04 link-specific target exemption (LTE) 검증 블록: 형상 보정 → 진단 장면 → 3 조건 closed-loop

## 0. T46d 결과의 기록 문구 (사용자 지정)
T46d 는 **"효과 없음" 이 아니다.** 기록은 다음과 같이 한다:
> **현재 gripper scope 에서는 LTE 와 global exclusion 의 비교가 퇴화하며, `link_*_arm_5` 를 추가했을 때 나타난 차이는 형상 근사 오류 (URDF arm_5 capsule 구가 손 영역 안에 놓임) 의 영향을 받는다.**
(근거: `T46d.verify.json` — gripper scope LTE≠global 0 chunk; arm_5 구 87 개가 권한 손 구 중심에서 11–47.5 mm; MJCF arm_5 geom 은 target 에서 > 100 mm, 실제 접촉 0/1296 step; MJCF `FT_SENSOR_*` 는 3–4/18 run 에서 ≤ 50 mm 이고 URDF 구가 덮지 않음.)

## 1. 검증할 가설 (사전 고정)
> **"지정된 link 에만 target 접촉 예외를 적용하면, 필요한 손의 접촉을 유지하면서 비허용 link 의 접촉을 줄일 수 있다."**
- 판정 차이 (LTE ≠ global chunk 수) 는 **메커니즘 설명용 보조 지표**일 뿐 contribution 의 근거가 아니다.
- **주 지표: 비허용 접촉 없는 작업 성공률** (task success ∧ 실제 MuJoCo geom 기준 비허용 link–target 접촉 0).
- 정지 (HOLD · TO 실패) 가 늘어 접촉률이 낮아진 결과는 보호 효과로 해석하지 않는다.
- 정확한 형상과 oracle extent 에서도 LTE 가 주 지표를 개선하지 못하면 그대로 보고하고 가설을 재검토한다. **사후 기준 변경 금지.**

## 2. 접촉 허용의 정의 (명시)
| 구분 | link / 접촉면 | target 에 대한 제약 |
|---|---|---|
| **허용 (authorized)** | active hand 의 손바닥 `ee_<side>` (MJCF `EE_BODY_*`) 와 손가락 `ee_finger_<side>1/2` | LTE 에서 target-free 층 조회 (접촉 허용) |
| **비허용 (non-authorized)** | **`FT_SENSOR_<side>`** (손목 F/T 센서, MJCF `link_*_arm_6` 의 자식 body), `link_*_arm_5` · `link_*_arm_6`, 반대 손 · 팔 | target 을 일반 obstacle 로 (`nonauthorized_target_margin` = obstacle) |
- **FT sensor 비접촉은 이 작업의 요구사항으로 정의한다** (센서 보호). 실제 접촉 판정은 MuJoCo `FT_SENSOR_*` geom 과 target geom 의 contact.
- target 영역 = target 과일 (oracle 단계에서는 T46e 의 **visible observed surface** oracle — 카메라에 실제 보인 target 표면 점에서 온 seed. 전체 형상 (full mesh) oracle 이 아니다). 접촉 허용 link 집합과 target 영역은 서로 다른 축이다.

## 4. 단계 1 — 충돌 형상 보정 (A14, implementer)
1. **FT sensor coverage 구 추가 (비허용).** 기존 coverage 코드 (`gripper_cover.link_surface` · `finger_body_spheres` · `_body_capsules`, T43 FC / T45 palm cover) 를 MJCF `FT_SENSOR_*` mesh 에 재사용. role 을 새로 두고 (예: `wrist_cover`), link 는 비허용 (target 예외 없음).
2. **arm_5 근사 구 보정.** URDF `link_*_arm_5` capsule (r 75 mm, 길이 250 mm) 구가 손 접촉 영역을 침범하지 않도록, MJCF 실제 arm_5 geom 기반 coverage 구로 교체하거나 손 영역과 겹치는 구를 제거. 보정하지 못하면 그 구에 의존한 보호 효과를 주장하지 않는다 (§9 에 기록).
3. **coverage audit (필수):** 각 보정 link 의 MJCF geom 표면 점 중 구 밖 비율 · 밖 거리 (median / p95 / max) = 형상 누락, 구가 geom 밖으로 나간 넘침 (실측 max) = 과도한 팽창, 그리고 **비허용 구와 허용 (손바닥 · 손가락) 구 · MJCF 손 geom 의 겹침**.
4. **새 link 집합** (예: `--links gripper_wrist` = gripper + 보정 arm_5 · arm_6 · FT sensor). 세 조건 · CL4 모든 arm 이 같은 집합을 쓴다 (LTE 에만 coverage 추가 금지).
5. **예외 없음 정책 추가:** `--target-field-policy none` (모든 link 가 target 을 일반 obstacle 로, 권한 link margin 완화도 없음). ② = `exclude_all`, ③ = `exclude_authorized` + `--target-permission-strict` + `--nonauthorized-target-margin obstacle`. 정책 외 조건은 동일.
6. 기본값은 모두 기존 그대로 (off bit-identical), tests, 전체 pytest. **격리 worktree 에서** (T47 측정 보호), 산출 `T46f-A14.impl.md`.

## 5. 단계 2 — 진단 장면 (A15 / V, 형상 보정 뒤)
기존 18 쌍은 **일반 작업 성능 · 부작용 평가**로 유지한다. 별도로 **손의 target 접촉과 FT sensor 회피가 동시에 필요한 진단 장면**을 만든다. 선정 기준 (방법별 결과를 보기 전에 고정):
- (S1) 실제 MuJoCo geom 기준 비허용 (FT sensor · arm) 접촉 위험이 존재 — 정책 rollout 에서 FT sensor–target 최소 표면 거리 ≤ 50 mm 는 **후보 선별 기준**일 뿐 충돌 · 보호 효과의 증거가 아니다.
- (S2) 접근 경로나 손목 자세를 바꾸면 작업 완료가 가능 — 같은 배치에서 다른 손목 yaw / 접근 방향의 성공 시연 (데이터셋 demo 또는 IK/계획 feasibility) 이 1 개 이상.
- (S3) 초기 관통 (t=0 접촉) 이나 구조적으로 성공 불가능한 배치 제외.
- (S4) **개발용 배치와 최종 평가용 배치를 분리** (episode id 로 사전 분할, 예: dev = train split, eval = held-out test split 1800–1999).
- 후보 생성 방법 (사전 고정): E0 (VLA 단독) rollout 과 기존 기록에서 S1 을 만족하는 배치를 찾고, 부족하면 target 을 crate 벽 · 이웃 과일 사이 등 손목이 낮게 들어가야 하는 위치로 옮긴 변형 배치를 규칙으로 생성.

## 6. 단계 3–5 — closed-loop 비교
- 단계 3: **소규모 진단 (dev)** — 회피 가능성 확인 (③ 에서 성공하는 경로가 존재하는가, 측정 장치 정상 여부).
- 단계 4: **oracle extent 로 ① · ② · ③** — 진단 장면 (dev → eval) + 기존 18 쌍.
- 단계 5: 효과가 확인되면 **AG3S extent (ball_owned + F1)** 로 같은 비교 반복.

## 7. 지표 (모든 단계 공통)
주: **비허용 접촉 없는 작업 성공률**. 함께: 일반 task success · 실제 geom 기준 비허용 접촉 발생률 · 지속 시간 (step) · 비허용 link–target 최소 표면 거리 · 정지 (HOLD) · TO 실패율 · 작업 완료 시간 · **실측** TO 계산 시간 · 같은 episode·seed 의 실패→성공 / 성공→실패 쌍 수 (McNemar). 보조: LTE ≠ global chunk 수.

## 8. 진행 · 중단 기준 (대규모 실행 전 사용자 확인)
- 단계 1 audit 에서 FT sensor 형상 누락 (구 밖 표면 비율) 이나 손 영역 침범이 남으면 단계 2 로 넘어가지 않는다.
- 단계 2 에서 S1–S3 를 만족하는 eval 배치가 사전 정한 최소 수 (예: 10) 에 못 미치면 사용자에게 보고하고 장면 생성 규칙을 판정받는다.
- 단계 4 전에 비교 조건 · 장면 수 · 예상 GPU 시간 · 진행/중단 기준을 정리해 **사용자 확인 후** 실행.
