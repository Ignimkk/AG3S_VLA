## 왜 지금 이것인가

T52 에서 두 가지가 측정됐다. 명사 query 는 장면 1800 에서 2D identity 실패가 0/30 이다 (L8H2 7/30). 그러나 명사 map 은 target 과 이웃에 고르게 퍼진다. 그래서 attention split 비율 조건 (≥ 2) 을 넘지 못해 병합 cluster 가 남았다 (L8H6 7/15 · L10H7 10/15 · L8H2 15/15).
→ 가설: **L8H2 가 만든 후보 중에서 target 을 고르는 일만 명사 정보로 바꾸면 identity 는 나아지고 purity 는 지킬 수 있다.** 이 STEP 은 이 가설을 수정에 쓰지 않은 T53 16 episode 에서 검증한다.

## 사전 고정 1 — arm

attention source 고정값 (사용자 판정 4):
- **L8H2** = 서빙 `last:L8H2` (현재 서빙 설정 그대로).
- **명사** = `noun_target:L10H7`, raw σ0, k1. 이것은 "GT 를 사용해 개발 데이터에서 선택한 고정 head" 다. 추론 때 GT 를 쓰는 oracle 은 아니다. **label-free 선택이라고 부르지 않는다.**

| arm | 역할 | lifting · seed · clustering | attention split 비율이 읽는 map | 최종 후보 (target) 선택 점수 |
|---|---|---|---|---|
| **L8H2** | 기준 (서빙) | L8H2 | L8H2 | L8H2 |
| **N** (명사 단독) | 비교 | 명사 | 명사 | 명사 |
| **A** (조합, **주 실험**) | 채택 후보 | **L8H2** | **L8H2** | **명사 map 질량** (후보 cluster 점에 lift 된 명사 attention 합) |
| **B** (조합, 원인 확인용) | 보조 · 채택 근거 아님 | 명사 (seed) | **L8H2** | 명사 |
| ablation `L12H4` · `A-L12H4` | 추가 ablation | L12H4 / L12H4 | L12H4 / L12H4 | L12H4 / 명사 | 
| 보조 `N-k3` · `A-k3` | 기존 방식 연결 | — | — | 명사 = T49 primary (`L8H6` · `L5H4` · `L4H2`, k3 σ1) 로 바꾼 N · A |

- A 는 "**L8H2 가 만든 후보에서 명사 정보로 target 을 더 잘 고를 수 있는가**" 만 검증한다. 선택 점수 말고는 L8H2 arm 과 bit 단위로 같아야 한다. implementer 는 split 전 · 후 cluster 목록이 L8H2 arm 과 같음을 test 로 보인다.
- **A 에는 `target_candidate_present` 를 기록한다.** 선택 직전 후보 cluster 중 엄격한 다수 class 가 target 인 것이 하나라도 있으면 참이다. A 의 실패는 둘로 나눈다. 후보 생성 실패 (`¬present`) 와 명사 선택 실패 (`present ∧ ¬identity_correct`) 다.
- B 의 판단: seed recall 이 높다는 것 (T49 0.995) 만으로 B 가 좋다고 보지 않는다. split 뒤 purity · coverage 를 함께 본다. **B 만 좋게 나오면 A 가설은 지지되지 않은 것으로 기록하고, B 는 별도 후속 후보로 다룬다** (이 STEP 에서 T57 로 보내지 않는다).
- 서빙 gate 와 flag 는 T53 rollout 과 같게 둔다 (C1a flag set, `clustering.placed_no_seed_certify` = off). 모든 arm 에서 같은 값이다.

## 사전 고정 2 — 재생 조건 (사용자 판정 2)

| 조건 | 정의 | 역할 |
|---|---|---|
| **현재 frame (주)** | frame 마다 독립으로 재생한다. `TargetConfirm` 이나 history 없이 그 frame 의 attention 과 point cloud 만 쓴다 | **source 개선 여부 판단** |
| **유지 포함 (보조)** | episode 를 시간 순서로 재생하고 `TargetConfirm` 을 켠다. **각 arm 은 자기 예측으로 자기 history 를 쌓는다.** L8H2 가 기록한 이전 geometry 를 다른 arm 에 넣지 않는다. grasp latch 상태 (freeze) 는 기록된 서빙 chunk 의 값을 모든 arm 에 똑같이 넣는다. 이 값은 grounding 이 아니라 robot feedback 에서 나온다 | 실제 사용 조건에서 개선이 사라지거나 역전되는지 확인 |

- 유지 포함 결과에 각각 유의한 개선을 요구하지 않는다. 기록 재생은 closed-loop 효과의 증명으로 취급하지 않는다. 궤적이 L8H2 서빙의 궤적이라는 점도 한계로 적는다.

## 사전 고정 3 — 지표 (frame 마다, GT = T53 GT cache)

대상 frame = GT 상 target 이 3 camera 중 하나 이상에서 보이는 frame (`has_target`). frame 을 빼서 지표를 좋게 만들지 않는다.

| 지표 | 정의 |
|---|---|
| `identity_correct` | T47 정의. chosen cluster 의 label 점 중 엄격히 가장 많은 class 가 target. **출력 없음 (no target) 도 거짓** |
| `no_target` 비율 | `has_target` 인데 chosen cluster 가 없는 frame 의 비율 |
| purity | chosen cluster 의 label 점 중 target 의 몫. 출력이 있는 frame 에서만 계산하므로 **반드시 `no_target` 비율과 함께 보고한다** |
| coverage | target 관측 점 중 chosen cluster 에 든 비율. **출력 없음 = 0** 으로 모든 `has_target` frame 에서 계산한다 |
| 이웃 혼입 | chosen cluster 안의 GT `other_object` 점 수 (destination · support 는 따로 보고) |
| `target_candidate_present` | A · B · L8H2 · N 모두에서 기록한다 (위 정의) |
| 처리 시간 | frame 당 e2e ms = attention 추출 (명사 행 추가 비용 포함) + lifting · grounding. median · p95. 같은 장치에서 잰다 |

- 중심 거리 (`on_target`) 는 참고로만 보고한다. **성공 판정에 쓰지 않는다** (사용자 판정 3).
- phase 분해는 T53 의 물리 grasp 상태 (`gt/<key>.grasp.npz` 의 `grasp_state`: pre · held · post · placed) 로 한다. 잡은 뒤에도 target 을 찾는 것은 grounding 성능이지 단계 전환의 증거가 아니다.

## 사전 고정 4 — 집계와 불확실성 (사용자 판정 6)

- 단위: **episode 평균** (episode 마다 frame 평균을 낸 뒤 16 episode 를 같은 가중으로). T53 은 episode 하나가 layout 하나이므로 episode = scene 이다.
- 차이: arm − L8H2 의 **episode 별 paired 차이** 와 그 평균.
- CI: **episode block bootstrap** (16 episode 를 복원 추출, B = 10000, seed 5407, percentile 95 %). 민감도로 episode 안 moving block (길이 5 frame) bootstrap 도 보고한다. frame 단위 검정은 참고로만 둔다.
- 장면 1800 은 T52 진단에 쓰였으므로 **최종 판정에 넣지 않는다.**

## 사전 고정 5 — T57 진입 기준 (사용자 판정 3, 2026-10-13)

"최종 채택" 과 "T57 에서 시험할 후보 선정" 을 나눈다. 여기서는 **후보 선정만** 한다. 대상은 A 이고, 현재 frame 조건, T53 16 episode, A − L8H2 기준이다.

| 항목 | 진입 기준 |
|---|---|
| identity | episode 평균 차이 ≥ −3 %p |
| coverage | episode 평균 차이 ≥ −5 %p |
| 개선 근거 | identity 증가 · purity 증가 · 이웃 혼입 감소 중 **하나 이상에서 개선이 관측됨** (purity 는 `no_target` 비율과 함께 본다) |
| 시간 유지 | 유지 포함 조건에서 개선이 사라지거나 역전되는지 확인한다. identity · coverage 에 같은 허용 하락폭 (−3 %p · −5 %p) 을 적용한다 |
| 처리 시간 | 전체 처리 시간을 보고한다. **기존 실행 예산을 넘으면 바로 본 실험으로 확대하지 않는다.** 예산 = T53 서빙 기록 (server `profile_ms`) 에서 현재 L8H2 서빙의 chunk 당 AG3S 처리 시간과 chunk 간격. verifier 가 T54 결과를 열기 전에 이 값을 읽어 `T54.verify.json` 의 `budget` 에 먼저 적는다 |

- −3 %p · −5 %p 는 **실무 허용폭으로 채택한 값이다. 통계적으로 도출한 값이 아니다.** episode 별 paired 차이와 block bootstrap 95 % CI 는 모두 보고하지만, CI 가 0 을 배제해야 T57 에 진입한다는 조건은 두지 않는다.
- 통과해도 "비열등성 · 우월성이 입증됐다" 고 쓰지 않는다. 정확한 표현은 **"offline 개선이 관측돼 closed-loop 확인 대상으로 선정했다"** 다. 차이가 미미하고 CI 가 넓으면 작은 paired pilot 까지만 한다. 최종 채택은 T57 의 작업 성공 · 비허용 접촉 · HOLD 로 정한다.
- **T53 은 평가 집합이다.** T54 결과를 보고 head · σ · 조합 정의를 바꾸면, 그 수정안에 대해서는 T53 을 개발 데이터로 취급한다 (다시 test 로 쓰지 않는다).
