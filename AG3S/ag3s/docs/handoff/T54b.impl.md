## 무엇을 했나 (평이한 요약 먼저)

T54 의 `hold` 재생은 latch flag 만 넣었고 attach / detach 는 재생하지 않았다. 그래서 새 재생 조건 **`hold_attach`** 를 **새 파일 `t54b_hold.py`** 에 만들었다.
- episode 를 시간 순서대로 돈다. `TargetConfirm` 은 켜고, **arm 마다 AG3S 를 하나씩** 둔다.
- frame 마다 서빙 chunk 기록의 값을 모든 arm 에 **같은 순서 · 같은 값으로** 넣는다. 순서는 `SafePolicy._scene_fn` 과 같다:
  1. 손가락 관절
  2. 기록된 grasp event (attach / detach)
  3. latch flag (`set_grasp_active` · `set_grasp_latched` · `set_subtask` · `set_placed` = freeze 상태)
  4. `process_multi_debug`
- attach 의 **시점과 parameter** (손, parent link, 접촉 허용 link, hold link, reach 한계) 는 기록값이다. 모든 arm 에 같다.
- 붙이는 **기하** 는 그 arm 자신의 `AG3S.manipulated` 다. L8H2 서빙 기하를 다른 arm 에 넣지 않는다. 그래서 history 는 arm 별로 따로 쌓인다.

기존 `hold` 는 그대로 남는다 (`t54_replay.py` · `t54_arms.py` 는 T54 와 byte 단위로 같다). 재생 충실도는 `--stage fidelity` 로 낸다. 비교 대상은 L8H2 arm 의 `hold_attach` 행과, 같은 frame 의 서빙 chunk 기록이다 (chosen target · manipulated identity · attached · frozen).

- 새로 생긴 플래그: `t54_study --conditions … hold_attach`, `--attach-reach serving|off` (기본 serving = 기록된 reach 한계), `--stage fidelity` (`--fidelity-arm`, 기본 L8H2), `--out-subdir`, `--extra-rows-dir`, `--hold-condition`, `--entry-arms`. **기본값 변경: 없음.**
- 재생산이 필요한 산출물: 없음. T54 rows 는 읽기만 한다.
- 옛 기록과 호환이 깨지는가: 없음. 출력 JSON 에 key 만 늘었다.
- **한계 (그대로 보고할 것)**
  - 서빙 latch 상태 기계 (`observe_grasp`) 는 arm 별로 다시 돌리지 않는다. 기록된 event 를 넣는다 (사전 고정 2: robot feedback).
  - 어떤 arm 의 manipulated 가 usable 이 아니거나 reach 밖이라 attach 가 거절되는 경우가 있다. 서빙이라면 `revert_attach` 로 latch 가 CLOSING 으로 돌아간다. 재생은 기록된 flag 를 계속 넣는다. 이런 frame 은 `attach_outcome.attach_result = "rejected"` 로 보인다.
  - 재생 궤적은 모든 arm 에서 서빙 (L8H2) 궤적이다. ESDF 는 legacy (CPU) 이고, `execution_path` · `active_manipulators` 는 재생하지 않는다 (T54 c1a profile 과 같다).
  - `--frames` 로 일부 frame 만 돌리면 history 가 그 frame 부터 시작한다 (smoke 전용).
- CPU 만 쓴다. GPU lock 은 필요 없다. worker 당 peak RSS 는 약 6 GB 다 (smoke 실측, 8 arm 이면 T54 `hold` 와 비슷한 4–6 GB). 4 worker ≤ 24 GB.
