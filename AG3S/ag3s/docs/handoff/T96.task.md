## 0. 왜 (우선순위 1 · 2 의 증거 요약 — 출처 링크)

```
depth → 로봇 mask → ATS [attention → 표면 영역 (T78)] → LTE [손 층 = target 을 지운 미세 거리장]
      → CCR [쥐는 손 손바닥 · 손가락 행만 손 층을 봄 → SQP → 검사 → 실행 / HOLD]
                ↑ 이 STEP: (A) 손 층에서 지우는 범위 = 영역의 "닫힌 부피"   (B) 손바닥 구 = 실제 mesh 크기
```

- **손바닥 구 부족:** 서버 시작 경고 "손바닥 몸체 구 6 mm, 덮으려면 33 mm, 27 mm 부족" (`AG3S/ag3s/robot_models/urdf_sphere_chain.py:66`). 기둥 두 개 장면의 손바닥 몸체 (`EE_BODY_L`) ↔ 작은 기둥 접촉 9 / 9 run (`outputs/2026-10-28_기둥두개장면_손바닥접촉_4구성x3_closedloop/README.md`).
- **손바닥을 제대로 덮으면 못 쥔다:** 1345 palm cover 1 episode — 오렌지 접촉 0, 쥐지 못함 (`outputs/2026-10-25_손바닥구_palmcover/README.md`). 같은 기록의 offline 표: 손바닥 URDF 굵기에서 요청 13 손바닥–target 0.6 mm · 접촉 영역 바깥 여유 음수 (`AG3S/ag3s/docs/handoff/AG3S-PALM-COVER-1345.verify.json`) = **손바닥 구가 target 잔여에 걸림** + 그 요청 손바닥 mesh–오렌지 0.76 mm (이웃도 가까움).
- **target 표면 표본 제외의 잔여:** 손 층 사과 voxel 잔여 (바닥 띠 제외) 기준 재생 13.5 %, hull · 유지 기억 · 접촉 여유가 최대 −2 %p 줄이면서 추가로 지운 voxel 의 21–26 % 가 이웃 과일 → 사전 기준 미통과 (`outputs/2026-11-03_T87_표면추출위_기능따로재기_HSR5단계/README.md` "고정 입력 재생").
- **그런데 hull · 접촉 여유를 빼면 closed-loop 이 무너진다:** T92b 9 run 17 / 18 → 11 / 18 (`outputs/2026-11-03_T92b_P0m확정_seed반복_hull접촉여유짝비교/README.md`). 즉 지금 두 기능은 "이웃까지 같이 지우는 대가로" 쥐기를 살린다.
- **이 STEP 의 가설:** target 소유 부피를 한 원리 (받침면까지 내린 닫힌 부피 − 이웃 관측 표면 τ 띠) 로 정하면, (i) 잔여가 줄고 (ii) 이웃은 τ 보호로 남는다. 잔여가 줄어야 실제 크기 손바닥 구가 target 에 걸리지 않는다. 둘은 따로 넣으면 각각 실패했다 (손바닥만: 위 1345 · 기둥 두 개 껍질 구, 지우기만: T87).
- **주의 — 기둥 두 개 장면은 기하적으로 못 쥘 수 있다:** 껍질 구 3 seed 모두 "기둥이 손바닥 들어갈 자리를 막아 접촉 없이 쥘 자세 없음, GIK 분석과 같은 결론" (같은 README). VLA 단독도 3 / 3 접촉. 그래서 §3.0 에서 쥘 수 있는 자세가 있는지 먼저 확인한다.

## 1. 구현 (→ `ag3s-implementer`)

### 1.1 (A) target solid 소유 — `--surface-solid-owned` (기본 꺼짐), `esdf.surface_solid_owned: bool = False`

- 전제: `--target-extent attention-surface --surface-keep-last --surface-no-ball` (P0m). 이것 없이 켜면 거절 (fail loudly).
- **부피 정의 (한 규칙):** 직전 채택 영역 (`_surface_hull_store` 가 저장하는 영역 node 위치, 없으면 아무것도 안 함) 의 점 `R` 과, 그 점들을 받침면 평면 (영역 중심 아래 RANSAC 평면, `_support_plane_z` 와 같은 평면 · normal) 에 수직으로 내린 점 `R⊥` 의 합집합의 convex hull = **target solid `S`**. 받침면 발자국 (footprint) 안 · 표면과 받침면 사이 · 안 보인 뒷면 (닫힌 물체 가정) 을 모두 담는다. 사과 전용 기하 (구) 는 쓰지 않는다.
- **지우는 voxel (손 층 미세 tier 의 seed):** `x ∈ S ⊕ δ` (S 바깥으로 거리 δ 안, `--surface-solid-dilate-mm δ`, 기본 0) ∧ `z ≥ z_floor` (지금 guard 그대로 — 탁자를 지우지 않는다) ∧ **`d_N(x) > τ`** ∧ `d_T(x) ≤ d_N(x)`.
  - `d_N` = 가장 가까운 **비 target 관측 표면 표본** (지금 `OracleVisibleEvidence.other_points` = 표면 기억의 code ≠ target 표본; 로봇 · 받침면 표본은 빼고 쓰는지 확인해 impl.md 에 적는다). `d_T` = 가장 가까운 target 표본 (영역 표본 ∪ `R⊥`).
  - `τ` = `--surface-solid-protect-mm` (기본 5 = "이웃 ≥ 5 mm" 가정과 같은 값, METHOD_GUIDE §7.1 경계 띠 τ). **τ 안의 voxel 은 어떤 길로도 지우지 않는다** (지금의 표면 · 띠 길 포함 — 이 flag 가 켜지면 기존 두 길에도 τ 보호를 건다).
  - 지금의 표면 · 띠 길은 그대로 합집합으로 남긴다 (τ 보호만 추가).
- **대체 관계:** `--surface-solid-owned` 는 `--surface-hull-fill` · `--surface-contact-allowance-mm` · `--surface-memory-target-sticky` 와 함께 주면 거절한다 (세 heuristic 을 한 원리로 바꾸는 것이 목적 — 같이 켜면 무엇의 효과인지 못 가른다).
- **창:** 구간 제한 없음 (손 층은 쥐는 손 권한 행만 본다 — 지금 구조 그대로). 쥐는 중 영역 고정 (`--surface-grasp-hold`) 그대로.
- **기록:** `target_exclusion.attention_surface.solid` 아래 JSON — hull 부피 cm³ · `R⊥` 점 수 · 지운 seed 수 (길별: 표면 · 띠 · solid · dilate) · τ 로 보호된 seed 수 · 시간 ms. 지금 hull fill 기록 형식 (`stats["target_free"]["hull_fill"]`) 을 따른다.
- 시간: 요청당 추가 p95 ≤ 20 ms (CPU, 지금 경로). 넘으면 GPU 이식은 하지 않고 수치만 보고.

### 1.2 (B) 실제 크기 손바닥 구 — 기존 `--palm-cover on` 을 쓰고, P0m 과의 조합만 확인

- 새 구 모델을 만들지 않는다. `--palm-cover on` (T45 A10, `serve_safe.py:696–731`) 이 손바닥 collision mesh 전부를 담는다. `--palm-shell` 과 같이 못 쓰므로 (`serve_safe.py:3858`) 조합은 `--palm-cover on` + `--palm-shell` 뺌 (+ `--palm-shell-margin` 뺌).
- 확인할 것 (impl.md 에 수치): P0m 인자 + `--palm-cover on` 으로 서버 시작 시 경고 ("… 부족") 가 사라지는지, 구 수 (기록상 466), TrajOpt 풀이 시간 (요청 중앙 · p95, 같은 고정 입력 몇 요청), palm cover 구에 걸리는 여유 (`--obstacle-margin 0.010` 행 규칙: target · 지지면 · 쥔 물체 행 0) 가 palm shell 과 같은 규칙인지.
- **target 에 한한 접촉 허용 = (A) 의 δ:** 쥐는 손 손바닥 · 손가락 행은 손 층 (target solid ⊕ δ 를 지운 층) 만 보므로, target 표면과는 여유 0 (δ = 0) 또는 δ mm 관통이 허용된다. 이웃은 τ 보호로 그대로 장애물 (여유 10 mm, P0m 의 이웃 허용 규칙 그대로). 따로 새 규칙을 만들지 않는다 — 다르게 해야 할 이유가 코드에서 보이면 구현 전에 lead 에게 알린다.

### 3.1 고정 입력 재생 (shared lock) — 기능 자체 효과

- 입력: T87 재생 입력 (B0 closed-loop k0 요청, 허들 211 제외 9 run). 정의 · 도구는 T87 재생 정의 그대로 (`outputs/2026-11-03_T87_…/재생_고정입력/README_definitions.md`; 쥐기 창 · `frac_left_nb` 바닥 띠 6 mm 제외 · freed 분류 · HOLD 뒤집힘).
- arm: R0 = 기능 없음 (T87 B0p 와 같은 표면 추출만, 비교 기준), R1 = P0m 의 손 층 (hull + 접촉 여유 10), R2 = solid τ 5 · δ 0, R3 = solid τ 5 · δ 5, R2p = R2 + `--palm-cover on` (HOLD · 여유만).
- **통과 (R2 · R3 각각, 둘 다):** (1) 쥐기 창 남은 target voxel (바닥 띠 제외) 요청 중앙 **< 5 %**, (2) R0 대비 추가로 지운 voxel 중 이웃 과일 + 탁자 + 바구니 **≤ 5 %**. 보고: R1 대비 같은 값, 장면별, 회귀 211 (붙은 바나나) 따로.

### 3.2 closed-loop (exclusive lock, 서버 1 개, `--stop-after-place 2.5`)

| 장면 묶음 | run | 구성 |
|---|---|---|
| 기존 9 run (허들 211 제외) × seed k0 · k1 | 18 | Q (P0m 은 T92b 결과 재사용 — §3.3 조건) |
| 1345 오렌지 × seed 13453 · 23453 · 33453 | 3 | P0m · Q · Q−손바닥 · P0m+손바닥 · Qb |
| 기둥 두 개 (라운드 6) × 같은 3 seed | 3 | 같은 5 구성 |

- 순서: Q 의 1345 · 기둥 6 run → 나머지 4 구성 각 6 run → Q 9 run k0 · k1. 약 48 run.
- 주 지표: 금지 접촉 없는 성공 (새 정의 = D2, 옛 정의도). 보조: 손바닥 몸체 (`EE_BODY_*`) –장애물 접촉 step 수, 쥐기 창 HOLD 요청 수, 쥐기 창 남은 target voxel (바닥 띠 제외).
- **판정 (Q 기준, 모두):**
  1. 9 run 합계 (k0 + k1) **≥ 16 / 18**, 금지 접촉 run ≤ 1, 탁자 · 바구니 0 (P0m 확정 조건과 같다).
  2. 1345 · 기둥 두 개 6 run 모두 **손바닥–장애물 접촉 0**.
  3. 1345 · 기둥 두 개 각 장면 **쥐기 성공 (정답 쥠) ≥ 2 / 3** — §3.0 에서 불가로 나온 장면은 이 조건에서 뺀다.
- **짝 가설 판정 (보고만):** 1345 · 기둥 6 run 에서 Q 가 Q−손바닥 · P0m+손바닥 둘 다보다 (접촉 0 ∧ 쥐기 성공) run 수가 많으면 "짝으로 넣어야 한다" 를 지지. 차이 ≤ 1 run 은 "구분 못 함".
- 실패 run 마다 첫 사건 (T87 §2.1 분류 a–d) 과 원인 층 (ATS · HSR · LTE · CCR, 궤적 = TrajOpt · 관측 · 기하 = AG3S) 을 적는다. HOLD 증가는 보호가 아니다.
- **채택은 사용자 판정** — 기준 계산 · outputs · 원인 층 진단까지 lead 가 하고 "채택할지" 를 묻는다.

## 5. 이 STEP 이 답하는 질문

## 6. 되돌아올 지점

- 재생 미통과 → 원인이 τ 띠 (붙은 이웃) 면 T97 (오목 꺾임 경계) 결과를 기다린다. 안 보인 면이면 `R⊥` 대신 카메라 광선 기반 "관측되지 않은 뒤쪽" 정의를 검토 (우선순위 7 (c)).
- closed-loop 에서 Q 가 9 run 을 잃으면 (≤ 15 / 18) P0m 유지, 손바닥 모델만 따로 원인 확인.
