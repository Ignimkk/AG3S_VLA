# SL11 §5 (latch 개도를 두 손가락 간격으로) — 구현

> writer: ag3s-implementer · 읽는 쪽: verifier, scribe, lead
> worktree `.runtime/worktrees/sl11-latch` (branch `wip/sl11-latch`, base main 67613cf1). GPU·서버 프로세스·push 없음.

## 무엇을 했나 (평이한 요약 먼저)
`--gripper-gap-opening` (기본 꺼짐, Panda만) 을 켜면 grasp latch가 읽는 측정 개도가 `abs(q1)/0.04` 가 아니라 `clip((q1 − q2)/0.08)` 이다.
서버가 매 요청의 `panda/robot_state` 로 exec feedback의 `measured_gripper[0]` 만 바꿔 latch에 준다 (정책에 주는 `state` 개도와 손가락 모델은 그대로).
개도 척도가 바뀌므로 개도로 "빈손"을 읽는 문턱 셋을 새 척도로 다시 두었다 (`robots/panda/description/gripper_gap_calibration.json`).

**빈손 판정은 간격 하나로 하지 않는다.** 기록에서 확인한 사실 두 가지가 기준을 정했다.
1. **손가락 사이 관측 점은 쓸 수 없다.** 두 기록의 `raw_cloud` 에서 EE(그립 위치)에서 가장 가까운 점이 59–62 mm 밖이다 (로봇 mask · self-filter + 가림).
   10 / 20 mm 구와 손가락 사이 슬랩 안의 점 수가 쥔 call · 빈손 call 모두 0이라 분리력이 없다 (AUC 0.5).
   손가락 접촉 신호는 요청에 없다.
2. **쓸 수 있는 둘째 증거는 (a) 명령 대비 손가락 정지 (settled ∧ 닫힘 명령 ∧ 개도 − 명령 ≥ blocked_gap), (b) 물체 존재 증거 (reach · 관측 centroid) 다.**
   기록에서 닫힌 손은 기계적 정지 간격 0.9996 mm (448 프레임) 에 서지만, 대상이 12 cm 이상 떨어진 빈손 닫힘도 1.4–3 mm 에 서는 경우가 많다.
   그래서 attach 문턱은 정지 간격이 아니라 **3.2 mm (0.04)** 로 잡고, 얇은 틈(< 3.2 mm)은 attach 시키지 않는다.
   HSR6 attach-assist 는 `closed ∧ blocked` 만 봐서 대상이 22–33 cm 떨어진 빈손 닫힘을 단계 오인(lift)만으로 attach 했으므로, `reach` 검사도 요구한다.
   이미 attach 된 얇은 쥠은 관측 centroid 가 쥔 구 안이면 (`observed_at_hand`) 회수 창에서 `not_blocked` 로 취소하지 않는다.

## 요구 2 — 빈손 판정 기준과 분리 숫자
정의는 `held_check.py` 와 같다 (정답 "손에 있음" = 대상이 처음 높이보다 3 cm 넘게 들렸고 EE 10 cm 안). 빈손 쪽은 정답이 없어서 "손에 없음 · 대상이 EE 에서 12 cm 이상 (손가락 사이에 대상이 있을 수 없음)" 을 `target_far` 로 썼다.
표는 정착한 닫힘 call (마지막 실행 명령 < 0.1, 간격 변화 < 1.6 mm, 간격 < 12 mm) 만 센다.

| 간격 구간 | LIBERO 9: 손에 있음 / target_far / 대상 근처·안 들림 | LIBERO-Safety 10: 손에 있음 / target_far / 대상 근처·안 들림 |
|---|---|---|
| < 1.35 mm (정지) | 0 / 3 / 0 | 2\* / 6 / 0 |
| 1.35–3.2 mm | 0 / 5 / 0 | 4 / 17 / 6 |
| 3.2–6 mm | 38 / 0 / 30 | 219 / 0 / 3 |
| 6–12 mm | 8 / 0 / 7 | 0 / 0 / 1 |

\* LS obstacle e2 call 49·50: 대상이 3.6 cm 높이의 받침 위에 정지, 손은 8.7–9.6 cm 떨어져 닫혀 있다 — "손에 있음" 정의의 오분류로 본다.

| 기준 (정착한 닫힘 call) | 손에 있음 통과 | target_far 통과 (= 빈손을 비어 있지 않다고 읽음) |
|---|---|---|
| 옛: `abs(q1)/0.04 ≥ 0.0253` | LIBERO 46/46 · LS 221/225 | LIBERO **4/8** · LS **7/23** |
| 새: `(q1−q2)/0.08 ≥ 0.04` (3.2 mm) | LIBERO 46/46 · LS 219/225 | LIBERO **0/8** · LS **0/23** |
| (참고) `(q1−q2)/0.08 ≥ 0.01678` (1.35 mm) | LIBERO 46/46 · LS 223/225 | LIBERO 5/8 · LS 18/23 |

읽는 법: 정지 간격 바로 위(1.35 mm)에 문턱을 두면 빈손을 못 거른다. 3.2 mm 로 두면 빈손은 다 거르고 쥔 call 은 LS 6/225 (얇은 틈 4 + 위 \* 2) 만 놓친다.
LS 에서 간격 하나로 갈리지 않는 구간은 1.35–3.2 mm 다 (쥠 4 : target_far 17 : 근처 6) — 이 구간에서는 attach 하지 않고, 이미 attach 된 쥠은 관측 / reach 근거가 있을 때만 유지한다.
문턱은 분포에서 정했다 (정지 0.0125 · 쥔 call 의 5 백분위 3.4 mm · 모호 구간 위끝 3.2 mm), replay 결과로 맞추지 않았다.
`hold_empty_below` 0.01678 은 정지(0.0125)와 가장 얇은 쥠(1.69 mm = 0.0211)의 중간이다.

**한계 (솔직하게).** 얇은 틈에서 "관측 점 / 접촉" 같은 직접 증거는 기록에 없다. 간격 1.35–3.2 mm 의 실제 쥠 (사용자가 든 obstacle e2 call 16 · human e2 call 22 의 2 mm 쥠) 은
  - attach 시점에는 놓친다 (이 구간은 빈손이 4배 많다).
  - 이미 attach 된 뒤라면 `observed_at_hand` 가 있거나 회수 창이 지난 뒤에만 유지된다. 창 안에서 관측이 없으면 `not_blocked` 로 취소된다 (테스트로 고정).
  - 참고: 사용자 사례 중 human e2 call 22 는 대상이 EE 에서 26 cm 떨어져 있어 (취소 이유도 `observed_elsewhere`, `not_following`) 간격과 무관한 취소였다.

## 요구 3 — offline replay 추정 (`panda_latch_replay.py`)
**추정일 뿐이다.** 입력은 옛 latch 로 돈 closed loop 의 기록이다 (손 · 물체 궤적이 옛 것이고 PLACED 는 끝 상태라 한 번 놓으면 replay 에서 다시 쥘 수 없다). 닫힌 루프가 결정한다.
충실도: 옛 latch · 옛 개도로 돌리면 **기록과 같은 숫자가 재현된다** (LIBERO 37/50 = 0.74, LS 185/419 = 0.4415; 기록된 상태와 일치하는 call 287/296 · 1115/1125; 남은 차이는 `AG3S.attach` 거절과 SEARCHING→LATCHED 잠금을 기록에서 가져오는 단순화).

| | LIBERO 9 (옛 → 새) | LIBERO-Safety 10 (옛 → 새) |
|---|---|---|
| 손에 있는 call 중 HELD | 37/50 = 0.74 → **50/50 = 1.00** | 185/419 = 0.44 → 213/419 = **0.51** |
| 같은 분모: 새 replay 의 첫 놓음 전 | 37/50 → 50/50 | 185/213 = 0.87 → **213/213 = 1.00** |
| 놓은 뒤 "손에 있음" (끝 상태 PLACED 라 replay 불가) | 0 | 206 (옛 176) |
| 빈손 HELD (손에 없음 ∧ HELD) | 38 → 46 | 20 → 48 |
| 그중 대상이 EE 12 cm 이상 (확실한 빈손) | 0 → **0** | 6 → **15** (+9) |

- LS 0.51 의 206 call 은 전부 놓은 뒤다: affordance e0 72 + human e2 62 는 놓은 물체가 높은 곳에 남아 "손에 있음" 정의가 과대 계산한 것 (README 의 지적), obstacle e0 의 42 는 놓은 뒤 다시 쥐는 구간으로 replay 는 재현할 수 없다. 이 분모를 빼면 1.00 이다. 정의대로의 0.51 은 LS ≥ 0.8 에 못 미치므로 닫힌 루프에서 봐야 한다.
- **빈손 HELD 는 늘었다 (LS 확실한 빈손 6 → 15).** 모두 같은 두 경로다: (i) 대상이 15–19 cm 떨어졌는데 sticky reach 가 앞서 통과해 attach-assist 가 attach (obstacle e2 call 25, human e2 call 20), (ii) 진짜 쥠이 떨어진 뒤 (obstacle e1 call 46 이후) 손이 열리기 전까지 HELD 가 유지 (옛 latch 는 애초에 쥐지 못했다). 판정 규칙 "빈손 HELD 가 기준보다 늘지 않아야 한다" 를 LS 에서는 만족하지 못한다. 문턱을 올리면 (0.05) 쥔 call 도 같이 잃는다 (LIBERO 25/50). 이 추정은 lead 에게 사실로 넘긴다.
- "HELD 인데 손에 없음" 의 증가분 일부는 맞는 HELD 다 (쥔 뒤 3 cm 들리기 전; 옛 latch 는 못 쥐었다).
