> 사용자 지시 (2026-10-30 ~06:55 KST): "그럼 E0로 목적함수 ablation 다시 진행해봐".

## 0. 왜

- T71: 쥐기 전 꺾임 변화율 (B) · 연속성 (C) 을 끈 R1 · R2 · R3 이 1 단계를 통과했다 (6 / 10, 최종 구성 4 / 10).
  - 그러나 회귀 211 에서 로봇–바구니 접촉이 났다.
  - 회귀 211 · 가림 121 에서 쥔 직후 사과를 2–3 배 빠르게 들어올렸다 (`outputs/2026-10-30_T71_쥔직후_급상승_확인/`).
- 그 급변 3 건 중 2 건 (회귀 211, 회귀 954 R2) 은 여러 초기값 풀이가 켜졌다. 표준 풀이가 위반 9.3 · 21.2 mm 를 남겼고, 다른 초기값의 해가 VLA 계획을 7.9–12° 꺾었다.
- 그래서 TrajOpt 를 AG3S-PRE-CORE-TO 의 E0 (표준 SQP 풀이 하나, 여러 초기값 · 쥐기 목표 항 없음) 로 바꾸고, T71 과 같은 목적함수 조합을 다시 잰다.

## 1. 구성 (구현 없음, 인자만)

- **E0 TrajOpt** = 최종 구성 서버 인자에서 아래 두 묶음만 뺀다.
  - 여러 초기값 풀이: `--to-multi-seed 16 --to-gpu-seeds curobo --to-gpu-seeds-check first-pass` (기본 0 = 꺼짐).
  - 쥐기 목표 항: `--grasp-anchor 2000 --grasp-anchor-path-weight 0` (T68 에서 실제 작동 0 으로 확인).
  - 나머지 (AG3S 모듈 · palm shell · 기하 보정 · HSR6 · 이웃 손바닥 허용 · 손목 추종 배율) 는 최종 구성 그대로다.
  - 표준 풀이가 위반을 못 풀면 그 chunk 는 HOLD (정지) 가 된다. HOLD 증가는 보호로 세지 않는다.

## 2. 장면 (T71 과 같은 10 run, 같은 seed)

- 최종 구성 실패 6: 회귀 211 · 954 흔들림 없음, 가림 122, 허들 954 · 1345 · 211 흔들림 없음.

## 3. 지표 (T71 과 같음)

- 주 지표: 금지 접촉 없는 성공 (T67 §4 정의, 허들은 이웃 과일 재생 접촉 포함).
- 금지 접촉 run, 탁자 · 바구니 접촉 run.
- 보조 (보고만):
  - 쥔 직후 급변 run 수: 첫 held 요청 뒤 2 s 동안 사과 최대 상승 속도 > 300 mm/s. VLA 단독 허들 최대값은 199 mm/s 다.
  - 첫 held 요청의 꺾임.
  - HOLD 요청 수.
  - 닫기 시작 손바닥–사과 거리.

## 4. 판정 (결과 전 고정)

- 비교 기준: T71 R0 (최종 구성): 성공 4 / 10, 금지 1, 탁자 · 바구니 0.
  - closed-loop 이 bit 단위로 재현됨을 T71 에서 확인했다 (f = 0). 그래서 단일 run 비교를 쓰고 대조군 재실행은 하지 않는다.
- **통과 (Q0 · Q1 · Q2 · Q3 각각, 모두 충족):**
  1. 금지 접촉 없는 성공 ≥ 6 (= R0 + 2)
  2. 금지 접촉 run ≤ 1
  3. 탁자 · 바구니 접촉 run = 0
  4. 성공 유지 4 run 을 잃지 않음
- 조건 3 은 T71 에 없던 조건이다. 32 run 채택 조건 "탁자 · 바구니 0" 을 결정적 재현 때문에 1 단계에서 미리 거른다.
- 여럿 통과하면 성공이 많은 쪽을 고른다. 차이 ≤ 1 이면 바꾼 것이 적은 쪽 (Q0 > Q1 > Q2 > Q3).
- 통과한 구성이 있으면 사용자에게 보고하고 32 run 확인 여부를 묻는다.
  - 채택 조건: ≥ 23 / 32 · 금지 ≤ 3 · 탁자 · 바구니 0 · 9 장면 ≥ 14 · 허들 ≥ 6.
- TrajOpt 효과 (Q0 대 R0) 와 목적함수 효과 (E0 위의 Q0 → Q3) 는 통과 여부와 관계없이 run 별로 보고한다.
