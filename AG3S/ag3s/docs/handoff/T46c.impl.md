## 무엇을 했나 (평이한 요약 먼저)

**목적.** 과일을 놓고 home 으로 가는 중에, VLA attention 의 상위 seed 가 전부 테이블 위에 떨어지는 frame 이 있다.
지지면 mask 가 그 seed 를 지우면 seed 가 0 이 되어 grounding 이 `no_seed` 가 된다.
같은 상황의 `no_admissible` (보이는 것이 crate 뿐) 은 SUBTASK-f 가 이미 "인증된 기하" 로 본다. `no_seed` 는 그 목록에 없었다.
그래서 위반 행이 0 이어도 "기하 인증 없음" 으로 HOLD 가 났다. 몇 run 은 episode 끝까지 멈춰 있었다 (T46b: C1a 37 · C1a+F1 129 · C1a+F1+F2 116 chunk).
W1 은 **같은 SUBTASK-f 조건 아래서** `no_seed` 도 인증하는 flag 다. **기본은 off** 이고, off 면 예전과 비트로 같다.

**이전 대비 무엇이 바뀌나.** V11AB · C1a · C1a+F1 의 서버 명령줄은 그대로면 동작이 하나도 바뀌지 않는다 (flag 를 주지 않으면 키도 생기지 않는다).

2. **`no_seed` 는 `no_admissible` 보다 근거가 약하다.** `no_admissible` 은 "cluster 를 보고 잡을 것이 없다고 판단했다" 이다. `no_seed` 는 "attention 이 지지면만 본다" 이고, 지지면 밖 물체를 하나도 보지 않았다는 뜻은 아니다.

   - 남는 위험은 "field 자체가 물체를 놓쳤다" 인데, 이것은 `validity` (degraded / incomplete) 가 따로 막는다 (W1 은 `valid` 에서만 연다).
3. **조건에 `released` 를 넣지 않았다** (SUBTASK-f 와 같다). 놓은 뒤 B3 해제를 거치지 않은 episode 도 이 칸에 든다. carve 가 없다는 조건은 그대로 걸린다.
4. W1 은 `home` 만 연다. CL3 placed `no_seed` 는 전부 `home` 이었다 (`place` 칸 0). `place` 로 넓힐 근거는 없다.
