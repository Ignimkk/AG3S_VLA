## 무엇을 했나 (평이한 요약 먼저)

VLA prefix 의 prompt 명사 token 이 image 를 보는 attention 을 꺼내는 study 를 새 파일 셋으로 만들었다.
GPU 단계 (`extract`) 는 checkpoint 를 serving 과 같은 방식으로 load 한다. 그 뒤 frame 마다 prefix pass 를 **한 번** 돈다.
그 pass 에서 target 명사 · `basket` · 마지막 text token, 이 세 query row 의 image 768 열만 jit 안에서 잘라 host 로 옮긴다.
결과는 frame 단위로 cache 에 쓰므로 중간에 끊겨도 이어서 돌 수 있다.
prompt 교체 variant (target 명사를 scene 의 다른 과일로 바꾼 prompt) 도 같은 경로로 뽑는다.
CPU 단계는 다섯이다: `tokens` (명사 위치 점검) · `select` (GT primary + label-free secondary) · `validate` (2D, 목적지 map,
mass 배분, 분리 지표) · `swap` (prompt 교체) · `e2e` (3D, T47b B2 label 지표 포함). 이 단계들은 T47 · T47b 의 함수를 import 해서 재사용한다.
**기존 파일은 하나도 고치지 않았다.** GPU 는 쓰지 않았고 checkpoint 의 params 도 load 하지 않았다.
MuJoCo 도 돌리지 않았다. CPU tokenizer 로 실제 기록 prompt (prompt 교체 variant 포함) 1040 (frame, prompt) 의
명사 index 를 검증했고, 오류는 0 이었다 (아래 "명사 index 검증").

- **query 3 개** (`QUERY_NAMES`): `target` (그 variant 의 과일 명사), `basket`, `last_text` (마지막 valid token =
  `"Action:"` 뒤의 `"▁"`, exploratory). 세 row 를 한 executable 로 뽑으므로 compile 은 한 번이다. `last_text` 를 같이
  남긴 이유는 task "되돌아올 지점" (명사 row 에 image mass 가 없을 때 query 를 바꾸는 것) 에서 GPU 를 다시 돌리지
  않기 위해서다. 선택이나 판정에는 쓰지 않는다.
- **mass 요약**: `image_mass` = image 768 열의 합, `text_mass` = text 열 전체의 합 (BOS 포함; padding 열은 softmax 에서
  mask 돼 ≈ 0), `bos` = 열 768, `self` = 자기 열. `image + text` 는 1 이어야 한다 (`mass_summary` 가 최대 편차를 보고한다).
- 출력 `extract/<variant>/<record>.npz`: `maps (F, 3 query, 18, 8, 3 camera, 16, 16)` float16 · `image_mass` ·
  `text_mass` · `bos` · `self` `(F, 3, 18, 8)` float32 · `token_index` · `prefix_row` · `token_id` `(F, 3)` · `ok` ·
  `error` · `prefix_ms` · `n_text_valid` · `t_step` · `stamp` (variant · record · prompt · noun · checkpoint · config ·
  record fingerprint · frame 수). frame cache 는 `extract/<variant>/<record>.frames/f0000.npz` 이고 atomic 으로 쓴다.
  stamp 가 다르면 거절한다. record 가 다 모이면 npz 로 조립하고 frame 디렉터리를 지운다 (`--keep-frames` 이면 남긴다).
- **안전장치**: `extract` 는 `nvidia-smi` 에 compute process 가 하나라도 있으면 시작하지 않는다 (`--allow-busy-gpu` 로만
  넘긴다. 어떤 process 도 건드리지 않는다). jax backend 가 gpu 가 아니어도 거절한다.
  `XLA_PYTHON_CLIENT_PREALLOCATE=false` · `XLA_FLAGS=--xla_gpu_enable_command_buffer=` 는 setdefault 로 둔다.
- **비용 (#8)** `_cost`: 첫 orig record 의 앞 `--cost-frames` (기본 10) frame 을 noun pass 와
  `AttentionSampler(policy._model).attention(obs, [0])` 에 각각 통과시켜 잰다. 후자는 `attention_policy` 가 serving 에서
  부르는 것과 같은 호출이고 prefix + suffix 10 회다. 앞 2 frame 은 compile 때문에 뺀다. 둘 다 preprocess 를 포함한다.

## phase 정의 (T47b 그대로)

`phase_for(t_step, phase_boundaries_for_path(record))` (`policy_record.py:555-600`, 경계는 **기록 전체**의 gripper
관측에서 뽑는다) → `t47b_metrics.phase_group` (`t47b_metrics.py:76-82`): `"grasp"` 이면 `post_grasp`, `transit ·
approach · pre_grasp` 이면 `pre_grasp`. T49 의 `phase_groups` (`t49_noun_query.py:149`) 가 이 두 함수를 호출한다.
e2e row 의 `phase_group` 은 `run_b2_record` 가 같은 함수로 붙인다. 경계와 그 근거 (`evidence`) 는 `validate.json` 의
`phase_boundaries` 에 남는다.

## prompt 교체 (exploratory)

- 문장: record 의 `meta.json` prompt (= action npz prompt, `check_pairing` 이 같음을 확인) 에서 target 단어를 **단어
  경계 정규식으로 정확히 한 번** 바꾼다 (`swap_prompt`; 0 회 · 2 회 이상이면 예외). 예:
  `"Place the apple into the basket."` → `"Place the pear into the basket."`,
  `"Pick up the banana and place it in the basket."` → `"Pick up the apple and place it in the basket."`.
  나머지 (state 문자열, 이미지) 는 원 frame 그대로다.
- 과일: scene 의 과일 body `apple · banana · orange · pear` (`t47_replay.FRUITS`, GT cache `named_bodies` / `body_cov`) 중
  target 이 아닌 **세 개 모두**를 쓴다. 기본은 7 record 전부이고 (`--swap-records` 로 줄일 수 있다) variant 이름은 `swap_<fruit>` 다.
  apple record (long · t2 · ep1807 · headfix · ep1800) 은 banana · orange · pear 로, ep1850 (banana) 은 apple · orange · pear 로,
  ep1900 (pear) 은 apple · banana · orange 로 바꾼다.
- 지표 (`swap_frame`): GT cache `body_cov` / `body_px` 의 새 과일 · 원 target body 로 잰다. 두 map (원 prompt · 교체 prompt)
  각각의 joint peak 가 새 과일 / 원 target 위에 있는가 (coverage > 0.05) 를 본다. `moved` = 원 map peak 가 원 target 위에
  있고 **동시에** 교체 map peak 가 새 과일 위에 있음이다 (둘 다 ≥ 200 px 보이는 frame 에서). camera 별 lift (body ≥ 200 px 인
  camera 평균), `lift_new_gain` (교체 − 원, 새 과일 lift), 두 map 의 Pearson 상관도 낸다. cell 은 select 의 `noun_gt` · `noun_lf` 와
  head-average 다. 같은 교체에서 `basket` map 이 얼마나 안정적인지 (상관, crate lift 원/교체) 도 따로 낸다.

## 명사 index 검증 (CPU, 실제 prompt)

`--stage tokens` 를 `.venv-openpi-live` CPU 로 돌렸다 (`JAX_PLATFORMS=cpu CUDA_VISIBLE_DEVICES=`). params 는 load 하지
않았다. policy input transform 은 `t48_hsr_features.build_cpu_input_transform` 으로 만들었고 (checkpoint 의
`assets/…/norm_stats.json` 만 읽는다), 실제 기록 state 로 7 record 전 frame × 4 prompt variant 를 돌렸다
(출력은 scratchpad, 33 s).

| "Place the {fruit} into the basket." | long · t2 · headfix · ep1800 (+ 각 swap 3) | 5 · 8 | 773 · 776 | 70–76 (state 길이에 따라) | 0 |
| "Pick up the {fruit} and place it in the basket." | ep1807 · ep1850 · ep1900 (+ 각 swap 3) | 6 · 12 | 774 · 780 | 75–81 | 0 |

- 28 (record, variant) · **1040 (frame, prompt) 에서 오류 0**. piece id: `▁apple` 15491 · `▁banana` 31985 · `▁orange` 10436 ·
  `▁pear` 21338 · `▁basket` 12220, `<bos>` 2. 모든 frame 의 text token 0 이 BOS 이고 valid token 은 prefix 를 이룬다
  (71–82 개, max_token_len 200 안).
- 명사 주변 piece (frame 0): `['▁Place', '▁the', '▁apple', '▁into', '▁the']`, `['▁into', '▁the', '▁basket', '.,', '▁State']`.
