## 0. 왜

- 외형 기반 시간 추적 (논문 설계 · T79) 은 같은 물체 두 개를 외형으로 가를 수 없다. "어느 사과가 target 인가" 는 위치 · 시간 연속성과 VLA 의도로만 정해진다.
- T75: 사과가 밀린 뒤 target 이 옛 자리에 남아 쥐지 못했다 (회귀 211). 실험 C 는 이를 통제된 조건 (이웃 없음, 정해진 이동) 에서 다시 본다.
- 학습 프롬프트 12 개에는 왼쪽 · 오른쪽 같은 위치 표현이 없다 (`meta/tasks.jsonl`). 실험 A · B 는 VLA 가 처음 보는 지시문에 어떻게 반응하는지도 함께 본다.

## 1. 구성 (두 가지)

- **VLA 단독:** 서버 `--no-safe`.
- **AG3S:** 최종 구성 + CCR 변경 확정분 = T74 Q1 (여러 초기값 풀이 · GPU 초기값 · 쥐기 목표 항 A4 뺌, `--deflection-rate-after-grasp --continuity-after-grasp`). ATS 는 최종 구성 그대로 (공 + 소유 비교, T78 표면 추출 없음). HSR 은 serving 그대로 (A9 5 단계는 serving 구현 전).
- 코드: HEAD `8ab3c7ef` + 이 STEP 의 client option (새 snapshot). 서버 코드는 T74 와 같다.

## 2. 장면 (결과 전 고정)

- 바탕: 16D dataset 의 target = apple 이고 **VLA 단독 성공 기록이 있는 episode** 2 개 (구현이 고르고 근거를 impl.md 에 적는다; 왼손 1 · 오른손 1 이면 좋다).
- **학습한 범위:** dataset `randomized_episodes.jsonl` 의 apple 초기 xy 분포 (바구니 기준, 쓰는 손별) 의 5–95 % 범위 안. 다른 물체와 표면 간격 ≥ 30 mm. 탁자 위, 떨어지지 않게 settle.
- **실험 A — 바구니 양쪽 사과 (2 episode × 프롬프트 2 × 구성 2 = 8 run):** 원래 사과는 그대로, 두 번째 사과를 바구니 반대쪽에 (바구니 중심 기준 좌우 대칭 위치에서 학습 범위 · 간격 조건을 맞추도록 가장 가까운 점).
  - 프롬프트: "Pick up the apple on the left side of the basket and place it in the basket." / "… right side …". (왼 · 오 = head 카메라 화면 기준, impl.md 에 로봇 좌표와의 대응을 적는다.)
- **실험 B — 한쪽에 같은 사과 두 개 (2 episode × 프롬프트 2 × 구성 2 = 8 run):** 원래 사과 옆 (같은 쪽, 화면 좌우 방향) 에 두 번째 사과, 표면 간격 30–50 mm, 학습 범위 안.
  - 프롬프트: "Pick up the left apple and place it in the basket." / "Pick up the right apple …".
- **실험 C — 사과 하나, 도중 이동 (2 episode × 이동 방향 2 × 구성 2 = 8 run):** 사과 아닌 과일은 모두 치운다 (`--remove-objects`), 장애물 설정 없음.
  - 이동: 쥐는 손의 손바닥–사과 거리가 처음 150 mm 아래로 내려간 제어 step 에 사과를 60 mm (화면 좌 / 우) 옮긴다. 옮긴 위치도 학습 범위 · 탁자 위. 속도 0 으로 놓는다.
- 모든 run: 같은 policy seed, 흔들림 없음, `--stop-after-place 2.5`.

## 3. 지표 (결과 전 고정, 판정 없음 — 보고)

- 공통: 금지 접촉 없는 성공 (기존 정의), 어느 사과를 쥐었나 (정답 MuJoCo), 탁자 · 바구니 접촉, 다른 사과 접촉 (금지).
- **A · B:**
  - VLA 가 프롬프트가 가리킨 사과를 집었나 (VLA 단독 · AG3S 각각).
  - AG3S target 이 요청마다 어느 사과 위에 있나 (target 점의 8 mm 정답 class 다수: 사과 1 / 사과 2 / 둘 다 / 없음) 와 VLA 가 실제로 손을 보내는 사과 (쥐는 손 손바닥과 가까워지는 사과) 가 같은가 — 요청 단위 일치율, 처음 어긋난 요청.
  - 쥐기 직전 손 층에서 지운 voxel 의 정답 class (다른 사과를 지웠나).
- **C:**
  - 이동 뒤 target 중심이 새 위치 사과 (보이는 표면 중심) 20 mm 안으로 들어오는 데 걸린 요청 수 (기한 없음, 못 들어오면 "못 따라감").
  - 이동 뒤 요청마다 옛 위치 (이동 전 사과 자리, 반지름 40 mm) 에 남은 target 점 수 · 손 층에서 지워진 voxel 수 (옛 자리 = 빈 공간을 지움) — 옛 위치가 지워지기까지 요청 수.
  - 새 위치 사과를 쥐었나.
