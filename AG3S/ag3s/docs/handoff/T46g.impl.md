## 무엇을 했나 (평이한 요약 먼저)

SL5b 실패의 기전은 "손이 물체를 들어 올리는 동안 물체가 가려지고, AG3S 는 물체의 centroid 를 마지막으로 본 자리
(테이블 위)에 남겨 두므로, 손가락 ↔ centroid 거리(`reach`)가 120 mm 를 넘어 attach 가 거절된다" 였다. 새 옵션
(`--latch-reach-hand-relative`, 기본 off) 을 켜면, 조작 대상이 이번에 **관측되지 않았을 때만** 그 마지막 관측
centroid 를 관측 frame 의 손바닥(hold link) 자세에 강체로 붙여 지금 자세로 옮긴 점에서 reach 를 잰다. 문턱
(120 mm) · 다른 check · TargetConfirm 정체 선택 · 관측된 frame 의 동작은 그대로다. 끄면 출력이 비트 동일하다
(base 와의 byte 비교, 아래).

## 설계 선택 (왜 이렇게)

1. **옮기는 식**: `c_now = T_hold(q_now) · T_hold(q_seen)⁻¹ · c_seen`, `reach = |c_now − origin_parent(q_now)|`.
   - task 의 식은 `T_parent` (손가락) 였다. **hold link (손바닥) 로 바꿨다.** 이유: 손가락 joint 는 model
     parameter 로 *이번* frame 의 측정 개도로 설정된다 (T29) — `T_finger(q_seen)` 은 q_seen 의 팔 자세에 지금 개도를
     섞은 자세가 된다. 손바닥은 손가락 joint 와 무관하다. 그리고 attach 스냅샷이 이미 hold link 에 탄다 (T32 H2) —
     latch · attach 관문 · 스냅샷이 같은 강체 가정을 쓴다. hold link = parent link 인 구성이면 task 의 식과 같다.
     진단의 `cf_hand_rel_mm` (panda_hand 로 옮기고 panda_leftfinger 원점에서 잼) 와 같은 정의다.
2. **q_seen 을 어디서**: `AG3S` (pipeline) 가 조작 대상을 **관측한 마지막 frame** (`last_seen_frame == frame`) 의
   robot_state 를 따로 하나 붙잡아 둔다 (`_manip_seen`). 이유:
   - 그 frame ↔ robot_state 대응은 pipeline 만 정확히 안다 (T32 H2 `_state_by_frame` 이 같은 자리에서 기록한다).
   - `_state_by_frame` 은 최근 16 frame 만 남기는데 SL5b 의 가림은 0–30 frame 이다 — 그 창을 늘리면 T32 H2 의
     스냅샷 동작이 바뀌므로 건드리지 않고 별도 slot 하나를 둔다. 순수 기록이라 읽는 쪽 (flag on 의 SafePolicy)
     외에는 아무것도 바뀌지 않는다.
   - **kept-anchor frame (`subset_kept_anchor` · `closing_keep_geometry`) 도 관측으로 센다** — 그 frame 에 물체는
     anchor 자리에서 관측됐다 (association 이 받아들였다). 처음 구현은 "centroid **값**이 바뀐 frame" 을 잡았는데,
     benchmark 기록에서 centroid 가 frame 0 의 값으로 고정된 채 (kept anchor) frame 16 까지 관측된 episode 가
     있었고 (V11AB-B t2), 그러면 손이 330 mm 떨어져 있던 frame 0 에서부터 옮겨 327 mm 가 나왔다. 재검에서 잡혀
     `last_seen_frame` 규칙으로 고쳤다 — T32 H2 `_snapshot_state` 와 같은 frame 이다.
   - 반환 조건: pin 의 frame = `manip.last_seen_frame`, id 같음, centroid 값 같음. 아니면 `None` → reach 는 옛 값
     (fail-closed: stale reach 는 거절 쪽이다). 기록에 `reason` 이 남는다.
3. **AG3S.attach 마지막 관문**: latch 만 통과시키면 `AG3S.attach(reach=0.12)` 가 같은 stale centroid 로 다시
   거절한다 (`revert_attach`). 그래서 hand-relative 로 통과한 call 에서만 `reach_centroid=c_now` (관문이 재는 점) ·
   `geometry_state=q_seen` (스냅샷 자세 — 16 frame 창 밖이어도 관측 frame 자세) 를 넘긴다. 둘 다 새 keyword 이고
   기본 `None` = 예전 그대로. 관문이 재는 값은 latch 의 값과 정의상 같다.
4. **observed 의 정의**: `manip.state == "visible"` 이면 그대로 (task 지시). 따라서 진단이 말한 1-call lag
   (`visible` 인데 geometry 는 직전 frame) 의 refusal 은 남는다 — 아래 재검에서 B t3 · B t8 · smoke4-A 의 첫
   attach 가 reach-only refusal 첫 call 보다 한 call 늦은 이유다.

## 알려진 한계

- **가려진 동안 미끄러지면**: carry 는 "물체가 손바닥에 강체로 붙어 있다" 를 가정한다. 가려진 채 물체가 손에서
  빠지거나 (떨어뜨림) 손이 물체 없이 움직이면 carried centroid 가 손을 따라가 reach 가 통과할 수 있다. 그때 attach 를
  막는 것은 개도 check (`blocked` · `not_empty` · `dropped` · `settled`) 와 attach 뒤 T34 revoke 창 (`opening_dropped`
  · `not_blocked` · 관측되면 `observed_elsewhere` · `not_following`) 이다 — reach 는 더 이상 그 방어선이 아니다.
  빈손 lift 를 reach 만으로 막던 경우가 있었다면 그 경우는 이 flag 에서 열린다 (재검 기록에서는 이런 call 을 찾지 않았다).
- **물체를 밀어 옮긴 경우** (손에 쥐지 않고 밀기) 도 같은 가정 위반이다.
- **kept-anchor**: 관측 frame 은 `last_seen_frame` 이고 centroid 는 anchor 의 값이다. anchor 를 지킨 동안 손이 물체를
  이미 움직이고 있었다면 (association 이 받아들인 범위 안) 그만큼 carry 의 출발점이 어긋난다.
- **visible 1-call lag** (geometry_frame = pipeline_frame − 1) 은 고치지 않았다 (task: 관측된 frame 은 그대로).
