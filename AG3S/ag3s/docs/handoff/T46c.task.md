## 3. F1 을 켠 뒤 close 이후 HOLD 가 늘어난 원인 (`T46b.verify.json`)
1. **늘어난 곳:** 늘어난 uncertified HOLD 는 전부 **과일을 놓은 뒤 (placed phase, subtask label `home`)** 다. closing · lift · carry 에서는 0 이다 (C1a 37 · F1 130 · F1F2 118 모두 placed).
2. **직접 원인 — 인증 규칙의 공백 (F1 이전부터 있었다):**
   - 놓은 뒤 VLA attention 의 상위 5 % seed 가 모두 테이블 지지면 위로 몰린다 → 지지면 mask 로 지우면 seed 가 0 → grounding = `no_seed` (`AG3S/ag3s/stages/target_grounding.py:1679-1686`, `pipeline.py:1518`).
   - placed · home 에서 subtask 인증 (`subtask_no_target`, `types.py:1069-1113`) 은 `subtask_gated` 와 `no_admissible` 만 인증하고 **`no_seed` 는 목록에 없다**.
   - 그래서 위반 행이 0 이어도 "기하 인증 없음" 으로 TO verdict 가 `violated` 로 강등되고 (`AG3S/trajopt/sqp.py:922`) HOLD 가 난다. C1aF1 에서 세 run (ep11_s111 · ep30_s301 · ep54_s541) 은 episode 끝까지 HOLD 가 이어졌다. ep54_s541 은 C1a 에서도 같고, F1 에서 새로 생긴 것은 앞의 두 run 이다 (scribe 대조로 정정, 2026-10-12).
   - 같은 HOLD 가 F1 이 없는 CL2 에도 있다: C0 (= V11AB) 73, C1a 37, C1b′ 70.
3. **F1 의 역할 — 간접:**
   - 그 HOLD chunk 130 개에서 F1 경로는 **한 번도 돌지 않았다** (target 이 없으니 F1 이 동작할 대상이 없다).
   - F1 이 바꾼 것은 grasp 직전 field 다 (점 1–12 개 제외). 그 결과 18 쌍 중 12 쌍의 궤적이 grasp 직전 window 에서 처음 갈렸다.
   - 궤적이 달라지면 놓은 뒤의 자세 · attention 도 달라지고, 그중 `no_seed` 에 빠진 run 이 F1 에서만 3, C1a 에서만 0, 둘 다 1 이었다 (p = 0.25 — F1 이 계통적으로 늘린다고 말할 수 없다).
4. **고칠 곳:** F1 이 아니라 인증 규칙. phase-gated F1 (close 뒤 F1 off) 은 0/130 chunk 만 바꿔 효과가 없다.
