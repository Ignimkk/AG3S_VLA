## 1. 문제 제기 — attention만으로는 "지금 무엇을 하는 중인지" 모른다

**한 줄 메시지:** 같은 attention이라도 작업 단계를 모르면, 들고 가는 동안과 놓은 뒤에 엉뚱한 물체를 "지금 다루는 물체"로 잡는다.

**그림:** `AG3S/ag3s/docs/figures/ppt-1013/t59-ppt-timeline-ep1809-key-N1.png` (크게, 슬라이드 폭의 대부분)

**슬라이드 글 (그림 옆이나 아래, 3줄 이내)**
- attention만 쓰면: 들고 가는 동안 10 frame 중 8 frame에서 다른 과일을 잡거나 아무것도 못 잡음
- 놓은 뒤에도 이미 바구니에 넣은 banana를 다시 잡으려 함
- 작업 단계를 함께 보면: 들고 가는 동안 banana 유지, 놓은 뒤 비움

**대본**
교수님, 먼저 왜 이 작업이 필요했는지 실제 기록 하나로 말씀드리겠습니다.
저희 시스템은 VLA가 이미지에서 어디를 보는지, 즉 attention을 이용해 로봇이 "지금 다루는 물체"를 정합니다. 그리고 그 물체에 대해서만 손가락이 닿는 것을 허용하고, 나머지 물체는 모두 장애물로 취급해 충돌을 피하게 합니다. 그래서 어떤 물체를 "지금 다루는 물체"로 보느냐가 안전에 직접 연결됩니다.
이 그림은 로봇이 banana를 집어 바구니에 넣는 실제 실행 기록입니다. 가로축은 시간이고, 한 칸은 로봇이 VLA에게 동작을 한 번 요청하는 단위로 약 0.5초입니다.
맨 위 줄은 시뮬레이터가 알려 주는 실제 상태입니다. 하늘색은 banana를 쥐기 전, 파란색은 두 손가락으로 banana를 들어 올린 상태, 남색은 바구니 안에 놓은 뒤입니다.
둘째 줄은 이번에 만든 HSR이 판단한 작업 단계입니다. 주황은 집으러 가는 중, 분홍은 옮기는 중, 빨강은 놓고 돌아가는 중입니다. 실제 상태와 거의 같은 시점에 바뀌는 것을 보실 수 있습니다.
셋째 줄은 작업 단계를 모른 채 그 순간의 attention만 보고 물체를 골랐을 때입니다. 초록은 banana를 맞게 고른 것, 주황은 다른 과일, 빈칸은 아무것도 고르지 못한 것입니다. 쥐기 전에는 잘 고르지만, banana를 들어 올리는 순간부터 10번 중 8번 틀립니다. 이때 VLA의 attention이 들고 있는 banana가 아니라 가야 할 바구니 쪽으로 옮겨 가기 때문입니다. 그리고 바구니에 놓은 뒤에도 이미 넣은 banana를 다시 다룰 물체로 잡습니다.
넷째 줄은 작업 단계를 함께 쓰는 현재 시스템입니다. 들고 가는 동안에는 banana를 계속 유지하고, 놓은 뒤에는 다룰 물체를 비웁니다. 결국 attention은 그대로 쓰되, 그것을 언제 믿고 언제 믿지 않을지를 작업 단계가 정해 줘야 한다는 것이 이 작업의 출발점입니다.
(참고: 둘째 줄의 HSR 판단은 매 순간의 판단을 그대로 표시했습니다. 실제 시스템은 같은 판단이 세 번 연속 나와야 확정하기 때문에 약 1초 늦게 바뀝니다.)

## 2. HSR 구현 — VLA를 다시 학습하지 않고 내부 상태에서 작업 단계를 읽는다

**한 줄 메시지:** VLA가 동작을 만들 때 이미 계산하는 내부 값에서, 작은 분류기 하나로 pick / place / home을 읽는다.

**그림:** 왼쪽에 도형으로 그린 간단한 흐름도, 오른쪽에 `AG3S/ag3s/docs/figures/subtask-b/subtask-b-scene.png` 의 위쪽 줄만 잘라서 (이미 잘라 둔 `doc/archive/presentations/hsr_phase_attention_20261013/crops/subtask-b-scene-top-row-compact.png` 사용 가능)

흐름도 (도형 4개, 왼쪽 → 오른쪽 또는 위 → 아래):
```
카메라 영상 + 작업 지시문 → VLA (π0.5, 그대로 사용) → 내부 값 (layer 4 의 KV cache, 512 차원으로 요약) → 작은 분류기 (logistic regression) → pick / place / home
```

**슬라이드 글**
- 처음에는 VLA가 작업 단계를 문장으로 말하게 해 봤지만 실패: 우리 모델은 그런 문장을 학습한 적이 없어 들고 가는 구간 36 frame 중 30 frame에서 엉뚱한 출력
- 대신 VLA 내부 값에서 단계를 읽는 작은 분류기를 학습
  - VLA 재학습 없음 · 판단 시간 0.1 ms 미만
  - 학습 데이터: 시연 영상의 단계 표시 (집기 / 옮기기 / 복귀)

**대본**
HSR은 Hidden-state Sub-task Recognition의 약자로, VLA 내부 상태에서 지금 하는 하위 작업을 알아낸다는 뜻입니다.
원래 저희가 쓰는 π0.5 논문에서는 VLA가 "사과를 집는다" 같은 하위 작업 문장을 먼저 말하고 그다음 동작을 만듭니다. 그래서 처음에는 그 문장을 읽어 오려고 했습니다. 그런데 저희가 fine-tuning한 모델은 그런 문장을 학습한 적이 없어서, 실제로 말하게 해 보니 들고 가는 구간 36번 중 30번이 문장이 아니라 동작 기호였습니다. 문장을 다시 학습시키려면 VLA 전체를 재학습해야 해서 이 방법은 택하지 않았습니다.
대신 VLA가 동작을 만들 때 이미 계산하는 내부 값을 꺼내서, 그 위에 아주 작은 분류기 하나만 학습했습니다. 분류기는 logistic regression이고, 입력은 이미지와 지시문을 읽은 뒤의 내부 값 512개입니다. 학습에는 시연 데이터에 이미 있는 단계 표시를 썼습니다. VLA는 전혀 바꾸지 않았고, 판단 한 번에 0.1 ms도 걸리지 않습니다.
오른쪽 그림은 실제 장면 세 개에서 분류기가 낸 확률입니다. 집으러 갈 때, 옮길 때, 돌아갈 때 각각 해당 단계의 확률이 거의 1로 나옵니다.

## 3. HSR 검증 — 단계는 잘 읽고, 그 덕분에 엉뚱한 물체를 잡는 일이 줄었다

**한 줄 메시지:** 단계 판단 정확도 0.96, 그리고 작업 단계를 쓰면 들고 가는 동안 올바른 물체를 유지하는 비율이 0.59 → 0.86.

**그림:** `AG3S/ag3s/docs/figures/ppt-1013/t59-ppt-phase-bars.png` (오른쪽 또는 아래)

**슬라이드 글 (작은 표 1개 + 한계 1줄)**

| 검증 | 결과 |
|---|---|
| 단계 판단 정확도 (실제 실행 기록) | 0.96 |
| 들고 가는 동안 올바른 물체 유지 (16 실행, 같은 순간 비교) | attention만 0.59 → 작업 단계 사용 0.86 |
| 놓은 뒤 다른 물체로 바뀐 실행 (48 실행) | HSR 없음 21 → HSR 사용 0 |
| 작업 성공 (48 실행) | 29 대 28 — 차이 없음 |

- 한계: HSR은 지시문의 물체 이름이 바뀌어도, 손에서 물체를 지워도 판단이 잘 바뀌지 않음 → 물체를 실제로 쥐었는지는 HSR이 아니라 gripper 측정값으로 판단

**대본**
검증은 세 가지로 했습니다.
첫째, 분류기 자체의 정확도입니다. 학습에 쓰지 않은 실제 실행 기록에서 단계를 0.96의 정확도로 맞혔습니다.
둘째, 작업 단계를 썼을 때 실제로 무엇이 좋아지는지입니다. 같은 16번의 실행 기록에서 매 순간 두 방식을 비교했습니다. 오른쪽 그래프에서 초록 막대가 올바른 물체를 고른 비율입니다. 쥐기 전에는 두 방식이 비슷하지만, 들고 가는 동안에는 attention만 쓰면 0.59, 작업 단계를 함께 쓰면 0.86입니다. 또 로봇을 실제로 48번 실행해 HSR을 쓰지 않았을 때와 비교해 보니, 놓은 뒤 다룰 물체가 다른 물체(이미 놓은 과일이나 테이블 위 다른 과일)로 바뀐 실행이 21번에서 0번으로 줄었습니다.
다만 작업 성공은 29번 대 28번으로 차이가 없었습니다. 이 과제에서는 그런 잘못된 물체 선택이 실패로 이어지는 경우가 드물었기 때문으로 보이며, 이 부분은 성공률 향상이 아니라 "잘못된 판단을 없앴다"로 말씀드리는 것이 정확합니다.
한계도 있습니다. 지시문의 물체 이름을 바꾸거나 손에 든 물체를 영상에서 지워도 HSR의 판단은 잘 바뀌지 않았습니다. HSR은 "물체를 쥐었다"보다 "팔이 이 자세에 있다"에 가까운 것을 읽고 있을 가능성이 있습니다. 그래서 물체를 실제로 쥐었는지는 HSR에 맡기지 않고 gripper가 닫힌 정도 같은 측정값으로 판단하도록 역할을 나눴습니다. 이 둘을 직접 비교하는 실험은 지금 진행 중입니다.

## 4. 단계별로 attention을 어떻게 쓰는가

**한 줄 메시지:** attention은 "무엇을 잡을지" 정할 때만 쓰고, 쥔 뒤와 놓은 뒤에는 작업 단계에 따라 물체의 역할을 바꾼다.

**그림:** `doc/archive/presentations/hsr_phase_attention_20261013/crops/c3_when_it_changes.png` (이미 잘라 둔 C3 패널: 다룰 물체 → 손에 붙은 물체 → 다시 장애물)

**슬라이드 글 (표)**

| 작업 단계 | attention 사용 | 그 물체를 어떻게 다루나 |
|---|---|---|
| 집으러 감 (pick) | **사용** — attention이 가장 강한 물체를 "다룰 물체"로 정함 (세 번 연속 같으면 확정) | 손가락만 그 물체에 닿는 것 허용, 나머지는 장애물 |
| 쥐는 순간 | attention이 흔들려도 다룰 물체를 바꾸지 않음 | 그대로 유지 |
| 들고 감 (place) | **사용하지 않음** — attention이 바구니 쪽으로 감 | 쥔 물체를 로봇 손의 일부로 붙여 함께 충돌 검사 |
| 놓은 뒤 (home) | **사용하지 않음** — 새 물체를 정하지 않음 | 놓은 물체를 다시 장애물로 |

- 누가 정하나: 쥔 순간은 gripper 측정값, 작업 단계는 HSR

**대본**
마지막으로 단계마다 attention을 어떻게 쓰는지 정리하겠습니다.
집으러 가는 단계에서만 attention을 씁니다. attention이 가장 강하게 가리키는 물체가 세 번 연속 같으면 그것을 다룰 물체로 정하고, 그 물체에 대해서만 손가락이 닿는 것을 허용합니다. 다른 물체와 로봇 팔의 다른 부분은 그 물체도 장애물로 봅니다.
손을 닫는 순간에는 손가락에 물체가 가려 attention이 흔들리기 때문에, 다룰 물체를 바꾸지 않고 고정합니다.
물체를 들어 올린 뒤에는 attention을 쓰지 않습니다. 앞에서 보셨듯이 이때 attention은 바구니 쪽을 보기 때문입니다. 대신 쥔 물체를 로봇 손의 일부로 붙여서, 들고 가는 동안 물체가 다른 장애물에 부딪히지 않는지 함께 검사합니다. 오른쪽 그림의 가운데 장면입니다.
놓은 뒤에는 HSR이 "돌아가는 중"이라고 판단하면 놓은 물체를 다시 장애물로 돌려놓고, 새 물체도 정하지 않습니다. 오른쪽 그림의 마지막 장면입니다.
정리하면, 물체를 실제로 쥐었는지는 gripper 측정값이 판단하고, 작업이 어느 단계인지는 HSR이 판단합니다. attention은 그 판단에 맞춰 필요한 단계에서만 씁니다.
