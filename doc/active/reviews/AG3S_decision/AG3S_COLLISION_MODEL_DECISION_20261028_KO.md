## 2. 손 — 채택 이유와 한계

### 이유

- 지금 serving 의 손 모델은 손바닥 · 손끝 몸체를 덜 덮었다.
  - 가림 장면의 막대 접촉 4 건이 TrajOpt 구 모델 밖에서 생겼다.
  - 껍질 구는 offline 에서 이 4 건을 TrajOpt 여유 −5…−13 mm 로 미리 보았다 (AG3S-PRE-CORE-TO SC).
- 같은 9 장면 × 5 흔들림 closed-loop 에서 금지 접촉 없는 성공 (출처: `AG3S/ag3s/docs/figures/pre-core-to/scmr-palm-shell-render-mask.json`):

| | VLA 단독 | 지금 serving | 껍질 구 | 껍질 구 + render mask |
|---|---|---|---|---|
| 가림 3 장면 | 15/15 | 4/15 | 11/15 | 10/15 |
| 회귀 6 장면 | 21/30 | 17/30 | 14/30 | 14/30 |
| 테이블 · 바구니 접촉 run (회귀) | 15/30 | 1/30 | 1/30 | 1/30 |

### 한계

- 회귀 장면 119 는 효과 기준 (장면 하나에서 4/5 이상 차이) 을 넘게 나빠졌다: 지금 serving 5/5 → 껍질 구 1/5.
- 회귀 6 장면 합계도 17/30 → 14/30 으로 줄었다. 효과 기준은 넘지 않는다.
- 껍질 구는 쥐기를 방해할 수 있다. offline 에서 성공 쥐기 20 run 중 12 run, 그리고 1345 오렌지 장면에서 방해가 보였다 (SC). 여유를 5 mm 로 줄여 방해 요청이 22 → 12 로 줄었지만 0 은 아니다 (SCM).
- 껍질 구의 새 위반 행 중 일부는 손 depth 가 구 mask 를 빠져나가 TSDF 에 들어간 "쥐는 손 자신" 표면이다 (1,663 중 316 = 19.0 %, AG3S-PRE-CORE-TO `numbers.LTE`).

## 4. 팔 — serving 기본값: lead 추천은 켬

### 추천 이유

1. 지금 팔 모델에는 측정된 기하 구멍이 있다 (위 표: 놓친 실제 침투 219 건, 최대 35.7 mm).
2. 그 구멍이 closed-loop 에서 실제 접촉으로 나타났다.
   - 이전 구성 (팔 덮개 없음) 의 가림 장면 기둥 접촉 1 건은 손이 아니라 손목 `link_left_arm_6` 였다 (geom 870).
   - 팔 덮개 구성은 그 장면 (가림 123) 에서 5/5 접촉 없이 성공했다.
3. 9 장면 × 5 흔들림 = 45 run 에서 금지 접촉과 성공은 이전 구성과 차이가 없다.
   - 이전 구성의 나머지 금지 접촉 7 run 은 모두 손이 이웃 과일에 닿은 것이다. 팔 링크 접촉은 0 이다.
   - 기준 재사용 확인: 팔 flag 를 끈 새 코드 2 run 이 이전 기록과 bit 단위로 같다.

| 45 run (이전 구성 = 손가락 덮개 + 껍질 구 + render mask) | 이전 구성 | + 팔 내접 덮개 |
|---|---|---|
| 금지 접촉 없는 성공 | 24/45 | 23/45 |
| 그중 가림 3 장면 · 회귀 6 장면 | 10/15 · 14/30 | 12/15 · 11/30 |
| 금지 접촉 run | 8 (이웃 과일 7 · 손목 기둥 1) | 9 (이웃 과일 8 · 권한 없는 link 가 target 1) |
| 테이블 · 바구니 접촉 run (회귀) | 1/30 | 1/30 |
| 불필요한 개입 (실제 거리 ≥ 20 mm 요청에서 0.5° 넘게 고침 또는 HOLD) | 1,034/1,536 = 67.3 % | 1,305/1,818 = 71.8 % |
| 그중 HOLD | 20 | 44 |
| TrajOpt 중앙 · 실행 창 533 ms 를 넘은 요청 | 70 ms · 119/2,167 | 246 ms · 714/2,485 |

### 한계 (켜기를 확정하기 전에 알아야 할 것)

- **이득의 closed-loop 증거가 얇다.**
  - 이 장면 묶음에서는 팔이 장애물 가까이 가는 상황이 드물다. 팔 덮개 덕분이라고 볼 수 있는 사건은 손목 기둥 접촉 1 건뿐이다.
  - 그래서 이 추천은 closed-loop 성적보다 1단계 기하 정확도에 더 기대고 있다.
- **회귀 250 이 효과 기준을 넘게 나빠졌다 (5/5 → 1/5).**
  - 진단 결과 (`outputs/2026-10-28_팔덮개_회귀250_원인진단`):
    - 팔 행은 75 요청 어디에서도 QP 가 받는 24 행에 들지 않았다.
    - 팔 덮개는 계산 끝자리 수준의 차이 (첫 요청 2.98e-8 rad) 만 만들었다.
    - 그 차이로 갈라진 궤적이 "손가락이 사과에 밀린 채 닫지 않는 상태" 에 들어갔고, 거기서 TrajOpt 해가 불안정했다 (같은 입력 재풀이 4.2–22.7° 차이). 원인 위치는 CCR.
  - 다만 팔 덮개 회차 5 회 중 4 회가 늦게 닫은 쏠림을 설명하는 체계적 경로는 찾지 못했다.
  - 우연이라면 확률은 약 2 % 다. 결과를 본 뒤 계산한 값이다.
- **개입이 조금 늘었다** (불필요한 개입 +4.5 %p, HOLD 20 → 44). 역할 3 (필요할 때만 최소로 고친다) 쪽 비용이다.
- **실행 시간이 크게 늘었다** (TrajOpt 중앙 70 → 246 ms, 533 ms 넘는 요청 119 → 714).
  - 채택 기준은 아니지만, 비동기로 실행하는 실물에서는 그대로 실행 지연이 된다. GPU 이식 작업에서 다뤄야 한다.
- **고정 필수 기준 1 은 통과하지 못했다.**
  - 놓친 실제 침투 31 건, 모두 ≤ 3.8 mm.
  - 이번 채택은 "TrajOpt 가 팔 행에 지키는 10 mm 여유 아래에서 놓침 0" 으로 읽었다. 이 해석은 결과를 본 뒤에 정했다.
- **거리장 오차의 원인이 미확인이다.**
  - 쥔 사과를 뺀 거리장 오차 p95 가 내접 덮개 13.2 mm, MorphIt 7.7 mm 다.
  - 보고 항목이고 채택 기준은 아니다.
- **50 mm target 여유가 쥐기를 방해하는지는 이 장면들에서 따로 재지 않았다.**
  - 이 여유는 팔 행이 target 에 가까울 때 적용된다.
  - 회귀 250 진단에서는 팔 행이 QP 에 들지 않아 해당하지 않았다.

### 끄기를 고를 때의 근거 (대안)

- 45 run 에서 성공 · 금지 접촉의 이득이 없고, 개입 · 시간 비용과 회귀 250 의 미해결 쏠림이 있다.
- 따라서 "팔이 장애물 가까이 가는 장면에서 이득이 확인될 때까지 꺼 둔다" 도 방어 가능하다.
- 이 경우에도 구 모델링 방법은 내접 덮개로 둔다. 다시 켤 때 형상을 새로 고를 필요가 없다.
