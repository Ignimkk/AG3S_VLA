# AG3S — 작업 의도와 기하 기반 6D grasp 목표를 이용한 TO 구현 계획

작성: 2026-10-26 KST · 상태: 구현 전 계획 · 범위: 3단계의 최소 구현과 개발 검증

## 1. 목표와 범위

**쥐기 전에는 작업 의도와 유효한 grasp 목표를 유지하면서 action chunk에서 벗어날 수 있게 하고, 파지 확인 후에는 현재 상태에서 이어갈 수 있는 작업 경로로 점진적으로 합류한다.**

| 사용자 요구 | 이번 구현 |
|---|---|
| 로봇이 경로에 끌리는 듯한 움직임 완화 | 현재 chunk 추종·이전 계획 연속성·회피 수정 이력의 영향을 기록하고, 유효한 grasp 목표가 있을 때 단계별로 조절 |
| TO가 grasp 가능한 6D pose 추종 | 손의 위치·회전 목표와 사전 접근 자세를 명시하고 닫기 조건까지 연결 |
| ATS·HSR·LTE가 작업 의도 보존 | 공유 작업 상태에 타겟·단계·접촉 규칙·선택한 grasp를 유지 |
| 포인트클라우드의 기하 관계 활용 | 타겟 표면 접촉점·법선과 실제 그리퍼 패드 형상으로 grasp 후보 생성 |

첫 범위는 **현재 사과 작업·한 팔·평행 2지 그리퍼**다. 새 학습 모델, 전역 planner, 일반 물체 전체 지원, VW 시야 비용 구현은 포함하지 않는다. 기존 솔버·ATS·HSR·LTE를 재사용한다. 새 기능은 독립적으로 끌 수 있고 기본은 꺼짐이다.

근거: DX3에서 연속성 항을 끄자 121–123의 안전한 작업 성공이 0/3→3/3으로 회복됐으나, 사전 거리 기준 ≤16 mm는 미충족이다. 이것을 종합 통과로 바꾸지 않는다. 기존 E1은 위치 목표 중심이며, E2·E3의 가림 발동 68 chunk에는 활성 grasp 목표가 없었다.

## 2. 단계 1 — 작업 상태와 기하 grasp 후보

**공유 상태 하나를 만든다.** ATS가 타겟 identity·표면·신뢰도를, HSR이 단계·파지 확인을, LTE가 허용 접촉을 제공한다. 각 모듈에 별도 의도 기억을 중복 구현하지 않는다.

- 상태: `target_id`, `phase`, 관측 시각·신뢰도, 접촉 후보 영역, 선택한 `grasp_id`, `T_world_gripper`, 개구폭, 사전 접근 자세, 허용 접촉 쌍, 유효/무효 사유.
- 타겟 identity와 선택한 접촉 관계는 chunk가 바뀌어도 유지하고, 자세는 관측으로 갱신한다. 타겟 변경·추적 상실·후보의 충돌/도달 불가 시 무효화한다. 후보 점수의 작은 변화만으로 매 요청마다 다른 grasp로 바꾸지 않는다.
- 사과처럼 대칭적인 물체의 불안정한 전체 회전 추정에 의존하지 않고, 추적된 중심·접촉 영역과 이전 후보의 일관성으로 갱신한다.

**기하 후보는 최대 8개만 반환한다.** ATS의 타겟 점군에서 표면 법선을 구하고, 두 패드가 서로 반대쪽에서 누를 수 있는 접촉점 쌍을 생성한다. 개구폭·패드 면적·법선 방향·가정한 마찰 범위를 확인한다. 두 점의 연결 방향으로 닫힘 축을 정하고, 남은 회전·접근 깊이는 소수의 방향을 샘플링한다. 패드 좌표에서 손목 좌표로 변환해 6D pose와 사전 접근 자세를 만든다.

- 그리퍼 전체와 주변 물체의 충돌, IK, 접근 구간을 검사한다. VLA는 유효 후보 사이의 접근 선호를 정하는 보조 정보로 사용한다.
- 관측되지 않은 반대쪽 표면을 빈 공간이나 확정 접촉면으로 취급하지 않는다. 누적 관측으로도 지지되지 않는 후보는 제외하고, 후보가 없다는 결과를 허용한다. 시뮬레이터 정답 기하는 평가에만 사용한다.
- 후보 검사는 도달 가능성의 사전 필터이며, 실제 경로의 안전성은 TO 반환 궤적 전체 검사로 확인한다. 알려진 손바닥 구 공백을 안전하다고 간주하지 않는다.

**완료 조건:** 기록된 점군에 후보·접촉면·그리퍼를 겹쳐 시각화하고, 좌표 변환·법선·개구폭·IK·충돌·후보 무효화 검사를 통과한다. 관측/마찰/pose 허용오차/갱신 문턱과 계산량 상한은 closed-loop 전에 설정 파일에 고정한다.

## 3. 단계 2 — 6D 목표와 단계별 TO 연동

기존 `grasp_anchor.py`의 위치 목표를 확장한다. 위치 오차와 회전 오차 `Log(R_goalᵀ R_hand)`에 각각 허용 범위를 두고, 비용·Jacobian·수락 검사·최종 기록에 같은 정의를 사용한다. 후보 생성/선택은 TO 밖에서 하고, 한 번의 풀이 중에는 선택한 목표를 고정한다.

| 단계 | TO 목표와 action chunk의 역할 |
|---|---|
| 접근 | 사전 접근 자세를 향한 진행을 유도. 유효한 기하 목표가 있을 때만 VLA 추종 비중을 낮추고 이전 계획에 끌리는 항을 완화. 먼 grasp를 짧은 horizon 끝에 강제로 도달시키지 않음 |
| 쥐기 | 위치·방향·접촉 영역을 맞춘 뒤 목표 폭으로 닫기. 손바닥–사과 거리 하나로 닫기를 결정하지 않음. 지정된 패드–타겟 접촉만 허용하고 손바닥·이웃·장애물 제약은 유지 |
| 파지 확인 후 운반 | 실제 파지 확인 전에는 들어 올리기로 전환하지 않음. 쥔 물체 형상을 포함해 검사하며, 최신 관측으로 재생성된 VLA 경로에 추종 비중을 점진적으로 복원. 과거 chunk의 시간 인덱스를 따라잡지 않음 |

- 구현 초깃값: 유효 grasp가 있는 접근·쥐기에서 `track_scale=0.25`, 연속성 가중치 0, 수정량 이력 항은 기준선 값을 유지한다. 운반에서는 3요청에 걸쳐 추종 비중을 기준선으로 복원한다. 이는 시험할 가설이며 검증된 설정이 아니다. 이력·목표는 전환 시 새 상태와 정렬하고, 속도·가속도 제약은 계속 적용한다.
- 목표 오차를 줄이려고 금지 접촉을 수락하지 않는다. 기존 안전 검사를 통과하지 못하면 목표 후보를 거절한다. 새 목표가 GPU seed 풀이에도 같은 의미로 적용되는지 검사하고, 미지원 경로는 조용히 목표를 생략하지 않고 명시적으로 비활성화한다.
- 기하 제어 시작 전에 후보가 없으면 기존 안전 경로로 동작하고 사유를 기록한다. 시작 후 목표를 잃으면 닫기를 중단하고 1회 재선정한다. 재선정 실패 또는 사전 고정한 진행 제한시간 초과는 안전 정지와 실패로 기록한다. 무기한 HOLD를 성공으로 세지 않는다.
- 기록: VLA 원본/TO 수정/실제 손의 위치·방향, 활성 비용항, 목표 오차, 후보 전환, 닫기·파지 확인, 경계 속도·가속도, 추종 오차, 금지 접촉, 처리 시간. 기하 목표가 실제 활성화된 구간의 수를 반드시 센다.

**구현 위치:** 공유 상태·후보 생성은 `AG3S/ag3s/`에 작은 모듈로 추가하고 `runtime/pipeline.py`의 ATS 결과에 연결한다. TO 연결은 `trajopt/safe_policy.py`, `grasp_anchor.py`, `refiner.py`, `sqp.py` 및 설정·CLI에서 한다. 기존 identity·HSR·접촉 권한 자료구조와 연결하며 새 상태 머신을 중복하지 않는다.

## 4. 단계 3 — 작은 비교 후 한 번의 전체 검증

**기준선:** 진행 중인 C0F(연속성 끔, 가림18·회귀18) 결과를 먼저 정리하고, 채택된 설정·코드 snapshot·장면·seed를 고정한다. 결과 전에는 연속성 끔을 전역 채택했다고 가정하지 않는다. SC 형상 보정과 VW를 이번 변경에 섞지 않는다. 형상 구성을 변경해야 한다면 모든 비교군에 동일 적용하고 기준선을 다시 확보한다.

| 비교군 | 설정 | 목적 |
|---|---|---|
| B0 | 고정한 기존 기준선 | 비교 기준 |
| B1 | B0 + 작업 상태·기하 6D 목표·닫기 제어 | 기하 목표의 기여 |
| B2 | B1 + 단계별 추종/연속성 조절·운반 복귀 | 과도한 경로 추종 완화의 추가 기여 |

1. **Offline·단위 검증:** 기능 꺼짐 출력 동일, 작업 상태 유지/무효화, 6D Jacobian, 접촉 권한, 목표–안전 충돌 시 안전 우선, 파지 전환과 추종 복원. 기존 기록 replay의 한계와 실제 실행 이력 의존성을 구분한다.
2. **Pilot:** 121–123과 321–323의 6 run에서 B0/B1/B2 비교. 후보 없음·목표 비활성도 실패/미작동으로 남기고 분모에서 빼지 않는다. 새 구성의 안전한 성공이 B0보다 늘고 금지 접촉이 늘지 않을 때만 다음으로 간다. 둘 다 통과하면 안전한 성공 → 접촉 감소 → 단순한 구성(B1) 순으로 하나를 고른다.
3. **전체 검증 1회:** 선택한 하나만 기존 가림18·회귀18에서 검증한다. 동일 설정의 유효한 기존 B0 기록은 재사용한다. **가림 안전한 성공 B0 대비 +1 이상, 회귀 안전한 성공 감소 없음, 각 집합 금지 접촉 run 증가 없음**을 개발 채택 기준으로 둔다. 장면별 성공→실패 변화도 별도 보고한다.

추가 통과 조건은 속도·가속도 한계 초과 증가 없음, 기하 계산을 포함한 TO 구간 p95 ≤533 ms(8 step 실행 창)다. 경계 명령 변화·실제 추종 오차·전체 요청 지연도 비교한다. 6D 오차와 손바닥–사과 거리는 원인 설명 지표로 보고하며, 기존 DX3 거리 기준을 사후 변경하지 않는다. 작은 개발 장면의 결과를 일반화 성능 주장으로 쓰지 않는다.

**중단 조건:** pilot 또는 전체 기준 미통과 시 실패 원인과 다음 최소 변경 1개만 제안하고 종료한다. 후보 수 확대·새 planner·추가 학습·연속적인 가중치 탐색으로 자동 확장하지 않는다.
