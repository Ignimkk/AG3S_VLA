# agents map — 누가 무엇을 내는가

역할 **정의**는 `.claude/agents/*.md`, 소유권 **차단**은 `.claude/roles/*.settings.json`,
띄우기는 `launch.sh`. 이 파일은 **남은 게이트에서 누가 무엇을 산출하는가** 하나만 답한다.

## 산출물 계약

```
A0 lead ──<G>.task.md──► A1 ──<G>.impl.md──► A2 ──<G>.verify.json──► A3 ──► 로그 + PLAN
         무엇을 왜          코드가 뭐가 바뀌었나   수치 · figure          확정된 것만
```

**A3 는 `verify.json` 의 `numbers` 에 없는 숫자를 쓰지 않는다.** A1 이 스크립트를 돌리다
흘린 숫자도 쓰지 않는다 — 그건 측정이 아니라 부수물이다.

| 역할 | 모델 · effort | 산출 | 절대 안 하는 것 |
|---|---|---|---|
| **A0** lead | opus · high | `<G>.task.md` · PLAN · 판정 진행 · **긴 실행 직접 기동** | 코드·문서·figure 를 직접 고치기 |
| **A1** 구현 | opus · high | `benchmark/**/*.py` · `tests/**` · `<G>.impl.md` | 측정, 로그 쓰기 |
| **A2** 검증 | opus · high | `docs/figures/**` · `<G>.verify.json` · `outputs/verify/**` | 코드 수정, 해석·판정 쓰기 |
| **A3** 기록 | sonnet · high | `docs/*.md` · `papers/**` | 코드, 실험, figure |

## 남은 게이트 — 누가 붙나

| 게이트 | 무엇을 묻나 | 주 담당 | 앞서 필요한 것 |
|---|---|---|---|
| **T1** 연속 프레임 AG3S | 지각이 쓸 만한가 (target 중심·지지면·카메라 정렬 오차, 로봇 마스크, completeness, frame card) | **A2** | 없음 — 기록·attention 준비됨 |
| **T2** pick-place 상태 전이 | 9 개 사건이 어느 프레임인가 | **A2** | 파지 포함 긴 기록 |
| **T3** 전 프레임 TSDF/ESDF | 모든 프레임에서 필드가 서나. `max_field_age_sec` 를 정한다 | **A2** | T1 |
| **T4** fail-closed 주입 | 고장을 넣으면 정말 닫히나 | **A1** → A2 | 주입 지점을 코드로 열어야 한다 |
| **T5** shadow 루프 | 판정만 하고 실행은 안 하는 루프가 서나 | **A1** → A2 | AG3S 를 클라이언트 in-process 로 |

| — 실시간성 | 청크 예산 533 ms 안에 드나 | **A1** → A2 | T6 전에 닫아야 한다 |

**T1~T3 은 측정이 본체라 A2 가 끌고 간다.** T4~T6 은 코드를 먼저 열어야 해서 A1 이 앞선다.

## agent 는 lead 에게 메시지를 못 보낸다

`SendMessage` 로 `lead` 를 부르면 **`No agent named 'lead' is reachable`** 이 난다. subagent 는
자기를 띄운 대화로 **결과를 돌려주는 것**이 유일한 통로다. 그래서:

- **"돌리기 전에 알려라" 같은 사전 통지를 agent 에게 요구하지 않는다.** 할 수 없다.
  겹치면 안 되는 실행(무거운 테스트·MuJoCo 측정)은 **A0 가 순서를 잡아 준다.**
- agent 가 중간에 판정을 받아야 하면 **거기서 멈추고 보고하게** 한다. 그 다음은 A0 가
  `SendMessage` 로 이어 붙인다 (A0 → agent 방향은 된다).
- agent 끼리도 서로 못 부른다. 산출물은 **파일로** 넘긴다 (`handoff/`).

## 규칙 — 오늘까지 값을 치르고 배운 것

- **긴 실행은 agent 안에 넣지 않는다.** A0 가 `python -u` + `nohup` 으로 띄우고, agent 는
  떨어진 파일만 소비한다. agent 는 세션과 함께 죽지만 프로세스는 산다.
- **한 agent = 한 산출 파일.** 쪼개면 중단돼도 한 조각만 잃는다.
- **브리핑에 숫자를 박고 "이 밖은 쓰지 마라"를 명시한다.** 열어 두면 모델이 클수록 그럴듯하게 채운다.
- **A1 과 A2 를 한 사람에게 몰지 않는다.** 고친 사람이 스스로 재면 기대한 것이 보인다.
- **세션 후반에 새 agent 를 띄우지 않는다.** 중단되면 그 조각을 통째로 잃는다.

## 세션과 context — 어디서 끊나

**context 가 몇 % 인지보다 "지금도 같은 일인가" 를 먼저 묻는다.** 30 % 여도 일이 바뀌면 끊는
것이 맞고, 70 % 여도 같은 문제를 파고 있으면 `/compact` 로 잇는 것이 맞다.

| 지금 상태 | 어떻게 |
|---|---|
| 같은 일 · context 깨끗함 | 그대로 간다 |
| 같은 일 · 실패한 시도와 옛 탐색이 쌓였다 | `/compact` — **남길 것을 명시한다** (architecture · 고친 파일 · 확정된 원인 · 수치 · 남은 TODO. 실패한 접근과 옛 log 는 버린다) |
| 다른 일로 넘어간다 | `/clear` |
| 이 일로 되돌아올 가능성이 있다 | 새 세션을 띄운다 — 지금 세션은 남겨 둔다 |
| 탐색은 많이 필요한데 본 세션에는 결과만 필요하다 | sub agent |

**`/compact` 로 줄지 않는 것이 있다.** hook 이 매 턴 붙이는 규칙 본문은 다음 턴에 또 붙는다 —
규칙 파일을 줄이는 것 말고는 방법이 없다 (꺼 둔 규칙 B·H 를 hook 에서 뺀 이유다).

### sub agent 의 context 는 크게 써도 된다

**"context 를 50 % 넘게 쓰지 마라" 같은 상한을 두지 않는다.** 한 가지 일을 하면서 80~100k 를
쓰는 것은 문제가 아니다. **100k 는 상한이 아니라 "일이 너무 큰가" 를 묻는 신호다** — 넘으면
이것부터 본다: 독립된 일 여럿이 한 덩이로 묶였나 · 필요 없는 log 나 파일을 퍼 읽고 있나.
이식 8 건을 한 agent 에 몰아 419k 를 쓴 것이 그 예다.

**좁히는 수단은 셋이고, 이 harness 에서 실제로 걸 수 있는 것도 셋이다.**

| 무엇을 | 어떻게 |
|---|---|
| **일의 크기** | 한 agent = 한 산출 파일. 쪼개면 중단돼도 한 조각만 잃는다 |
| **손에 쥔 도구** | 정의의 `tools` 에서 뺀다 — A2 에 `WebSearch`·`WebFetch` 가 없는 이유다. 소유권은 `roles/*.settings.json` 의 deny 로 막는다 (`Edit` 과 `Write` 를 **둘 다**). 단 `Bash` 로는 우회된다 |
| **모델과 effort** | 위의 모델 표. 개념을 다루면 올리고, 정해진 칸을 채우는 일이면 내린다 |

**`maxTurns` 는 여기 없다.** Agent SDK 와 `claude -p --max-turns` 의 것이고 대화형 세션의
Agent tool 에는 그 파라미터가 없다 (2026-09-25 확인). turn 을 세는 대신 위의 셋으로 좁힌다.

### 본 세션에 돌려주는 것은 요약이 아니라 파일이다

agent 가 안에서 80k 를 읽었어도 돌려주는 것은 **산출 파일 경로 + 세 줄 상태**다. 요약을
돌려받지 않는 이유는 둘이다 — 요약은 손실이 있어 나중에 감사할 수 없고, **세션이 죽으면 함께
사라진다.** 파일은 남아서 `한 세션 = 한 STEP` 의 재개를 성립시킨다.

**중단은 세션을 끝낼 때만 오지 않는다.** network 가 끊겨 재시도가 소진되면 그 agent 의 turn 이
실패하고 **쌓아 둔 context 는 checkpoint 없이 0 이 된다** — 세션 전체가 끝나지 않아도 그렇다.
2026-09-25 의 700k 손실이 어느 쪽이었는지는 기록에 없다. 어느 쪽이든 규칙은 같다:
**agent 의 context 는 어떤 이유로든 중단되면 0 이고, 파일에 떨어진 것만 남는다.**
