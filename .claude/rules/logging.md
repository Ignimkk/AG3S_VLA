# 기록 규칙 — 이 파일들을 만질 때만 들어온다

**`AG3S_T0T6_LOG.md` 가 정본이다. 여기에 이어 쓴다. 새 기록 파일을 만들지 않는다** (규칙 D).
단, Panda/LIBERO 계열 benchmark 단계(SL-0~, P1~)는 사용자 지시(2026-10-12)로 `AG3S/ag3s/docs/AG3S_BENCHMARK_LOG.md` 가 정본이다.
옛 `AG3S_REVIEW_LOG.md` 는 모듈 검토 국면의 archive 다 — 2026-09-24 부터 이어 쓰지 않는다.
발견 번호(`E3`·`F19`·`C5`·`N2` …)의 **원 측정**을 찾을 때만 그리로 간다.

**병렬 세션에서는 이 파일의 writer 가 `ag3s-scribe` 하나다.** 다른 역할이 로그를 고치면
같은 절을 두 번 쓰거나 서로 덮어쓴다. 네가 scribe 가 아니면 `AG3S/ag3s/docs/handoff/` 로 넘겨라.

## 무엇을 쓰는가 (규칙 H)

**구현과 검증의 기록이다.** 코드가 무엇이 바뀌었고 무엇을 수치로 확인했는지만 남긴다.
발표 자료·슬라이드·대본·에이전트 설정처럼 산출물을 만든 과정은 쓰지 않는다.

## 어떻게 쓰는가

- **모든 수치는 `AG3S/ag3s/docs/handoff/<STEP>.verify.json` 의 `numbers` 를 출처로 갖는다.** 출처 없는
  숫자는 쓰지 않는다 — 필요하면 verifier 에게 측정을 요청한다. (*추측을 기록에 남기지 않는다*)
- **규칙 A** — figure 를 `AG3S/ag3s/docs/figures/` 경로로 링크한다. 숫자를 문장 안에 흩어 놓는 것은
  시각화가 아니다. 단면 그림에는 어디를 어느 방향에서 잘랐는지 배치도가 함께 있어야 한다.
- **규칙 C** — 새 용어는 그 자리에서 풀어 쓰고 로그의 **"용어"** 절에 추가한다.
- **규칙 G** — 발견 ID 를 그냥 쓰지 않는다. `E3(쥔 물체가 optimizer 에 도달하지 않는다)` 처럼
  그 자리에서 한 줄로 푼다. 스텝 번호도 같다.
- **규칙 I** — 기술 용어는 영어로 쓴다. **이 문서의 옛 줄들이 한국어 번역어를 쓰고 있어도
  새로 쓰는 문장은 따라가지 않는다.** 옛 줄을 고치러 다니지는 말되, 새 문장에는 아래 왼쪽을
  쓰지 않는다:

  | 쓰지 않는다 | 쓴다 |
  |---|---|
  | 문턱 · 점수 문턱 | `threshold` · `score threshold` |
  | 여유거리 | `clearance` |
  | 미세 계층 · 거친 계층 | `fine layer` · `coarse layer` |
  | 화소 | `pixel` |
  | 무게중심 | `centroid` |
  | 복셀 | `voxel` |
  | 잠금 | `latch` |
  | 덩어리 | `cluster` |

  그 밖에도 같은 원칙이다: `violated` · `feasible` · `swept volume` · `eikonal` · `carving` ·
  `grounding` · `attention` · `chunk`. **사용자가 여러 번 지시한 규칙이고 세 번 어겼다.**
- **규칙 F** — 수행한 내용은 `AG3S_REVIEW_PLAN.md` 의 계획에도 반영한다.
- 갈림길에서 고르지 않은 선택지는 **"되돌아올 지점"** 절에 전환 신호와 함께 남긴다.
